# 2 · 方法库

可复用的研究方法放这里；方法资产的权威正文在此维护，**不回写本体**。单次任务选了哪个方法、得出什么结论，写在 [`instances/`](../instances)，不写回本库。

| 编号 | 目录 | 回答什么 |
|------|------|----------|
| 00 | [`00_登记`](00_登记) | 方法能力总表（系统用，人一般不用翻） |
| 02 | [`02_判断结构`](02_判断结构) | 这类问题通常怎么拆、选哪个框架 |
| 03 | [`03_取证`](03_取证) | 要什么证据、去哪找、完备度最高到哪 |
| 04 | [`04_裁决`](04_裁决) | 证据够了之后，判断说到多强、何时改判 |

编号与研究阶段对齐：做 02 时主要看判断结构，做 03 时看取证，做 04 时看裁决。

注意：取证方法编号是 A01—A09，裁决方法也是 A01—A10，**名字撞号但含义不同**。引用时写清「取证 A0x」或「裁决 A0x」，系统侧分别记为 `kb03` / `kb04`。

## 统一方法定义合同

[`00_登记/method_assets.yaml`](00_登记/method_assets.yaml) 是方法 ID、版本和能力类型的唯一登记入口，当前版本权威为：判断结构 `2.0.0`、取证 `3.2.0`、裁决 `1.0.0`。每个方法必须能解析出适用条件、前置条件、输入、输出、不适用条件、降级策略、替代方法和反例；缺任一项均不得进入当前发布。

- 判断结构方法从 `entry_requires`、`output_gates`、`quality_gates` 和交接关系派生统一合同。
- 取证方法在 `03_取证/03_registry.yaml` 的各方法 `contract` 中定义。
- 裁决方法在中心登记表中定义；`kb04:A00` 是全局通用裁决方法，也必须登记和校验。

方法定义只描述“怎样使用”。某次研究是否选用、为何拒绝、绑定了哪些证据及输出了什么，必须写入 `MethodApplication`，不得回写方法资产。
