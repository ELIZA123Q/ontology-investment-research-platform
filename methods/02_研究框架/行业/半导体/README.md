# 半导体行业框架库

先选 **1 个主框架**回答核心机制；有产品 / 技术 / 事件特有增量时再挂 **0—1 张场景卡**。场景卡是差异适配器，不是缩小版主框架。需要核对进入条件与可写到哪一层时，见根目录依赖说明。

## 研究员最短路径

1. 用一句话写清本次问题的产品、环节、客户、地区和时间；
2. 判断核心分歧属于周期、国产替代、应用需求、设计商业化、制造、封装、设备还是材料；
3. 选 1 个主框架；有明确场景增量时再选 0—1 张场景卡（复杂卡先定一个互斥主判断模式）；
4. 输出主路径、竞争解释、什么事实会推翻它，以及交给 03 的决胜证据；裁决由 04 决定。

想的时候可以对照看几个候选；写入 02 时每个关键判断单元只留 1 个直接框架（详见[框架库 README「怎样选用」](../../README.md#3-怎样选用)与[选用细则](../../../../runtime/workflow/stage_specs/02_结构/02_附录1_框架裁剪与选用细则.md)）。

## 1. 理解半导体的五个共同规律

1. **多时钟**：终端、订单、库存、价格、投片、良率、产能和收入确认不同步；
2. **强分层**：产品、节点、晶圆尺寸、客户和地域混在一起时，总量结论经常失真；
3. **有效供给小于名义供给**：认证、良率、关键工序、设备材料和系统配套会折损；
4. **技术成功不等于商业成功**：样品、验证、design win、量产、复购和现金是不同阶段；
5. **产业受益不等于公司兑现**：产品暴露、客户结构、产能、成本、合同和财务确认决定最终弹性。

主框架围绕稳定机制，并在「洞见层」给出领先/滞后关系、状态组合→区分性预测、利润池控制者与承担者。场景卡只补特殊约束。**暂时不新增主框架**；新机制优先下场戏卡，并由真实任务触发。

### 3.1 常见交接

```text
IF-APP-01 净内容量/消耗候选 → IF-SC-01 周期时钟
IF-DES / FAB / PKG / EQP / MAT 准备度 → BF-EE-01
IF-LOC 读取下游采用阶段，输出约束相对反事实的增量
市场通道（地缘情绪/估值）→ BF-EG / BF-RS / BF-VA，不在产业场景卡内推股价
部署/利用、SOP/装车等 → 对应场景卡增量，不塞进 APP 通用桥
```

### 3.2 怎样组合

判断单元级默认：**1 个主框架（作直接框架或行业增强）+ 0—1 张主要场景卡**；需要通用机制时再先后接基础框架前置 / 下游。不要因「可能相关」并列多个主机制。每个框架可含洞见层：领先滞后、组合预测、利润池线索、反常组合。先后接上的前置或下游，不算同时并用了多个框架。

## 6. 选用规则

服从 02 三层选用（见 [`02_框架裁剪与选用细则`](../../../../runtime/workflow/stage_specs/02_结构/02_附录1_框架裁剪与选用细则.md)）：

- **探索可多看、落盘要收敛**：对照候选可以；每个关键判断单元正式只留 1 个直接框架。
- **场景卡**挂判断单元，最多 1 张主要场景卡；是可选适配器，不是硬前置；没用不必解释。复杂卡先选互斥主判断模式。
- **行业主框架**常作本单元的直接框架或行业增强；**基础机制框架**常作必要前置——叠加，不是二选一。
- 需要核对进入条件与可写到哪一层时，见根目录依赖说明；先后接上的前置或下游，不算同时并用了多个框架。
- 02 形成候选、03 取证、04 裁决；行业框架不直接生成收入、利润或估值。

## 7. 系统登记（维护用）

暂不新增主框架。新机制先场景卡；模拟/MCU 渠道周期、先进节点晶圆经济性等须由真实任务重复触发后再建卡。

每主框架至少：1 个成立案例 + 1 个高迷惑性失败案例，方可记为已通过两次真实任务验证。推荐失败方向见各框架组合节。

**禁止**：把部署利用当全应用必经环节；把备份设备当主工艺突破；把无口径国产份额当韧性；把模块收入当芯片价值；在地缘场景卡内直接推股价；从行业供需跳估值；存储长协叙事直接当估值切换。
