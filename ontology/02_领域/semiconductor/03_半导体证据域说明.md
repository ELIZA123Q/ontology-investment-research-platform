# 半导体证据域说明

## 研究员先看什么

说明各类判断变量需要什么证据、反证、口径与时效，以及不足/冲突时如何降级。继承一级证据对象，不重定义存储与抽取。

研究时用它：某类问题（需求订单、产能供给、认证量产……）通常要哪类证据组合；质量维度怎么看；商业化阶段说到哪一层。

> 12 类证据画像权威：`business_instances.yaml`。`evidence.yaml` 定义质量维度、来源原则、商业化阶段与覆盖规则。

---

## 1. 域定位

半导体证据域说明每类判断变量需要什么证据、什么构成反面证据、口径和时间如何对齐，以及证据不足或冲突时如何降级。

本域继承平台的 SourceDocument、EvidenceClaim、EvidenceFact 和证据关系，不重新定义材料存储、抽取、归一和冲突对象。

领域证据要求围绕判断变量组织，而不是围绕数据库、数据供应商或接口字段组织。

状态变量到证据画像的绑定写在 `business_instances.yaml` 的 `StateVariable.evidence_profile_ref`（单向）；`reasoning.yaml` / `evidence.yaml` 只通过 `business_instance_graph_ref` 指向该图，不在画像中反向列举状态变量。`evidence.yaml` 另定义质量维度、商业化阶段和最低覆盖规则。

半导体证据画像不替代一级证据对象，而是作为 03 生成 `EvidenceRequirement`、`EvidenceBasket`、`SourceProfile`、`AcquisitionChannel`、`ProxyIndicator` 和 `EvidenceReadinessAssessment` 的领域配置。比如 `inventory_cycle` 证据画像会展开为库存、多层库存反证、终端需求对照和代理指标折扣等必要证据组合与「证据是否够用」要求。

## 2. 商业化阶段

`commercialization_stages` 定义八个稳定阶段：概念 → 样品 → 认证 → Design Win → 试产 → 量产 → 复购 → 规模采用。认证类证据画像要求标明所处阶段，不得混用。

## 3. 证据在推理中的位置

```text
SourceDocument
→ EvidenceClaim
→ EvidenceFact
→ EvidenceRequirement / EvidenceBasket / EvidenceReadinessAssessment
→ Event / Observation / Signal
→ StateVariable / Hypothesis
→ Judgment
```

证据不能绕过关键变量、假设、其他可能解释和预期比较直接产生判断或资产影响。

## 4. 变量与观测分离

关键变量定义观察口径，Observation 记录某一业务时间的具体事实或明确来源估算。

| 内容 | 正确承载方式 |
|---|---|
| 供给可得性 | StateVariable |
| 某时点可交付数量或交期 | Observation |
| 良率成熟度 | StateVariable |
| 某工厂某批次良率 | Observation |
| 库存周期位置 | StateVariable |
| 某季度库存数量和覆盖期 | Observation |
| 技术成熟度 | StateVariable |
| 某路线通过某项验证 | Observation 或 Event |
| 市场一致预期水平 | StateVariable / MarketExpectation |
| 某机构在某时点的预测 | EvidenceClaim / MarketExpectation |

公司指引、分析师预测、目标价和方向性观点不是已发生的 Observation。它们可以作为 Signal、Hypothesis 的依据或 MarketExpectation，但必须保留其表述性质。

## 5. 证据质量维度

`evidence.yaml` 从六个维度评价证据：

| 维度 | 核心问题 |
|---|---|
| 来源权威性 | 来源主体是否有权掌握并披露该信息？ |
| 可追溯性 | 能否定位到原文、表格、页码、记录或数据口径？ |
| 独立性 | 多条证据是否真正独立，而非相互转述？ |
| 时间相关性 | 业务时间是否覆盖当前判断窗口？ |
| 范围匹配 | 产品、地域、客户、工艺和统计口径是否一致？ |
| 表述性质 | 是事实、数据、估算、预测、指引、观点还是假设？ |

来源数量不能替代质量判断。多个转载同一公告只算一个原始来源。

## 6. 来源类型使用原则

### 6.1 官方一手来源

政策、法律、规则、监管文件、公司公告、财报、标准原文和官方统计，优先用于确认：

- 已发生事件；
- 政策适用范围；
- 正式披露数据；
- 法律、许可、认证和治理状态。

### 6.2 经营一手来源

采购、认证、交付、制造、设备材料验收和质量记录，优先用于确认订单、产能、良率、质量、交付和认证。

### 6.3 行业权威来源

行业协会、标准组织、权威技术路线图和海关贸易数据，用于行业分类、技术路线、设备材料、贸易和区域供给判断。

### 6.4 公司沟通材料

管理层指引、业绩说明会、产品资料和技术白皮书可用于经营展望、路线和计划，但不能把计划写成已完成事实。

### 6.5 研究与渠道来源

卖方研报、产业调研、专家访谈和渠道数据可提供估算、其他可能解释和交叉验证。必须保留原始来源、转述链、业务时间和估算性质。

### 6.6 市场数据

价格、成交、估值、持仓、资金流和一致预期用于判断预期差和定价反映程度。资产价格变化本身不证明基本面因果。

## 7. 十二类证据配置

`business_instances.yaml` 中的证据画像定义 12 类证据配置；状态变量到证据画像的绑定单向维护。

### 7.1 需求、资本开支与订单

适用变量：终端需求强度、客户资本开支、订单能见度、未交付订单压力。

支持证据：

- 终端销量、部署、使用量、利用率和实际出货；
- 客户预算、项目清单、招标和采购；
- 订单覆盖、排产、交付和收入确认；
- 下游与供应链的独立交叉验证。

反面证据：需求下修、预算削减、订单取消、重复下单、渠道囤货和交付延期。

### 7.2 产能、供给与韧性

适用变量：供给可得性、产能紧张度、扩产进展、供给响应弹性、供应链韧性。

支持证据：有效产能、利用率、维护停机、扩产阶段、设备搬入、试产、认证、交期、许可、替代供应和恢复时间。

反面证据：可切换闲置产能、替代供应已认证、库存充足，以及表面多供共享同一单点上游。

### 7.3 制造、良率、周期与可靠性

适用变量：良率成熟度、制程能力、生产周期压力、质量可靠性。

支持证据：跨批次良率、缺陷、返工、过程能力、设备与材料一致性、制造周期、可靠性测试、现场失效和客户退货。

反面证据：样品良率冒充量产良率、牺牲可靠性换取良率、减少检验造成表观周期缩短。

### 7.4 库存周期与缓冲

适用变量：库存周期位置、库存缓冲能力。

支持证据：供应商、渠道、客户和终端多层库存，覆盖期、在途库存、安全库存、消耗速度和补库去库时间序列。

反面证据：库存规格不匹配、所有权不清、重复计算、新旧产品切换和终端需求背离。

### 7.5 价格、成本、定价权与利润池

适用变量：产品价格压力、投入成本压力、定价权、产业利润池迁移。

支持证据：合同价和成交价、产品组合、成本拆分、涨价兑现、客户流失、份额、毛利、资本强度和现金流。

反面证据：挂牌价未成交、汇率或产品组合造成表观变化、成本被效率抵消、涨价后份额明显下降。

### 7.6 技术路线、微缩与替代

适用变量：制程微缩、技术成熟度、技术竞争力、技术替代强度。

支持证据：路线图、标准、论文、专利、同口径性能功耗成本比较、原型、试产、量产、客户采用和生态准备。

反面证据：只有实验室结果、基准不可比、可靠性或良率不足、软件与供应生态缺失，以及新旧路线实际互补。

### 7.7 认证、采用、量产与本地替代

适用变量：采用渗透、客户认证、量产准备、本地化替代。

支持证据：送样、测试、认证、定点、采购、工艺固定、良率、质量、量产出货、重复采购和上游依赖穿透。

反面证据：非约束性意向、认证不覆盖量产规格、供应未就绪、仅替代低端规格或仍依赖受限核心投入。

### 7.8 竞争结构、切换成本与壁垒

适用变量：竞争强度、客户切换成本、进入壁垒。

支持证据：份额、产能、报价、招标、产品差异、认证周期、重新设计、软件迁移、专利、人才和规模经济。

反面证据：市场分层使参与者不可比、规划产能未量产、标准化和双供认证降低切换成本。

### 7.9 产业政策、贸易与合规

适用变量：政策支持、出口管制、合规摩擦。

支持证据：正式原文、适用对象、性能门槛、最终用途、主体、地域、生效时间、预算、许可、执法、处罚和企业交易变化。

反面证据：政策未生效、预算未落实、不适用、存在许可豁免、范围收窄、执行宽松或替代供应缓冲。

### 7.10 公司暴露、执行与业绩弹性

适用变量：价值链暴露、技术路线暴露、执行交付、业绩弹性、产品组合结构。

支持证据：业务和利润结构、客户和地域、产能良率、订单交付、价格成本、费用、资本开支、现金流和营运资金；客户集中度、单一客户订单波动与客户议价能力对暴露和执行的影响。

反面证据：相关业务占比低、内部对冲、无法交付、收入不能确认、折旧费用或营运资金抵消改善；客户集中但合同长期锁定或客户结构多元形成对冲。

### 7.11 市场预期、预期差与定价

适用变量：一致预期、预期差、市场反映程度。

支持证据：同期一致预期、管理层和研究者预期、价格隐含预期、估值、成交、持仓和预期修正。

反面证据：预期陈旧或口径不一、事件前已经反应、价格由宏观和风格驱动、估值变化来自利率而非盈利。

### 7.12 反面证据与其他可能解释

适用变量：反面证据强度。

需要主动寻找：

- 直接否定核心前提的事实；
- 同口径、同时点、同范围的相反观测；
- 能解释同一现象的替代机制；
- 历史上反复导致传导失效的条件。

反面证据本身也必须被验证，不能因为措辞负面就自动升级为逻辑失效。

## 8. 支持、削弱与逻辑失效

### 8.1 支持证据

支持证据必须与目标变量或假设明确关联。行业需求增长不能自动支持某家公司利润改善，中间还需要公司暴露、执行、价格成本和份额证据。

### 8.2 削弱证据

削弱证据降低幅度、概率、持续时间或置信度，但不一定否定核心方向。

### 8.3 逻辑失效证据

逻辑失效证据命中假设不可缺失的核心前提。例如产品未通过客户认证，可以逻辑失效“近期进入量产”的假设；它不一定逻辑失效长期技术可行性。

逻辑失效范围必须明确，不能把局部失败外推为整个技术路线失败。

## 9. 其他可能解释

半导体研究中的常见其他可能解释包括：

- 订单改善来自补库，而不是终端需求；
- 价格上涨来自短期停产，而不是长期供给壁垒；
- 毛利改善来自产品组合或原料下降，而不是定价权；
- 技术性能提升来自软件或系统优化，而不是器件路线；
- 本地替代增长来自低价或政策，而不是技术竞争力；
- 行业景气改善，但公司因执行、质量或产品结构落后未受益；
- 资产价格反应来自宏观、流动性或风格，而不是本次事件。

进入高等级判断前，必须记录主要其他可能解释及其排除或未排除状态。

## 10. 时间对齐

证据必须区分：

- 事实发生时间；
- 文档发布时间；
- 系统记录时间；
- 判断适用窗口。

半导体不同变量的合理更新频率不同：

- 政策、生效、许可和供应中断按事件更新；
- 订单、库存、价格和交期通常按月度或季度更新；
- 扩产按建设、设备搬入、试产、认证和量产节点更新；
- 技术路线按原型、试产、客户验证和量产里程碑更新；
- 财务、现金流和一致预期按报告期和重大修正更新。

技术原型、试产、认证和量产证据不得跨阶段混用。

## 11. 独立性

- 多家媒体转述同一公告不是多源验证；
- 多个平台转载同一研报不是多源验证；
- 公司披露与客户、供应商或行业数据可以形成交叉验证，但需要检查关联关系；
- 协会汇总数据可能来源于参与公司，不能默认完全独立；
- AI摘要和搜索摘要只作为线索。

## 12. 冲突处理

冲突证据不得删除或覆盖。系统应保留所有主张，并记录：

1. 冲突对象；
2. 数值、范围、时间或解释冲突类型；
3. 原始来源与转述关系；
4. 各自适用口径；
5. 未解决冲突对判断等级的影响。

优先核对原始来源，不能按来源数量简单投票。冲突未解决时，判断保持 observation 或 contested。

## 13. 证据缺口与降级

| 缺口 | 处理方式 |
|---|---|
| 缺少一手来源 | 只保留线索，不形成已确认事实 |
| 缺少业务时间 | 不参与趋势和跨期比较 |
| 范围不匹配 | 不外推到全行业或公司 |
| 未检查反面证据 | 不形成高置信判断或资产影响 |
| 缺少市场预期 | 只输出基本面观察，不形成正式预期差 |
| 冲突未解决 | 保持 contested 或 observation，并列补证任务 |

## 14. 证据域禁止项

- 把预测、指引和观点当作已发生事实；
- 把价格上涨直接当作供给紧张的证明；
- 把多次转载当作多源验证；
- 用事后预期证明事前存在预期差；
- 删除与主判断不一致的材料；
- 在缺少反面证据和市场预期时形成高置信资产影响；
- 在领域本体中保存具体观测值、数据库字段或接口绑定。
