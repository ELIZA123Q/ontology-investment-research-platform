# 半导体状态与判断连接说明

## 1. 定位

本文件说明半导体业务参数如何进入通用五模型，不定义新的推理动作或 A01—A10 方法。状态变量和传导模板的机器权威是 `business_instances.yaml`；Signal、Hypothesis、CompetingExplanation、BlockingFactor、RuleEvaluation、Judgment 与 ReasoningTrace 使用通用判断模型。

## 2. 领域状态变量

46 个状态变量按需求、供给、制造、库存周期、经济性、技术、商业化、竞争、政策韧性、公司和市场预期分类。它们是稳定“观察什么”的定义，不是某次观测值。

任务中的具体读数进入 `Observation`，并记录观测时间、有效时间、公布时间和研究截止时间。状态更新形成 `StateChange`，通过依赖关系使相关 EvidenceAssessment、EvidenceBasket、RuleEvaluation 和 Judgment 失效或重算。

## 3. 领域事件

半导体事件 ID 由 `semiconductor_extension.yaml.event_taxonomy` 扩展 `Event.event_type`。事件实例仍必须有主体、范围、发生/生效/公布时间和研究截止时间。公告扩产不等于产能状态已经变化；只有设备搬入、试产、认证、良率和有效产出等观测才能更新产能或量产状态。

## 4. 传导模板的边界

28 个 `PropagationTemplate` 是领域业务参数，描述候选变量路径、时间滞后、适用条件、削弱条件、阻断条件和默认竞争解释。它们不是已执行推理，也不能直接生成判断。

一次研究必须经过：

```text
ResearchQuestion → JudgmentUnit → StateVariable / Event
→ EvidenceRequirement → EvidenceFact / Observation
→ Signal → Hypothesis + CompetingExplanation / BlockingFactor
→ RuleEvaluation + MethodApplication → Judgment → ReasoningTrace
```

传导模板只能帮助 02 建路径、03 取证、04 检查中间节点；任何未被证据接通的节点都必须停止向下游外推。

## 5. 商业化阶段

设备、材料和产品导入统一使用九阶段：概念、样品、客户评估、认证、定点、试产、量产、复购、规模采用。判断强度不得超过证据已确认阶段；送样不能支持量产，认证通过不能自动支持收入确认，单次采购不能自动支持规模采用。

## 6. 更新与失效

新证据先更新 EvidenceFact/Assessment，再更新 Observation 或 Signal；只有受正式关系图影响的下游对象进入 stale。若出现新对象、新关系或新判断路径，返回 02；仅新增既有路径证据时，从 03 开始局部重算。
