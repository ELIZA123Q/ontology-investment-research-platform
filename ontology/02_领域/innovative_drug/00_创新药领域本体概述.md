# 创新药领域本体概述

## 1. 唯一权威

创新药领域当前采用“通用五模型 + 领域业务参数 + 方法资产”的轻量结构，暂不新增正式领域 extension：

- 正式对象、关系、证据链和判断链复用 [`../../01_通用`](../../01_通用)。
- 领域状态变量、证据画像、传导模板和代理指标：[`business_instances.yaml`](business_instances.yaml)。
- 取证与裁决方法：[`../../../methods`](../../../methods)。

本目录保存创新药研究中稳定“观察什么、如何约束口径、哪些证据能支撑到哪一层”的领域信息，不保存单次产品事实、临床读数、销售额、研究结论或投资建议。

## 2. 领域边界

纳入创新药产品、适应症、临床阶段、注册审批、医保支付、医院准入、处方放量、生产供应和商业化兑现。早期管线长期想象空间、未公开临床数据、渠道传闻和交易建议不进入领域定义。

药品、适应症、审批事件、临床证据、支付状态和销售兑现必须分开建模。获批不等于放量，临床成功不等于医保准入，医保纳入也不自动等于收入改善。

## 3. 正式新增对象

本阶段不新增正式对象类型。领域对象投影到通用模型：

| 领域对象 | 通用投影 | 说明 |
|---|---|---|
| 药品/疗法 | `Product` / `Technology` | 具体药品、疗法平台或给药方式 |
| 适应症 | `Application` / `ResearchScope` | 适用患者范围和疾病场景 |
| 临床或审批事件 | `Event` | 临床读出、申报、受理、获批、医保纳入 |
| 销售、处方、患者数 | `Metric` | 兑现观察指标 |
| 药企 | `Company` | 经营主体 |

## 4. 领域能力

领域包支持以下问题：

- 审批事件是否改变产品阶段；
- 临床证据是否足以支撑适应症和患者范围；
- 支付、准入和指南是否接通商业化路径；
- 单产品能否传导到公司收入、利润和现金流；
- 竞品、安全性、价格和渠道约束是否削弱兑现。

## 5. 冻结条件

只有同时满足以下条件，才考虑把创新药从轻量领域包升级为正式领域扩展：

1. 至少两个产品案例跑完 01—05；
2. 审批阶段、适应症、支付准入和销售兑现字段反复出现；
3. 通用对象不能清晰表达的关系被稳定识别；
4. 领域证据画像和状态变量通过评测样例验证；
5. 不把单次临床结果、销售数字或公司观点写入领域定义。
