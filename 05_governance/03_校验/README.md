# 校验

跨阶段与全库的质量检查工具、高质量判别标准都在这里。用来回答：「结构合不合规」「能不能发布」——不等于「结论一定赚钱」。

## 给谁看

- **研究员：** 高质量判别标准；偶尔看运行是否结构合规
- **维护者：** 各类 validate 脚本与发布闸门

## 材料从哪来

| 想确认 | 打开或运行 |
|--------|------------|
| 高质量原则与发布规则 | [`00A_高质量产出判别标准.md`](00A_高质量产出判别标准.md) |
| 一次运行是否结构合规 | `python3 05_governance/03_校验/validate_run.py <运行目录>` |
| 全库自检 | `python3 05_governance/03_校验/validate_project.py` |
| 跨阶段 ID 约定 | [`../02_合同/public_contract.yaml`](../02_合同/public_contract.yaml) |

各阶段填写模板仍在 `02_tasks/04_workflows/deep_research/templates/`（历史模板）。

## 怎么用

### 各阶段产出（人看什么）

| 阶段 | 面向研究员 | 结构化文件 |
|------|------------|------------|
| 01 | 投研需求说明 | — |
| 02 | 研究逻辑 | 本体视图 YAML |
| 03 | 数据与证据准备 | 实例清单 + 快照目录 |
| 04 | 判断简报 | 推理审计 YAML |
| 05 | 研报正文 | 表达审计 YAML |

发布闸门另有「独立语义审查」。走完结构校验 ≠ 一定 `PUBLISHABLE`。

### 03 快照目录长什么样

```text
03-主题数据与证据快照-日期-序号/
├─ manifest.csv
├─ 01_plan/           证据需求、配方、来源画像
├─ 02_assets/         来源与规范化证据链
├─ 03_gate/           各判断证据是否够用
└─ 04_05_materials/   图表、表格、研报素材就绪情况
```

## 怎么维护

- 新增校验脚本放本目录，并在治理 registry / 项目校验入口挂上。
- 字段与版本规则与合同目录保持一致。
- 失败时先看脚本输出与 `00A`，再修产物或合同，不要关掉校验凑合通过。
