# 评测与体验（evals）

这里评估「研究质量与相对价值」：有没有洞察、有无遗漏、是否帮助决策、相对基线如何。
确定性的 schema/来源检查不在这里（见 [`../15_verifiers/`](../15_verifiers/README.md) 与 [`../03_校验/`](../03_校验/README.md)）。

## 给谁看

- **研究员：** 决策日志、体验基线说明；部分案例可读
- **维护者：** 案例、协议、执行配置与报告目录

## 材料从哪来

| 区域 | 白话含义 |
|---|---|
| `01_协议` 等（若存在） | 评测怎么跑的约定 |
| `02_案例` | 具体评测案例（如 RV-T01） |
| `03_执行` | 执行配置与校验脚本 |
| `04_报告` | 报告产出（可能不入仓） |
| [`05_决策日志/`](05_决策日志/README.md) | 里程碑决策与硬门槛 |
| [`06_第二领域压力测试/`](06_第二领域压力测试/README.md) | 领域无关性小样本压力测 |
| [`07_研究员体验基线/`](07_研究员体验基线/README.md) | TTFC 等体验指标 |
| [`registry.yaml`](./registry.yaml) | 本目录登记 |

## 怎么用

1. 想知道「为什么还不能对外宣称增益」→ 先看决策日志。
2. 想了解体验指标口径与是否够样本 → 看体验基线 README。
3. 对照案例 → 打开 `02_案例` 下具体任务目录。

## 怎么维护

- **status:** migrating
- 新案例登记进 registry；报告若含敏感路径注意 gitignore。
- 未达样本门槛前，禁止把临时数据写成「已证明流程增益」。
