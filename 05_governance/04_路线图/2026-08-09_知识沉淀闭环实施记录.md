# 2026-08-09 知识沉淀闭环实施记录

## 结论

当前 vNext Agent Kernel 已完成第一版知识学习控制面及第二波使用回流补强。研究主链保持用户无感；Task 终态后异步生成候选，只有已评测、已审批、已发布且在 `asOf` 时点有效的资产才能被后续 Context 使用。

## 已实施

- 增加 KnowledgeScope、KnowledgeLock、AssetRevision、Candidate、Evaluation、Release、Usage 和 TemporalFact 合同。
- SQLite 增加知识锁、挖掘运行、候选、出现记录、审批、评测、版本、发布和使用观测表。
- Task 创建时冻结 global/tenant/user 资产视图；Context 记录 Release、版本和选择理由。
- global 初始 Release 只引用五域 `registry.yaml` 权威入口，不复制五域正文；tenant/user 按稳定身份键覆盖读取。
- 增加时态事实、语义、能力、评测和记忆五类确定性挖掘器。
- 增加双 Diff/rebase、冲突阻断、风险分级、角色审批和原子 Release。
- Worker 支持 `mine_assets`、`evaluate_candidate`、`publish_release`、`rebuild_knowledge_index`。
- 增加内部候选、评测、审批、发布、资产血缘和 Mining 重试 API。
- 增加环境开关控制的内部知识治理页面，不进入普通用户导航。
- 治理页面展示 KnowledgeLock、三方 Diff、冲突/相似候选、受影响 Run、Replay 指标、审批和 Release 历史。
- 回滚通过复用已验证旧基线创建新 Release，记录 `rollbackOfReleaseId`，不修改历史 Manifest。
- 增加机器合同漂移校验，并接入全项目正式验收链。

## 第二波：Context 与效果回流

- KnowledgeLock 增加不可变 `asOf`，按 `validFrom <= asOf < validTo` 过滤未生效和过期时态事实。
- 历史事实仍保留在 Release 和 Lineage 中，显式历史 `asOf` 仍可重放。
- ContextPackage 通过 append-only `context.assembled` Event Manifest 持久留痕，不新建可编辑的平行业务表。
- Manifest 记录 KnowledgeLock、三层 Release、`asOf`、AssetRef 版本/指纹和选择理由。
- 增加 `asset.selected/used/helpful/regression` 运行事件；`helpful/regression` 只能写回该 Task KnowledgeLock 真正选中的资产。
- 增加结果回流 API，重复观测幂等，伪造 AssetRef 或跨 Task 写回会被拒绝。

## 实现边界

- 全局正式资产仍引用现有五域文件权威；数据库不复制另一套全局真相。
- v1 使用 SQLite + FTS 派生索引，没有引入 Neo4j 或外部向量数据库。
- 当前 Miner 先做确定性结构提取；模型型 Schema 抽取保留为后续 Adapter，不在本轮伪造。
- 当前评测门实现 provenance、出现次数、任务族、时态字段、脱敏和分数提升的确定性检查；真实模型 A/B 与金融来源 Tool 接入后扩充指标。
- user/tenant 资产默认不能晋升 global；本轮未提供跨作用域晋升 API。
