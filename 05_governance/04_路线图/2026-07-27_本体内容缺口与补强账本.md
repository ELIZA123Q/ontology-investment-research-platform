# 2026-07-27 本体约束优势评估与落地路径

目的：纠正「本体写差了 / 没落工程」的误判，记录真实根因，并按性价比排出落地路径。本账本以正式本体为中心；方法与运行控制不写回本体。

## 一、评估结论

| 假设 | 结论 | 要点 |
|---|---|---|
| 假设 1「本体没写好 / 写差了」 | **不成立** | 正式元模型与关系/元素合同齐全，不是流程本体草稿。 |
| 假设 2「本体写得好但没落工程」 | **部分不成立** | 核心规则已进生产流；真问题是 YAML↔TS 双源与语义深度不足。 |
| 评语「合格流程本体 + 半导体参数库」 | **前半对、后半偏苛且有误** | 不是写砸了；也不是「流程本体」，工程侧确实已落地。 |

## 二、根因

1. **A（治本）** 本体不是执行的唯一真相源：规则语义手写在 TS 分支，与 YAML 分离。
2. **B** 语义深度不够：缺因果传导、估值链路、风险联动等深公理。
3. **C** 范围与广度：资本市场按需；领域目前仅半导体。

## 三、落地路径（按原计划）

| 优先级 | 动作 | 验收 |
|---|---|---|
| **P1** 治本·消除 YAML↔TS 漂移 | 用小解释器读取 `models/*.yaml` 的 `condition` / `counter_conditions` / `preconditions` 驱动 fixture 与 Runtime 判定；`REQUIRED_RULES` 从权威表派生；`validate_v3.py` 结构检查 + executable 示例断言。 | 解释器可挡错误 fixture；TS/Python 规则集合 ≡ registry；新规则优先走谓词判定 |
| **P2** 加深语义公理 | 在 judgment/semantic 新增：产业链传导一致性、估值假设与结论等级挂钩、风险暴露与阻断因素联动；同步 `semantic_execution` + `rule_authority_registry.execution_surface`。 | YAML + registry + Runtime + 测试全齐 |
| **P3** 按需资本市场 | 已提前激活则维持、暂停扩大。 | 不扩大直至研究需要 |
| **P4** 可选·第二领域 | 验证扩展机制复用。 | 新扩展通过冻结门 |
