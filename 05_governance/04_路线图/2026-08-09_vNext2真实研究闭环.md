# vNext.2：真实研究闭环优化路线

## 一、目标

下一轮不增加架构层级，也不急于启用多 Agent。唯一目标是把当前“会规划、会恢复、会正确停止”的 Runtime，升级为能利用现有资产和真实来源完成高质量研究的单 Agent 系统。

成功定义：Research Lead 在不依赖旧 Runtime 的前提下，完成真实的 `目标 → 受约束计划 → 真实取证 → EvidenceFact → Claim → Judgment → Report`，并通过三轮 gold eval 与八个新旧配对任务。

## 二、P0 工作流

### 1. Semantic 与历史资产 Adapter

交付：

- `SemanticGateway` 的 FTS、structured query 与 domain graph adapter。
- 本体 registry、词典、方法库和历史 Artifact 的只读索引器。
- Domain Semantic Graph 与 Research Provenance Graph 的独立存储/查询接口。
- Context Builder 返回引用、版本、选择理由、新鲜度和 token budget，不复制整库正文。

验收：同一实体或概念能返回稳定 ID、版本和来源；图检索不可替代普通 FTS；Context Event 可解释为什么选择每条引用。

### 2. 真实来源与 EvidenceFact 晋级链

交付：

- `source.discover`：按证据分组返回候选来源与搜索活动。
- `source.capture`：保存快照、locator、短引文、内容哈希、获取时间和权限范围。
- 金融 MCP Tool adapter：把现有通道映射为统一 Tool 结果，不把 MCP 当来源生产者。
- Source → Capture → EvidenceFact 的确定性 Verifier。
- SourceSnapshot、EvidenceFact、Claim 的 schema 与 provenance edge。

验收：未经 capture 的来源无法成为 EvidenceFact；无法定位原文的事实无法支持 Claim；有副作用的抓取/发布支持幂等恢复。

### 3. Model-driven Planner + Deterministic Compiler

交付：

- 模型只输出 `PlannerProposal`：候选节点、依赖、预算、停止条件和理由。
- Runtime Compiler 只接受 Node Catalog 中的类型，验证依赖、前置条件、权限、预算和输出 schema。
- 非法计划自动修复一次；仍非法则回退确定性 planner 或请求用户输入。
- 模型/只读 Tool 使用 request fingerprint 与 cached result 尽可能避免重复调用。

验收：LLM 不能创造任意节点、绕过 Source Capture 或直接把候选来源写成 Judgment；只取证、局部改判和分支任务使用不同最小路径。

### 4. 失效传播与局部重算

交付：

- Artifact dependency index：记录输入版本、时间范围、来源新鲜度和下游消费者。
- 时间窗、来源版本或事件变化生成 `InvalidationSet`。
- Planner 明确 `reuse / refresh / recompute / supersede`，只重跑受影响节点。
- 分支任务与父任务共享不可变 Artifact，修改产生新版本而非静默覆盖。

验收：把“2025—2026”改成“未来六个月”时，系统能列出失效 Evidence、需重算 Judgment 与可复用 Artifact；父分支保持不变。

### 5. 可编辑动态工作台

交付：

- Artifact PATCH API、optimistic version 与编辑 Event。
- 计划节点调整通过 Runtime 重新编译，不允许 UI 绕过 Node Catalog。
- 证据矩阵支持补充材料、来源核验和只补一手来源。
- 判断卡支持直接编辑 statement、confidence 与 change conditions，并触发 Verifier。
- 报告编辑器只允许从正式 Artifact 引用 Claim；发布前需要审批。
- 移动端动态画布改为抽屉。

验收：研究员无需输入内部 ID；“删掉这条判断”“只补一手来源”“改时间范围”既可直接编辑，也可用自然语言完成。

### 6. Eval 与切换证明

交付：

- 3 个 gold task：正常成功、证据不足正确停止、事件导致局部改判。
- 每个 gold task 至少运行 3 次。
- 8 个真实任务与切换前冻结结果进行配对评测。
- 指标：任务成功率、引用正确率、证据覆盖、正确停止率、成本、TTFC、总延迟、Tool 错误和人工返工。
- Verifier 与模型/人工 Eval 分栏呈现。

切换门槛：引用正确率和正确停止率不下降；TTFC 中位数降低 30%；人工操作数降低 40%；无 P0 数据、溯源或恢复缺陷。

## 三、实施顺序

1. 先建 provenance schema、资产 adapter 和一条真实 Source Capture 链。
2. 再把真实 Evidence 接入当前确定性 planner，跑通第一个 gold task。
3. 然后引入 model-driven PlannerProposal，但保留 compiler 和确定性 fallback。
4. 完成失效传播、直接编辑和分支复用。
5. 最后执行 3×3 gold eval 与 8 个配对任务。

每个步骤必须形成可运行垂直切片，不先建设独立“中心”。

## 四、明确不做

- 不启用 Analysis Specialist 或 Independent Critic。
- 不建设多租户、完整 RBAC、远程 A2A 网络或 Neo4j 集群。
- 不把所有查询改成图查询。
- 不恢复阶段 Agent、Skill 镜像或固定 Workflow。

只有 Evidence Investigator 在取证并行评测证明有显著收益时，才进入下一版本。
