# 02 分析框架知识库

本库保存可复用的分析框架，回答：这类问题通常应判断什么、怎样拆解、哪些机制和竞争解释需要检查。单次任务如何选择、裁剪并写出研究逻辑，由 [`02_判断结构与本体视图规范.md`](../../02_tasks/04_workflows/deep_research/stages/02_structure.md) 规定。

## 1. 库里有什么

| 目录或文件 | 内容 |
|---|---|
| [`基础框架库`](基础框架库/00_基础框架编写与验收标准.md) | 供需、政策、产业链、价格、公司兑现、财务、预期和估值等通用框架 |
| [`行业框架库/半导体行业`](行业框架库/半导体行业/README.md) | 半导体主框架与高频场景卡 |
| [`00_framework_dependency_registry.yaml`](00_framework_dependency_registry.yaml) | 进入条件、可写到哪一层、下游可接什么（机器权威） |

## 2. 和 03 / 04 的边界

- 本库决定**判断什么、按什么结构验证**。
- [`90_compat/methods/03_取证`](../03_取证/README.md)决定**需要什么证据、去哪里找、怎样验收**。
- [`90_compat/methods/04_裁决`](../04_裁决/README.md)决定**合格证据怎样形成、削弱、打断或修改判断**。

框架不是现实事实、正式本体、研究结论或报告模板。02 只写清「什么事实可能推翻当前判断」；具体怎么裁由 04 执行。

## 3. 怎样选用

不要按题目关键词选框架。先在任务级写出核心待验证命题和 2—3 个关键判断单元；每个单元只解决一种主要分歧。

| 分歧本质 | 合格问题 | 不合格 |
|---|---|---|
| 状态 | 当前渠道库存是否低于正常区间 | 行业情况如何 |
| 趋势/周期 | 合约价上行斜率是否正在放缓 | 价格怎么看 |
| 归因 | 本轮订单回升主要来自终端还是补库 | 需求为何增长 |
| 传导 | 管制如何经过许可与客户行为影响交付 | 管制影响多大 |
| 分化 | 同一冲击下谁因暴露和承接不同而分化 | 谁最受益 |
| 预期差 | 新信息相对事件前共识改变了什么 | 股价会不会涨 |
| 风险 | 哪个触发会穿透缓冲并造成不可逆后果 | 有哪些风险 |

**研究员口径：** 每个关键判断单元只留 **1 个直接框架**；可有多个判断单元；行业增强挂在该单元上；场景卡可选。细则见 [`02_附录1`](../../02_tasks/04_workflows/deep_research/supporting/02_structure_framework_selection.md)。

推荐最小组合：**1 判断类型 + 1 直接框架 + 0—1 行业增强 + 0—1 场景卡**。

### 3.1 十类原子判断类型

| 类型 | 核心问题 | 系统对照 |
|---|---|---|
| 状态 | 对象当前处于什么状态 | JF-STATE / state_measurement |
| 趋势 | 变化是否持续、斜率是否改变 | JF-TREND / trend_direction |
| 周期 | 当前处于周期哪一段、切换条件 | JF-CYCLE / cycle_phase |
| 归因 | 已观察变化主要由什么造成 | JF-ATTR / causal_attribution |
| 机制 | 某项机制是否真实运行 | JF-MECH / mechanism_validation |
| 传导 | 事件或变量如何传到行业/公司/资产 | JF-TRANS / transmission_path |
| 分化 | 为什么对象间影响或兑现不同 | JF-DIFF / object_differentiation |
| 影响兑现 | 已成立路径如何落到经营/财务/资产 | JF-IMPACT / impact_realization |
| 预期差 | 新信息相对事前预期是否构成差异 | JF-EXPECT / expectation_gap |
| 估值影响 | 判断变化影响哪些估值假设或区间 | JF-VALUATION / valuation_impact |

风险重估等复合意图须拆成上表原子判断。

### 3.2 常见问题 → 框架

| 常见问题 | 首选 |
|---|---|
| 紧缺与价格持续性 | 供需、价格周期 |
| 政策产业影响 | 政策影响、产业链传导 |
| 行业改善到公司 | 商业模式、业绩弹性、财务质量 |
| 预期差 | 预期差判断（先固定事前基线） |
| 存储周期切换 | SCN-MEM-CYCLE + IF-SC-01 |
| 国产设备突破 | IF-EQP-01 + IF-LOC-01 |

## 4. 怎样写可验证判断（待验证观点）

> 在【对象/范围】和【时间窗口】内，若【关键前提】成立，则【变量/结果】更可能【方向/阶段/差异】。

纪律：一句只判一件事（可证伪、有边界、不跳步）；写清对象/时间/条件；不确定给范围。

五问：判谁、判什么、还有谁在争（竞争解释）、靠什么分开（区分信号）、什么会推翻它（推翻条件）。答不上后三项 = 尚未形成可验证待验证观点。证据不足时须可降级，由 04 裁决。

系统落盘：`atomic_claim` / `mechanism_ref` / `falsifiers`；须可区分竞争解释。

选用自检：可证伪、有边界、不跳步、可区分、可降级。
