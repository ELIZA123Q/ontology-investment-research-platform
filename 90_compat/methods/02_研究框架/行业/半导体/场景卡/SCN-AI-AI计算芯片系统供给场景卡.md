# AI计算芯片系统供给场景卡

适用问题：AI 计算芯片从系统供给、部署利用到瓶颈迁移，需求如何落到可交付供给。

## 决胜分歧

AI 需求不能用算力芯片出货单点代表。真实系统供给取决于加速芯片、HBM、先进封装、网络、电力散热、服务器组装与软件利用的共同匹配；最窄瓶颈迁移时，单一环节扩产未必增加集群可用算力。相对收窄后的 IF-APP，本卡专门追加部署/利用时钟——它们不是通用内容量门，而是 AI 场景增量。

## 1. 本场景相对于主框架增加什么

相对 IF-APP-01，本卡增加：

1. 算力芯片、HBM、封装、网络、电力和软件的系统匹配结构；
2. 采购、交付、部署、上线、利用五阶段时钟（APP 通用桥不含部署利用）；
3. 最窄瓶颈迁移；**互斥主判断模式**：需求真实性 / 系统瓶颈 / 架构替代（每次只选一个）。

## 2. 和哪个主框架一起用

| 项目 | 内容 |
|---|---|
| 默认主框架 | IF-APP-01 |
| 条件辅助框架 | 问芯片商业化→IF-DES-01；问封装瓶颈→IF-PKG-01；问晶圆有效供给→IF-FAB-01 |
| 默认排除 | IF-SC-01、IF-LOC-01、IF-EQP-01、IF-MAT-01（除非已定位具体瓶颈） |
| 不适用问题 | 纯周期判断、纯国产替代、与 AI 系统无关的单点芯片财务 |

## 3. 场景特有判断脊柱

```text
工作负载/服务量
→ 系统BOM与有效算力需求
→ 芯片/HBM/封装/网络/电力/软件约束
→ 采购/交付/部署/上线/利用
→ 瓶颈迁移与供应商兑现
```

## 4. 场景增量变量与竞争解释

| 决胜变量 | 主解释成立时 | 竞争解释成立时 | 最低验证 |
|---|---|---|---|
| 需求真实性 | 部署上线且利用率高 | 只有capex或订单意向 | 系统配置+实际部署+利用率 |
| 系统瓶颈 | 最窄环节交期/产能约束交付 | 瓶颈已迁移他处 | 分工序BOM+瓶颈环节交付 |
| 架构替代 | 客户采用并复购替代架构 | 软件生态不足或迁移成本高 | 客户采用+软件栈+迁移证据 |
| 配套交付 | 机房/电力/网络同步就绪 | 机房电力延期拖累上线 | 配套部件交付与上线时间 |

## 5. 对 02 和 03 的增量交接

以下为系统登记，研究员可不读。

```yaml
scenario_additions:
  required_splits:
    - 采购 / 交付 / 部署 / 上线 / 利用
    - 芯片 / HBM / 封装 / 网络 / 电力
  mandatory_evidence:
    - 系统BOM与关键瓶颈分工序
    - 客户实际部署与利用率
    - 主判断模式选定（需求真实性|系统瓶颈|架构替代）
  counter_evidence:
    - 电力与机房延期
    - 软件利用不足
    - 瓶颈不在目标芯片
  stop_if:
    - 只能取得capex和芯片订单
    - 只有峰值算力无利用率
    - 未选定主判断模式
```
