# 研究问题图 — 意图、场景、任务怎么拼成一张图

> 上级目录：[`02_scenario_task/`](../README.md) | 根目录：[`README.md`](../../README.md)

这里定义「用户的研究问题怎么展开成一张可分支、可合流、可失效传播的研究问题图」。好比拿到课题后的拆解规则——把研究意图、场景约束和任务模板组合成一张完整的研究地图。

## 里面有什么

| 文件 | 一句话说明 |
|------|-----------|
| `contract.yaml` | **机器合同**：图怎么装配的正式定义 |
| `registry.yaml` | **登记入口** |

## 三张图不能混

| 图 | 回答的问题 | 在哪 |
|----|-----------|------|
| **研究问题图** | 这项研究由哪些问题、判断和缺口组成 | 本目录装配 |
| **研究溯源图** | 一个正式结论为什么成立 | `01_semantic_knowledge/03_knowledge_graph/` |
| **执行任务图** | 这一次 AI 具体执行哪些节点 | `06_runtime/` |

## 怎么维护

- Intent、Scenario、Task 是图的输入，**不是**固定先后阶段
- 一个请求可以激活多个 Task，可以共享判断单元和证据
- 规划器每次只选择未解决或已失效的 frontier（未解决部分）
- 停止依据是问题图覆盖、阻断或显式降级，不是「阶段跑完」
