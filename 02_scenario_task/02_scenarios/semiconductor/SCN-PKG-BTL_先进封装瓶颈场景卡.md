# 先进封装瓶颈场景卡

适用问题：先进封装是否成为系统交付瓶颈，以及利润池由谁控制、谁承担损失。

## 决胜分歧

先定位瓶颈在设备、材料、基板/中介层、工序、测试、良率还是认证；名义扩产只有最窄环节同步且良率达标才增加系统交付。预设瓶颈迁移。互斥主判断模式：瓶颈定位 / 瓶颈迁移 / 利润池归属（每次一个）。

## 1. 本场景相对于主框架增加什么

相对 IF-PKG-01，本卡增加：

1. AI/HBM/Chiplet 架构下的先进封装 BOM 拆分；
2. 瓶颈迁移领先信号（原工序缓解后测试/基板/散热接棒）；
3. 控制者 / 良率损失承担者 / 增量捕获者分离（对接 PKG 洞见层）。

## 2. 和哪个主框架一起用

| 项目 | 内容 |
|---|---|
| 默认主框架 | IF-PKG-01 |
| 条件辅助框架 | 系统需求→IF-APP；设备材料成瓶颈→IF-EQP / IF-MAT；前道 die→IF-FAB |
| 默认排除 | 未定位前不并联全部辅助框架 |
| 不适用问题 | 传统封测无架构瓶颈、与先进封装无关的周期题 |

## 3. 场景特有判断脊柱

```text
选定主判断模式
→ 产品架构与封装路线
→ 分工序/基板/测试/良率约束
→ 最窄瓶颈与迁移信号
→ 责任与价值捕获分离
```

## 4. 场景增量变量与竞争解释

| 决胜变量 | 主解释成立时 | 竞争解释成立时 | 最低验证 |
|---|---|---|---|
| 瓶颈定位 | 单环节 WIP/交期独紧 | 多环节满载 | 两道以上工序数据 |
| 瓶颈迁移 | 原环节缓解交付仍差 | 系统交付同步改善 | 前后环节时序 |
| 利润池 | 捕获者与控制者一致 | 客户议价或良率责任吃掉 | 定价/责任条款 |
| 真实需求 | 系统架构驱动封装 | 需求在HBM/前道非封装 | 架构BOM穿透 |
