# 本机工作台

你在电脑上做投研实验的操作界面。按 01—05 五步推进研究，每一步的结果自动落盘，还能跟同一证据下模型直接生成的版本做盲评对照。

目前正式支持半导体行业；其他领域会提示知识覆盖不足。

## 启动

打开 **http://127.0.0.1:3000**（唯一入口，不要用 localhost）。

```bash
cd runtime
cp .env.example .env.local        # 填入 DEEPSEEK_API_KEY
npm install
npm run dev:singleton              # 同时启动界面与后台执行器
```

`dev:singleton` / `prod:singleton` 会随界面进程自动启动并回收后台执行器。
仅在调试任务队列时，才需要另开终端单独运行 `npm run worker`。

SQLite 数据默认写在 `instances/00_本机运行/workbench.sqlite`（不进 Git）。

## 你能做什么

- **做一次完整研究**：创建运行 → 填写研究问题 → 选分析框架 → 找证据 → 做判断 → 写成报告
- **MCP 自动取证**：后台 worker 可调 18 个数据通道（公告、研报、行情、新闻等）自动找证据；返回的是线索/摘录，写正式证据前需核验原文
- **同证据盲评**：冻结证据后，把工作台产出跟模型直出的版本对比，看"加了这套流程有没有更好"
- **独立审阅**：让另一个模型或另一位研究员审阅你的判断，输出结构化审阅意见
- **导出正式包**：确认所有阶段后导出 `formal_pack`，附带完整追溯链

## 操作要点

- 界面主要三个区域：运行列表（左侧）→ 阶段工作区（中间）→ 证据/对象面板（右侧）
- 每次研究走 01_受理 → 02_结构 → 03_证据 → 04_判断 → 05_表达
- 证据不够时，合格结果往往是「边界清楚的弱判断」；不要硬撑
- 缺数据不代表不能判断——写明缺什么、边界在哪就行

更多操作细节见工作台内的阶段指引。

### 工程边界

- 安全：API 绑定 127.0.0.1，禁止暴露公网
- 恢复：worker 中断后从当前阶段起点重试，旧 worker 的 fencing token 失效
- 预算：`RESEARCH_JOB_MAX_SOURCES` 限制来源数，`RESEARCH_JOB_MAX_TOKENS` 限制 token
- 方法注入：02-04 阶段注入选中的方法正文，同一 method_id/内容哈希去重
- 13 条正式规则在 04 判断时自动挡门，含状态时间、代理披露、认证阶段、产能/良率口径及三条深投研公理
- 校验通过只说明写法合规，不代替对数据真伪和研究价值的判断
