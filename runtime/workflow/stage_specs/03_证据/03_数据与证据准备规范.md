# 03_数据与证据准备规范

## 研究员先看什么

03 回答：**为验证 02 里的核心判断，证据够不够、能说到哪一层、展示素材齐不齐。**

**阶段定位：** 03 是证据策略执行与证据实例构建，不是简单搜集材料。它继承 02 的 `MA-nn` 身份，绑定具体证据与前置条件检查，并显式产出证据缺口与结论强度上限。

| 你要交什么 | 业务说法 |
|---|---|
| 准备说明 | 用研究语言写清：范围、需要什么证据、取到了什么、缺口与可用边界 |
| 证据归档 | 来源、事实、评价与「证据是否够用」的可复核记录 |
| 实例清单 | 本次确认的语义/证据对象与关系，以及**冻结的推理输入**（Observation/Event 等；机器侧另存）。文件名虽写「语义域与证据域」，YAML 仍含 `reasoning_domain`（`frozen_inputs_only`）；**不得**在此产出 RuleEvaluation / Judgment |

**怎样算完成：** 先为每个核心判断设好「至少要什么证据」，再取证；分别说清「能否判断」与「图表/表格/注释等素材是否就绪」——二者不能互相替代。交付须遵守**证据压缩协议**：Record（原始事实与 quote）→ Summary（趋势/对比/确定性计算）→ Bundle（按判断单元的支持/反证/缺口）；04 默认消费 Bundle + Summary，不得把未压缩的原始材料堆直接塞给推理。

**常见失败：** 没设证据要求就泛搜；用材料数量代替关键证据；把预测/观点当成已发生事实；静默换口径；在 03 里写方向性结论或替 05 排章节；把十几篇研报原文未压缩直接交 04。

短例见 [`instances/02_V3样例/01_memory-cycle-run-002`](../../../instances/02_V3样例/01_memory-cycle-run-002) / [`instances/02_V3样例/02_us-controls-localization-run-002`](../../../instances/02_V3样例/02_us-controls-localization-run-002) 的 03 证据产物。取证方法见 [`methods/03_取证`](../../../methods/03_取证/README.md)。

## 1. 本阶段负责什么、不负责什么

### 1.1 负责

1. 确认 02 入口可用，固定本次范围与数据截止时点；
2. 为每个核心判断预设实际需要的证据角色，以及缺失时如何降级或停止；
3. 按核心判断取证并留痕，不按宽泛主题泛搜；
4. 把材料整理成可比较的事实、对象关系与固定推理输入，并产出 Evidence Summary / Evidence Bundle（高语义密度压缩，供 04 默认消费）；
5. 评价证据质量，主动查反证、冲突与竞争解释；
6. 给出各核心判断最终证据把握（充分 / 受限 / 观察 / 不可用）、路径是否够用与可用边界；
7. 独立输出「证据是否够用」与「展示素材是否就绪」；
8. 判定本阶段为草稿、最低通过或高质量通过。

### 1.1a 证据压缩三类产物

| 产物 | 职责 | 结构化字段 |
|---|---|---|
| Evidence Record | 原始事实、来源、时间、口径、逐字 quote | `evidence_drafts` + `sources` |
| Evidence Summary | 趋势、分布、对比、异常；同比/环比/测算等确定性数字 | `evidence_summaries` |
| Evidence Bundle | 按判断单元组织的支持、反证、缺口 | `evidence_bundles` |

**数字纪律：** 具体数值只能来自 Record 的 quote/字段或 Summary 中的确定性计算；LLM 不得自造数字。

### 1.2 不负责

1. 不改 01 需求说明或 02 已定命题、路径与最低验证条件；
2. 不为“完整”而泛搜无关材料；
3. 不把搜索摘要、模型记忆、二手转述或获取工具本身当作证据来源；
4. 不把预测、观点、假设、指引与已发生事实混为一类；
5. 不执行推理规则，不形成方向性投研结论；
6. 不因主源不可用而静默换口径；不用覆盖率替代关键质量门槛；
7. 不替 05 决定素材用不用、放哪、如何论证；不写章节、故事线、标题或投资要点；
8. 发现结构缺口时不自行加变量或路径——冻结本波次并退回 02。

```text
03：素材有没有、是否可用、限制是什么
05：用不用、放在哪里、如何形成论证
```

02 结构不清 → 退回 02；问题边界仍有关键歧义 → 退回 01。

## 2. 本阶段怎么做

### 2.1 入口与研究口径

开始前确认：已有配对的研究逻辑与任务本体视图；核心待验证观点、最小问题树、关键路径与每节点的最低验证条件已齐；反证与竞争解释方向已说明。

| 02 质量状态 | 03 怎么处理 |
|---|---|
| 高质量通过 | 可进入正式 03 |
| 最低通过 | 可进 03，但须标明上游限制，不得默认证据已够用 |
| 草稿 | 不进正式 03 |
| 需返工 | 退回 02 |

缺公司、产品、数值、来源等现实材料 → 继续准备。缺命题、路径或最低验证条件 → 退回 02。

入口通过后固定：任务与运行标识、数据截止时点、时间/对象/来源/口径范围。同一次研究中，准备说明、归档与后续 04 必须用同一套范围。扩大对象、改时间或换关键口径时开新运行，不得覆盖旧归档。

### 2.2 先设证据要求，再取证

预设只回答：为达到某种强度的判断，至少需要什么证据；哪些必需、可替代、仅可代理；缺失时如何降级或停止。它不是结论，不得写成“已经证明”。

工作顺序：

```text
核心判断 → 主取证方法 → 必需证据角色 → 本次证据要求
→ 来源与取数 → 来源说法 → 归一事实
→ 单项评价 → 证据是否够用 → 04 最多能说到哪一层
```

02 给出的每条证据要求，本阶段结束时须有对应证据、缺口说明，或明确的「无法取得 / 阻断」策略。

本阶段的执行与验收粒度必须保持为同一条 `ER-nn`：

```text
ER-nn
→ 取证任务与来源路线
→ EV-nn / GAP-nn.evidence_requirement_ids
→ 逐 ER 满足评估
→ JU 证据把握
→ task_answer_contract 根问题可回答性
```

每条 EvidenceDraft 必须用 `evidence_requirement_ids` 指向它实际满足或暴露缺口的 ER。只绑定 JudgmentUnit 不足以证明某项具体证据要求已满足；同一 JU 有多个同角色 ER 时，不得把一条宽泛事实自动复用于全部 ER。旧产物只有在“同 JU、同角色且唯一候选”时才允许确定性迁移，否则视为未绑定并返工。

若 02 使用了候选结构，03 可继续准备，但须写明依赖、可用边界，以及对结论强度的限制；关键路径依赖候选结构时，路径通常记为「受限可用」。

### 2.3 按核心问题拆解，不按主题泛搜

从 02 的核心问题与传导环节拆可执行需求。判断类型决定主取证方法（见知识库 A01—A09），不得根据手头材料反推问题类型。发现判断拆分或类型错误 → 退回 02。

**证据角色**（材料在本次判断中起什么作用）只用五类：主证据、比较基准、机制或承接、独立交叉验证、反证与限制。范围与口径是所有材料的有效性前置检查，不是可选角色。不得为填满五类而补材料。

**最小充分：** 先关键节点硬性证据 → 再支持/反证的最低交叉验证 → 再显著降不确定性的材料 → 再目标报告通常需要的展示素材。达到门槛且新增信息不再改变节点状态时应停止。“没有找到”只表示当前权限与检索范围内缺失。

**覆盖率 ≠ 门槛：** 覆盖率回答变量—锚点完成了多少；门槛必须逐 ER 回答主体、时间、口径、角色和独立来源数是否满足。只有必需 ER 满足，04 才能使用对应观点；“某 JU 已有材料”不能替代逐 ER 验收。

### 2.4 证据质量（研究员语言）

| 把握 | 含义 | 04 最多能形成的结论 |
|---|---|---|
| 充分 | 直接证据、口径匹配、必要交叉验证与重大反证检索完成 | 明确判断（含明确支持与明确否定） |
| 受限 | 主证据基本可用，但样本、范围、时效、独立性或冲突消解有限 | 有条件判断 |
| 观察 | 主要依赖代理、单点、二手或间接材料 | 方向观察与待验证项 |
| 不可用 | 关键证据缺失、不可追溯或口径错配 | 暂不可判断 |

把握先逐 ER 评估，再按 JU 的最薄弱必需 ER 汇总，最后按 02 `task_answer_contract` 判断根问题能否完整回答。任一必需 JU 不可用时，其他单元材料再多也不能把根问题抬成完整回答。核心证据完全依赖代理时，不得高于「受限」。图表数量、「像不像研报」不属于证据质量。

进入有效计数的材料须可追溯、来源清晰、主张类型清晰、动态内容有业务时间、口径与权限明确，并与当前核心判断直接相关。不得计入：无法定位原文的摘要、搜索页或 AI 回答、权限不清的内部材料、无业务时间的动态变量、未区分事实与观点的二手转述。

### 2.5 来源与材料处理

正式选源规则见知识库 [`B00`](../../../methods/03_取证/B00_来源选择与使用边界.md)。03 只负责把本次实际采用的来源与获取过程记清楚：谁生产、描述什么对象与期间、如何取得、是否有权使用、原文在哪、本次能证明什么与不能证明什么。

改用替代来源须说明口径差异及对结论强度的影响。同源或同转述链不得记为独立交叉验证。

四类材料须分开：

| 类型 | 含义 |
|---|---|
| 原始材料 | 尚未处理的接口响应、表格、公告、财报、网页等 |
| 语义实例 | 公司、产品、材料、环节及稳定关系 |
| 推理输入 | 有业务时间的事件、观测、信号或市场预期 |
| 证据记录 | 来源文档、最小主张、归一事实及其支持/削弱/阻断作用 |

来源观点不得归一为已发生事实；预测和指引不得替代实际观测。

### 2.6 两套独立结果

| 结果 | 回答 | 不得受什么影响 |
|---|---|---|
| 证据是否够用 | 证据是否足以形成判断，04 最多可说到多强 | 图表数量、版式、报告表现力 |
| 展示素材是否就绪 | 目标报告类型下，图表/表格/来源注释有没有、是否可用、限制是什么 | 不得反向抬高或压低证据把握；不得据此预写 05 章节或投资要点 |

因此既可以出现“证据充分、展示素材仅部分就绪”，也可以出现“证据不足但缺口表/来源注释等展示素材已就绪”。两项必须由各自输入独立派生，不得因为证据门通过就自动把展示素材记为 `ready`，也不得因缺图表压低证据把握。

素材限制只写形态上限（例如“缺统一分母故不可制国产化率图”），不写章节安排或标题草稿。

### 2.7 交给 04 什么

交给 04 的是写明使用边界的推理依据，不是材料堆砌。对每个核心判断须说清：允许方向性推理 / 只能条件判断 / 只能暂不可判断；反证与竞争解释状态；冲突、代理依赖及口径/时间/权限限制；目标报告下哪些展示素材已具备。04 必须逐观点继承，不得用整份材料包状态支持所有观点。

## 3. 质量门槛与返工

本节是 03 质量要求与返工条件的唯一权威。全局定义见 [`00A`](../../../governance/03_校验/00A_高质量产出判别标准.md)。

### 3.1 阶段质量状态

| 状态 | 含义 | 处理 |
|---|---|---|
| 草稿 | 尚未完成或未校验 | 不进入 04 |
| 最低通过 | 流程和文件完整，可供 04 草稿 | 可进 04 草稿，不得正式发布 |
| 高质量通过 | 通过规则校验 | 可作为正式 03 交付 |
| 需返工 | 关键证据、口径、来源、权限或「是否够用」未解决 | 返工 |
| 缺口停止 | 当前条件不足以支撑方向性推理 | 输出缺口说明 |

### 3.2 最低通过（可进 04 草稿）

1. 02 入口校验通过；研究范围已固定；证据要求已预设；
2. 需求按核心判断拆解；取证方法、来源与取数方式已说明；
3. 证据归档完整；状态变量覆盖可复核；阶段状态可解释；
4. 每个核心判断的最终把握、反证依据和关联路径已给出。
5. 每条 EvidenceDraft 已绑定具体 ER；每条 02 ER 都有事实、显式 gap 或阻断记录，并形成逐 ER 满足评估。

### 3.3 高质量通过

1. 围绕核心判断取证，而非主题泛搜；每个核心判断完成证据要求预设与门槛判断；
2. 已调用合适取证规则；来源生产者、内容领域、获取方式、权限与材料形态已区分并评价；
3. 反证与竞争解释有实际检查；代理指标边界、失效条件与折扣已说明；冲突有处理或降级；
4. 受限路径与只能暂不可判断的核心判断已写清原因与边界；
5. 准备说明与归档一致；已独立输出展示素材就绪度，且未预写 05 表达、未反向改变证据质量。
6. 关键 ER 的主体、时间、口径、角色与独立来源门槛逐项满足；未用同 JU 的其他材料或全局覆盖率替代。
7. 已按 `task_answer_contract` 检查必需 JU 是否足以回答 01 根问题；不能完整回答时明确限制为部分回答或暂不可判断。
8. 确认时已用 01 截止时点、02 研究范围和当前 Source Registry 重算本体预检；范围/时点漂移、代理披露缺失、商业化阶段缺失、产能/良率六维口径不全均已修复或转为显式 gap。

### 3.4 不得进入 04 方向性推理

未完成证据要求预设；EvidenceDraft 未绑定具体 ER；核心 ER 门槛未满足；必需证据缺失；反证检查缺失；来源不可复核或不独立却当交叉验证；口径/时间不匹配；动态变量缺业务时间；权限不清；冲突未处理；代理越权；可用边界未列出；或 `ontology_precheck.blocking_soft_count > 0`。

### 3.5 返工去向

| 问题 | 处理 |
|---|---|
| 02 路径、核心判断或最低验证条件不清 | 退回 02 |
| 新证据只能通过新变量/新路径/新竞争假设解释 | 冻结波次，完整重做受影响的 02 后再做 03 |
| 新证据已映射到既有 02 结构 | 保持 02，新开 03 波次 |
| 需求过宽、规则选错、来源混乱、口径不匹配、反证缺失、代理越权、边界不清、准备说明与归档不一致 | 在 03 内补证、降级或重写相应部分 |

---

## 4. 一句话原则

> 先为关键判断设定证据要求，再取得匹配口径、可追溯、可复核、经过反证检查的足够证据，并清楚告诉 04 只能判断到哪里——好坏不取决于材料数量。

| 阶段状态枚举 | `draft` / `minimum_pass` / `high_quality_pass` / `return_required` / `stop_with_gap_report`；取证完成填 `stage_status=complete` |
| 候选结构路径 | 关键依赖时原则上 `path_readiness_status=restricted` |
| 波次 | 先冻结整批证据再实例化与映射；对象级传播 stale；不得每条来源全链重跑 |

增量证据波次必须先记录 `changed_roots`，再通过主体、范围、时间、口径和证据角色匹配得到 `direct_impacts`。新增 EvidenceFact 自身保持 current；已有 EvidenceBasket、取证 MethodApplication 或 Signal 只有在被直接命中或从直接影响对象可达时才标记 stale。不得因为新证据属于 03，就把整个 03—05 阶段全部作废。

## 5. Ontology 3.0 方法输入绑定

03 必须完整继承 02 的 `method_applications`，不得只保留取证方法而省略裁决候选。以单条 `EvidenceFact` 为最小单位填写 `input_evidence_refs`，不得用整个 EvidenceBasket 同时支撑多个语义不同的判断。取证方法可更新为 `selected / degraded / rejected / blocked`，尚未裁决的方法保持 `candidate`；所有 MA 必须沿用 ID、方法版本、能力类型和目标判断单元，逐项记录前置条件、支持/反证证据、未满足输入、代理关系与局限。03 禁止确认 `executed`。

`EvidenceBasket` 只负责把同一判断单元、同一角色的证据组织起来，并通过 `basketFulfillsRequirement` 指向 02 已存在的具体 ER；不得在 03 临时创建“ER-RUNTIME-*”宽泛门槛替代 02 合同。篮子不能充当 04 的最小推理输入。03 交接时必须保留篮子内的具体 `EV-nn`；如果只能引用篮子而不能指出具体事实，该证据组合不得进入规则条件或最终表达。

03 只能把候选方法推进为 `selected`、`rejected`、`blocked` 或 `degraded`；是否真正 `executed` 由 04 确认。事实、信号和判断必须分层：来源陈述归一为事实，事实可以支持观测、事件、信号或假设，但不得直接形成最终 Judgment。
