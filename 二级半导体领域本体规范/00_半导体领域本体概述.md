# 半导体领域本体概述

## 1. 定位

半导体领域本体是平台级投研本体在半导体行业中的领域扩展。它负责定义半导体研究中稳定、可复用的对象类型、分类语言、关系结构、判断变量、证据要求和传导骨架。

它不是公司库、产品型号库、材料牌号库、工厂数据库、指标库或资讯库，也不承载一次研究任务的运行配置。

本体希望回答的是：

- 一个研究对象在半导体产业中是什么、处于哪里、与什么稳定连接；
- 判断需求、供给、技术、政策、竞争和公司影响时应该观察什么；
- 这些变量通常如何传导，哪些条件会削弱或逻辑失效传导；
- 每个判断需要什么证据，什么材料构成反面证据或其他可能解释。

## 2. 与平台本体的关系

本领域本体继承 `../一级通用本体规范` 的三层结构和治理边界：

| 平台层 | 领域本体的职责 |
|---|---|
| 语义层 | 补充半导体对象扩展、产业分类、稳定关系和受控词表 |
| 证据层 | 按判断变量说明证据、反面证据、口径和时效要求 |
| 推理层 | 补充半导体事件类型、判断变量、传导模板和通用情景 |

平台已有的 Concept、Organization、Company、PolicyInstrument、Industry、Segment、Product、Material、ProcessStep、Region、Application、Asset、FinancialInstrument、Identifier、IdentificationScheme、TradingVenue、Listing、RoleAssignment、StateVariable、Event、Hypothesis、Signal、Judgment、MarketExpectation、AssetImpact、Scenario 及证据对象均直接复用，不在领域本体中重新定义。

领域仅新增两个无法由现有对象清晰表达的对象类型：

- `TechnologyRoute`：稳定的制程、器件架构、互连、封装和系统集成路线；
- `ManufacturingFacility`：具有独立位置、运营主体和工艺能力的制造设施。

半导体需求来源复用 `Application`，政策、贸易、许可、产能和设施所在地复用 `Region`；半导体相关证券、基金份额、指数、交易代码和上市挂牌安排复用一级金融对象与识别对象。

## 3. 产业边界

### 3.1 纳入范围

本体覆盖核心半导体产业：

1. 基础研发、器件和系统工程；
2. EDA、设计 IP、芯片设计和设计服务；
3. 掩模、晶圆、设备、设备子系统和半导体材料；
4. 前道晶圆制造、特色工艺和化合物半导体制造；
5. 晶圆测试、组装、传统封装、先进封装和成品测试；
6. 逻辑、存储、模拟、分立器件、光电子、传感器与执行器；
7. 硅基、化合物半导体、功率、射频、光子、MEMS、先进存储、Chiplet、2.5D/3D、异构集成和 Beyond CMOS 路线；
8. 半导体需求来源、商业模式、竞争格局、供应链韧性、地域和政策暴露。

### 3.2 相邻但不并入核心的范围

显示面板、光伏、PCB 和电子整机只作为相邻产业或下游应用。它们可以通过 Industry、Application、Product 等关系与半导体对象连接，但不在本体中展开自身完整产业结构。

### 3.3 明确排除

- 具体公司、金融工具、识别码、交易场所挂牌、客户、工厂、产品型号和材料牌号实例；
- 实时或历史价格、收入、库存、交期、产能、良率、估值等读数；
- 已发生的新闻、政策、事故和公司事件；
- 已确认观测、研究观点、正式判断和投资结论；
- 买卖建议、目标价、收益率预测和仓位建议；
- manifest、runtime index、loading profile、data bindings、refs、evidence slots 和 validation report。

## 4. “完整”的含义

本体的完整性指领域表达能力完整，而不是现实样本穷举。

一个完整、可用的半导体领域本体应满足：

- 任一常见半导体产品能归入稳定产品类别；
- 任一主要工艺、设备和材料能找到分类与关系端点；
- 任一公司都能在具体任务中表达其商业模式、产业链位置、设施、产品、技术路线和需求暴露；
- 需求、库存、产能、良率、价格、技术、政策和竞争变化能够通过通用变量进入推理；
- 产业变化到公司经营、市场预期和资产影响之间存在可检查的中介变量；
- 支持证据、其他可能解释、削弱条件和判断不再成立的条件能被同时保留。

完整性不要求把全球所有公司、产品或工厂预置进本体。

## 5. 文件结构

| 文件 | 作用 |
|---|---|
| `common.yaml` | 版本、平台依赖、产业边界、命名和质量门槛 |
| `semantic.yaml` | 对象扩展、稳定关系和完整受控分类体系 |
| `reasoning.yaml` | 事件类型、46 个判断变量、28 条传导模板、四类结果情景和九类业务场景标签 |
| `evidence.yaml` | 12 类证据 profile、商业化阶段、最低覆盖规则和质量约束 |
| `01_半导体语义结构域说明.md` | 解释对象、分类和关系如何使用 |
| `02_半导体判断推理域说明.md` | 解释变量、传导、反面证据和情景如何使用 |
| `03_半导体证据域说明.md` | 解释证据如何进入判断并约束结论 |

分类体系直接放在 `semantic.yaml`，因为它是语义对象属性和关系使用的受控语言。场景模板直接放在 `reasoning.yaml`，因为它是变量条件的通用组合，而不是独立运行包。

## 6. 分类体系与实例的区别

分类体系规定“允许有哪些类别、类别之间是什么层级”，实例说明“现实世界中的某个对象属于什么类别”。

例如：

```text
逻辑器件 → 加速处理器
存储器件 → 堆叠与高带宽存储
化合物半导体衬底 → 某种具体材料实例
先进封装 → 2.5D与3D集成
```

前者属于领域本体，具体厂商、型号、订单和时点状态属于后续任务或数据层。

稳定的产品、材料和技术类别可以进入分类体系。例如 HBM、SiC、GaN、InP、Chiplet 等可以在具体任务或更细分类中使用，因为它们是跨公司复用的领域术语；它们不得被写成某个场景已经成立的事实。

## 7. 推理边界

本体只保存通用业务结构：

```text
需求增强
→ 订单能见度改善
→ 产能或供给压力变化
→ 价格、交期、设备材料需求变化
→ 公司暴露与执行能力决定经营结果
→ 与市场预期比较
→ 形成资产影响或降级结论
```

这不是确定性规则。每一步都需要证据、适用条件、时间尺度、其他可能解释和反面证据检查。

以下跳跃被明确禁止：

- 事件直接推出资产影响；
- 需求增长直接推出利润改善；
- 产品发布直接推出收入兑现；
- 政策发布直接推出受益公司；
- 技术指标领先直接推出大规模替代；
- 行业景气直接推出某家公司业绩改善。

## 8. 证据与观测

关键变量定义“持续判断什么”，Observation 记录“某一时点观察到了什么”。两者不得混用。

例如，“库存周期位置”是关键变量；某季度的库存数量是 Observation。“良率成熟度”是关键变量；某条产线某批次的良率是 Observation。

分析师预测、公司指引和市场观点不是已发生观测，应分别作为 Signal、Hypothesis 或 MarketExpectation 使用。

## 9. 参考依据

分类和领域边界综合参考：

- Semiconductor Industry Association 的器件分类和设计—前道—后道价值链；
- SEMI 的设备、材料、电子设计、制造、封装与测试分类；
- IEEE IRDS 的制程微缩、器件架构、互连、先进封装、量测、良率和新型计算路线；
- NIST CHIPS for America 对设施、设备材料依赖、专业化供应链和地域集中风险的描述。

## 10. 使用方式

领域本体在运行时应被作为稳定母结构消费：

1. 识别用户问题涉及的对象类别；
2. 建立本次涉及的公司、产品、材料、设施、技术路线或需求来源记录；
3. 选择相关关键变量和传导模板；
4. 按证据配置收集支持材料和反面证据；
5. 创建有业务时间的 Observation、Event、Signal 和 Hypothesis；
6. 经过其他可能解释、预期比较和逻辑失效检查后形成分级判断；
7. 将可复用、经过复盘的新增内容提交本体治理，而不是直接写回正式本体。

## 11. 一句话定义

半导体领域本体是在平台投研本体之下，完整表达核心半导体产业对象、分类、稳定关系、判断变量、证据要求和通用传导能力的行业母本体；它不是现实样本数据库、单一场景包或运行配置。
