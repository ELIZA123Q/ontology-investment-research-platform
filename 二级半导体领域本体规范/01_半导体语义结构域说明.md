# 半导体语义结构域说明

## 1. 域定位

半导体语义结构域定义行业中稳定存在什么，以及这些对象如何连接。它提供推理和证据共同使用的语义锚点。

本域保存：

- 对象类型和属性扩展；
- 产品、工艺、设备、材料、技术路线、商业模式和需求来源分类；
- 产业链归属、生产、使用、依赖、替代、设施和地域关系。

本域不保存：

- 某一时点的需求、价格、库存、交期、产能、良率或预期；
- 技术采用率、量产进度、替代强度和政策执行强度；
- 具体公司、产品、设施或事件实例；
- 关系当前增强或减弱的判断。

## 2. 复用的平台对象

| 对象 | 半导体领域中的用途 |
|---|---|
| `Concept` | 术语、上下位概念和概念边界 |
| `Industry` | 核心半导体、支撑产业、下游产业和相邻产业 |
| `Segment` | EDA/IP、设计、设备材料、制造、封测和应用等产业链位置 |
| `Company` | 后续任务进入的现实组织主体 |
| `Product` | 半导体器件、设备、软件/IP、制造与工程服务 |
| `Material` | 器件、前道、封装测试和厂务使用的材料 |
| `ProcessStep` | 设计、制造、封装、测试、认证和失效分析工序 |
| `Application` | 稳定产生半导体需求的终端行业、系统形态、应用场景和工作负载 |
| `Region` | 公司、设施、政策、贸易、许可和市场准入的地域锚点 |
| `Organization` | 政府、监管、标准和行业组织 |
| `PolicyInstrument` | 政策、法律、监管规则、管制措施和行业标准 |
| `Asset` | 后续判断最终关联的股票、债券、商品或其他资产 |
| `FinancialInstrument` | 半导体相关证券、基金份额、指数工具、衍生品和其他金融工具 |
| `Identifier` | 证券代码、ISIN、LEI、MIC、交易代码和内部主数据编码 |
| `IdentificationScheme` | 识别码规则、适用范围和管理主体 |
| `TradingVenue` | 交易所、场外市场、替代交易系统或市场分段 |
| `Listing` | 金融工具在交易场所或市场分段的上市挂牌安排 |
| `RoleAssignment` | 发行人、管理人、担保人、交易场所运营方等上下文角色 |

设备不单独建成对象类型。设备是 Product，并通过 `equipmentCategory` 进入半导体设备分类。这样可以继续使用产品生产、竞争、依赖和公司关系，避免重复建模。

## 3. 新增对象

### 3.1 TechnologyRoute

`TechnologyRoute` 表示可跨公司、产品和场景复用的稳定技术路径。

适合建成 TechnologyRoute 的内容：

- 制程微缩和晶体管架构；
- 特色工艺、功率、射频、光子和MEMS路线；
- 先进存储、芯片互连、先进封装和异构集成；
- 设计工艺协同优化和 Beyond CMOS。

不进入其静态属性的内容：

- 当前采用率；
- 当前良率和成本；
- 当前客户验证和量产进度；
- “某路线正在加速替代”的判断。

这些内容分别由 `technology_maturity`、`technology_competitiveness`、`technology_substitution_intensity` 等状态变量承载。

### 3.2 ManufacturingFacility

`ManufacturingFacility` 用于表达需要独立位置、运营主体、工艺能力和生命周期的设施类型，包括晶圆厂、封装厂、测试设施、掩模设施、材料和设备生产设施。

设施的稳定工艺能力可以进入语义域；当前产能、利用率、投产进度和良率属于推理域。

需求来源不再新增对象，统一扩展一级 `Application`；辖区也不再新增对象，统一使用一级 `Region`。原有半导体需求分类继续作为 Application 的受控分类，设施和公司位置关系改为指向 Region。

## 4. 分类体系

分类体系直接定义在 `semantic.yaml.controlled_vocabularies`。每个分类值包含稳定键、中文名称、定义和可选父级。

### 4.1 产业角色

| 分类 | 定义 |
|---|---|
| 核心半导体产业 | 半导体器件及其直接设计制造体系 |
| 支撑产业 | EDA、IP、设备、材料、设施和专业服务 |
| 下游产业 | 采购并集成半导体的终端行业 |
| 相邻产业 | 工艺或供应链相关但不属于核心范围的产业 |

### 4.2 产业链环节

产业链从研发到应用依次覆盖：

```text
基础研发
→ EDA/IP、芯片设计、设计服务
→ 掩模、设备、设备子系统、材料、晶圆与衬底
→ 前道晶圆制造、特色与化合物半导体制造
→ 晶圆测试、组装、封装、成品测试
→ 分销、模组与系统集成
→ 下游应用
```

`upstreamOf` 只表达稳定上下游结构。需求增强、交期拉长、价格变化和利润迁移必须进入推理域。

### 4.3 产品五轴分类

Product 使用五个受控轴：

| 轴 | 字段 | 词表 |
|---|---|---|
| 领域总类 | `productDomain` | `product_domain` |
| 器件功能 | `semiconductorDeviceCategory` | `semiconductor_device_category` |
| 存储细类 | `memoryProductCategory` | `memory_product_category` |
| 设备类别 | `equipmentCategory` | `equipment_category` |
| 模组系统 | `moduleSystemCategory` | `module_system_category` |

存储细类包含 DRAM、NAND、NOR、HBM、DDR、LPDDR、企业级 SSD 等稳定分类。

分类允许多选。一个 SoC 可以同时包含逻辑、模拟和存储功能；一个光电传感产品也可能同时命中光电子和传感器分类。
同一分类轴内遵循最细粒度优先：能确认 HBM 时不再把 memory 作为并列分类；父类仅用于层级归属或细类未知时兜底。

### 4.4 工序分类

工序覆盖五个阶段：

1. 设计：产品定义、架构、逻辑与电路、验证、物理设计、流片和掩模数据；
2. 晶圆与前道：晶体生长、外延、清洗、氧化扩散、沉积、光刻、刻蚀、注入、热处理、CMP、互连；
3. 过程控制：量测、检测、缺陷控制和晶圆测试；
4. 后道封装：切割、贴装、互连键合、塑封、封装组装；
5. 测试与验证：成品测试、可靠性、失效分析和芯片后验证。

ProcessStep 是稳定工序，不记录某次生产批次。

### 4.5 设备分类

主要设备类别包括：

- 晶圆制造、掩模与光罩；
- 清洗与表面处理、涂胶显影、曝光与图形化；
- 刻蚀、薄膜沉积、离子注入、热处理、CMP；
- 量测检测、厂务与设施、自动化搬运；
- 组装封装、晶圆测试、成品测试、可靠性与分析；
- 光源、真空、射频、电源、阀泵、运动控制等设备子系统。

设备分类用于约束 Product；工序通过 `processUsesEquipment` 连接具体设备产品或产品类别。

### 4.6 材料分类与组成轴

材料分类使用 `semiconductorMaterialCategory`；组成体系使用 `materialCompositionAxis`（Si、SOI、SiC、GaN、GaAs、InP）。ABF 归入封装基板材料，不与技术路线混放。

- 元素半导体、化合物半导体、SOI和其他工程衬底；
- 外延、掩模与光罩、光刻胶及配套材料；
- 电子气体、湿电子化学品、沉积前驱体、靶材和掺杂材料；
- 介质、导体、互连、CMP和工艺耗材；
- 封装基板、引线框架、键合互连、塑封底填和热管理材料；
- 厂务和污染控制材料。

具体化学品、规格和牌号是 Material 实例或属性，不进入分类树主体。

### 4.7 技术路线分类

技术路线覆盖：

- CMOS 微缩、晶体管架构和设计工艺协同优化；
- 存储架构、特色工艺、功率、化合物半导体；
- 光子与光电子、MEMS与传感；
- 芯片互连、传统封装、晶圆级封装；
- Chiplet与异构集成、2.5D与3D集成；
- 先进测试和 Beyond CMOS。

技术路线可通过 `technologyRouteDependsOn` 连接其关键工艺、材料、设备产品或其他路线，通过 `technologyRouteCanSubstituteFor` 表达稳定可替代范围。

### 4.8 商业模式

Company 可同时承担多个角色：Fabless、IDM、Foundry、OSAT、EDA、IP、设计服务、设备、子系统、材料、分销、模组系统和终端客户。

角色必须来自实际业务结构。不能仅因公司被市场称为“设备公司”或“AI公司”就建立正式角色。

### 4.9 需求来源

需求来源覆盖数据中心与云、个人计算、通信网络、消费电子、汽车、工业自动化、能源电力、医疗、航空航天与国防、IoT与边缘计算、存储系统、科研与量子系统。

需求来源只描述稳定需求类别。当前景气和资本开支由状态变量表达。

### 4.10 政策工具分类

政策分类包括产业激励、政府采购、出口管制、进口限制、制裁、关税、投资审查、技术许可、环境健康安全、网络与供应链安全、标准认证、人才与移民政策。

分类不是事件。只有具备政策原文、生效时间、适用范围和证据的事实才能创建 Event。

## 5. 新增稳定关系

### 5.1 技术路线关系

| 关系 | 起点 → 终点 | 含义 |
|---|---|---|
| `technologyRouteAppliesTo` | TechnologyRoute → Segment/Product/ProcessStep | 路线适用于对象 |
| `technologyRouteDependsOn` | TechnologyRoute → Product/Material/ProcessStep/TechnologyRoute | 路线结构性依赖 |
| `technologyRouteCanSubstituteFor` | TechnologyRoute → TechnologyRoute | 路线在明确范围内可替代另一条路线 |

实际成熟度、采用进度和替代强度不写在关系中。

### 5.2 需求关系

| 关系 | 起点 → 终点 | 含义 |
|---|---|---|
| `productUsedInApplication` | Product → Application | 产品满足某类稳定应用需求 |
| `applicationBelongsToIndustry` | Application → Industry | 应用归属终端产业 |
| `companyExposedToApplication` | Company → Application | 公司长期暴露于某类应用需求 |

### 5.3 工艺投入关系

| 关系 | 起点 → 终点 | 含义 |
|---|---|---|
| `processUsesEquipment` | ProcessStep → Product | 工序使用某类设备产品 |
| `processUsesMaterial` | ProcessStep → Material | 工序使用某类材料 |

关系表达稳定使用结构，不表达当前采购数量、价格或供应紧张度。

### 5.4 设施与地域关系

| 关系 | 起点 → 终点 | 含义 |
|---|---|---|
| `facilityOperatedBy` | ManufacturingFacility → Organization | 设施由组织拥有或运营 |
| `facilityLocatedIn` | ManufacturingFacility → Region | 设施位于地区 |
| `facilitySupportsProcess` | ManufacturingFacility → ProcessStep | 设施具备某工艺能力 |
| `facilityProducesProduct` | ManufacturingFacility → Product | 设施具备某类产出能力 |
| `facilityProducesMaterial` | ManufacturingFacility → Material | 设施具备某类材料生产能力 |
| `facilityUsesTechnologyRoute` | ManufacturingFacility → TechnologyRoute | 设施具备某路线能力 |

公司总部或注册地使用一级 `organizationLocatedIn`；生产、销售和服务活动使用 `companyOperatesInRegion`。

当前产能、利用率、扩产阶段和设施受政策影响的程度属于推理域。

## 6. 平台关系扩展

以下平台关系允许连接新增对象：

- `conceptMapsToObject` 可映射 TechnologyRoute 和 ManufacturingFacility；Application 与 Region 已由一级关系覆盖；
- `identifierIdentifiesObject` 可识别 TechnologyRoute 和 ManufacturingFacility；
- `upstreamOf` 仅用于 TechnologyRoute 之间的稳定上下游结构；`dependsOn` 用于 TechnologyRoute 及设施到技术/产品/材料/工序的稳定依赖；
- `assetExposedTo` 可关联技术路线和设施；Application 与 Region 已由一级关系覆盖；
- `roleAppliesToObject` 可把一级 RoleAssignment 作用到 TechnologyRoute 或 ManufacturingFacility。

资产的当前影响方向、强度和是否已定价仍由 AssetImpact 和 MarketExpectation 表达。

## 7. 建模判断

### 7.1 对象还是属性

需要独立身份、被多方连接、被证据引用或具有生命周期的内容建对象；只描述对象的轻量特征建属性。

例如，制造设施需要连接公司、地域、工艺和产品，因此建成对象。设施当前利用率只是一项动态观测，不建成语义对象。

### 7.2 分类还是实例

跨公司长期复用的类别进入分类；具有现实身份的成员进入实例层。

### 7.3 关系还是传导

“某工序使用某类设备”是稳定关系；“制程升级提高设备需求”是变量传导。后者必须进入 `reasoning.yaml`。

### 7.4 技术路线还是产品

产品回答“交付什么”，技术路线回答“通过什么技术路径实现”。同一产品可采用多条路线，同一路线也可服务多个产品。

## 8. 语义域禁止项

- “需求正在增强”“价格正在上涨”“交期正在延长”；
- “某路线将替代另一条路线”；
- “某政策利好某公司”；
- 某公司当前产能、份额、订单或客户；
- 某设施当前投产、利用率或良率；
- 任何结论等级、置信度、目标价或交易建议。

这些内容必须进入推理、证据或运行层。
