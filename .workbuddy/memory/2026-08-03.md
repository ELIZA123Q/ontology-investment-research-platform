## start-light.command 打不开 — 根因与修法
- 现象：双击 `start-light.command` 后平台打不开 / 一闪而过。
- 根因：`.next` 目录存在但**无有效生产构建产物**（缺 BUILD_ID），`prod-singleton.sh` 判定 `.next` 存在即跳过 build，直接 `next start` → 报错 `Could not find a production build in the '.next' directory` 并立即退出。
- 修法：前台跑 `npm run build`（= `next build --webpack`）生成 BUILD_ID；构建完成后 `npm run prod:singleton` 正常起服务，HTTP 200 已验证。
- 重要坑：Bash 工具里后台 `nohup ... &` 启动的 `next build` 会被沙箱在调用结束后回收（日志冻结、BUILD_ID 不生成），所以**构建必须在前台单次调用跑完**；启动服务则可后台。
- 复发预案（已自动化）：`start-light.sh` 已改造——启动前用 `[ -s .next/BUILD_ID ]` 判断有效生产构建：有效则 `npm run prod:singleton`（MAX_WAIT=30s，秒起）；无效/缺失则自动改用 `npm run prod:rebuild`（先 `next build` 再起，MAX_WAIT=600s，构建期每 30s 提示进度）。`start-light.command` 仅 exec 该 sh，无需改。以后双击即自愈，无需手动 rebuild。服务地址固定 http://127.0.0.1:3000/。
