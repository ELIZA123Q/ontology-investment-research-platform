# 2026-08-02 工作日志

## 轻量启动一键脚本
- 新建 `start-light.sh`（项目根目录）：诊断端口 3000 → 强杀残留/卡死进程 → 后台 `npm run prod:singleton` → 轮询确认 HTTP 200。日志 `/tmp/workbench-prod.log`。
- 用户意图：封装"诊断→强杀→重启"为终端一键脚本，避免手动敲命令。
- 踩坑1：macOS 无 `setsid`（Linux 才有），首版用 `setsid nohup ...` 直接 `command not found` 导致 npm 从未启动。已改为 `nohup ... &`（macOS 兼容，关终端不受影响）。
- 踩坑2：Write 首版在 `$LOG_FILE` 处混入隐藏非法字节，`set -u` 报 `LOG_FILE<�>: unbound variable`；整体重写后解决（`bash -n` + `cat -v` 校验通过）。
- 工具行为注意：在 WorkBuddy Bash 工具里以"脚本为后台任务"启动时，脚本退出后 npm 子进程被一起回收（工具清理 process group），服务不持久。要让服务在工具会话里常驻，须直接以 `npm run prod:singleton` 为后台任务（run_in_background），不要经包装脚本。脚本本身在用户自己终端运行正常。
- 运行模式仍是 `prod:singleton`（轻量，skip build）。dev 模式 `dev:singleton` 内存高易卡死（8GB 机器已知问题）。

## 双击启动支持
- macOS 双击 `.sh` 会被 Finder 当文本打开、不执行。已新增 `start-light.command`（扩展名 .command，macOS 默认用终端执行），内容 `exec bash ".../start-light.sh"`，已 `chmod +x`。
- 双击 .command → 终端打开运行 → 打印 HTTP 200 后窗口停留；npm 经 `nohup &` 脱离，关终端仍常驻。
- 完整脚本入口现时两份：`start-light.sh`（终端用）+ `start-light.command`（双击用），逻辑同源。
