## 第二轮校正（用户追问"预估下降多少、不能牺牲质量"）——重要纠错
- **实测推翻假设**：写临时测量脚本（已删）用真实代码量出 `loadSelectedMethodGuidance(kb03Ids,{totalChars:56000})` 对全部 9 个 kb03 方法（A01–A09）实际只产出 **10,653 字符（≈10K token），truncated=0**——即 56K 上限是**虚的**，真实正文才 10.6K。因此：
  - 第二轮的"56K→28K 省 ~72K token"是**错的**（28K 上限也没触顶，仍装下全部 10.6K）。
  - 注入的 digest（~2,038 字符≈1.9K token/批）是**净增加**，且门禁内容与方法正文里已完整发送的 10.6K **重复**（正文未截断，gates 都在 payload 里）。
- **已回退/调整**：
  - 删除 `context_assembler.ts` 的 `method_guidance_supplement: 28000` 死旋钮（误导性，省 0）。
  - `evidence_auto_supplement.ts` 的 `loadSelectedMethodGuidance` 预算改回 `CONTEXT_SLOT_BUDGETS.method_guidance`（56K，实际仍只用 10.6K）。
  - **保留 digest 注入**：它是方法级硬性门禁的"高亮保险"，成本仅 1.9K token/批（占 1M ~2%），契合用户"不牺牲质量"要求；注释改为说明其角色是 prominence 而非省钱。
- **真相：唯一真金白银的模型侧节省来自第一轮**（引文窗口 1200→300 / 2400→400）。因为它缩小了**逐轮重发、且随轮增长的 `current_evidence_draft`**——这是 stage_03 token 真正的大头（每批次固定 26K token：system 4.3K + digest 1.9K + method_guidance 10.1K + type_cards 2.3K + routes 5.4K + hints 0.8K + caps 1.3K）。12 条源时，草稿从 ~14.8K token 降到 ~4.5K token，**每轮重发省 ~9.5K token**（随源数与轮数放大）。
- **结论口径**：token 总量不会"断崖下降"，但在相同覆盖率下，因草稿更小+12 批精准+不截断，同等证据量所需 token 显著低于旧版（旧版 1M 只换 20% 覆盖且截断）；延迟上每轮调用输入更小→单 call 更快，且能跑完而非半途截断。
- **下一步真杠杆（未做）**：逐轮重发的 `current_evidence_draft` 是最大乘数——可考虑只发 batch-scoped 来源 + 近 N 条，或发 delta，而非整份增长草稿。这是比"砍 method_guidance"实在得多的优化。
- 测试：回退后 `evidence_auto_supplement`(23)/`context_assembler`(12)/`method_registry`(22) 共 57 全过（首跑偶发 1 失败，重跑稳定，判为并行负载偶发）。

## 启动服务：脱离进程树（解决"打不开 / 命令结束即死"）
- **现象**：用户 `npm run prod:singleton` 或直接 `nohup next start &`，服务 Ready 后能开，但下一条 Bash 命令一结束端口就没了（HTTP 000）。根因＝沙箱 Bash 在命令结束时清理整个进程组，`nohup` 只挡 SIGHUP 挡不住进程组级清理；且本机可用内存长期仅 ~64–127MB，`prod:singleton` 同拉 `next start`+`research-worker` 两进程易被 OOM。
- **稳妥启动法**（已验证可跨命令边界存活）：
  1. 用 Node 启动器 `spawn(cmd,{detached:true,stdio:['ignore',log,log]})` + `child.unref()`，让 `next start` 成为独立会话/进程组 leader（等价于缺失的 `setsid`）。脚本 `/tmp/launch-next.js`（cwd=runtime，env 清代理、设 HOST/PORT）。
  2. **只起 `next start`、不拉 worker** 省内存；研究/后台 job 需 worker 时再单独以同样 detached 方式起 `tsx scripts/research-worker.ts`。
  3. 停止：`kill <pid>`（lsof -i :3000 -sTCP:LISTEN 拿 pid）。
- 验证：`curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:3000/` 跨命令仍为 200、标题「投研判断工作台」。
- 内存仍紧：开重型页或跑研究任务再崩时，先关 Claude/飞书/Cursor/Chrome 释放内存。
