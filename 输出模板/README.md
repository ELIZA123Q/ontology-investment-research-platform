# 输出模板

01—04 的总体分工和正式产物见 [`00_项目定位与边界.md`](../00_项目定位与边界.md)。本目录只保存各类产物的结构、字段和填写说明。

当前 02 任务产物版本为 `1.1.0`；03 准备/快照契约版本为 `1.2.0`；04 报告/审计契约版本为 `1.3.0`。

## 1. 01 模板

- `01_投研需求说明模板.md` 文首「模板使用说明」集中保存通过版的 YAML 字段、文件命名、动态范围填写规则与完成检查；其后为正式模板结构。
- `01_不予受理说明模板.md` 文首保存不予受理版的精简 YAML 与正文要求。
- 正式生成文件时不得输出模板维护说明。

## 2. 02 模板

- `02_研究逻辑模板.md` 面向研究员，重点解释问题拆解、关键判断、判断路径、反证和证据计划；它不是 YAML 的文字版。
- `02_判断结构与本体视图模板.yaml` 面向系统，保存本体引用、路径节点、实例需求、证据要求、任务候选、缺口风险和机器校验。
- 正式文件分别命名为 `<核心主题>研究逻辑-<YYYYMMDD>-<当日序号>.md` 和 `<核心主题>本体视图-<YYYYMMDD>-<当日序号>.yaml`；两者必须使用相同主题、日期和序号。
- 两份产物必须共享任务身份和逻辑 ID，并完成双向定位；技术校验统一保存在本体视图 YAML 的 `validation` 中，不进入研究逻辑正文。
- 02 选中的每个状态变量都必须完成“路径节点—状态绑定—观测需求—evidence profile”链，并由 `state_variable_chain_complete` 控制是否允许进入 03。
- `02_本体缺口说明模板.md` 只诊断缺失的判断能力、原因和影响，不直接确定正式本体应新增什么；它不替代 02 配对产物，也不是数据证据准备的输入。

02 和 03 中形成的任务候选都不能写入正式领域本体。

## 3. 03 模板

- `03_数据与证据准备模板.md` 用于说明本次需要什么、如何取得和处理，以及是否达到进入 04 的条件；正式文件命名为 `<核心主题>数据与证据准备模板-<YYYYMMDD>-<当日序号>.md`。
- `03_数据与证据快照模板/` 保存一个同名快照摘要 Markdown 和 10 张 CSV；`state_variable_coverage.csv` 以“状态变量×必需锚点”为覆盖单元，逐项承接输入、原子证据、`evidence_gate_status` 和 04 使用上限。正式目录命名为 `<核心主题>数据与证据快照-<YYYYMMDD>-<当日序号>/`，其中摘要文件与目录同名。
- 03 准入状态为 `normal_pass`、`restricted_pass`、`incomplete_pass`、`failed`；低于 95% 且来源层级未耗尽时不得冻结准入。
- 两项产物使用相同主题、日期、序号和运行标识，并相互引用。03 不再生成任务本体包、质量报告或其他附加文件。

## 4. 04 模板

- `04_推理报告模板.md` 面向研究员，固定使用“核心判断—主导机制—分对象/环节判断—决定性不确定性与情景—跟踪与改判”五段正文。
- 正文使用“已确认、倾向判断、条件判断、暂不可判断”四类观点标签，不展示覆盖率、准入码、路径 ID 或完整变量表。附录 A 只保留证据边界摘要和审计定位。
- `04_推理审计模板.yaml` 面向系统复核，保存证据准入、整体系统等级、观点登记、不确定性分级、本体命中、路径结果、全部状态变量和数据逻辑。审计只引用 03 记录，不复制证据明细。
- 04 每次配对生成 `<核心主题>推理报告-<YYYYMMDD>-<当日序号>.md` 和 `<核心主题>推理审计-<YYYYMMDD>-<当日序号>.yaml`，两者使用同一任务、运行、判断时点、主题、日期和序号，并双向引用。
- `validate_04_outputs.py` 用于检查报告/审计配对、路径与状态变量完整性、03 引用解析、不确定性映射和正文语言边界。
- 04 用 01 校准研究需求和结论边界，用 02 决定研究逻辑、本体结构和规则，用 03 决定本次可使用的事实、证据及其不足；不得把 03 的路径就绪状态直接当作推理结论。
