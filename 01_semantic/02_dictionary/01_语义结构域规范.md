# 投研本体 3.0：语义对象模型规范

版本：3.0.0

机器权威：`models/semantic.yaml`

## 1. 职责

语义对象模型定义跨研究场景保持身份稳定的对象，以及对象之间不依赖某种研究方法的结构关系。对象的动态数值进入状态与事件模型，来源材料进入证据模型，分析结论进入判断模型。

## 2. 核心对象

| 对象 | 边界 |
|---|---|
| `Organization` / `Company` | 组织主体及商业公司子类 |
| `Industry` | 共同供需和竞争结构形成的经济活动集合 |
| `ValueChainSegment` | 产业价值创造中的稳定功能位置 |
| `Product` / `Material` | 可生产、交易或交付的产品；材料是进入制造过程的产品子类 |
| `Technology` | 具有稳定能力边界的技术体系 |
| `Application` | 产品、材料或技术被使用的稳定用途 |
| `ProcessStep` | 具有明确输入、输出和功能边界的制造步骤 |
| `Region` | 地理、经济或监管范围 |
| `PolicyInstrument` | 对对象行为、准入或资源配置形成约束的政策工具 |
| `Metric` | 具有定义、单位和时间口径的度量 |
| `Asset` / `FinancialInstrument` | 经济资产及其金融工具子类 |
| `TradingVenue` / `Listing` | 交易场所与公司金融工具的挂牌安排 |
| `ResearchScope` | 对象、地域、产品、指标和时间边界的可引用集合 |

`Segment` 不再作为核心类型。旧文件中的行业链环节统一映射为 `ValueChainSegment`，原词可保留为别名。

## 3. 身份和继承

- `Company` 继承 `Organization`。
- `TradingVenue` 继承 `Organization`。
- `Material` 继承 `Product`。
- `FinancialInstrument` 继承 `Asset`。

继承只表示身份和约束收窄。子类不得改变父类 ID、放宽必填性或用同名属性表达不同含义。

## 4. 正式关系

基础结构关系为：

- `belongsTo / contains`
- `produces / producedBy`
- `competesWith`
- `supplies / suppliedBy`
- `dependsOn / dependedOnBy`

新增的通用关系为：

- `scopeIncludesObject / objectInScope`：研究范围与具体语义对象的正式连接。
- `usedInApplication / applicationUses`：产品、材料或技术与应用。
- `processConsumes / consumedByProcess`：工艺步骤与其所需材料、产品或技术。
- `policyAppliesTo / governedByPolicy`：政策工具与适用对象。
- `listingOfCompany / companyHasListing`：挂牌安排与公司。
- `listingForInstrument / instrumentHasListing`：挂牌安排与金融工具。
- `listingAtVenue / venueHostsListing`：挂牌安排与交易场所。

所有关系必须使用 YAML 中声明的源、目标和双端基数。关系实例具有时间变化时保留历史，不覆盖旧边。

## 5. 研究范围

`ResearchScope.dimensions` 保存范围维度的结构化定义，`scopeIncludesObject` 保存具体对象成员。两者必须一致：维度声明不能代替对象边，成员边也不能绕过维度边界。

判断单元、状态变量、证据事实、判断和研究场景都引用同一 `ResearchScope`，禁止各自复制并维护一套范围文本。

## 6. 时间和证据

公司归属、供应、依赖、政策适用和挂牌均是可随时间失效的关系。其关系实例必须记录有效时间；声明 `evidence_required: true` 的边必须能够追溯到证据事实，不能仅以研究员印象创建。

## 7. 领域扩展

领域对象必须继承或投影至少一个核心对象。半导体扩展可增加设备、晶圆厂、产线、制程节点等专用类型，但 `Application`、`Material`、`ProcessStep`、`PolicyInstrument`、`Asset`、`FinancialInstrument`、`TradingVenue` 和 `Listing` 已属于通用核心，不得在领域文件中重新定义。

领域关系应声明其核心父关系；确无父关系时必须说明独立语义。子关系端点必须是父关系端点的同类或子类。

## 8. 禁止项

- 不在对象文件中登记研究步骤、程序能力或阶段编排。
- 不把状态描述写成语义对象，例如“库存高位”应进入观测或快照。
- 不把事件写成对象关系，例如“发布管制”应进入事件模型，政策工具本身才进入语义模型。
- 不把判断写成对象属性，例如“公司受益”应进入判断模型。
