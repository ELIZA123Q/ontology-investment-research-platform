# 投研本体 3.0：证据模型规范

版本：3.0.0

机器权威：`models/evidence.yaml`

## 1. 职责

证据模型把“材料中写了什么”“可作为何种事实”“对本判断单元是否可用”分开建模，并提供从判断单元到证据要求、证据组合、证据评估、证据事实、原始陈述和来源文档的双向追溯。

## 2. 六类证据对象

### 2.1 `SourceDocument`

可定位、可版本化并具有发布主体的原始材料。必须记录标题、URI、发布时间和来源等级。来源等级只表示来源类别，不自动决定其中每条陈述的真实性。

### 2.2 `EvidenceClaim`

从来源中按原意提取的原子陈述。必须有精确定位、提取时间和研究截止时间，并通过 `claimCitesSource` 指向唯一来源。混合多个主体、时间或断言的句子必须拆分。

### 2.3 `EvidenceFact`

由一个或多个原始陈述归一、对齐后形成的事实。事实不得包含“因此”“说明”“有望”等分析推断。它必须记录主体、范围、时间口径、观察时间、有效时间、最早公布时间和研究截止时间。

### 2.4 `EvidenceRequirement`

单一判断单元、单一证据角色的最低输入合同，记录最低独立来源数及支持、反证、背景或边界角色。它通过 `requirementForJudgmentUnit` 指向唯一判断单元。

领域运行时还必须保存 `evidence_profile_refs`、`evidence_recipe_ref` 与 `derivation_refs`，使证据要求能从判断单元、状态变量和路径稳定回溯到受治理的 EvidenceProfile / EvidenceRecipe。二者是领域参数引用，不是已经取得的证据；厂商、URL、MCP 名称、查询参数和优先顺序不得写入本体，继续由 03 方法层来源路由维护。正式 StateVariable 无可用 EvidenceProfile 时属于阻断缺口；`task_local` 变量允许以 `no_profile_reason` 明示缺省。

### 2.5 `EvidenceAssessment`

对一项证据事实在特定判断单元语境中的直接性、可靠性、相关性、时效和局限评价。评估不是来源的永久属性；同一事实用于不同判断单元时可以有不同评估。

### 2.6 `EvidenceBasket`

为单一判断单元和单一证据角色组织的已评估证据集合。篮子不能覆盖多个不同判断单元，也不能把支持、反证和背景角色混在一起。

## 3. 正式追溯关系

```text
JudgmentUnit
  -> judgmentUnitRequiresEvidence
EvidenceRequirement
  -> requirementFulfilledByBasket
EvidenceBasket
  -> basketIncludesAssessment
EvidenceAssessment
  -> assessmentEvaluatesFact
EvidenceFact
  -> factDerivedFromClaim
EvidenceClaim
  -> claimCitesSource
SourceDocument
```

每条关系都有显式逆关系，因而既可以从判断单元向来源回溯，也可以从新证据向受影响判断单元正向定位。

## 4. 证据进入状态与推理

证据事实只允许进入以下中间对象：

- `factGroundsObservation`：事实奠定状态观测。
- `factGroundsEvent`：事实证明事件发生、时间或范围。
- `factSupportsSignal`：事实以支持、削弱、阻断或背景角色进入信号。

证据事实、来源文档、原始陈述或证据组合均不得直接连接 `Judgment` 或 `AssetImpact`。这条限制保证事实、解释和结论层分离。

## 5. 范围、时间、单位和口径

证据进入篮子前必须完成：

1. 主体一致，或明确披露主体代理关系。
2. 研究范围一致，不把局部样本静默外推为全行业。
3. 观察时间、有效时间、公布时间与研究截止时间一致。
4. 单位和计算口径可比，换算过程可追溯。
5. 直接证据、间接证据和代理变量明确区分。

截止时间之后才公布的材料不能进入当期证据组合。动态事实缺少业务时间时只能降级或拒绝。

## 6. 冲突与反证

`evidenceConflictsWith` 仅用于同一主体、范围、时间和口径下不能同时成立的陈述或事实。不同口径数值不同不自动构成冲突，应先完成对齐。

反证必须进入角色为 `counter` 的独立证据要求和证据组合。支持组合不能用“未发现反证”替代反证检查。决定性反证会使下游判断进入 `blocked` 或 `indeterminate`，未解决冲突会使判断进入 `contested`。

## 7. 满足状态

`basketFulfillsRequirement.fulfillment` 只有：

- `met`：最低证据角色、独立来源数和对齐要求全部满足。
- `partially_met`：存在可用证据但未满足完整门槛。
- `unmet`：无可用证据或关键约束失败。

该状态是证据语义，不等同于阶段输出许可。判断等级上限由正式证据门槛规则决定；表达权限由公共合同决定。

## 8. 增量失效

来源撤回、事实被替代或新事实形成冲突时：

```text
SourceDocument/EvidenceClaim
-> EvidenceFact
-> EvidenceAssessment
-> EvidenceBasket
-> Observation/Event/Signal
-> RuleEvaluation
-> Judgment
-> ReasoningTrace
```

只重算沿正式关系可达的节点。无关判断单元不进入重算范围。所有旧评估、旧篮子和旧判断保留历史，不原地覆盖。

## 9. 质量底线

- 每项事实至少引用一项原始陈述。
- 每项评估只评价一项事实。
- 每个篮子只满足一项证据要求。
- 每项证据要求只对应一个判断单元。
- 每个关键判断单元同时声明支持要求和反证要求，除非反证确实不适用并给出边界理由。
- 不以来源数量代替独立性，不以来源等级代替事实可靠性，不以整篮子支撑多个不同结论。
