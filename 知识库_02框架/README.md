# 02 分析框架知识库

本库保存可复用的分析框架，回答：这类问题通常应判断什么、怎样拆解、哪些机制和竞争解释需要检查。单次任务如何选择、裁剪并写出研究逻辑，由 [`02_判断结构与本体视图规范.md`](../02_判断结构/02_判断结构与本体视图规范.md) 规定。

## 1. 库里有什么

| 目录或文件 | 内容 | 用途 |
|---|---|---|
| [`基础框架库`](基础框架库/00_基础框架编写与验收标准.md) | 供需、政策、产业链、价格、公司兑现、财务、预期和估值等通用框架 | 跨行业可复用的拆法 |
| [`行业框架库/半导体行业`](行业框架库/半导体行业/README.md) | 半导体「两横六纵」主框架和高频场景卡 | 行业特有机制、变量和场景增量 |
| [`00_framework_dependency_registry.yaml`](00_framework_dependency_registry.yaml) | 框架之间的进入条件、可写到哪一层、下游可接什么 | 维护依赖关系时以根目录 YAML 为准 |

内容资产只有基础框架与行业框架（含场景卡）。判断类型、怎样写待验证判断、怎样组合框架，是下面的用法说明，不是第三套并列内容库。

## 2. 和 03 / 04 的边界

- 本库决定**判断什么、按什么结构验证**。
- [`知识库_03取证`](../知识库_03取证/README.md)决定**需要什么证据、去哪里找、怎样验收**。
- [`知识库_04推理`](../知识库_04推理/README.md)决定**合格证据怎样形成、削弱、打断或修改判断**。

框架不是现实事实、正式本体、研究结论或报告模板。不要把库中文本直接拼成这次的研究逻辑。

02 只写清「什么事实可能推翻当前判断」，不预先规定看到某事实就必须降到某等级；具体怎么裁，由 04 执行。

## 3. 怎样选用

不要按题目关键词选框架。先在任务级写出核心待验证命题和 2—3 个关键判断单元；再在**每个判断单元**问：若拿到一项新证据，它主要会改变「当前是什么 / 往哪走 / 为什么 / 怎样传导 / 谁不同 / 市场是否知道」中的哪一个？那就是该单元的主判断类型。一个单元只解决一种主要分歧，其他问题拆成前置或后续单元。

| 分歧本质 | 合格问题 | 不合格的宽泛问题 |
|---|---|---|
| 状态 | 当前渠道库存是否低于正常区间 | 行业情况如何 |
| 趋势/周期 | 合约价上行斜率是否正在放缓 | 价格怎么看 |
| 归因 | 本轮订单回升主要来自终端还是补库 | 需求为何增长 |
| 传导 | 管制如何经过许可与客户行为影响交付 | 管制影响多大 |
| 分化 | 同一冲击下谁因暴露和承接不同而分化 | 谁最受益 |
| 预期差 | 新信息相对事件前共识改变了什么 | 股价会不会涨 |
| 风险 | 哪个触发会穿透缓冲并造成不可逆后果 | 有哪些风险 |

基础框架、行业框架和场景卡只补充变量、事件约束和公司映射，不能替代判断类型选择。行业框架与基础机制框架经常是**叠加**（行业增强 + 机制前置），不是二选一。

**研究员口径：**

- 想的时候可以对照看 2—3 个候选；写进 02 时，每个关键判断单元只留 **1 个直接框架**。
- 不是整次任务只能用一个框架：任务可以有多个判断单元，前置和下游还可以先后接上。
- **行业增强**通常就是把行业主框架挂在该单元上，不是另找一套文件。
- **场景卡**是可选适配器，不是正式框架；没用不必解释。
- 裁剪裁的是路线 / 模块 / 变量；不要把三个直接框架各留一点继续并列。

### 3.1 最短选用顺序

```text
01 的研究问题与边界
→ 核心待验证命题 + 2—3 个关键判断单元（任务级）
→ 【探索，可选】对照 2—3 个候选框架，记下淘汰理由
→ 每个判断单元：选择 1 个主判断类型
→ 写成一句可验证的判断（结论与原因分开）
→ 列 1—2 个主要竞争解释
→ 写清区分信号，以及什么事实会推翻它
→ 想清楚这次要写到哪一层结论，收敛为 1 个直接框架 + 必要前置
→ 必要时加 0—1 个行业增强 + 0—1 张场景卡
→ 需要核对进入条件与可写到哪一层时，见根目录依赖说明
→ 交给 03 准备证据
```

一次任务可以有多个判断单元，但**每个单元只设一个主判断类型**和**一个直接框架**。若一句话同时包含状态、归因、公司影响和估值，应拆开。

推荐最小组合（判断单元级）：**1 个判断类型 + 1 个直接框架 + 0—1 个行业增强 + 0—1 张场景卡**。先后接上的前置或下游，不算同时并用了多个框架。

详细裁剪与返工触发见 [`02_框架裁剪与选用细则`](../02_判断结构/02_附录1_框架裁剪与选用细则.md)。

默认研究方向（不是必须跑完的流水线）：

```text
判断类型 + 待验证观点
→ 直接框架机制输出（必要时含行业增强）
→ 公司暴露与兑现输出
→ 条件预测与情景输出
→ 事前预期差输出
→ 估值输入与区间输出
```

### 3.2 八类判断类型

| 类型 | 核心问题 | 默认竞争解释 | 关键区分信号 | 主要反证或推翻条件 | 判断句骨架 | 系统对照 |
|---|---|---|---|---|---|---|
| 状态 | 对象当前处于什么状态，范围和强度如何 | 统计口径、季节性、局部样本造成假象 | 同口径直接指标、横向基准、业务时间 | 指标口径不匹配；独立来源不支持 | 对象 + 当前状态 + 范围/时点 + 限制 | JF-STATE / state_measurement |
| 趋势 | 变化是否持续，斜率是否改变 | 一次性波动、低基数、季节性 | 连续序列、斜率、扩散度、相邻变量 | 序列中断；变化不持续；相邻变量反向 | 对象 + 趋势/阶段 + 时间窗 + 驱动 + 限制 | JF-TREND / trend_or_phase |
| 周期 | 当前处于周期哪一段，切换条件是什么 | 结构性成长被误认作周期；单一子市场主导 | 需求、供给、库存/订单、价格的先后与共振 | 库存回升、需求下修、供给提前释放、分项显著背离 | 对象 + 周期阶段 + 主导分项 + 驱动 + 切换条件 | JF-CYCLE / cycle_phase |
| 归因 | 已观察到的变化主要由什么造成 | 同期政策、供给、需求、价格或会计口径变化 | 时间先后、暴露差异、反事实、解释力比较 | 主因发生在结果之后；低暴露对象同样变化；替代解释更强 | 变化 + 主要原因 + 次要原因 + 适用范围 + 保留解释 | JF-ATTR / causal_attribution |
| 传导 | 事件或变量如何传到行业、公司或资产 | 路径被库存、合同、替代、执行或能力约束吸收 | 起点事实、中间节点、暴露、实际结果 | 起点未发生；中介无变化；存在有效缓冲或替代 | 起点 → 第一影响变量 → 路径 → 时间窗 + 阻断条件 | JF-TRANS / mechanism_transmission |
| 分化 | 为什么对象间影响或兑现不同 | 对象不可比；规模或基数差异造成表面排序 | 暴露度、弹性、承接能力、约束、同口径结果 | 可比基础不成立；排序对指标或窗口敏感 | 对象组 + 分化方向 + 决定变量 + 约束 + 比较口径 | JF-DIFF / object_comparison |
| 预期差 | 新信息相对事前预期是否构成差异 | 基本面变化已被价格或一致预期吸收 | 事前预期基线、预测修订、价格反应、估值输入变化 | 无事前基线；信息已充分反映；风险溢价解释更强 | 新信息 + 事前预期 + 差异 + 收敛条件 + 风险 | JF-EXPECT / valuation_expectation |
| 风险 | 风险概率、损失幅度或恢复能力是否改变 | 叙事升温但实际暴露未变；短期冲击被缓冲 | 触发概率、暴露、缓冲、损失路径、恢复窗口 | 触发条件消失；暴露被对冲；替代或恢复快于预期 | 风险因子 + 暴露对象 + 影响路径 + 缓冲 + 重估范围 | JF-RISK / risk_reassessment |

### 3.3 常见问题 → 先看哪一类框架

| 常见问题 | 首选框架或场景 |

### 3.4 组合示例

估值不是通用入口：只有产业/机制判断、公司业绩桥、经营情景和事前预期差都已建立时，才进入 BF-VA-01。

- 「美伊冲突对半导体影响」从传导判断开始，再接 SCN-GEO、相关主框架和公司兑现。
- 「存储是否进入上行周期」从周期判断开始，再接 SCN-MEM-CYCLE 和 IF-SC-01。
- 「谁更受益」从分化判断开始；若影响路径未成立，先补传导。
- 「是否存在预期差」必须先有带时间戳的事前预期基线。

### 3.5 选用自检

- [ ] 任务级先定核心命题与关键判断单元；判断单元级再选判断类型、直接框架和场景卡。
- [ ] 一句只含一个结论；原因另写；有对象、时间或限制（可证伪、有边界、不跳步）。
- [ ] 至少有一个竞争解释，以及一个可执行的推翻条件（可区分）。
- [ ] 区分信号对不同解释给出不同预期，而不是泛泛「关注数据」。
- [ ] 证据不足时能降到更弱、但仍有意义的判断，而不是硬写满结论（可降级）；具体降级由 04 裁决。
- [ ] 最终组合不超过完成本次判断所需的最小链；先后接上的前置或下游，不算同时并用了多个框架。

## 4. 怎样写可验证判断

一条好判断读完后，另一位研究员应立刻知道：去找什么证据、什么事实会让它变弱。

标准句式：

> 在【对象/范围】和【时间窗口】内，若【关键前提】成立，则【变量/结果】更可能【方向/阶段/差异】。

写法纪律：

1. **一句只判一件事**：结论与原因分开；原因另写解释路径，不要塞进同一句。
2. **写清对象、时间、条件**：不要用「有望、持续受益、空间广阔、景气向上」这类无法单独证伪的词。
3. **不确定就给范围**：数值精度不够时写区间，不要用模糊形容词藏不确定性。
4. **不要跳步**：不要在一句里串完「库存低 → 需求强 → 公司受益 → 估值提升」。

| 类型 | 怎么写 | 不要这样写 | 改写示例 |
|---|---|---|---|
| 状态 | 谁、现在处于什么状态、覆盖哪一段口径 | 行业景气很好 | 当前通用 DRAM 现货端偏紧，但合约端和消费规格改善仍不一致。 |
| 趋势 | 谁、在什么窗口、往哪走、靠什么驱动、什么条件下不延续 | 需求持续增长 | AI 服务器相关需求仍在增长，但斜率取决于部署兑现和非 AI 需求是否接力。 |
| 周期 | 处于哪一段、改善/恶化集中在哪一分项、何时切换 | 存储景气向好 | 存储处于结构性改善阶段，改善主要由 AI 相关需求驱动，传统需求尚不足以确认全面上行。 |
| 归因 | 这个变化主要由什么解释，什么竞争解释还要保留 | 涨价由需求推动 | 本轮涨价主要由高端供给约束解释，需求恢复提供补充，但消费规格仍需排除渠道补库。 |
| 传导 | 事件先动什么，经哪条路径、在多长窗口传到谁，受什么缓冲 | 出口管制影响产业链 | 出口管制首先改变关键设备可得性，经许可与认证影响扩产节奏，但短期受库存和既有许可缓冲。 |
| 分化 | 谁因暴露/弹性/约束不同而分化，比较口径是什么 | A 公司更受益 | 在相同验证阶段口径下，已有量产复购的设备商兑现确定性高于仅完成样机验证的厂商。 |
| 预期差 | 新信息相对事前预期差在哪，可能怎么收敛，什么已计价 | 市场存在预期差 | 盈利指引上修高于公告前一致预期，但估值已扩张，后续重估取决于订单兑现而非指引本身。 |
| 风险 | 哪个风险、对谁、概率/损失/恢复期怎么变，何时再评估 | 地缘风险上升 | 关键航线中断提高交付延迟风险，但多地库存和替代路线限制了短期产量损失。 |

交给 03 时，这句话至少要能拆成：对象与口径、状态或方向、解释路径（若有）、什么事实会推翻它、切换条件。拆不出来的形容词必须改写或删除。

### 4.1 判断生成五问

每个关键判断至少回答：

1. **判谁**：对象、范围、时间和比较基准是什么？
2. **判什么**：状态、趋势、周期、归因、传导、分化、预期差还是风险？
3. **还有谁在争**：除主解释外，最可能的 1—2 个竞争解释是什么？
4. **靠什么分开**：哪些可观察信号会让主解释和竞争解释给出不同预测？
5. **什么会推翻它**：什么事实可能削弱、打断或推翻？交给 04 决定怎么裁。

若只能列出「相关变量」，答不上 3—5，说明还没形成可验证判断。

### 4.2 落盘字段（以下给系统和校验用）

系统落盘时，一句可验证判断对应字段 `atomic_claim`；原因或路径对应 `mechanism_ref`（没有则为 null）；可能推翻它的事实写入 `falsifiers`。这就是文档和校验里说的待验证观点（CandidateClaim）。

```yaml
judgment_framework_ref: JF-CYCLE
judgment_type: cycle_phase
candidate_claim:
  atomic_claim: "<一句可验证的判断>"
  mechanism_ref: "<解释路径；没有则为 null>"
  output_gate_ref: "<登记表中的框架ID.输出门槛ID>"
primary_explanation: "<主解释>"
alternative_explanations: ["<竞争解释1>"]
discriminating_signals: ["<能区分解释的观测>"]
falsifiers: ["<可能推翻它的事实；不预写裁决等级>"]
minimum_validation_condition: "<证据齐到什么程度才允许往下推>"
gate_status: provisional
prerequisite_judgment_refs: []
```

## 5. 系统登记（维护用）

以下内容主要给系统落盘、依赖维护和自动校验；研究员日常选用以第 3—4 节为准。

[`00_framework_dependency_registry.yaml`](00_framework_dependency_registry.yaml) 是框架层级、进入条件、可写到哪一层、质量要求、下游可接续内容与职责交接的登记表。框架 front matter 不得出现 `builds_on`；正文不得重新声明 `hard_prerequisites`、`quality_gate` 或静态 `downstream_unlocks`。

### 5.1 四种登记概念（系统对照）

| 概念 | 回答什么 | 失败后的动作 |
|---|---|---|
| `entry_requires` | 是否已具备对象、范围和判断单元，可以进入框架拆问题 | 不进入，返回 01/02 补边界 |
| `output_gates` | 现有前置和最低证据允许写出哪一种待验证观点 | 只禁止该级输出；较低级输出仍可保留 |
| `quality_gates` | 输出是否达到所需精度、强度和可用范围 | 限制为条件式、区间或 `provisional` |
| `downstream_unlocks` | 哪个输出通过后，下一步可以考虑什么 | 只是允许进入，不代表自动调用或自动成立 |

`boundary_handoffs` 只声明职责归属。例如价格框架可以输出价格状态和实现价路径，但「能否进入利润」由 BF-EE-01 承接；这不是 BF-PC-01 对 BF-EE-01 的反向依赖。

选用时不要只按主题相关性正向挑：从本次关键判断单元需要写到的那一层出发，沿登记表读取必要前置，再决定是否继续接下游。行业增强与场景卡只在改变对象拆分、特殊变量、反证或停止条件时加入。

### 5.2 门槛状态 `gate_status`

| 状态 | 含义 | 下游动作 |
|---|---|---|
| `passed` | 本次实际使用的输出层全部满足 | 可按登记表考虑相应下游 |
| `provisional` | 仅由待验证前置或降级证据满足 | 允许条件式输出；下游不得更强 |
| `failed` | 关键前置、口径或最低证据缺失/被反证 | 禁止该层输出；检查是否可降到更弱一层 |
| `not_applicable` | 经说明与本次判断无关 | 裁剪，不视为缺口 |

任何下游输出继承最弱前置状态。`failed` 不等于整份框架不可使用：例如价格归因失败时，已验证的价格状态仍可保留。

### 5.4 估值专门要求

BF-VA-01 的 `valuation_entry` 必须同时具备：产业/机制判断单元、`BF-EE-01.earnings_bridge`、`BF-FS-01.conditional_forecast`、`BF-EG-01.prior_expectation_baseline`、明确的 `valuation_input_change`。缺少任一项时只记录失败与缺口；任一前置为 `provisional` 时，估值只能保持条件式或区间。

### 5.5 读登记表示例

以 BF-PC-01 为例：只有同口径成交/结算序列时可判断价格状态；要解释涨价驱动才需要供需平衡结论；要讨论公司实现价需补合同与产品结构；要讨论利润则交给 BF-EE-01。精确字段以登记表为准。

### 5.6 质量与准入

一个框架只有满足以下条件，才可作为正式知识资产：

1. 解决反复出现的问题，而不是保存某次结论；
2. 说明适用与不适用范围、核心问题、关键变量和传导机制；
3. 给出最低证据、竞争解释、反面证据、停止条件和常见误判；
4. 能输出待验证观点、区分信号、证据要求和候选改判信号；裁决动作由 04 决定；
5. 不复制研究阶段流程、来源清单或最终报告结构；
6. 新增行业框架或场景卡应经过至少两个任务验证。

单次经验先进入框架使用记录或复盘，不直接改写正式框架。编写细则见 [`基础框架编写与验收标准`](基础框架库/00_基础框架编写与验收标准.md)。
