# 车规芯片认证与装车场景卡

## 决胜分歧

车规问题首先是**产品商业化与客户采用**（定点→PPAP→SOP→装车→复购），不是终端销量内容量。AEC/功能安全资质只证明进入候选；最有辨识力证据是平台/车型、SOP、单车用量、实际装车与复购。

## 1. 本场景相对于主框架增加什么

相对 IF-DES-01（标准芯片路线），本卡增加：

1. 车规认证—定点—PPAP—SOP—装车—复购时钟；
2. 年降、质量责任、长期供货与跨车型平台复用约束；
3. 互斥主判断模式：定点兑现 / 装车供货 / 平台销量渗透（每次只主攻一个）。

## 2. 调用路由

| 项目 | 内容 |
|---|---|
| 默认主框架 | IF-DES-01 |
| 条件辅助框架 | 问汽车销量/配置/单车价值量→IF-APP-01；问国产替代/供应安全→IF-LOC-01 |
| 默认排除 | IF-SC-01、IF-FAB-01、IF-EQP-01（除非已转向制造/设备） |
| 不适用问题 | 非车规应用、纯整车销量总量无芯片采用问题 |

## 3. 场景特有判断脊柱

```text
车规资质与目标平台
→ Tier1/主机厂定点与PPAP
→ SOP时间与份额
→ 实际装车与稳定供货
→ 复购/跨平台与年降质量约束
```

## 4. 场景增量变量与竞争解释

| 决胜变量 | 主解释成立时 | 竞争解释成立时 | 最低验证 |
|---|---|---|---|
| 定点兑现 | 平台/SOP/份额明确 | 只有定点金额无SOP | 车型平台+SOP+份额 |
| 装车供货 | 实际装车与量产稳定 | 只有认证或样品 | 装车量+供货证据 |
| 质量责任 | 售后质量稳定 | 召回/失效率上升 | 质量/召回/保修 |
| 平台销量 | 销量与配置渗透达标 | 销量不及预期或延期 | 平台销量+配置渗透 |

## 5. 对 02 和 03 的增量交接

```yaml
scenario_additions:
  required_splits:
    - 认证 / 定点 / PPAP / SOP / 装车 / 复购
    - 主判断模式：定点兑现|装车供货|平台销量渗透
  mandatory_evidence:
    - 车型平台/SOP/采购份额
    - 分阶段验证与装车证据
    - 年降/质量/召回条款
  counter_evidence:
    - 定点项目延期或取消
    - 平台销量不及预期
    - 年降抵消放量收益
  stop_if:
    - 只有样品或单项认证
    - 只有定点金额无SOP
    - 未选定互斥主判断模式
```
