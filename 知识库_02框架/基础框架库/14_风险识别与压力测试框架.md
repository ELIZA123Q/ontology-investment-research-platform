# 风险识别与压力测试框架

## 研究员先看什么

风险清单不等于风险研究。每个重大风险必须连成 `触发 → 暴露 → 传导 → 缓冲 → 财务/经营结果 → 恢复`，并判断多个风险是否会在同一时点共振。

压力测试先找现金、融资、契约、关键供应和产能的脆弱点，再设情景。重点不是极端损失点估计，而是何时触发不可逆后果、缓冲能撑多久、管理层有哪些现实选择，以及二阶影响是否被忽略。

## 本框架应交付什么

```yaml
framework_layer: market_pricing
```

## 1. 适用问题与边界

用于识别可能改变研究假设、经营结果、现金流、资本结构和持续经营能力的风险，并通过压力情景检验公司或行业的暴露、缓冲和恢复能力。

风险不是通用清单，也不是波动率的同义词。本框架不使用“高/中/低”标签替代机制分析，不把低概率风险忽略，也不生成交易执行或资金配置指令。

## 2. 核心判断任务与关键口径

核心任务是把风险写成“风险源—暴露对象—触发条件—传导路径—缓冲—结果—恢复”的可观察链条，并区分削弱、逻辑失效和可管理波动。

- **固有风险**：未考虑控制和缓冲前的暴露。
- **剩余风险**：考虑库存、合同、保险、对冲、现金、冗余和治理后的风险。
- **风险承受能力**：现金、资本、契约、运营冗余和融资渠道能够吸收多大冲击。
- **压力测试**：使用内部一致的低概率高影响情景检验现金和约束，不是任意下调数字。
- **恢复能力**：冲击后修复供应、客户、产能、流动性和声誉的时间与成本。

## 3. 核心问题树

1. 哪个外部或内部风险源会作用于哪个对象和关键假设？
2. 暴露在产品、客户、供应商、地域、技术、政策、融资或治理中的集中度如何？
3. 什么触发条件会使风险从潜在变为现实，领先信号是什么？
4. 冲击如何传导到订单、价格、成本、产能、现金和资本结构？
5. 库存、合同、保险、对冲、冗余、现金和融资能缓冲多少？
6. 哪些阈值会触发契约、流动性、合规或持续经营约束？
7. 管理层能否在目标窗口内修复，二阶效应是什么？
8. 风险出现时应削弱哪个假设，何时构成 `blocking`？

## 4. 分析模块与传导机制

| 模块 | 核心变量与机制 | 主要信号 | 典型窗口 |
|---|---|---|---|
| RS-M1 风险分类 | 战略、经营、财务、治理、合规和外部风险确定来源 | 风险披露、事件、行业数据 | 持续更新 |
| RS-M2 暴露映射 | 集中度、依赖和不可替代性决定固有风险 | 客户/供应商/地域/债务集中 | 中长期及事件触发 |
| RS-M3 触发与传导 | 触发事件 → 业务状态 → 财务与资本约束 | 领先信号、事件、订单、利差 | 明确业务窗口 |
| RS-M4 缓冲与控制 | 库存、合同、保险、冗余、现金和治理降低风险 | 覆盖天数、保险、备用产能、现金 | 冲击窗口 |
| RS-M5 压力测试 | 情景变量共同变化 → 现金、契约和资本结果 | 现金缺口、覆盖、杠杆、契约 | 压力期与恢复期 |
| RS-M6 恢复与二阶效应 | 修复行动可能带来成本、稀释、份额和声誉变化 | 复产、替代、融资、客户流失 | 冲击后数月到数年 |
| RS-M7 假设治理 | weakening/blocking 信号改变假设状态和下游路径 | 信号强度、有效期、审核记录 | 事件触发 |

## 5. 最低证据与交叉验证

- 使用公司风险披露、审计附注、合同、监管信息、供应链数据和历史事件，不用二手清单替代。
- 每个重大风险必须绑定具体暴露对象、关键假设、业务时间和可观察触发。
- 缓冲能力需核对可用性、覆盖范围、期限和交易对手，而非只记录“已投保/已对冲”。
- 压力测试同时调整相关收入、成本、营运资本、资本开支和融资变量。
- 低概率情景若无可估概率，可以保留条件情景，不伪造精确频率。

## 6. 其他可能解释、逻辑失效与停止条件

其他可能解释包括短期波动而非结构风险、行业共同冲击而非公司特有问题、会计重分类、季节性和已被有效对冲的名义暴露。

风险信号在缺乏事实或作用对象时只能作为线索。关键 `blocking` 条件包括核心经营许可失效、关键客户/供应中断且无替代、现金和融资不能覆盖目标窗口、审计或持续经营受到重大质疑。逻辑失效确认后，依赖假设和预测必须重建。

## 7. 情景设置

| 情景 | 冲击特征 | 必查结果 |
|---|---|---|
| 基准波动 | 历史常见范围内的单一或轻度冲击 | 利润与现金敏感度 |
| 经营压力 | 需求、价格、供应或交付显著恶化 | 订单、库存、毛利、现金转换 |
| 财务压力 | 融资成本上升、再融资受限或契约收紧 | 流动性缺口、杠杆、稀释、资产处置 |
| 复合压力 | 经营、融资、政策或治理同时冲击 | 持续经营、二阶效应和恢复时间 |

压力结果至少包括最低现金、债务到期覆盖、契约余量、关键运营阈值和恢复所需资本。

## 8. 本体映射

**一级正式本体**：风险来源和暴露对象使用现有 `Industry`、`Company`、`Product`、`Material`、`Region`、`PolicyInstrument`、`Asset` 等；具体风险发生使用 `Event`，风险指标使用 `StateVariable` 与 `Observation`，削弱/逻辑失效证据使用 `Signal`，压力路径使用 `Scenario`、`Hypothesis`、`Judgment` 和 `ReasoningTrace`。

**领域扩展可选项**：设施、技术路线、合同、自然人、金融机构细分风险等只有在领域本体已有定义时引用。

**任务候选或本体缺口**：暴露集中度、缓冲覆盖、流动性跑道、契约余量、恢复时间和复合压力强度等先作为候选变量或规则。

## 9. 组合与裁剪

- 行业、业务、财务、资本和治理风险分别接 BF-IC-01、BF-BM-01、BF-FQ-01、BF-CA-01、BF-CG-01。
- 压力结果进入 BF-FS-01 情景预测，再由 BF-VA-01 研究估值输入变化。
- 快速风险筛查至少覆盖经营集中、现金与债务、治理/合规和关键替代路径。
- 风险未绑定具体假设时，不进入正式判断链。

## 11. 框架自检

- [ ] 每个重大风险绑定了对象、假设、触发和时间窗口。
- [ ] 固有风险、缓冲和剩余风险已区分。
- [ ] 压力情景内部变量一致，没有只改利润。
- [ ] 现金、契约、运营阈值和恢复资本均被检查。
- [ ] weakening 与 blocking 的条件和作用对象明确。
- [ ] 风险清单没有替代传导机制分析。
