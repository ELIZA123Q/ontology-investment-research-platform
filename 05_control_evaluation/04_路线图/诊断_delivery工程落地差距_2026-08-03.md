## 7. 关键决策点

在执行修复前，需要确认一个架构决策：

**`projectExpressionAuditYaml()` 的重构方向：**

- **方案A：runtime 全量投影** — runtime 从 Stage05 data 字段（`report_claims`, `research_edge`, `research_value_review` 等）派生全部新增检查节的布尔值。优点：LLM 不需要理解审计结构；缺点：runtime 代码复杂度显著增加。

- **方案B：LLM 生成 + runtime 归一化** — LLM 按模板生成完整审计 YAML，runtime 仅做字段校验和哈希填充（`delivery_content_hash`, `source_04_audit_hash`）。优点：runtime 代码简单；缺点：LLM 可能生成不一致的结构，需要更严格的 runtime 校验。

- **方案C：分层投影** — 确定性字段（`metadata`, `claim_expression_register` 的 `source_rcs` 等）由 runtime 投影；语义判断字段（`main_judgment_check` 的布尔值）由 LLM 生成但 runtime 校验。优点：平衡；缺点：需要清晰定义边界。

**建议：** 方案C。理由：`claim_expression_register` 的追溯字段（`source_rcs`, `inherited_judgment_level`, `conditions` 等）是确定性投影，必须由 runtime 生成以保证正确性；`main_judgment_check` 等语义判断可以由 LLM 产出，runtime 仅校验字段存在性和类型。
