# Ontology 4.0 切换记录

## 切换决策

- `01_semantic_knowledge/01_ontology/platform_registry.yaml` 是新的统一目录，同时加载 semantic、operational 与 kinetic 定义。
- Ontology 3.0 实例图和字段仅通过兼容投影读取；新运行只写 4.0，不双写。
- 旧的两份 Runtime Action 注册表已退出，Action 和 Function 类型均从统一 Catalog 生成。
- 正式语义写入的唯一入口是 `OntologyActionService`；Skill、Tool、Function 和 TaskNode 不具有提交权。

## 数据边界

- `ResearchCase` 是长期业务身份；`Task` 是一次临时执行，多个 Task 可共享同一 Case。
- Domain Semantic Graph 与 Research Provenance Graph 可以物理分存，但由同一 Ontology API 查询与操作。
- Runtime 继续负责队列、重试、模型调用、缓存、Checkpoint 和 UI 状态，这些不进入业务本体。
- 项目边界内不登记评级、目标价、仓位、订单或交易 Action。

## 验收门

1. `python3 01_semantic_knowledge/01_ontology/validate_v4.py`
2. `cd 06_runtime && npm run ontology:check`
3. `cd 06_runtime && npm test && npm run typecheck && npm run build`
4. 源码回归保证 `ontology_objects` 与 `ontology_links` 的 SQL 写入只存在于 `src/ontology/store.ts`。
5. 治理校验保证高风险 Action 有审批政策且目录不包含交易类 Action。
