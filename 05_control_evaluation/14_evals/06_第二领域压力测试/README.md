# 06 · 第二领域压力测试（验证通用核心，非扩产品）

目的：在半导体之外，用**最小成本**检验 `01_semantic_knowledge/01_ontology/` 与 kb02/03/04 判断类型体系是否真的领域无关。  
**不是**建设完整第二行业框架库；项目在半导体深度验证完成前，仍遵循「不横向扩本体」。

## 给谁看

维护者与评测执行者；研究员可跳过，除非参与该压力测题目。

## 材料从哪来

- 用例模板：[`case_template.yaml`](case_template.yaml)
- 通用本体与基础方法库（禁止为此新建行业 extension）
- 结论摘要写入 [`../05_决策日志/`](../05_决策日志/README.md)

## 怎么用

满足准入条件后，复制模板填一题并跑通；按成功标准区分「缺通用能力」与「仅缺行业卡片」。

## 怎么维护

不横向扩本体；失败记入决策日志。勿把本目录扩成第二行业产品库。

## 准入条件

1. 多供应商评测档案可满足五角色隔离（见 `05_control_evaluation/14_evals/03_执行/model_profiles.yaml`）。
2. 至少再有 1 条半导体复杂冲突链闭环（见冲突链续跑清单）。

## 最小用例设计原则

| 项 | 要求 |
|----|------|
| 领域 | 选一个公开数据易得、与半导体机制差异明显的小问题（如单一发行人财报同比核查，或单一宏观利率事件对某行业的短路径影响） |
| 本体 | **禁止**新增领域 extension YAML；只用通用对象（Company、Metric、Event、Evidence*、Judgment*） |
| 方法 | 只用 `03_agent_capability/05_method_libraries/02` 基础框架 + kb03/kb04 按判断类型路由；不写新行业主框架 |
| 成功标准 | 01—05 能受理、能诚实停判或给出有边界观察；失败应归因到「缺通用能力」还是「仅缺行业卡片」 |
| 失败处理 | 若通用核心卡住 → 记入决策日志并开本体/方法缺口；若仅缺行业来源卡 → 不扩本体，记为领域深度债 |

## 建议模板

复制 [`case_template.yaml`](case_template.yaml) 填一题即可。跑通后把结论摘要写入 `05_control_evaluation/14_evals/05_决策日志/`。
