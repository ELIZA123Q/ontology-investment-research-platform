# AI 原生投研判断工作台架构

## 核心原则

**确定性负责边界，Agent 负责路径。**

系统从「固定流程驱动的研究系统」转向「Agent 驱动的认知工作系统」：

- **Workflow 不再是顶层** — Deep Research 等流程是任务的可选执行策略，不是系统骨架
- **Agent 不再是阶段执行器** — Research Lead 组合 typed nodes，可选择、跳过、并行或局部重跑
- **知识资产不再只是文件库** — 经候选→评测→发布后成为可复用认知资产
- **Runtime 不是业务能力** — 它是承载 Agent 运行的基础设施（调度、执行、事件、checkpoint）

机器可读的模块关系、心智名映射与禁止项见：[`architecture.yaml`](architecture.yaml)。  
五域写入口索引见：[`five_domain_authority.yaml`](five_domain_authority.yaml)。

## 逻辑分层（心智名）

不要把下列条目都当成平级「写入口权威域」。职责域与承载层分开：

| 逻辑层 | 心智名 | 现行物理路径 | 回答什么 |
|---|---|---|---|
| 职责域 | Semantic Knowledge | `01_semantic_knowledge/` | AI 知道什么？ |
| 职责域 | Scenario & Task | `02_scenario_task/` | 为了完成什么任务？ |
| 职责域 | Agent Capability | `03_agent_capability/` | 能调用什么能力？ |
| 职责域 | Context & State | `04_context_state/`（合同） | 当前处于什么状态？ |
| 职责域 | Control & Evaluation | `05_control_evaluation/` | 是否可信？ |
| 承载层 | Runtime | `06_runtime/` | Agent 如何被执行？ |
| 承载层 | Workspace | `07_workspace/` + `06_runtime/app/` | 人如何与 Agent 协作？ |
| 主题（挂 Control） | Asset Evolution | 知识沉淀合同 | 如何沉淀为长期资产？ |
| 横切通道 | Data / Evidence Channels | 语义 + 取证方法 + Runtime 摄取 | 材料从哪来、如何留痕？ |

**Data / Evidence 不升为第九平级写入口。** Evidence 语义在 Semantic；怎么找在 Capability（方法库/MCP）；一次怎么采在 Runtime + Control。

**Asset Evolution 暂不独立顶层目录。** 机器权威：[`../02_合同/knowledge_learning_contract.yaml`](../02_合同/knowledge_learning_contract.yaml)；说明：[`03_知识沉淀闭环.md`](03_知识沉淀闭环.md)。

## 五域（后台职责）

五域只回答后台职责，不生成五个产品中心。心智名与顶层物理目录已 1:1 对齐；**domain key**（`semantic` / `task` / …）保持不变。

| 域 | 心智名 | 职责 | 运行入口 |
|---|---|---|---|
| Semantic | Semantic Knowledge | 世界模型、词典、证据语义、两类图 | `01_semantic_knowledge/`、`06_runtime/src/semantic/` |
| Task | Scenario & Task | Intent、Task、typed TaskGraph、可选模板 | `02_scenario_task/`、`06_runtime/src/runtime/planner.ts` |
| Capability | Agent Capability | Agent、Skill、Tool、方法资源、协议 | `03_agent_capability/`、`06_runtime/src/capabilities/registry.ts` |
| Execution | Context & State | Context、Memory 合同；实现在 Runtime | `04_context_state/`、`06_runtime/src/runtime/` |
| Governance | Control & Evaluation | 规则、权限、Verifier、Eval、审计、知识闭环合同 | `05_control_evaluation/`、`06_runtime/src/governance/` |

产品面登记在 `07_workspace/`，唯一实现位于 `06_runtime/app/`。Runtime 单独作为承载层，**不嵌进 Context & State**。

## 运行主链

```text
Conversation
  → Intent
  → Task / typed TaskGraph
  → Skill / Tool / Service / Policy / Verifier
  → Event + key Checkpoint
  → Artifact
  → trusted UI surface
  →（可选）Asset Candidate → 评测/审批 → Released Asset
```

- vNext.1 只有 Research Lead 可运行；planned Agent 可登记，不得被调度。
- Deep Research 01—05 仅作为可选模板和历史评测基线，不是系统入口。
- Message、Trace 从 Event 投影；ContextPackage 临时存在。
- 未经 Source Capture 不得形成 EvidenceFact；无合格 Evidence 时 Judgment 必须降级。
- Domain Semantic Graph 与 Research Provenance Graph 分开治理。
- 程序性研究框架留在 Capability `method_libraries`，不并入 Semantic。
