# B01 路径成立与逐段验证

## 目的

判断 02 已固定的路径可以从起点走到哪里。路径不是“整体成立/不成立”二选一，每一段都要单独通过验证。

## 每段六问

1. 起点是否在本次对象和窗口真实发生；
2. 作用关系为何适用于本次情形；
3. 预期的主体行为或中间状态是否出现；
4. 当前时点是否已进入合理结果窗口；
5. 削弱、吸收或阻断条件是否命中；
6. 该段证据最多允许传到下一节点还是终点。

## 路径状态

本表与 `04_推理输出规范.md` 的正式值域唯一对应。B01 负责写入边状态，A06 不另造一套状态。

| 正式状态码 | 研究员用语 | 含义 | 后续动作 |
|---|---|---|---|
| `established` | 成立 | 关键前提、作用关系和承接满足 | 可以继续验证下一段 |
| `partially_established` | 部分成立 | 主方向存在，但范围、幅度或对象受限 | 可以继续，但降低强度并保留限制 |
| `weakened` | 受到削弱 | 相反证据削弱路径，但尚未命中决定性前提 | 降级、缩小范围或缩短窗口后再判断下游 |
| `blocked` | 被阻断 | 决定性前提失败或必要关系不成立 | 停止全部对应下游推导 |
| `insufficient_evidence` | 证据不足 | 不能判断该段是否发生 | 不继续推导，也不能写成没有发生 |
| `contested` | 存在争议 | 支持和反证冲突且未消解 | 暂停强结论，设置区分信号 |
| `not_applicable` | 不适用 | 该段不属于本次对象或范围 | 排除该段，不参与合成 |

“条件成立”是结论表达方式，不是正式路径状态：若当前节点已有方向但受明确条件限制，使用 `partially_established`；若结果尚未出现且不能确认该段发生，使用 `insufficient_evidence`，并另记继续验证的条件。

## 逐段验证规则

1. 只有 `established` 可以无附加降级地进入下一段；
2. `partially_established` 或 `weakened` 可以继续验证，但下游不得高于该限制所允许的强度和范围；
3. `insufficient_evidence` 或 `contested` 在当前时点停止方向性下游验证；
4. `blocked` 关闭对应全部下游；
5. `not_applicable` 只排除本段，不得被当作支持或反证。

## 研究员输出

每次至少输出：

```text
逐边正式状态
→ 最后一个已验证节点
→ 第一条未通过验证的路径及原因
→ 尚未满足的继续验证条件
→ 因此不能推出的后续结果
```

B01 不形成行业、经营、财务或投资结论。需要回答“影响实际传到了哪里”时，把上述结果交给 A06；不要用弱化措辞绕过缺失中介。
