# 04 判断执行与推理规则库

> 物理目录继续使用 `04推理方法库`，以保持项目引用稳定。研究员可见名称为“判断执行与推理规则库”：它负责说明证据怎样形成或改变判断，不重新设计研究问题，也不寻找新证据。

> 本文件是判断方法库导航，不是 04 阶段规范。单次任务的输入、报告与审计格式、质量检查和 04→05 交接，以 [`04_推理输出规范.md`](../04_推理输出规范.md) 为准。本库只维护可复用的判断方法、反证处理和改判规则。

## 一句话定位

> 02 告诉你应该判断什么，03 告诉你证据目前够到哪里，04 说明这些证据怎样改变判断，05 负责把判断准确表达出来。

第一次使用请读 [研究员判断工作台](00_研究员裁决工作台.md)。

## 为什么按 A/B/C/D 分类

04 按“要判断的对象”分类，不按行业、报告类型或数据类型分类：

| 类别 | 要判断的对象 | 解决的问题 |
|---|---|---|
| A_单项判断方法 | 一个关键判断或投资命题 | 状态至预期差怎样形成判断，研究判断何时足以形成投资命题 |
| B_推理路径验证 | 路径、边、正式规则 | 逻辑可以继续到哪一步，影响在哪里减弱、延迟或停止 |
| C_反证与竞争解释 | 反证、替代解释和冲突证据 | 相反证据影响哪一层判断，应降低强度、缩小范围、停止推导、改写还是保留争议 |
| D_改判与复盘 | 随时间更新的判断 | 新信号如何触发版本变化，历史经验反馈到哪个库 |

行业特殊性进入案例和参数，不新增“半导体推理”“政策推理”等平行目录。报告类型属于 05，不进入 04 分类。

## 与 02、03、05 的边界

三库及单次产物的正式边界统一见 [`00B_文档职责与用语规范.md`](../00B_文档职责与用语规范.md#3-0204-的规范与库怎样分工)，本 README 不再维护平行职责表。

本库只说明合格证据怎样影响判断。发现缺路径或变量时退回 02；发现证据不足、冲突未整理或需要更新时退回 03；报告结构和 05 交接按 04 阶段规范执行。本库不补结构、不找材料，也不规定最终报告目录。

## 最小调用

```text
确认 02 结构与 03 证据版本一致
→ 用 A00 选择主要判断方法，并继承 03 给出的 J0—J4 上限
→ 用 B 确定关键路径能走到哪里
→ 用 C 处理反证、竞争解释与冲突
→ 形成有边界的判断及实际等级
→ 若任务需要投资观点，用 A10 判断是否足以形成投资命题
→ 用 D 记录证据变化、等级更新与下次改判条件
```

简单判断不要求全量调用。选择哪些方法，应由本次最难判断的环节决定。

## 维护与准入规则

本库由研究员维护。本体维护者检查正式对象和规则冲突，工程人员只维护引用与校验，不替研究员选择判断方法。

新方法只有同时满足以下条件才入库：

1. 解决反复出现的判断问题，不是一次任务结论；
2. 不能由现有 A/B/C/D 方法表达；
3. 至少在两个不同任务出现并经研究员复核；
4. 说明适用和不适用情形、输入、步骤、反证、处理方式和常见误判；
5. 不复制 02 的研究结构、03 的证据规则或 05 的写作要求；
6. 不依赖代码、字段或英文状态才能执行。

单次经验先进入 D02 的复盘候选。只是行业名词不同的案例，不新增方法文件。

## 文件写法

新增方法按“要判断什么—何时使用或不能使用—判断步骤—可能的处理方式—案例与误判—反馈位置”编写。ID 和机器字段只放在附录或系统映射，不进入正文主叙事。

## 库管理员附录

```bash
python3 04推理方法库/validate_methods.py
```

该脚本检查分类资产、兼容入口和 02/03/04/05 边界，不生成研究结论。
