# 研究员体验追踪

我们在追踪：用这套工作台做完一个真实投研任务，**你花了多少时间、走了多少步、一次能不能做完**。

为什么要追踪这个？方法框架再严谨，如果操作流程让人反复返工、补证据、来回跳转，那么这个流程的体验成本就太高了——要么需要改进工具，要么需要简化流程。

## 追踪什么

三个核心指标：

- **TTFC**（Time to First Conclusion）：从创建运行到第一条可用的判断结论，花了多久
- **操作负担**：研究员需要手动做多少步（不是系统自动执行的步数）
- **一次完成率**：能不能不返工就走到 Stage05

其他指标（返工次数、补证据命中率、AI 耗时、Token 用量）用来解释主指标为什么好或不好，不单独追求好看。

## 当前状态

- 已准备 10 个半导体任务（覆盖正常完成、证据不足停止、增量改判等场景），但还没人实际跑
- 需要至少 8 个真实任务完成后，才能叫"有体验基线"
- 在此之前，所有体验数据只能作为临时参考，不能拿来下结论

## 什么任务能计数

要进入正式统计，任务必须满足：
- 来自真实研究需求（不是 UI 测试）
- 创建时就记录了时间戳（不能事后补记）
- 问题、信息截止日、证据在开始前冻结
- 每次把工作台方案和模型直出做同一证据的盲评对照

历史任务（在体验追踪工具就绪前完成的）可以当参考边界，但不计入正式指标分母。
