# 02 案例与数据契约

## 1. 可评案例的最低条件

一个案例进入正式评测前，必须同时具备：

- 公开任务输入（不泄漏预期结论）；
- 冻结证据包；
- 已冻结的系统产物；
- 密封裁决契约；
- 四类证据扰动；
- 明确分层（`report_value` / `restraint` 等）。

## 2. 公开任务输入

`case.yaml` 中的 `task_input` 只包含研究者在真实研究开始前可见的信息：问题、对象范围、信息截止日、允许终点。不得夹带标准答案、期望等级或密封判断原文。

## 3. 冻结证据包

`evidence.yaml` 每条证据至少包含：发布者、标题、URL、发布日、业务时点、独立来源组、陈述性质、定位、短摘录、内容哈希、支持点与限制点。

正式评测不得临时联网补证。截止日之后的材料一律拒绝。

## 4. 系统产物冻结

系统产物在打开密封裁决契约前必须已经冻结并计算哈希。保留实际推理内容、判断路径和改判条件；删除内部质量标签后再进入盲化。

## 5. 密封裁决契约

`sealed/adjudication.yaml` 只在产物冻结后开放。它不是标准答案报告，而是裁决边界，必须声明 `not_a_reference_report: true`。

### 5.1 核心判断单元

每个案例准备 3—7 条 `core_claims`：

| 字段 | 含义 |
|---|---|
| `claim_id` | 密封判断标识 |
| `statement` | 需要被覆盖或正确限制的研究判断 |
| `criticality` | `primary`、`supporting` 或 `boundary` |
| `strength_ceiling` | 当前证据允许的最高强度 |
| `minimum_evidence_basket` | 该判断最低需要的冻结证据组合 |

`primary` 判断用于案例级 `R` 的最低等级聚合；`boundary` 用于检查窗口、预测和弃答边界。

### 5.2 其他密封字段

- `allowed_disagreements`：允许研究者合理分歧的空间；
- `strongest_counterevidence`：必须实际处理的最强反证；
- `prohibited_expressions`：会构成越级或误导的表达；
- `update_scenarios`：新增信息、预期动作和受影响判断；
- `downstream_required_units`：复述、跟踪和调研任务必须覆盖的关键单元。

### 5.3 独立性与防循环验证

密封契约的有效性取决于**谁制定裁决边界**，而不是格式是否完整。

正式扩展案例必须采用双轨独立生成：

1. **路线一**：模型 A 只阅读冻结证据，独立提出核心判断、证据上限与反证；
2. **路线二**：模型 B 只阅读原始问题与证据，独立制作裁决契约；
3. **协调模型**：只合并双方共同认可项，并明确记录争议；
4. **体系规则**：02/03/04 规则只能作为边界检查（截止日、硬错误类型等），不得直接成为答案来源。

对应 `provenance.independence_mode`：

| 模式 | 含义 |
|---|---|
| `dual_route_independent` | 正式模式；必须记录 route_a / route_b / coordinator |
| `pilot_manual` | 试点人工密封契约；必须声明局限，扩展时改为双轨 |

另需声明 `framework_rules_usage: boundary_check_only`。

### 5.4 客观检查

密封契约必须声明以下客观检查为 `required`，并在校验中至少落实最低证据存在性与截止日约束：

- 数字、时间、对象、来源对应关系；
- 最低证据是否真实存在于冻结包；
- 是否使用截止日以后材料；
- 是否把预测写成事实。

由此形成：**规则校验 + 独立 AI 裁决边界 + 证据事实核验**，而不是单一 AI 裁判闭环。

## 6. 隔离规则

| 角色 | 可以读取 | 不得读取 |
|---|---|---|
| 系统生产者 | `task_input`、规定证据材料 | 系统产物答案、推理材料、密封裁决、缺陷目录 |
| 基线生产者 | 对应弱基线/同证据条件 | 系统流程、密封裁决、质量标签 |
| 密封路线提议者 | 问题与冻结证据 | 系统产物、另一路线结果、02/03/04 答案 |
| 密封协调器 | 两路线结果 | 用体系规则直接填答案的权限 |
| 核心判断提取器 | 盲化系统产物 | 冻结证据、密封裁决、报告来源 |
| 归并协调器 | 两份提取结果、盲化产物、密封判断单元 | 评分权和新增论证权 |
| 证据审阅器 | 判断、冻结证据、最低证据组合 | 生产者自评和包外事实 |
| 推理审阅器 | 判断、盲化推理材料、强度上限 | 质量标签和包外论证 |
| 对抗审阅器 | 判断与冻结证据 | 总体评分权 |
| 裁决器 | 三份审阅记录 | 原始报告、原始证据、重新论证 |
| 下游执行模型 | A—E 对应上下文 | 密封评分单元 |
| 下游评分模型 | 任务输出、冻结证据、密封单元 | 执行模型自评分 |

校验器要求生产者可见字段恰好为 `task_input` 与 `evidence.yaml`，并显式禁止系统产物、推理材料、密封裁决和缺陷目录。

## 7. 扰动契约

每个案例至少准备四类扰动：

1. 删除关键证据；
2. 替换公司、产品、指标或时间口径；
3. 注入最强反证或竞争解释；
4. 调整判断时点并过滤截止日后的证据。

每项扰动必须预先保存 `expected_action`。运行后直接比较评测器动作与预期方向。

## 9. 新增案例准入条件

新增案例必须同时满足：

- 公开任务输入不泄漏预期结论；
- 至少三条可离线复核的冻结证据；
- 全部证据通过截止日和哈希校验；
- 3—7 条密封核心判断及最低证据组合；
- `provenance.independence_mode = dual_route_independent`；
- 客观检查四项齐全；
- 至少一个最强反证和两个更新场景；
- 四类扰动齐全；
- 系统产物已经冻结；
- 明确属于 `report_value`、`restraint` 或未来新增的独立分层；
- 案例组合逐步覆盖：正常成功、诱导失败、边界越级；
- 先通过缺陷校准，再进入正式结果统计。
