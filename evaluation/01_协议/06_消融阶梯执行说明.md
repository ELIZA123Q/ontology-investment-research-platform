# 06 消融阶梯执行说明

配套 [`01_评测总纲.md`](01_评测总纲.md) §4.4a。用于回答：**本体约束是否产生可观测研究价值**，而不是「是否调用了本体」。

## 1. 四组输入

| 组 | Prompt / Runtime 配置 | 禁止 |
|---|---|---|
| P0 | 单次：仅 `question` | 不得注入 02/03/04 产物、本体、方法正文 |
| P1 | 可按 01→05 分阶段，但 `ontology_object_set` 置空；不注入正式本体切片 | 不得把领域业务参数图当「无本体」对照的隐藏本体 |
| P2 | 同 P1 流程 + 任务本体切片（JU/变量/关系摘要） | 不得额外注入 methods 全文与证据压缩 Bundle |
| P3 | 现行主链：本体切片 + method_candidates / guidance + evidence Bundle/Summary 约束 | — |

Runtime 实现提示：P1 可在装配层将 `assembleStageContext` 的本体槽位置空并跳过领域图；P2 保留 `semantic_route` 与 `ontology_object_set`；P3 为默认 `generateArtifact` 路径。

## 2. 评分量表（每诊断项 1—5）

1 = 明显劣于可接受研究纪律；3 = 可工作但有明显缺口；5 = 符合本仓库高质量门禁期望。

对每个案例、每个组（P0—P3）填写八项诊断分，再计算：

```text
score(P) = 八项算术平均（不加权）
Δ_ontology = score(P2) − score(P1)
Δ_methods  = score(P3) − score(P2)
```

不得把 Δ 包装成「系统准确率」或百分比置信度。

## 3. 案例交付物

每个参与消融的案例目录下建立 `ablation/`：

```text
ablation/
├── protocol_ref.yaml      # 引用本说明与评测总纲版本
├── scores.yaml            # P0—P3 八项分数与 Δ
└── notes.md               # 评分说明、最弱项、是否需返工
```

## 4. 发布纪律

- 单案例消融只能写「在该冻结证据与评分者条件下的观察」
- 案例数 < 10 时只报告分布与符号方向（Δ 正/负/接近 0），不写总体有效结论
- 若 P2 ≤ P1，必须在 notes 中解释：是本体切片噪声、切片过粗，还是评分不稳定
