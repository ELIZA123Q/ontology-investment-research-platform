# 03 评测流程与角色协议

## 1. 运行阶段

正式运行分为准备、评测器校准、可靠性评测、下游任务实验、相对基线盲评、聚合与报告六个阶段。校准是硬门槛，不是最后附加的一项分数。

准备阶段至少：

- 校验案例、证据、密封隔离和扰动契约；
- 校验密封契约 provenance 与客观检查字段；
- 冻结系统产物哈希；
- 生成 A—E 上下文骨架与缺陷变体。

## 2. C：评测器校准门

先运行十一类缺陷、正常版错杀和四类证据扰动。

- 任一模型低于 `C2`：不进入正式裁决集；
- 整体低于 `C2`：停止运行，不发布案例集层代理可靠率或系统通过结论；
- 全部至少 `C2`：继续 R/U/delta。

C 的等级分界为 `pilot_threshold`，仅用于校准门与方案比较。

## 3. R：多角色对抗评测

### 3.1 核心判断提取

两个独立评测模型只阅读盲化产物，各自提取 3—7 条决定研究价值的核心判断。提取器不得看冻结证据和密封裁决，以免按预期答案改写报告内容。

### 3.2 归并

协调器合并两份提取结果，保留分歧，并将报告中实际存在的判断映射到密封判断单元、最低证据组合与强度上限。

纪律：

- 不为了覆盖密封契约而创造新观点；
- 必须标明未被报告覆盖的密封单元。

### 3.3 三审一裁

证据审阅、推理审阅、对抗审阅分别给出定位化意见；裁决器只基于三份审阅记录给出 `R0—R3`，并单列硬错误、最弱判断、最强反证与主要分歧。

同一角色由两个评测模型各运行三次，共六次案例裁决。案例最终 `R` 取保守中位数；同时报告裁决支持频率（六次中 `R≥R2` 的比例），**不得**称为可靠概率。

## 4. U：下游任务实验

### 4.1 五组上下文

| 组别 | 下游模型获得的内容 | 用途 |
|---|---|---|
| A | 原始问题 | 弱基线，观察裸模型 |
| B | 问题与冻结证据 | 原始材料能力 |
| C | 问题与同证据直接生成完整报告 | **主对比基线**（不用 02/03/04） |
| D | 问题与系统最终允许产物 | 系统核心实验组 |
| E | 问题、系统产物与关键证据 | 诊断信息上限 |

### 4.2 四项任务

1. 核心判断复述：阶段、对象分化、依据和暂不可判断事项；
2. 跟踪计划：五项指标，每项含对象、来源、频率、支持/削弱/推翻含义和优先级；
3. 新信息更新：注入密封场景，要求保持、削弱、改判、重开问题或继续弃答；
4. 调研问题：分别面向公司、客户和专家，注明待验证假设、竞争解释和答案影响。

任务通过阈值为 `pilot_threshold`。

### 4.3 执行与评分分离

两个下游模型只执行任务，不提供有效自评分。其输出由独立评测模型根据冻结证据、密封判断、必需信息单元和更新场景评分。

评测模型与下游执行模型的 `model_id` 必须不同。

## 5. delta：相对同证据基线盲评

系统产物 D 分别与以下**主对比**候选成对比较：

- 同证据直接生成完整报告（与系统使用完全相同的冻结证据，但不走 02/03/04）；
- 同证据普通摘要稿。

问题直答稿可生成并保留为弱基线诊断，**不得**作为流程价值主证据。

### 5.1 生成公平性

主对比基线与系统产物应尽量控制：

- 生产模型相同；
- 输出长度接近（当前强制 ±15%，仍属最低要求）；
- 最大 token 预算相同；
- 生成次数相同；
- 温度设置相近。

仅控制长度不足以保证公平；正式报告须声明生成条件。

### 5.2 盲评规则

每次比较只出现两份匿名候选。候选顺序六次中各有三次 D 在前、三次 D 在后。评测器可判平局，平局按 0.5 胜计入胜率。

比较维度包括：判断可靠性、研究增量、后续跟踪支持、不确定性表达、误导风险、作为下一轮研究输入的价值。评测器必须引用具体位置。

## 6. 模型、提示和重复运行规则

正式运行（`formal_full`）要求：

- 一个生产模型档案；
- 两个不同 `model_id` 的评测模型档案；
- 两个不同 `model_id` 的下游执行模型档案；
- 生产模型不得兼任评测模型；
- 生产模型不得兼任下游执行模型，两个下游档案也不得只是同一 `model_id` 的别名；
- 下游执行模型不得为自己的输出评分；
- 每个正式评测角色由两个模型各运行三次；
- 使用种子 11、22、33；
- A/B 两套等价提示表述在两个模型之间平衡；
- 成对候选顺序三次 D 在前、三次 D 在后。

优先选择不同模型家族的两个评测器。

### 6.1 首轮轻量配置（`pilot_light`）

若目标是先验证评测能否区分好产物、差产物与“表面专业但错误”的产物，可暂用轻量配置：

保留：C 校准；两评测模型独立裁决；U 复述/更新/跟踪；delta 相对同证据直出与摘要；S 模型分歧与候选顺序。

可暂缓：每角色三次重复；A/E 诊断组全量；次级指标概率区间；大量等价提示组合。

正式发布结论仍须回到 `formal_full`。

## 7. 盲化纪律

候选和推理材料不得暴露文件名、流程来源、内部质量标签、置信标签，以及哪份候选来自复杂流程。

## 8. 聚合与报告

六次裁决和下游评分完成后：

1. 聚合案例级 R（中位数 + 裁决支持频率）、U、delta；
2. 聚合案例集层分层分布与代理可靠率（仅比例，四题不报区间）；
3. 依据跨模型、提示和顺序差异计算 S；
4. 附上先行得到的 C；
5. 分别汇总 `report_value` 与 `restraint`；
6. 生成 YAML、JSON 和 Markdown。
