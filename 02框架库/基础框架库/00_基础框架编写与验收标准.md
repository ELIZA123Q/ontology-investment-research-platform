# 基础框架编写与验收标准

## 研究员可读性优先

第一版框架先服务研究判断，再服务系统登记。每份框架开头都应让研究员快速看懂四件事：最难的判断是什么、最容易混淆什么、哪组信号能区分、什么情况下必须停。ID、本体映射、版本和字段合同可保留在后半部分，不能遮住研究逻辑。

框架若只有变量清单和通用问题树，不算有深度；至少要写出变量之间的方向、非线性、领先滞后、关键分歧与真实失败案例。

## 1. 文件定位

基础框架用于回答“一类投研问题通常应如何拆解、验证和反面证据”。它是研究者独立搭建本次研究逻辑时的参考资产，不是现实事实、正式本体、研究结论或必须逐项填写的报告模板。

框架只定义需要研究什么、观察什么和什么条件会改变判断。具体对象、业务时间、观测值、证据充分性和结论由 01—04 的任务流程处理。

## 2. 固定结构

每个基础框架必须包含“研究员先看什么”、`Framework Output Contract` 声明和以下十一部分：

1. 适用问题与边界。
2. 核心判断任务与关键口径。
3. 核心问题树。
4. 分析模块与传导机制。
5. 最低证据与交叉验证。
6. 其他可能解释、逻辑失效与停止条件。
7. 情景设置。
8. 本体映射。
9. 组合与裁剪。
10. 权威依据卡。
11. 框架自检。

Front matter 固定保留 `framework_id`、`name`、`library` 和 `version`。既有框架 ID 不因改写而改变；发生结构性重写时升级主版本号。

`Framework Output Contract` 必须显式列出 `judgment_types`、`candidate_claims`、`state_variable_candidates`、`signal_candidates`、`evidence_requirements`、`falsification_conditions`、`scenarios`、`output_objects` 和 `downstream_unlocks`。运行时完整容器、层级依赖和前置条件状态以[框架依赖图与输出协议](../01_框架依赖图与输出协议.md)为准。

## 2.1 层级与依赖前置条件

基础框架必须登记在基础机制层、公司兑现层或市场定价层。框架文件的“组合与裁剪”必须说明必要前提、条件性前提、失败时的停止动作和可以继续使用的下游框架。不能因题目出现“估值、利润、涨价”等关键词跳过前置关键判断。

其中三条边界为强制验收项：供需解释变化原因，价格解释价格表现，利润由公司业绩弹性承接；商业模式描述长期经济结构，业绩弹性描述短中期变化；财务质量判断历史数字能否作为基线，经营预测推演未来数字。

## 3. 关键变量与信号

关键变量必须是可持续观察、可时间比较、可形成方向性假设并能参与传导的口径。一次性事实、某期数值或管理层表态不是关键变量，应在具体任务中分别作为观测、事件或信号处理。

每个核心模块至少说明：

- 源变量与目标变量；
- 方向映射及可能的非线性；
- 领先、同步或滞后信号；
- 观察窗口或传导时滞；
- 适用边界和失效条件。

支持信号和削弱信号必须分开。`blocking` 只用于逻辑失效关键假设或前置条件，不直接替代最终判断。

## 4. 证据等级

框架的来源证据与具体任务的现实证据必须分开管理。

| 等级 | 使用条件 | 允许表述 |
|---|---|---|
| 单来源方法论候选 | 仅一个可追溯来源 | 只作研究线索 |
| 多来源方法论候选 | 至少两个独立机构或原始来源支持相近方法 | 可作为基础框架参考 |
| 历史支持模板候选 | 多来源方法论加明确历史样本、反例、窗口和失效边界 | 可申请沉淀为历史支持模板候选 |

本轮基础框架统一按“多来源方法论候选”管理。权威或经典不等于已经完成本项目的历史回放；没有历史样本时不得写成“历史支持模板”。

现实任务中的最低证据遵循：关键事实优先官方文件、公司公告、审计财报和原始数据；机制判断至少需要两个相互独立的来源或一条核心来源加一条不同类型的交叉验证；预测、公司指引和市场观点不得冒充实际观测。

## 5. 本体映射层级

框架中的映射分为三层，不能混写：

1. **一级正式本体**：只引用一级通用本体已定义的对象、关系、推理对象和动作。
2. **领域扩展可选项**：只在相应领域本体已正式定义时引用，并标明领域范围。
3. **任务候选或本体缺口**：尚无正式定义但本次研究不可缺少的变量、事件类型、传导模板或规则；不得使用正式本体口吻。

基础框架可以给出“候选关键变量名称”，但这些名称不会因出现在框架中自动成为正式 `StateVariable`。具体任务仍须先查询正式本体，再决定复用、临时定义或登记缺口。

## 6. 权威依据卡

每个框架的权威依据卡至少记录：

- 来源机构、材料名称、版本或访问入口；
- 采用了什么分析机制；
- 为本项目做了什么本地化改写；
- 哪些原内容未采用及原因；
- 当前证据等级和历史样本缺口。

来源优先级为：监管机构和标准制定者、专业资格与学术机构、原始公司披露、可追溯的机构研究、二手解释。AI 摘要只能帮助定位，不作为独立权威来源。

## 7. 表达边界

- 不输出交易指令、单点资产价格、确定性回报或资金配置指令。
- 不从政策、行业、价格或订单直接跳到资产影响。
- 不把相关性、时间先后或同向变化直接写成因果。
- 不把“行业受益”自动等同于“公司兑现”。
- 不用主观印象替代市场预期基线，也不用单一价格变化替代供需判断。
- 不删除反例、失败路径和被否定的候选逻辑。

## 8. 验收门槛

基础框架可展示前必须同时满足：

- 研究对象、适用范围、时间口径和停止条件清楚；
- 关键变量可观察，信号注明来源类型与窗口；
- 传导链包含前置验证、商业转化、履约兑现、经营影响及必要的预期环节；
- 已声明所属层级、前置条件、失败停止动作和 Framework Output Contract；
- 至少列出一个其他可能解释和一个可观察判断不再成立的条件；
- 本体引用能回到正式规范，领域项和候选项未冒充一级定义；
- 权威依据卡包含至少两个独立来源；
- 没有越界生成交易指令或确定性资产结论。
