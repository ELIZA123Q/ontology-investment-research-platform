# 02 研究员使用工作台

## 一句话定位

02 不是“框架仓库”，而是研究员把一个宽泛问题收敛成少数可验证判断的工作台。使用后的结果应让另一位研究员看懂：**现在真正有分歧的是什么、为什么会这样、看什么能分出对错、什么情况必须改判。**

## 先做一张判断卡

开始查资料前，先用自然语言写完下面六格。写不出来，说明问题还没有收敛，不要急着套行业框架。

| 六格 | 研究员要写的内容 | 合格示例 |
|---|---|---|
| 要回答的问题 | 对象、时间、范围、比较基准 | 未来两个季度通用 DRAM 合约价能否继续上行 |
| 当前主判断 | 带条件、可被推翻的一句话 | 若服务器需求兑现且原厂复产克制，合约价仍有上行空间，但斜率可能放缓 |
| 真正的分歧 | 市场或团队在哪个环节意见不同 | 需求是终端增长还是补库；供给何时恢复 |
| 主路径 | 3—6 个不能跳过的因果节点 | 终端消耗→采购→库存→投片/产品组合→合约价 |
| 最强竞争解释 | 最可能让主判断看似正确但实际错误的解释 | 补库和重复下单制造了需求复苏假象 |
| 改判信号 | 出现什么事实会减弱、阻断或推翻 | 客户库存连续回升且订单取消；原厂投片提前恢复 |

## 再选框架，不要反过来

1. 先选一种主判断：状态、趋势、周期、归因、传导、比较、预期差或风险。
2. 再从基础机制层选一个最能解释核心矛盾的基础框架，并按[框架依赖图](01_框架依赖图与输出协议.md)检查前置。
3. 半导体问题再补一个行业主框架；有明确产品或事件时最多加一张场景卡。
4. 公司利润、预期或估值只有在前置产业判断逐段放行后再接，不要一开始全铺开。估值必须依次具备产业/机制判断、公司业绩桥、条件预测和事前预期差。

通常 `1 个判断类型 + 1 个主框架 + 0—1 张场景卡` 已足够。框架越多不代表研究越深；能删掉不改变判断的模块，才说明研究逻辑真正收敛。

## 判断深度的四级台阶

| 层级 | 研究内容 | 常见浅层错误 |
|---|---|---|
| 1 现象 | 发生了什么，方向和幅度如何 | 罗列数据或新闻 |
| 2 机制 | 哪些中介把原因传到结果，时滞多长 | 用相关性替代因果 |
| 3 辨识 | 主解释与竞争解释会产生哪些不同信号 | 只有支持证据，没有反证 |
| 4 决策 | 判断改变什么、何时验证、错误成本是什么 | 结论正确但不能行动或复盘 |

02 的核心判断至少达到第 3 层；critical 判断应达到第 4 层。若只做到第 1—2 层，必须在研究逻辑中标为“待辨识假设”，不能包装成结论。

## 交给 03 的不是指标清单

每个核心判断只需交出一张“取证委托单”：

- 要证明或区分的具体命题；
- 主路径中最容易断的 1—2 个节点；
- 主解释和最强竞争解释各自预期出现的信号；
- 必须获得的直接证据，以及可接受的代理；
- 最低通过条件、改判条件和截止时间；
- 若证据不可得，允许写到什么强度。

03 应围绕这些分歧取证，而不是围绕框架里的所有变量搜集资料。

正式交接使用统一 `Framework Output Contract`：至少记录框架层级、前置 JudgmentUnit、`gate_status`、CandidateClaim、变量/信号候选、证据要求、反证、情景、下游放行和未决缺口。前置为 `provisional` 时，下游结论不得写得更强；前置为 `failed` 时必须停止依赖路径。

## 研究员自检

- 不看框架名称，是否仍能用三句话讲清核心矛盾？
- 是否解释了“为什么是现在”，而不只是“长期空间很大”？
- 主解释和竞争解释是否会导出不同的可观察结果？
- 是否区分领先信号、同步确认和滞后兑现？
- 是否把行业改善跨越式地写成公司受益？
- 是否明确下一次更新看什么、何时看、看到什么要改判？
