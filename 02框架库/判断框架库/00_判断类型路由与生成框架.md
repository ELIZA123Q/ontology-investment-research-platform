# 判断类型选择与生成框架

## 研究员先判断“分歧是什么”

不要按题目关键词选类型。问自己：如果拿到一项新证据，它主要会改变“当前是什么”“往哪走”“为什么”“怎样传导”“谁不同”“市场是否知道”中的哪一个？这就是主判断类型。一个判断单元只解决一种主要分歧，其他问题拆成前置或后续单元。

| 分歧本质 | 合格问题 | 不合格的宽泛问题 |
|---|---|---|
| 状态 | 当前渠道库存是否低于正常区间 | 行业情况如何 |
| 趋势/周期 | 合约价上行斜率是否正在放缓 | 价格怎么看 |
| 归因 | 本轮订单回升主要来自终端还是补库 | 需求为何增长 |
| 传导 | 管制如何经过许可与客户行为影响交付 | 管制影响多大 |
| 分化 | 同一冲击下谁因暴露和承接不同而分化 | 谁最受益 |
| 预期差 | 新信息相对事件前共识改变了什么 | 股价会不会涨 |
| 风险 | 哪个触发会穿透缓冲并造成不可逆后果 | 有哪些风险 |

## 1. 定位

本文件是 02 框架库的第一入口。它不按行业回答“应该分析哪些章节”，而是先回答：**本次到底要形成什么判断，哪些解释在竞争，什么信号能区分，什么条件会推翻。**

行业框架、场景卡和基础框架均为第二层组件。它们用于补充行业变量、事件约束和公司映射，不能替代判断类型选择。

## 2. 最小调用顺序

```text
01 的研究问题与边界
→ 选择 1 个主判断类型
→ 写出 CandidateClaim
→ 列 1—2 个主要竞争解释
→ 指定区分信号与反证
→ 组合 0—1 张场景卡 + 0—1 个行业主框架
→ 按框架依赖图依次检查基础机制、公司兑现和市场定价的前提条件
→ 输出 JudgmentUnit、Framework Output Contract 和 03 证据要求
```

一次任务可以有多个 JudgmentUnit，但每个 JudgmentUnit 只设一个主判断类型。若一句话同时包含状态、归因、公司影响和估值，应拆成前后相接的判断单元。

## 3. 八类基础判断框架

| ID / `judgment_type` | 核心问题 | 默认竞争解释 | 关键区分信号 | 主要反证或推翻条件 | CandidateClaim 骨架 |
|---|---|---|---|---|---|
| JF-STATE / `state_measurement` | 对象当前处于什么状态，范围和强度如何 | 统计口径、季节性、局部样本造成假象 | 同口径直接指标、横向基准、业务时间 | 指标口径不匹配；独立来源不支持 | 对象 + 当前状态 + 范围/时点 + 限制 |
| JF-TREND / `trend_or_phase` | 变化是否持续，斜率是否改变 | 一次性波动、低基数、季节性 | 连续序列、斜率、扩散度、相邻变量 | 序列中断；变化不持续；相邻变量反向 | 对象 + 趋势/阶段 + 时间窗 + 驱动 + 限制 |
| JF-CYCLE / `cycle_phase` | 当前处于周期哪一段，切换条件是什么 | 结构性成长被误认作周期；单一子市场主导 | 需求、供给、库存/订单、价格的先后与共振 | 库存回升、需求下修、供给提前释放、分项显著背离 | 对象 + 周期阶段 + 主导分项 + 驱动 + 切换条件 |
| JF-ATTR / `causal_attribution` | 已观察到的变化主要由什么造成 | 同期政策、供给、需求、价格或会计口径变化 | 时间先后、暴露差异、反事实、解释力比较 | 主因发生在结果之后；低暴露对象同样变化；替代解释更强 | 变化 + 主要原因 + 次要原因 + 适用范围 + 保留解释 |
| JF-TRANS / `mechanism_transmission` | 事件或变量如何传到行业、公司或资产 | 路径被库存、合同、替代、执行或能力约束吸收 | 起点事实、中间节点、暴露、实际结果 | 起点未发生；中介无变化；存在有效缓冲或替代 | 起点 → 第一影响变量 → 路径 → 时间窗 + 阻断条件 |
| JF-DIFF / `object_comparison` | 为什么对象间影响或兑现不同 | 对象不可比；规模或基数差异造成表面排序 | 暴露度、弹性、承接能力、约束、同口径结果 | 可比基础不成立；排序对指标或窗口敏感 | 对象组 + 分化方向 + 决定变量 + 约束 + 比较口径 |
| JF-EXPECT / `valuation_expectation` | 新信息相对事前预期是否构成差异 | 基本面变化已被价格或一致预期吸收 | 事前预期基线、预测修订、价格反应、估值输入变化 | 无事前基线；信息已充分反映；风险溢价解释更强 | 新信息 + 事前预期 + 差异 + 收敛条件 + 风险 |
| JF-RISK / `risk_reassessment` | 风险概率、损失幅度或恢复能力是否改变 | 叙事升温但实际暴露未变；短期冲击被缓冲 | 触发概率、暴露、缓冲、损失路径、恢复窗口 | 触发条件消失；暴露被对冲；替代或恢复快于预期 | 风险因子 + 暴露对象 + 影响路径 + 缓冲 + 重估范围 |

`causal_attribution` 和 `risk_reassessment` 是 02 的生成标签。进入 03 时，前者优先映射 `mechanism_transmission + counter_explanation`，后者优先映射 `mechanism_transmission + object_comparison`，避免为近义问题重复建设取证主规则。

## 4. 判断生成五问

每个 critical / important JudgmentUnit 至少回答：

1. **判断对象**：对象、范围、时间和比较基准是什么？
2. **主命题**：要确认的是状态、趋势、周期、归因、传导、分化、预期差还是风险重估？
3. **竞争解释**：除主解释外，最可能的 1—2 个解释是什么？
4. **区分信号**：哪些可观察变量能让主解释与竞争解释产生不同预测？
5. **推翻条件**：出现什么事实必须缩小范围、降低强度、阻断路径或改判？

若只能回答“相关变量有哪些”，但不能回答第 3—5 问，说明尚未形成判断框架。

## 5. 组合规则

```text
主判断框架（必选 1）
+ 场景卡（可选 0—1，用于事件或产品特殊约束）
+ 行业主框架（可选 0—1，用于专业变量和产业机制）
+ 资产映射框架（可选 0—1，用于公司业绩、预期或估值）
```

这里的“+”表示候选组合，不表示四类组件平行调用。正式顺序和前置条件见[框架依赖图与输出协议](../01_框架依赖图与输出协议.md)。估值不是通用资产映射入口：只有产业/机制判断、公司业绩桥、经营情景和事前预期差均已建立时，才允许调用 BF-VA-01。

- “美伊冲突对半导体影响”通常从 JF-TRANS 开始，再接 SCN-GEO、相关半导体主框架和 BF-EE-01；不能只因出现“半导体”就从行业目录开始。
- “存储是否进入上行周期”从 JF-CYCLE 开始，再接 SCN-MEM-CYCLE 和 IF-SC-01。
- “谁更受益”从 JF-DIFF 开始；若前置影响路径未成立，应先补 JF-TRANS。
- “是否存在预期差”从 JF-EXPECT 开始；没有事前预期基线时停止使用“预期差”。

## 6. 输出到 02/03 的最小字段

```yaml
judgment_framework_ref: JF-CYCLE
judgment_type: cycle_phase
candidate_claim: "<可证伪命题>"
primary_explanation: "<主解释>"
alternative_explanations: ["<竞争解释1>"]
discriminating_signals: ["<能够区分解释的观测>"]
falsifiers: ["<削弱/阻断/推翻条件>"]
minimum_validation_condition: "<达到何种证据组合才允许判断>"
gate_status: provisional
prerequisite_judgment_refs: []
```

这些字段是任务运行内容，不是正式本体定义。正式对象、变量、路径和证据要求仍按 02 规范映射。

## 7. 自检

- [ ] 先选择判断类型，后选择行业框架和场景卡。
- [ ] CandidateClaim 包含范围、时间或限制，不是宽泛主题句。
- [ ] 至少有一个竞争解释和一个可执行反证。
- [ ] 区分信号对不同解释给出不同预期，而非泛泛“关注数据”。
- [ ] 关键前置节点失败时，后续公司或资产映射会停止。
- [ ] 最终组合不超过完成当前判断所需的最小框架集合。
