# 02 框架库使用说明

> **研究员从这里开始：**先读 [00_研究员使用工作台](00_研究员使用工作台.md)，用一张六格判断卡写清问题、分歧、主路径、竞争解释和改判信号；再按本页目录选择框架。YAML 头、ID 和校验脚本是系统接口，不是第一版的使用门槛。

> 本文件是方法库导航，不是 02 阶段规范。02 的输入、执行顺序、框架选择与裁剪、交付物和质量要求，以 [`02_判断结构与本体视图规范.md`](../02_判断结构与本体视图规范.md) 为准。本库只说明有哪些可复用框架、分别适合解决什么问题。

## 1. 定位

本目录为 02 提供可复用的判断生成参考。框架回答“本次要判断什么、有哪些竞争解释、什么信号能够区分、什么条件会推翻”，再用行业机制和场景约束补充变量与路径。框架用于帮助研究者更快搭建并检查本次研究逻辑，但不代替独立判断。

对研究员而言，本库先按研究动作分三步：

1. **先把判断说清楚**：判断类型与 Claim 模板；
2. **再把机制想深入**：基础框架和半导体主框架；
3. **最后处理具体问题**：场景卡。

治理表、ID、版本、脚本和本体映射放在使用之后，不要求研究员从技术结构开始理解。

基础框架之间不是平行关系。选好判断类型后，应按[框架依赖图与输出协议](01_框架依赖图与输出协议.md)沿“基础机制层 → 公司兑现层 → 市场定价层”逐段验证；机器可读依赖登记见 [`00_framework_dependency_registry.yaml`](00_framework_dependency_registry.yaml)。标题命中只表示框架可能相关，不表示已满足调用条件。

02 应先根据 01 的研究需求识别真正需要辨别的核心矛盾，再参考本目录检查遗漏、补充视角，最后形成属于当前任务的研究框架并映射正式本体。库中框架不是现实事实、正式本体、研究结论或必须照填的报告模板。

本库止步于“应该判断什么、按什么结构验证”。现实证据怎样取得和验收属于 [`03取证策略库`](../03取证策略库/README.md)；合格证据怎样影响路径、观点和改判属于 [`04推理方法库`](../04推理方法库/README.md)。02 可以预先定义反证方向和停止条件，但不能判断本次反证是否成立，也不能形成最终观点。

```text
01 研究需求
→ 识别核心矛盾并独立搭建基本问题树
→ 选择主判断类型并形成待验证观点
→ 明确竞争解释、区分信号和推翻条件
→ 按依赖图调用场景卡、行业框架和基础框架
→ 按本次对象、范围和时间裁剪组合
→ 匹配正式本体并形成任务本体视图
→ 按统一交接要求记录待验证观点、变量、证据要求和前置条件状态
→ 03 准备现实实例、观测和证据
```

第一入口是[判断类型选择与生成框架](判断框架库/00_判断类型路由与生成框架.md)，待验证观点的写法见[观点模板与检查清单](Claim模板库/00_Claim模板与检查清单.md)。基础框架的固定结构、证据等级、本体映射和验收要求见[基础框架编写与验收标准](基础框架库/00_基础框架编写与验收标准.md)。半导体行业的主框架、场景卡、调用规则与治理见[半导体行业框架库](行业框架库/半导体行业/README.md)和[总纲与治理规则](行业框架库/半导体行业/00_半导体行业框架库总纲与治理规则.md)。

## 2. 判断框架与 Claim 模板（第一入口）

| 资产 | 解决的问题 | 使用边界 |
|---|---|---|
| [判断类型选择与生成框架](判断框架库/00_判断类型路由与生成框架.md) | 状态、趋势、周期、归因、传导、分化、预期差、风险重估如何生成判断 | 每个关键判断只选一个主判断类型 |
| [观点模板与检查清单](Claim模板库/00_Claim模板与检查清单.md) | 好的待验证观点如何做到可证伪、有边界、可降级 | 模板不预填现实方向，不替代证据 |

推荐的最小组合为：`1 个判断框架 + 0—1 张场景卡 + 0—1 个行业主框架 + 0—1 个资产映射框架`。若需要更多组件，应说明它们分别改变了哪条主路径、竞争解释或停止条件。

## 5. 框架选择矩阵

| 判断起点 | 首选判断框架 | 机制/专业组件 | 最容易误判的跳步 |
|---|---|---|---|
| 行业是什么、好坏由什么决定 | JF-STATE / JF-ATTR | BF-IC-01、BF-SD-01 | 分类代码直接当竞争市场 |
| 产品是否紧缺或过剩 | JF-STATE / JF-CYCLE | BF-SD-01、BF-PC-01 | 订单等同终端需求；产能等同供给 |
| 涨价能否持续 | JF-TREND / JF-CYCLE | BF-PC-01、BF-SD-01 | 报价等同成交和公司实现价 |
| 政策是否产生实际影响 | JF-TRANS | BF-PI-01、BF-VT-01 | 文本直接跳行业或公司结果 |
| 冲击如何跨产业链传导 | JF-TRANS | BF-VT-01、BF-RS-01 | 概念邻近当稳定供应关系 |
| 公司靠什么挣钱 | JF-ATTR | BF-BM-01、BF-IC-01 | 收入增长不检查单位经济和现金 |
| 行业改善能否变成公司利润 | JF-TRANS | BF-EE-01、BF-FQ-01 | 认证、订单、收入和现金混用 |
| 财报改善是否真实可持续 | JF-TREND / JF-ATTR | BF-FQ-01、BF-BM-01 | 单指标红旗直接定性 |
| 管理层是否有效配置资本 | JF-DIFF / JF-ATTR | BF-CA-01、BF-CG-01 | ROE高等同增量回报高 |
| 如何预测未来经营 | JF-TREND / JF-RISK | BF-FS-01、BF-RS-01 | 指引等同事实；单情景线性外推 |
| 治理是否影响长期结果 | JF-TRANS | BF-CG-01、BF-CA-01 | 形式合规等同治理有效 |
| 公司能否承受冲击 | JF-RISK | BF-RS-01、BF-FQ-01 | 风险清单替代现金与传导测试 |
| 宏观变化如何落到行业 | JF-TRANS | BF-MF-01、BF-SD-01 | 政策工具直接等同金融或实体条件 |
| 基本面如何改变估值输入 | JF-TRANS / JF-EXPECT | BF-VA-01、BF-FS-01 | 倍数低等同价值被低估 |
| 新事实是否形成预期差 | JF-EXPECT | BF-EG-01、BF-VA-01 | 没有事前预期基线也声称存在差异 |

| 晶圆厂扩产何时形成供给 | JF-TRANS | IF-FAB-01、IF-EQP-01 | 厂房或设备搬入等同量产 |
| 国产设备是否真正突破 | JF-TRANS / JF-DIFF | SCN-LOC-EQP、IF-EQP-01 | 样机、首单等同复购和份额 |
| 国产材料是否进入放量 | JF-TRANS / JF-DIFF | SCN-LOC-MAT、IF-MAT-01 | 送样等同产线批量供应 |
| 车规芯片是否兑现 | JF-TRANS | SCN-AUTO、IF-DES-01 | 单项认证或定点等同装车 |
| SiC是否加速渗透 | JF-TREND / JF-TRANS | SCN-PWR-SIC、IF-APP-01 | 材料性能等同系统经济性 |
| AI芯片与HBM是否紧张 | JF-STATE / JF-CYCLE | SCN-AI、SCN-MEM-HBM | capex或峰值算力等同实际需求 |
| 先进封装是否成为瓶颈 | JF-STATE / JF-TRANS | SCN-PKG-BTL、IF-PKG-01 | 名义封装产能等同有效交付 |
| 光互连需求如何传导 | JF-TRANS | SCN-OPTO、IF-APP-01 | 模块收入并入半导体器件口径 |

## 6. 常用组合链路

### 6.1 政策到公司兑现

```text
BF-PI-01 政策工具与执行

→ BF-EE-01 公司暴露、执行和财务兑现
```

### 6.2 行业价格到公司利润

```text

→ BF-PC-01 报价、成交和实现价
→ BF-EE-01 量价结构、成本、利润和现金桥
→ BF-FS-01 情景预测
```

### 6.3 财报改善到预期和估值

```text
BF-BM-01 商业模式与收入驱动
→ BF-FQ-01 报告与盈利质量
→ BF-CA-01 资本配置和现金回报
→ BF-FS-01 可持续经营预测
→ BF-EG-01 事前预期比较
→ BF-VA-01 估值输入和风险变化
```

### 6.4 宏观冲击到公司风险

```text
BF-MF-01 周期、政策和金融条件

→ BF-EE-01 公司经营传导
```

## 7. 怎样使用本库

完整调用规则只在 02 阶段规范维护。本库提供三个入口：

1. 不确定属于哪类判断时，先看[判断类型选择与生成框架](判断框架库/00_判断类型路由与生成框架.md)；

框架文件中的系统 ID 和输出字段供任务本体视图引用。研究逻辑正文应把它们改写为“核心问题、待验证观点、关键变量、相反证据和下一步验证”，不复制系统字段表。

## 10. 质量边界
