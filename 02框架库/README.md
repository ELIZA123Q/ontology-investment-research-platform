# 02 分析框架知识库

本库保存可复用的分析框架，回答“这类问题通常应判断什么、怎样拆解、哪些机制和竞争解释需要检查”。单次任务如何选择、裁剪并输出研究逻辑，由 [`02_判断结构与本体视图规范.md`](../02_判断结构与本体视图规范.md) 规定。

## 1. 库里有什么

| 目录或文件 | 内容 | 用途 |
|---|---|---|
| [`判断框架库`](判断框架库/00_判断类型路由与生成框架.md) | 状态、趋势、周期、归因、传导、分化、预期差和风险等判断类型 | 先确定本次主要判断动作 |
| [`Claim模板库`](Claim模板库/00_Claim模板与检查清单.md) | 可证伪观点的写法和检查项 | 把宽泛主题改写为可验证观点 |
| [`基础框架库`](基础框架库/00_基础框架编写与验收标准.md) | 供需、政策、产业链、价格、公司兑现、财务、预期和估值等通用框架 | 补充跨行业机制 |
| [`行业框架库/半导体行业`](行业框架库/半导体行业/README.md) | 半导体“两横六纵”主框架和高频场景卡 | 补充行业特有机制和变量 |
| [`01_框架依赖图与输出协议.md`](01_框架依赖图与输出协议.md) | 框架前置关系和统一输出内容 | 防止跳过必要前提 |
| `00_framework_dependency_registry.yaml` | 框架 ID、依赖和机器引用 | 供校验器和任务本体视图使用 |

## 2. 本库与其他资产的边界

- 02 框架库决定**判断什么、按什么结构验证**。
- [`03取证策略库`](../03取证策略库/README.md)决定**需要什么证据、去哪里找、怎样验收**。
- [`04推理方法库`](../04推理方法库/README.md)决定**合格证据怎样形成、削弱、阻断或修改判断**。
- 正式本体定义稳定对象、关系和规则；单次 `02` 产物只保存本次采用的最小结构。

框架不是现实事实、正式本体、研究结论或报告模板。不得把库中文本直接拼贴为本次研究逻辑。

## 3. 如何使用

1. 用自然语言写清要回答的问题、当前分歧、主路径、最强竞争解释和改判信号。
2. 从判断框架库选择一个主要判断类型。
3. 选择一个最能解释核心矛盾的基础框架，并检查其前置条件。
4. 半导体问题按需增加一个行业主框架；具体产品或事件最多增加一张场景卡。
5. 删除不会改变判断、证据要求或改判条件的模块。
6. 形成单次 `02-研究逻辑.md` 和 `02-本体视图.yaml`，再交给 03 准备证据。

推荐最小组合：`1 个判断框架 + 0—1 个基础或行业主框架 + 0—1 张场景卡`。需要更多组件时，必须说明每个组件改变了哪条路径、竞争解释或停止条件。

## 4. 框架选择索引

| 常见问题 | 首选框架或场景 |
|---|---|
| 产品是否紧缺、价格能否持续 | 供需判断、价格周期 |
| 政策是否产生实际产业影响 | 政策影响、产业链传导 |
| 行业改善能否兑现到公司 | 商业模式、公司业绩弹性、财务质量 |
| 新事实是否形成预期差 | 预期差判断；先固定事前预期基线 |
| 存储周期何时切换 | `SCN-MEM-CYCLE` + `IF-SC-01` |
| 国产设备是否真正突破 | `SCN-LOC-EQP` + `IF-EQP-01` |
| 半导体材料是否进入放量 | `SCN-LOC-MAT` + `IF-MAT-01` |
| 先进封装是否成为瓶颈 | `SCN-PKG-BTL` + `IF-PKG-01` |

完整框架目录见各子目录 README；机器可读依赖以 `00_framework_dependency_registry.yaml` 为准。

## 5. 质量与准入标准

一个框架只有满足以下条件，才可作为正式知识资产：

1. 解决反复出现的问题，而不是保存某次结论；
2. 说明适用与不适用范围、核心问题、关键变量和传导机制；
3. 给出最低证据、竞争解释、反面证据、停止条件和常见误判；
4. 能输出可执行的待验证观点、证据要求和改判信号；
5. 不复制阶段流程、来源清单或最终报告结构；
6. 新增行业框架或场景卡应经过至少两个任务验证。

单次经验先进入框架使用记录或复盘，不直接改写正式框架。

## 6. 自动校验

```bash
python3 02框架库/validate_frameworks.py
```

校验器检查框架和场景卡结构、ID、依赖、内部链接、本体标识符及半导体框架覆盖，不生成研究结论。
