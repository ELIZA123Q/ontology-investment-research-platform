# 半导体行业框架库总纲与治理规则

## 1. 定位

本框架库面向中国为主、兼顾全球供应链的半导体投研问题，提供一组可组合、可验证、可反证、可裁剪的行业分析框架。

框架库不回答“现在事实是什么”，也不直接给出投资结论。它只回答：

> 一类半导体问题通常应该如何定界、拆解、观察、验证、反证和停止推导。

框架的作用是帮助 02 阶段形成研究逻辑，并为 03 阶段的数据与证据准备提供变量、证据、来源和验证路径。

## 2. 总体行业理解

半导体不是单一周期行业，而是由需求、库存、产能、技术、认证、资本开支和财务兑现等多种时钟叠加形成的复杂产业系统。

至少需要同时区分六类时钟：

| 时钟 | 回答的问题 | 常见误判 |
|---|---|---|
| 需求时钟 | 终端需求、系统配置、单机内容量是否变化 | 把订单等同终端需求 |
| 库存时钟 | 原厂、渠道、模组、客户库存处于什么位置 | 把补库误判为真实复苏 |
| 产能时钟 | 晶圆、封装、测试、材料、设备是否形成有效供给 | 把名义产能等同合格供给 |
| 技术时钟 | 节点、架构、工艺、封装和软件生态是否成熟 | 把路线图等同量产现实 |
| 认证时钟 | 样品、认证、定点、量产、复购是否跨过商业阈值 | 把送样或定点等同收入 |
| 财务时钟 | 行业变化是否兑现为收入、利润、现金和资本回报 | 把行业景气直接推导为公司业绩 |

## 3. 主框架层：两横六纵

主框架层只保留能够跨多个半导体问题复用的核心判断机制。主框架数量应保持稳定，不随热点扩张。

### 3.1 两个横向框架

| ID | 框架 | 作用 |
|---|---|---|
| IF-SC-01 | 半导体周期与库存框架 | 判断周期位置、库存、价格、稼动、资本开支和供给释放 |
| IF-LOC-01 | 外部约束、国产替代与供应链韧性框架 | 判断政策、管制、地缘、供应安全、国产替代和韧性 |

### 3.2 六个产业链主干框架

| ID | 框架 | 作用 |
|---|---|---|
| IF-APP-01 | 应用需求与半导体内容量框架 | 终端和系统如何转化为芯片、存储、功率、光互连等需求 |
| IF-DES-01 | 芯片设计、IP与产品商业化框架 | 产品定义、EDA/IP、流片、验证、Design Win、量产、复购 |
| IF-FAB-01 | 晶圆制造、工艺平台与产能框架 | 设施、晶圆尺寸、节点、工艺平台、良率、稼动、折旧 |
| IF-PKG-01 | 封装测试与异构集成框架 | 传统封测、先进封装、Chiplet、测试、良率和利润池 |
| IF-EQP-01 | 半导体设备需求、验证与放量框架 | Fab项目、设备强度、客户验证、复购、验收和收入 |
| IF-MAT-01 | 半导体材料需求、认证与放量框架 | 投片、工艺步骤、单位耗用、材料认证、复购和跨厂复制 |

## 4. 场景卡层

本版取消“产品/应用适配卡”作为独立资产层，产品应用型问题统一进入场景卡。

场景卡分为两类：

| 类型 | 作用 | 示例 |
|---|---|---|
| 产品应用型 | 承接高频产品、应用或技术族 | HBM、AI计算芯片、车规芯片、SiC、光电子/硅光 |
| 事件问题型 | 承接高频事件、政策、周期、替代和瓶颈问题 | 地缘冲击、国产设备突破、国产材料放量、存储周期、先进封装瓶颈 |

场景卡不是正式主框架。它负责说明：

1. 这个问题应调用哪些主框架；
2. 最小判断链是什么；
3. 特殊变量和关键证据是什么；
4. 哪些反证会削弱或阻断判断；
5. 什么情况下必须停止推导；
6. 本次任务应该如何裁剪。

## 5. 新增资产准入规则

新增正式主框架必须同时满足以下条件：

| 准入条件 | 要求 |
|---|---|
| 独立核心矛盾 | 不是已有框架简单换对象 |
| 独立变量体系 | 存在稳定、可观察、可复用的关键变量 |
| 独立传导机制 | 机制不能被现有主框架覆盖 |
| 独立反证方式 | 有不同于其他框架的阻断和停止条件 |
| 跨案例复用 | 至少可服务 3—5 个不同研究案例 |
| 权威来源支撑 | 至少两个独立来源，其中至少一个为中国官方、协会、标准或产业组织来源 |
| 本体可映射 | 能映射到现有一级本体或明确提出领域扩展缺口 |

不满足以上条件的内容，不得新增正式主框架，只能登记为场景卡、案例复盘、本体缺口或证据模板。

## 6. 共同禁止项

任何半导体框架或场景卡都不得：

1. 把集成电路产量、销售额、进口额、晶圆面积和公司收入混为同一景气指标；
2. 把终端销量直接等同芯片需求；
3. 把订单、补库、抢货和真实需求混写；
4. 把设计、流片、送样、认证、定点、量产、复购和规模采用合并为“已突破”；
5. 把厂房、设备搬入、名义产能直接当作有效供给；
6. 把路线图、标准、实验参数直接当作现实量产能力；
7. 把政策支持、外部限制或国产化意愿直接推导为公司收入和利润；
8. 把单一公司、单一客户或单一价格口径外推为行业结论；
9. 把行业供需判断直接跳到估值或投资建议；
10. 为追求完整而扩展 01 没有纳入的对象、时间、地域和产业链范围。

## 7. 研究任务最小使用记录

每次 02 使用框架库，只需记录五件事：

1. 本次研究的核心矛盾是什么；
2. 选择了哪张场景卡、哪个主框架和哪个横向框架；
3. 场景卡补充了哪些特殊变量、证据、反证和停止条件；
4. 哪些模块被裁剪，为什么裁剪；
5. 哪些路径因证据不足、本体不足或边界不足被降级或停止。

不要求把框架完整搬进研究逻辑。框架负责检查遗漏，场景卡负责组织调用，本次研究仍要独立形成判断。
