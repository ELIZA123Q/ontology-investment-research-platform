# 03_数据与证据准备规范

## 1. 文档定位

本文档规范 03 阶段如何把 02 的研究逻辑和任务本体视图，转化为可执行、可复核、可追溯的数据与证据准备过程。

03 的核心目标不是泛搜资料或用覆盖率制造“证据充分”的错觉，而是判断：

> 各核心判断是否取得了匹配口径、足够质量、经过反证检查的证据；哪些观点可以交给 04；哪些只能受限使用；哪些必须暂不可判断或返工。目标 05 的展示素材有没有、是否可用、限制是什么，必须另行评价为 `delivery_readiness`（交付素材是否就绪），不得反向改变证据质量结论；证据足够判断，不代表一定适合做图或写成深度报告。

03 必须先设定证据要求，再执行取证。不得先搜索资料，再倒推“证据充分”。

本阶段形成三份正式交付物，必须使用同一组任务标识、运行标识、固定研究范围、数据截止时点、来源版本和证据要求预设，不得拆开流转：

```text
03-<核心主题>数据与证据准备-<YYYYMMDD>-<当日序号>.md
03-<核心主题>语义域与证据域实例清单-<YYYYMMDD>-<当日序号>.yaml
03-<核心主题>数据与证据快照-<YYYYMMDD>-<当日序号>/   （本次证据归档）
```

`stage_status`（阶段状态）只记录本阶段是否完成。每个核心判断能说到多强，由最终 `evidence_grade`（证据等级）、机器归一化反证结果和关联 `path_readiness_status`（路径是否够用），按 [`../运行校验/status_derivation.py`](../运行校验/status_derivation.py) 的规则给出结论强度上限；不对整份材料包一刀切给出单一“够不够用”标签。正式交付还必须满足本规范第 12 章，以及 [`../00_全局/00A_高质量产出判别标准.md`](../00_全局/00A_高质量产出判别标准.md)。

字段表、状态枚举与快照职责见 [`03_附录1_证据要求与快照字段参考.md`](03_附录1_证据要求与快照字段参考.md)；取数留痕、质量细则、归一与执行清单见 [`03_附录2_取数留痕与材料处理操作手册.md`](03_附录2_取数留痕与材料处理操作手册.md)；交付素材场景见 [`03_附录3_交付素材检查场景参考.md`](03_附录3_交付素材检查场景参考.md)；机器 schema 以 [`模板/03_数据与证据快照模板/字段清单.csv`](模板/03_数据与证据快照模板/字段清单.csv)、[`../运行校验/README.md`](../运行校验/README.md) 与 `snapshot_layout_03.py` 为准；取证知识见 [`../知识库_03取证/`](../知识库_03取证/README.md)。

## 2. 本阶段负责什么、不负责什么

### 2.1 本阶段负责

1. 校验 02 入口，固定本次范围与数据截止时点；
2. 为每个核心判断预设六类证据角色中实际需要的角色和降级规则；
3. 调用取证策略库，按核心判断拆解数据与证据需求并完成取证留痕；
4. 清洗、归一并将材料映射为语义实例、证据实例与固定推理输入；
5. 评价证据质量，主动检查反证、冲突与竞争解释；
6. 输出各核心判断最终 `evidence_grade`、路径是否够用与可用边界；
7. 独立输出 `evidence_readiness`（证据是否够用）与 `delivery_readiness`（交付素材是否就绪）：前者回答证据是否足以判断，后者只回答展示素材有没有、是否可用、限制是什么；不得互相替代；
8. 判定本阶段输出为草稿、最低通过或高质量通过。

### 2.2 本阶段不负责

1. 不修改 01《投研需求说明》或 02 已确定的命题、路径、本体结构与最低验证条件；
2. 不为“完整”而泛搜无关材料；
3. 不把搜索结果、网页摘要、模型记忆、二手转述或获取工具本身当作证据来源；
4. 不把预测、观点、假设、指引和已发生事实混为一类；
5. 不执行 02 的推理规则，也不形成方向性投研结论；
6. 不因主源不可用而静默更换口径；不用数量或覆盖率替代关键质量门槛；
7. 不在运行产物中保存敏感凭据；
8. 不替 05 决定素材用不用、放在哪里、如何形成论证；
9. 不输出章节建议、故事线、标题、投资要点或研报目录。

对 05 素材的边界固定为：

```text
03：素材有没有、是否可用、限制是什么
05：用不用、放在哪里、如何形成论证
```

02 结构不清时退回 02；问题边界仍有关键歧义时退回 01。发现可复用新能力只提交本体候选与缺口，不得把新事实直接写入 `evidence.yaml`。

## 3. 入口检查、固定本次研究口径与证据要求

### 3.1 入口校验

03 开始前须确认：已收到配对的研究逻辑与任务本体视图；二者对应同一问题、范围与任务 ID；02 已形成核心待验证命题、最小问题树、关键路径节点及每节点的实例/观测/证据/反证与最低验证条件；反证、竞争解释、停止与降级规则已说明；候选结构或本体缺口限制已传递；阶段与质量状态可解析。

| 02 状态 | 03 处理 |
|---|---|
| `high_quality_pass` | 可进入正式 03 |
| `minimum_pass` | 可进入 03，但应标记上游质量限制，不得自动视为证据已够用 |
| `draft` | 不进入正式 03 |
| `return_required` | 退回 02 |

缺现实公司、产品、关系、事件、数值、来源或材料 → 03 继续准备。缺命题、路径、本体承接、对象拆分或最低验证条件 → 退回 02。研究问题或对象边界仍有关键歧义 → 退回 01。

### 3.2 固定本次研究口径

入口通过后必须固定：任务标识、运行标识、数据截止时点、时间范围、对象范围、来源范围、口径范围、取数方式范围、02 文件指纹。同一次研究中，准备 Markdown、快照与后续 04 必须使用同一套范围与截止时点。扩大对象、改时间、换关键口径、改来源或新增取数方式时，应生成新运行版本，不得覆盖旧快照。

### 3.3 证据要求预设

03 不得在未预设证据要求的情况下开始正式取数。预设只回答：为达到某种强度的 04 判断，至少需要什么证据；哪些必需、可替代、仅可代理；缺失时如何降级或停止。它不是结论，不得写成“当前已经证明”。

每个核心判断必须先形成 `evidence_requirements.csv`。对象链路为：

```text
核心判断 → 主取证方法 → 必需证据角色 → 本次证据要求
→ 来源画像 / 取数通道 → 来源文档 → 来源说法 → 归一事实
→ 单项评价 → “证据是否够用”评价 → 04 最多能形成的结论
```

03 必须继承 02 全部规范主键 `ER-nn`（及独立编号的 `CER-nn`，若有）。可另增 `ER-JU-nn` 作为按判断单元汇总的计划行，但不得替代 `ER-nn`。每条 `ER-nn` / `CER-nn` 在本阶段结束时必须有对应证据记录（`EV-*`）、缺口（`GAP-*`）或明确的无法取得/阻断策略。最小跨阶段引用约定见 [`../00_全局/00_项目定位与边界.md`](../00_全局/00_项目定位与边界.md#51a-最小跨阶段引用约定)。

`judgment_units` 只说明判断类型与证据角色；`evidence_requirements` 只说明本次必须取得什么。通用方法与推荐来源由知识库提供；来源类型等由证据域定义。单项可用性由 `EvidenceAssessment` 说明；核心判断可否进入 04 由 `EvidenceReadinessAssessment` 说明。字段明细见附录字段参考第 2 节。

### 3.4 候选结构的处理

若 02 使用任务候选结构，03 可继续准备，但必须说明依赖项、使用边界、受影响传导环节、对 04 观点强度的限制，以及是否需本体优化。关键路径依赖候选结构时，原则上记 `path_readiness_status=restricted`（受限可用），除非 02 已说明不影响本次强度。

## 4. 取证策略调用与数据需求拆解

### 4.1 按核心问题拆解，不按主题泛搜

03 应从 02 的核心问题与传导环节出发拆解可执行需求，不得围绕宽泛主题泛搜。需求维度见附录字段参考第 1 节。

### 4.2 判断类型与取证规则

应根据 02 已明确的规范判断类型选择一个主取证方法，不得根据手头材料反推问题。判断类型与 A01—A09 方法见 [`知识库_03取证/README.md`](../知识库_03取证/README.md)；机器映射只在 [`03_registry.yaml`](../知识库_03取证/03_registry.yaml) 维护。单次任务在沿用原字段名的 `evidence_recipe_matches.csv` 中必须填写：

1. `judgment_type`：与 02 一致的八类规范类型；
2. `library_recipe_id`：填写 A01—A09 方法 ID；该字段名仅为既有快照兼容，不再表示一套独立 Recipe；
3. `library_basket_ids`：填写 `primary / baseline / mechanism / cross_check / counter` 中本方法需要的角色；历史快照中的 `scope` 视为有效性检查已做，不再当作可收集角色；
4. `strategy_library_ref`：直接指向本次使用的 A 方法文件。

任务本地 `R-*` / `EB-*` 可继续作为本次快照内编号，但不再升级为跨任务治理对象。单次任务须记录主方法、适用理由与缺失时如何降级。A03—A07 正式调用 A08；A01/A02 仅做轻量反向检查。仅在直接指标不可得、明显滞后或权限受限时调用 A09，并说明代理关系、适用范围、失效条件与完备度上限。

### 4.3 必需证据角色

单条证据回答“某个来源说了什么/某个字段是多少”；证据角色回答“它在本次判断中承担什么作用”。全库只使用主证据、比较基准、机制或承接、独立交叉验证、反证与限制五类角色。范围与口径是所有材料的共同有效性前置检查，不是可选角色；任务卡可显示该检查摘要。每个 A 方法已经给出最少需要的角色，任务只实例化与当前问题有关的内容；不得为填满五类而补材料，也不得用材料数量代替关键主证据是否存在。

### 4.4 最小充分原则

只准备回答当前问题与目标 05 原型所需的最小充分集合：先关键节点硬性证据 → 再支持/反证/竞争解释的最低交叉验证 → 再显著降低不确定性的材料 → 再目标报告类型通常需要的展示型素材（图表数据、排序表、来源注释）。达到最低门槛且新增信息不再改变节点或素材状态时应停止。补充性材料不得阻塞 `stage_status=complete`，但应计入 `delivery_readiness`。03 只登记素材有无、可用性与限制，不据此规划 05 章节或论证。“没有找到”只表示当前权限与检索范围内缺失，不表示事实不存在。

### 4.5 核心结论证据门槛

必须把“证据覆盖率”与“核心结论证据门槛”分开。覆盖率回答变量—锚点完成了多少；门槛回答某方向性观点最低需要哪些证据、目前是否满足。必须形成核心问题证据门槛表（字段见附录字段参考第 3 节）。覆盖率高不代表可方向性输出；只有门槛满足，04 才能使用该观点。

## 5. 数据质量控制

### 5.1 三层质量控制

```text
基础质量底线：所有材料都必须满足；
判断类型加严：不同证据角色有不同专项要求；
取数方式修正：不同获取方式有不同留痕和审计要求。
```

数据质量不是单独打分项，而是直接决定 04 最多能形成的结论。检查维度、角色加严与问题映射见操作手册第 2—4 节。

### 5.2 证据质量与研究语言

研究员和任务卡只使用四档语言：

| 等级 | 含义 | 04 最多能形成的结论 |
|---|---|---|
| 充分 | 直接证据、口径匹配、必要交叉验证和重大反证材料检索完成 | 明确判断（含明确支持与明确否定） |
| 受限 | 主证据基本可用，但样本、范围、时效、独立性或冲突消解有限 | 有条件判断 |
| 观察 | 主要依赖代理、单点、二手或间接材料 | 方向观察和待验证项 |
| 不可用 | 关键证据缺失、不可追溯或口径错配 | 暂不可判断 |

完备度与命题支持状态是两条轴：高质量证据明确否定原命题时，完备度仍可为充分；命题支持状态由 04 输出。既有快照和统一状态派生仍使用 `evidence_grade=Q0—Q4` 作为机器字段：不可用→Q0，观察→Q1，受限→Q2，充分→Q3/Q4。该映射只在 [`03_registry.yaml`](../知识库_03取证/03_registry.yaml) 和校验器中使用，研究员不逐项打 Q 分。

质量等级不得高于其最薄弱关键环节。核心证据完全依赖代理指标时，研究语言不得高于“受限”；图表数量、排序表与“是否像研报”不属于证据质量。

03 不为每个核心判断另填一套权限表。每个核心判断只写最终 `evidence_grade`，并提供可归一化的反证记录与关联路径；校验器调用 [`../运行校验/status_derivation.py`](../运行校验/status_derivation.py) 按规则给出结论强度上限、证据权限和允许表达。任何模板、策略或单次运行不得手工填写这些计算结果。最终等级是对整个核心判断的审慎综合评价，不是最好一条证据的等级。

### 5.3 硬限制摘要

进入有效证据计数的材料必须可追溯、来源清晰、主张类型清晰、动态内容有业务时间、口径与权限明确、交叉验证真正独立，并与当前核心判断直接相关。不得计入：无法定位原文的摘要、搜索页或 AI 回答、权限不清的内部材料、无业务时间的动态变量、未区分事实与观点的二手转述、无直接绑定的宽泛背景。

EvidenceAssessment 必须解释可用性，不能只继承来源层级。五维打分与硬限制细则见操作手册第 1 节。硬限制优先于总分：无法追溯或权限不清直接 blocked；缺业务时间不得支撑趋势；同源转述不得提高独立验证分；口径错配时匹配度不得高于 2 分；代理指标必须记录置信折扣；单项 reliability_band 不得直接复制为单元或 Judgment 的 confidence。

搜索结果不得作为证据；获取工具不能冒充来源。取数方式留痕见操作手册第 5—7 节。

## 6. 来源结构、推荐取证来源与取数方式

来源生产者、内容领域、获取方式、权限与材料形态的正式定义见[一级通用本体证据域](../一级通用本体规范/03_证据域规范.md)；选源与替代见 [`B00 来源选择与使用边界`](../知识库_03取证/B00_来源选择与使用边界.md)。本规范不再复制概念表、来源分层和选源顺序。

03 只负责把本次实际采用的来源和获取过程记录清楚：谁生产/发布、描述什么对象与期间、如何取得、是否有权使用、原文或字段在哪里、本次可证明什么与不能证明什么。MCP、API、搜索、文件检索和模型抽取只能记为获取或处理方式。

单次计划应记录首选、交叉验证与替代来源及理由。改用替代来源时必须说明口径差异及对结论强度的影响。同源或同转述链不得记为独立交叉验证。每次获取必须可复核、可回放；未保存原文须明示 `capture_kind=structured_evidence_packet` 且按未保存原文限制处理。缺少来源身份、业务时间、权限或复核位置的材料可作线索，不得计入关键证据已满足。

## 7. 材料处理、归一与实例入库

03 必须区分四类材料：

| 类型 | 含义 |
|---|---|
| 原始材料 | 尚未处理的接口响应、表格、公告、财报、网页、访谈等 |
| 语义实例 | 公司、产品、材料、环节、设施、资产及稳定关系 |
| 推理输入 | 有业务时间的事件、状态绑定、观测、信号或市场预期 |
| 证据记录 | 来源文档、最小主张、归一事实候选及其支持/削弱/阻断/冲突作用 |

结构化数据不因来自数据库就自动成为事实；一手文本也不自动满足目标口径。所有材料都必须经过来源确认、范围对齐、口径检查、时间匹配和质量判断。不能回溯的材料不得进入有效证据计数。

身份/关系、数值/时间、证据主张与原始定位的归一字段与操作细则见操作手册第 8—9 节。来源观点不得归一为已发生事实；预测和指引不得替代实际观测。

## 8. 质量判断与阶段结果

质量判断至少分六层，不得互相替代：证据要求质量、来源质量、记录质量、映射质量、证据门槛、核心判断与路径边界（最终 `evidence_grade`、反证结果与 `path_readiness_status`）。尤其不得用覆盖率、材料数量或整份材料包的笼统标签替代各核心判断的证据门槛。

每个核心问题只维护一个最终 `evidence_grade`。支持、交叉验证、反证、冲突、代理、时效与范围仍须逐项记录，作为形成 Q 与反证归一化的依据；不另为每一项单独给出一套“04 最多输出”状态。`conditions` 非空时 04 必须保留条件；反证结果归一为 `weakened` / `contested` / `decisive`；关联路径只填 `path_readiness_status`。

取证、评级、反证与路径记录完成后填 `stage_status=complete`；无法完成时填 `blocked` 或 `returned`。04 能说到多强，必须按每个核心判断调用规则给出结论强度上限，不能从整份材料包的笼统标签继承。高质量的 J0/J1 缺口结果允许发布；不要求整份材料包至少有一个核心判断达到方向判断级（J2）才算合格。

单项需求状态、覆盖率计算与证据包可信程度见附录字段参考第 4—6 节。

## 9. `evidence_readiness` 与 `delivery_readiness` 双结果

| 结果 | 回答的问题 | 不得受什么影响 |
|---|---|---|
| `evidence_readiness` | 证据是否足以形成判断，以及 04 最多可形成多强判断 | 图表数量、排序表、版式和报告表现力 |
| `delivery_readiness` | 目标报告类型下，图表/表格/来源注释等展示素材有没有、是否可用、限制是什么 | 不得反向提高或降低 `evidence_grade` 或 03 `quality_status`；不得据此预写 05 章节、故事线、标题或投资要点 |

因此可以同时出现：证据 `Q4` 且路径 ready，但 `delivery_readiness.status=partially_ready`。这表示足以判断，但不等于一定适合做图或写成深度报告。

03 不写 05 正文，不判断投研观点，也不替 05 规划表达；应从 01 的 `delivery_archetype.primary` 读取目标报告类型，并独立检查展示素材的有无、可用性与限制。字段与状态见附录字段参考第 7 节；按报告类型的场景检查见交付素材附录。不得把所有素材单元一律要求为 `report_grade_ready`；素材状态仅影响 `delivery_readiness`。检查表只回答素材就绪度，不回答 05 应如何组织章节或论证。

`delivery_limit` 只写素材层面的形态上限与必须保留的限制（例如“不得写成投资排序”“缺统一分母故不可制国产化率图”），不得写成章节安排、故事线、标题或投资要点草稿。

03 可以写证据与素材资产说明（口径、可比性、有无、可用性、使用限制）；不应写方向性观点判断（属于 04），也不应写用不用、放在哪里、如何形成论证，以及标题、故事线、投资要点（属于 05）。

## 10. 单次运行产物与执行顺序

三份正式交付物的字段与章节以准备模板、快照模板为准；本次证据归档四层目录与文件职责以运行校验 README、`snapshot_layout_03.py` 及附录字段参考第 9 节为准。03 不生成推理规则执行结果或 Judgment，不填写 J 等级或任何 04 输出上限。

准备 Markdown 须用研究员可快速复核的语言说明：范围与基线、证据需求、来源与口径、实例如何形成、各核心判断的支持/反证/独立来源、覆盖与缺口、04/05 可用边界、阶段结果与归档索引。

`display_data_candidates` 与 `04_05_materials` 只标明后续制图/制表条件、展示成熟度与使用限制；候选必须来自本次证据归档，不得为图表补造数值。没有可制图数据不自动导致证据质量降级，只在目标报告类型通常需要相应素材且本次缺失时限制 `delivery_readiness`。是否放入正文、放在哪一章、如何服务论证，由 05 根据 04 已批准判断决定。字段见附录字段参考第 8 节。

执行顺序、补充/停止与反馈细则见操作手册第 10—11 节。原则是：先固定口径与证据要求 → 按核心判断取证与留痕 → 归一入库与质量评价 → 形成门槛表与双 readiness → 输出三份正式交付物。不得因时间耗尽或覆盖率表面达标而将 `stage_status` 标为 `complete`。

## 11. 与 04 推理阶段的接口

03 交给 04 的是写明使用边界的推理依据，不是简单材料堆砌。每个核心判断只交接最终 `evidence_grade`、机器可归一化的反证记录、关联路径的 `path_readiness_status`、范围限制和条件。04 校验器据此按规则一次计算结论强度上限与允许表达；03 和 04 均不得重复手工填写该上限。

必须明确：哪些核心问题允许方向性推理 / 只能条件判断 / 只能暂不可判断；哪些路径难以继续成立；反证与竞争解释状态；冲突、代理依赖及来源/口径/时间/权限限制；置信度上限与不得外推范围；目标 05 下哪些展示素材已具备、是否可用、限制是什么（不含章节、故事线、标题或投资要点建议）。04 必须逐观点继承，不得用整体阶段结果支持所有观点。

## 12. 质量门槛与返工规则

本节是 03 阶段质量要求和返工条件的唯一权威。全局质量定义和正式发布规则见 `../00_全局/00A_高质量产出判别标准.md`。运行核对清单见操作手册第 12 节，不替代本节。

### 12.1 阶段质量状态

| 状态 | 含义 | 处理 |
|---|---|---|
| `draft` | 证据准备尚未完成或未校验 | 不进入 04 |
| `minimum_pass` | 流程和文件完整，可供 04 草稿使用 | 可进入 04 草稿，但不得正式发布 |
| `high_quality_pass` | 通过规则校验 | 可作为正式 03 交付物交付 |
| `return_required` | 关键证据、口径、来源、权限、质量或“证据是否够用”问题未解决 | 返工 |
| `stop_with_gap_report` | 当前条件不足以支撑方向性推理 | 输出缺口说明 |

### 12.2 进入 04 草稿前的最低条件

达到以下条件，才可标记为 `minimum_pass`：

1. 02 入口校验通过；
2. 研究范围已经固定；
3. 已完成证据要求预设；
4. 数据需求按核心判断拆解；
5. 取证规则、推荐取证来源、SourceProfile 和取数方式已说明；
6. 本次证据归档文件完整；
7. 状态变量覆盖情况可复核；
8. `stage_status` 可解释；
9. 每个核心判断的最终 Q、反证依据和关联路径已给出。

### 12.3 高质量语义门槛

达到以下条件，才可标记为 `high_quality_pass`：

1. 证据准备围绕核心判断，而不是主题泛搜；
2. 每个核心判断已完成证据要求预设；
3. 核心结论证据门槛已单独判断；
4. 已调用合适的取证规则，而不是临时自由搜索；
5. 来源生产者、内容领域、获取通道、权限边界和材料形态已区分；
6. 来源直接性、独立性、可复核性、时效性、口径和权限均已评价；
7. 不同取数方式的留痕要求已满足；
8. 反证和竞争解释有实际检查；
9. 代理指标使用边界、失效条件和置信度折扣已说明；
10. 证据冲突有处理或降级；
11. `path_readiness_status=restricted` 的路径/核心判断已明确列出可用边界；
12. 结论强度上限仅为 J0/J1 的核心判断已明确说明为什么只能暂不可判断；
13. 各核心判断交给 04 的可用边界清楚、可执行；
14. 准备 Markdown 与本次证据归档 CSV 一致；
15. 已独立输出 `delivery_readiness`，明确目标报告类型下各素材维度的有无、可用性、限制与补齐路径；未预写章节、故事线、标题或投资要点；该结果未反向改变证据质量或本阶段 `high_quality_pass`。

### 12.4 不得进入 04 方向性推理的情况

出现以下任一情况，不得进入 04 方向性推理：

1. 未完成证据要求预设；
2. 核心判断证据门槛未满足；
3. 必需证据组合缺失；
4. 反证检查缺失；
5. 来源不可复核；
6. 来源不独立却被当作交叉验证；
7. 口径与 02 核心判断不匹配；
8. 时间窗口不匹配；
9. 动态变量缺业务时间；
10. 权限或合规边界不清；
11. 证据冲突未处理；
12. 代理指标越权使用；
13. 各核心判断与路径的可用边界没有明确列出；
14. 03 无法说明 04 最多能形成的结论。

### 12.5 返工去向

| 问题表现 | 处理 |
|---|---|
| 02 路径、核心判断或最低验证条件不清 | 退回 02 |
| 无法设定证据要求 | 退回 02 或重做 03 证据要求预设 |
| 证据需求拆解过宽 | 重做 03 需求拆解 |
| 取证规则选择错误 | 重选取证规则并重做必要证据组合 |
| 来源结构混乱 | 重新区分来源类型、内容领域、获取方式、访问范围和材料形态 |
| 来源不直接或不可复核 | 更换或补充来源 |
| 证据口径不匹配 | 重新取数或降级 |
| 获取方式留痕不足 | 补充查询参数、原始响应、字段血缘或内容指纹 |
| 缺少反证检查 | 补充反证检索 |
| 代理指标越权 | 降级或补充直接证据 |
| 覆盖率高但核心观点门槛不足 | 降级或补证据 |
| 可用边界不清 | 重写证据是否够用评价和 04 结论适用范围 |
| 本次证据归档与准备 Markdown 不一致 | 同步修正并重新校验 |

## 13. 一句话原则

03 的好坏不取决于材料数量，而取决于：

> 是否先为关键判断设定证据要求，再取得匹配口径、可追溯、可复核、经过反证检查的足够证据，并清楚告诉 04 只能判断到哪里。
