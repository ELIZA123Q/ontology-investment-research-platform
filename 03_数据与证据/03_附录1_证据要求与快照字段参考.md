## 1. 数据需求拆解维度

每项数据需求至少说明：

| 维度 | 说明 |
|---|---|
| 需求目的 | 用来支持、削弱、阻断或验证哪个判断节点 |
| 证据角色 | 事实确认、状态测量、趋势判断、机制验证、对象比较、财务测算、估值预期或反证 |
| 本体目标 | 对应对象、关系、事件、状态变量、观测、信号或证据 |
| 最低字段 | 身份、数值、单位、时间、范围、来源等不可缺字段 |
| 时间要求 | 业务时间、发布时间、数据频率、截面或时间序列要求 |
| 口径要求 | 产品规格、地域、币种、价格类型、产能类型等 |
| 覆盖要求 | 需要覆盖哪些对象、时间点、来源或反面证据条件 |
| 质量门槛 | 可用于后续推理所需满足的最低条件 |
| 来源结构 | 对应 SourceProfile、ContentDomain、AccessScope 和 ArtifactType |
| 获取方式 | 对应 AcquisitionChannel，如网页、数据库、API、MCP、文件、人工、内部系统 |
| 路径绑定 | 对应路径、节点或判断问题 |
| 反证绑定 | 对应削弱、阻断或竞争解释 |
| 05 展示用途 | 是否可能作为图表、表格、来源注释、强弱排序或改判信号的素材候选（只记用途标签，不规划 05 章节） |
| 优先级 | 关键、必要或补充 |

## 2. evidence_requirements 建议字段

`evidence_requirements.csv` 建议字段如下：

| 字段 | 说明 |
|---|---|
| `evidence_requirement_id` | 单项证据需求 ID。规范主键为 `ER-nn`（须继承 02）；反证可另用 `CER-nn`；`ER-JU-nn` 仅为按单元汇总的操作行，不能替代 `ER-nn` |
| `target_judgment_unit_id` | 对应 02 的核心判断单元 |
| `target_path_node_id` | 对应路径或节点 |
| `target_state_variable_id` | 对应状态变量 |
| `requirement_purpose` | 支持、削弱、阻断、验证、交叉验证或背景 |
| `evidence_role` | 主证据、交叉验证、反证、阻断、代理或背景 |
| `required_evidence_category` | 价格、需求、供给、库存、订单、政策、估值等 |
| `required_content_domains` | 财务、经营、产业、政策、市场价格等内容域 |
| `required_object_scope` | 公司、产品、地区、产业链环节等对象范围 |
| `required_time_scope` | 时间窗口 |
| `required_grain` | 日度、月度、季度、事件点、文本主张等粒度 |
| `minimum_quality_level` | 本判断最低需要的证据等级 |
| `minimum_source_tier` | 最低来源层级 |
| `minimum_independent_source_count` | 最少独立来源数 |
| `mandatory_baskets` | 必须满足的必要证据组合 ID |
| `counter_baskets` | 既有快照兼容字段；填写本次任务局部反证组，不引用全局稳定 ID |
| `allowed_proxy` | 是否允许代理指标 |
| `preferred_source_profiles` | 首选 SourceProfile ID；来源清单仅提供推荐优先来源 |
| `allowed_acquisition_channels` | 允许的取数方式 |
| `forbidden_sources` | 禁止来源 |
| `required_freshness` | 时效要求 |
| `required_traceability` | 可追溯要求 |
| `required_comparability` | 可比口径要求 |
| `stop_condition` | 什么情况下不得进入方向性推理 |
| `missing_policy` | 缺失时如何处理 |
| `evidence_grade_if_met` | 满足后应达到的最低最终 Q 等级 |
| `missing_action` | 不满足时应降级 Q、补证、阻断路径或退回的动作 |

## 4. 单项需求状态

单项需求状态建议使用：

| 状态 | 含义 |
|---|---|
| `met` | 满足最低证据要求 |
| `partial` | 有有效输入，但不足以完整支持 |
| `missing` | 未取得有效材料 |
| `conflicted` | 存在无法消解的证据冲突 |
| `blocked` | 关键来源、权限、口径或实例缺失，无法继续 |
| `not_applicable` | 经确认不适用于本次范围 |

## 5. 关键变量证据覆盖率计算

关键变量覆盖率用于检查 02 要求的变量—锚点单元是否完成证据链。计算必须说明：

1. 分母如何确定；
2. 哪些单元计入；
3. 哪些单元不计入；
4. 每个计入单元是否完成来源—主张—事实候选—关键变量绑定；
5. `partial` 是否计入，计入理由是什么；
6. 未计入单元的影响。

不得通过删除锚点、缩小范围或复用宽泛主张来提高覆盖率。覆盖率高不代表核心结论证据门槛已满足。

## 6. 证据包可信程度判断因素

证据包可信程度建议使用 `high`、`medium`、`low`。判断时应考虑：

1. 证据要求预设是否完整；
2. 关键来源质量；
3. 独立交叉验证程度；
4. 时间和口径匹配程度；
5. 反证检查程度；
6. 冲突处理情况；
7. 关键判断单元满足比例；
8. 代理指标依赖程度；
9. 对 04 结论强度的限制；
10. 对判断目标的任务适配程度。

可信程度不能高于关键核心问题证据门槛的实际满足程度；不得用单项 Evidence Reliability Score 的平均值替代。关键单元的最低门槛、反证和冲突具有一票降级作用。

## 7. delivery_readiness 字段与状态

正式结果写入 `04_05_materials/delivery_readiness.csv`，至少包含：

| 字段 | 含义 |
|---|---|
| `target_report_type` | 目标 05 报告类型，继承 01 `delivery_archetype.primary` |
| `status` | 总体交付准备度：`ready / partially_ready / not_ready` |
| `chart_readiness` | 图表维度：`ready / partial / missing / not_applicable` |
| `table_readiness` | 表格或排序表维度：`ready / partial / missing / not_applicable` |
| `source_annotation_readiness` | 来源注释维度：`ready / partial / missing / not_applicable` |
| `delivery_limit` | 素材层面的形态上限与必须保留的限制；不得写成章节、故事线、标题或投资要点 |
| `gap_action` | 若未就绪，应补齐素材、调整报告类型还是降级交付 |

`status` 判定按目标报告类型下该类素材是否必需、是否齐备，不使用统一图表数量门槛，也不预判 05 论证结构：

| 状态 | 含义 |
|---|---|
| `ready` | 已准入素材足以支撑目标报告类型；不适用的素材维度可为 `not_applicable` |
| `partially_ready` | 素材部分可用，05 须删减相应表达、保留限制或等待补齐 |
| `not_ready` | 无法稳定支撑目标报告类型，应补充素材、调整报告类型或停止交付 |

来源注释对引用了外部事实、数据、公告、文件或访谈的交付原则上必须 `ready`；图表和排序表只有在目标报告类型通常需要、且本次有相应展示需求时才构成门槛。`delivery_readiness` 只回答素材有无、可用性与限制；用不用、放在哪里、如何形成论证属于 05。

## 8. display_data_candidates 字段

`display_data_candidates.csv` 至少包含：

| 字段 | 说明 |
|---|---|
| `data_candidate_id` | 可展示数据候选 ID |
| `linked_judgment_unit_ids` | 绑定的核心判断单元 |
| `linked_input_ids` | 对应推理输入 |
| `linked_evidence_ids` | 对应证据记录 |
| `object` | 展示对象 |
| `indicator` | 指标名称 |
| `value_field` | 使用 `raw_value`、`normalized_value` 或文本事实字段 |
| `unit` | 单位 |
| `period` | 业务时间或统计期 |
| `grain` | 时间序列、横截面、事件、文本观测等粒度 |
| `source_ids` | 来源 ID |
| `quality_level` | 证据质量等级 |
| `data_status` | `ready / partial / missing` |
| `visual_role` | `quant_chart / ranking_table / event_timeline / supporting_table / qualitative_table` |
| `chart_readiness` | 制图成熟度：`ready / partial / missing` |
| `quantitative_or_qualitative` | 数据性质：`quantitative / qualitative / mixed` |
| `time_points_count` | 可用于时间序列或窗口比较的时间点数量；非时间序列可填对象数量或 0 |
| `comparison_baseline` | 可比较基准，例如前期、同业、强弱排序、基准情景等 |
| `ranking_support` | 是否支持对象强弱排序：`none / weak / medium / strong` |
| `report_grade_status` | 是否达到研报级展示标准：`report_grade_ready / usable_with_caveat / not_report_grade` |
| `gap_to_report_grade` | 未达到研报级展示时缺少什么 |
| `usage_limit` | 可展示但不可外推的限制 |
| `caveat` | 数据缺口、口径差异或解释注意事项 |

可展示数据候选必须来自本次证据快照，不得为图表补造新数值。若没有可展示数据，应生成空表头，并在准备文档中说明原因。

## 9. 快照文件职责

快照目录按四层组织（`01_plan` / `02_assets` / `03_gate` / `04_05_materials`）。完整目录树以运行校验 README 与 `snapshot_layout_03.py` 为准。职责概要：

1. `manifest.csv` 保存总索引、`stage_status`、`quality_status` 和版本；
2. `01_plan` 保存 02 已固定的证据要求在本次运行中的执行计划；
3. `source_documents`、`evidence_claims`、`evidence_facts`、`evidence_relations` 和 `evidence_assessments` 构成规范化证据域实例；
4. `semantic_instances` 和 `semantic_relations` 保存本次确认的语义域实例；
5. `reasoning_inputs` 只保存有证据支撑并已固定的 Observation、Event 等推理输入；
6. `evidence_readiness_assessments` 保存判断单元最终 `evidence_grade`、反证归一化依据、关联路径和范围限制；
7. `04_05_materials` 保存可供 04 判断定稿核对、并由 05 组织进入最终研究稿的图表、表格与来源注释素材；
8. `evidence_records.csv` 汇总原子证据的任务级使用属性；来源、主张和事实必须回溯到规范化证据链。

每个快照文件应职责单一。摘要用于人读，CSV 用于机器校验；同一信息同时出现时口径必须一致。
