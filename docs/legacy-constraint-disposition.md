# 旧约束处置矩阵

本矩阵是从固定 01—05 运行链迁入动态执行引擎的删除前检查表。最终运行不读取旧阶段文件；下列约束必须先由新权威承接。

| 旧约束族 | 新权威 | 处置 |
|---|---|---|
| 对象类型、关系端点、基数、枚举、身份与有效期 | 语义本体 + OWL/SHACL/SKOS 编译器 | 迁为语义约束 |
| 来源定位、主张原子性、事实来源独立性、冲突保留 | `研究规则/rules.yaml` | 迁为可执行 Rule |
| 证据篮子、反证、准入与判断等级上限 | `研究规则/rules.yaml` | 迁为可执行 Rule |
| 研究拆解、取证、事实合成、推理、表达 | `研究能力/capabilities.yaml`、`研究能力/logics.yaml` | 迁为 Capability/Logic |
| 报告结构和表达边界 | `研究能力/报告模板/` | 迁为输出模板 |
| 任务、证据、判断、审批、执行状态与审计 | `研究运行合同/dynamic_execution.yaml` 及 RDF 运行图 | 迁为运行对象 |
| 固定阶段序号、阶段文件名、阶段版本影响表和退回阶段 | 无 | 删除；由 DAG 依赖和规则结果替代 |
| `task_ontology_view`、`ontology_dependency_projection` | `ExecutionPlan`、`ExecutionEdge` 与 provenance | 删除 |
| 旧 YAML/CSV 双权威及兼容展开 | 无 | 删除；样例迁为可装载 TriG |
| 旧本体目录中的重复说明和 deprecated stub | 无 | 删除；Git 历史承担追溯 |

## 必须保留的质量不变量

1. 正式事实必须可回到 SourceDocument、EvidenceClaim 和原文位置。
2. 同源转述不得计为独立来源；冲突不得静默覆盖。
3. 正式判断必须经过证据准入、规则评价和判断等级上限检查。
4. 证据不足只能补证、降级或停止，不能通过表达升级结论。
5. 动态计划只能调用已登记能力，写入范围必须显式授权。
6. 正式发布必须存在人工 ApprovalRecord。
7. 所有计划修订、执行尝试、规则评价和审批均追加写入并可追溯。
