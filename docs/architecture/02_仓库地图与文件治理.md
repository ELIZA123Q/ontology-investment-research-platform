# 仓库地图与文件治理

## 唯一运行入口

`06_runtime/` 是唯一可执行工程。仓库中不得再出现 `vnext/`、旧 Runtime 镜像或编号兼容目录。

## 目录地图

| 目录 | 内容 | 是否可执行实现 |
|---|---|---|
| `01_semantic_knowledge/` | 本体、词典、证据语义、图合同 | 仅校验/adapter 合同 |
| `02_scenario_task/` | 场景、任务定义、角色、可选模板 | planner 在 Runtime |
| `03_agent_capability/` | 治理索引、方法资源、MCP/A2A | manifest 在 Runtime |
| `04_context_state/` | Context / State / Memory / Workspace 合同 | 实现在 `06_runtime/src/runtime` |
| `05_control_evaluation/04_verifiers/fixtures/reference_runs/research_runs/` | 历史示范案例（非 Workspace） | 否 |
| `05_control_evaluation/` | 架构、规则、权限、Verifier、Eval | Runtime Verifier 在 `06_runtime/src/governance` |
| `06_runtime/` | Next App、API、Kernel、Store、Worker、Tests、产品路由与可信组件登记 | 是 |

## 文件规则

1. 先查 `five_domain_authority.yaml` 与域 registry。
2. 程序性研究知识写入 5 个 Skill 对应的方法资源；Runtime 动作不写成 Skill。
3. 单次研究正文写 Artifact/Workspace，不写回本体或方法库。
4. 历史样例与 eval 可以保留旧字段用于回放，但不得成为 Runtime import。
5. 任何新路径必须通过 `npm run audit:cutover`。
