# 公开发布前检查

这是首次公开开源前的人工签核清单。项目原创代码、配置和文档使用 [Apache-2.0](../LICENSE)；该授权不能替第三方数据、报告、商标或他人贡献授予权利。此文档是发布流程提示，不构成法律意见。

## 1. 内容范围

- 核对[目录导览](repository-layout.md)与实际仓库一致；保留 `examples/` 作为稳定样例，`research_outputs/` 作为带日期的历史运行，勿把后者写成当前建议。
- 逐项复核 `research_outputs/*/runtime/` 下的 Oxigraph、SQLite、日志、锁文件。它们是本地运行状态，文本扫描看不到全部内容；确认是否确有公开复现价值，并检查路径、审计标识、来源记录与个人信息后再决定是否发布。不要直接删除或移动已有运行权威图。
- 复核研究输出中的审批者标识、内部路径、对话记录、市场数据许可和原始研报摘录。公开版本必要时使用经核对的脱敏副本，同时保留私有原件。
- `outputs/` 只放有清楚来源、信息截面与审批状态的新交付；缓存和临时文件留在仓库外。

## 2. 授权与来源

- 确认项目所有原创文件的权利归属允许以 Apache-2.0 发布；对来源不明的代码或文档单独求证。
- 保留 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) 和依赖原有许可；Apache-2.0 不改变 Semantica 等依赖的许可。
- 核查报告引用、行情、数据库字段和分析师视角卡的再分发权限。链接与必要短摘要通常比复制完整原文更适合公开仓库，但具体材料仍须逐项核对。
- 不在公开文档中宣称历史研究可用于实时交易，或把候选判断写成人工已批准的正式结论。

## 3. 安全与可复现

- 对当前文件和完整 Git 历史进行密钥、令牌、邮箱、绝对本机路径扫描；当前文件扫描无法覆盖历史提交及二进制文件。
- 在干净目录从公开仓库重新克隆，按[根目录 README](../README.md)运行 `uv sync --frozen`、`pytest`、`ir-platform validate` 和样例装载；检查没有隐含的私有服务或付费数据源硬依赖。
- 核对 `.gitignore`、CI 和 `uv.lock`；公开仓库不要包含真实 API 密钥或机器生成的临时凭据。
- 发布前明确记录最后一次人工审查者、日期和允许公开的文件范围；本仓库不会自动执行公开推送。
