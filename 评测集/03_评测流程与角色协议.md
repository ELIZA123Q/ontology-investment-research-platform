# 03 评测流程与角色协议

## 1. 流程概览

正式运行分为准备、评测器校准、可靠性评测、下游任务实验、相对基线盲评、聚合与报告六个阶段。校准是硬门槛，不是最后附加的一项分数。

## 2. 准备阶段

`prepare` 完成以下工作：

- 校验案例、证据、密封隔离和扰动契约；
- 冻结系统产物哈希与案例哈希；
- 生成 A—E 五组上下文；
- 删除候选中的文件名、流程来源、质量状态、置信标签和内部发布标签；
- 将候选一级标题统一为“候选研究产物”；
- 生成十类确定性缺陷变体；
- 写入运行 manifest 和请求计划。

盲评不截断报告正文。直接生成稿和证据摘要稿以系统产物长度为目标，必须落在系统稿字符数的 ±15% 区间。

## 3. 评测器校准与 C 门

### 3.1 十类确定性缺陷

| 类别 | 主要影响 |
|---|---|
| 核心事实错误 | R |
| 范围外推 | R |
| 结论强度升级 | R |
| 删除关键反证 | R |
| 因果跳跃 | R |
| 删除研究机制和行动信息 | U |
| 无关冗长 | U |
| 无证据新观点 | R |
| 过度保守 | U |
| 推理到表达失真 | R |

每个缺陷预先固定：基础案例、替换或追加操作、注入位置、严重程度、影响维度及“正常版应排在缺陷版之前”的关系。

### 3.2 正常版错杀

除缺陷变体外，两个评测模型还要重复检查正常版本。没有严重缺陷时仍判失败，计入正常版错杀率。

### 3.3 扰动敏感性

四类扰动检查评测器是否对证据变化敏感。关键证据删除后仍保持原强度，或注入决定性反证后不更新，均计为敏感性失败。

### 3.4 发布门

两个评测模型分别计算 `C`，再计算整体 `C`：

- 任一模型低于 `C2`：不进入正式裁决集；
- 整体低于 `C2`：停止运行，不发布代理可靠概率或系统通过结论；
- 全部至少 `C2`：继续 R/U/delta。

## 4. R：核心判断多角色对抗评测

### 4.1 双提取器

两个独立评测模型只阅读盲化产物，各自提取 3—7 条决定研究价值的核心判断。提取器不得看冻结证据和密封裁决，以免按预期答案改写报告内容。

### 4.2 归并协调器

协调器合并两份提取结果，保留分歧，并将报告中实际存在的判断映射到密封判断单元、最低证据组合与强度上限。

协调器：

- 不评分；
- 不补充报告中不存在的判断；
- 不为了覆盖密封契约而创造新观点；
- 必须标明未被报告覆盖的密封单元。

### 4.3 三个独立审阅角色

| 角色 | 只判断什么 | 关键输出 |
|---|---|---|
| 证据审阅器 | 事实、独立来源、时间对象、最低证据组合、预测事实混淆 | 支持程度、证据 ID、最大限制、严重度 |
| 推理审阅器 | 跳步、相关到因果、范围外推、强度上限、改判条件 | 路径完整性、具体位置、越级类型 |
| 对抗审阅器 | 最强反证、竞争解释、单点依赖、删除证据后的脆弱性 | 最可能推翻判断的新事实 |

三个角色对同一判断互不替代。证据充分不能抵消推理跳跃，对抗发现也不能自行给总体等级。

### 4.4 裁决器

裁决器只能读取三份审阅记录和判断标识，不能读取原始报告或原始证据，也不能加入新论证。

裁决器输出：

- `R0—R3`；
- `hard_failures`；
- 最弱判断；
- 最强反证；
- 主要分歧；
- 是否严格只使用三份审阅记录。

同一角色由两个评测模型各运行三次，共六次案例裁决。

## 5. U：下游任务实验

### 5.1 五组上下文

| 组别 | 下游模型获得的内容 | 用途 |
|---|---|---|
| A | 原始问题 | 无材料基线 |
| B | 问题与冻结证据 | 原始材料能力 |
| C | 问题与直接生成报告 | 普通生成基线 |
| D | 问题与系统最终允许产物 | 系统核心实验组 |
| E | 问题、系统产物与关键证据 | 诊断信息上限 |

### 5.2 四项任务

1. 核心判断复述：阶段、对象分化、依据和暂不可判断事项；
2. 跟踪计划：五项指标，每项含对象、来源、频率、支持/削弱/推翻含义和优先级；
3. 新信息更新：注入密封场景，要求保持、削弱、改判、重开问题或继续弃答；
4. 调研问题：分别面向公司、客户和专家，注明待验证假设、竞争解释和答案影响。

### 5.3 执行与评分分离

两个下游模型只执行任务，不提供有效自评分。其输出由独立评测模型根据冻结证据、密封判断、必需信息单元和更新场景评分。

评测模型与下游执行模型的 `model_id` 必须不同；配置重合时正式校验失败。

## 6. delta：相对基线盲评

系统产物 D 分别与以下候选成对比较：

- C：只根据问题生成的直接报告；
- B 的衍生基线：同一冻结证据条件下生成的普通证据摘要。

每次比较只出现两份匿名候选。候选顺序六次中各有三次 D 在前、三次 D 在后。评测器可判平局，平局按 0.5 胜计入胜率。

比较维度包括：

- 判断可靠性；
- 研究增量；
- 后续跟踪支持；
- 不确定性表达；
- 误导风险；
- 作为下一轮研究输入的价值。

评测器必须引用具体位置，不接受“逻辑严谨、研究价值高”等空泛理由。

## 7. 模型、提示和重复运行规则

正式运行要求：

- 一个生产模型档案；
- 两个不同 `model_id` 的评测模型档案；
- 两个不同 `model_id` 的下游执行模型档案；
- 生产模型不得兼任评测模型；
- 下游执行模型不得为自己的输出评分；
- 每个正式评测角色由两个模型各运行三次；
- 使用种子 11、22、33；
- A/B 两套等价提示表述在两个模型之间平衡为三次对三次；
- 成对候选顺序三次 D 在前、三次 D 在后。

优先选择不同模型家族的两个评测器；同一家族即使 `model_id` 不同，也应在正式报告中声明相关性风险。

## 8. 盲化纪律

候选和推理材料不得暴露：

- 文件名和流程来源；
- `high_quality_pass`、`PUBLISHABLE` 等内部结论；
- 置信标签、发布标签和阶段自评；
- 哪份候选来自复杂流程；
- 哪份是正常版或缺陷版，校准协议明确要求的排序标签除外。

正文中无法安全删除的内部标签会导致准备失败，不允许静默带入正式评测。

## 9. 聚合与报告

六次裁决和下游评分完成后：

1. 聚合 R、U、delta；
2. 依据跨模型、提示和顺序差异计算 S；
3. 附上先行得到的 C；
4. 分别汇总 `report_value` 与 `restraint`；
5. 生成 YAML、JSON 和 Markdown；
6. 报告最弱判断、最强反证、主要分歧、硬错误和适用边界。

任何执行错误、缺失裁决或无效结构化结果都不得被静默跳过。完整聚合只接受状态为 `completed` 的运行。
