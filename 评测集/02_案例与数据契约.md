# 02 案例与数据契约

## 1. 契约目的

一个案例只有在评测前冻结问题、证据、裁决边界、系统产物和实验配置，才具备可重复性。案例契约用于避免三种污染：

- 生产者提前看到预期答案；
- 评测器在运行时临时搜索有利材料；
- 结果不理想后修改阈值、截止日或最低证据组合。

每个案例目录至少包含：

```text
cases/RV-Txx/
├── case.yaml
├── evidence.yaml
├── perturbations.yaml
├── system_artifact.md            # 案例自带产物时使用
└── sealed/
    └── adjudication.yaml
```

T01/T02 的系统产物来自仓库完整示例；T07/T08 的争议或暂不可判断产物直接保存在案例目录。

## 2. 公开任务输入

`case.yaml.task_input` 是生产前可见的任务边界，必须包含：

| 字段 | 含义 |
|---|---|
| `question` | 原始研究问题 |
| `object` | 研究对象 |
| `scope` | 时间、地域、产业链及明确排除项 |
| `information_cutoff` | 允许使用信息的最晚日期 |
| `terminal_artifact_type` | 报告、判断简报或其他允许终点 |

公开输入不得出现：

- 预期 `R/U` 等级；
- 预期终点是“争议”还是“暂不可判断”；
- 密封核心判断原文；
- 最低证据组合；
- 禁止表达和缺陷注入位置；
- 系统产物路径或内部质量标签。

## 3. 冻结证据包

`evidence.yaml` 是事实核验的唯一证据边界。每条证据至少包含：

| 字段 | 说明 |
|---|---|
| `evidence_id` | 案例内唯一标识 |
| `publisher`、`title`、`source_url` | 来源身份与原始地址 |
| `published_at` | 发布时间，用于截止日过滤 |
| `business_time` | 数据或事实对应的业务时间 |
| `independence_group` | 同源识别组，防止把同一披露算作多源交叉验证 |
| `source_type` | 公司披露、监管文件、行业调查、价格数据等 |
| `statement_nature` | 已报告事实、预测、计划、观察或解释 |
| `locator` | 页码、章节、表格或段落定位 |
| `excerpt` | 可离线复核的短摘录或表格单元 |
| `content_hash` | 对摘录内容计算的 SHA-256 哈希 |
| `supports` | 该证据允许支持的判断范围 |
| `limits` | 不得越过的对象、时间和口径边界 |

### 3.1 证据有效性规则

- `published_at` 晚于 `information_cutoff` 时案例校验失败；
- 摘录哈希不一致时校验失败；
- 没有定位、摘录或来源地址时校验失败；
- 同一 `independence_group` 不能被解释为多个独立来源；
- 预测、计划和公司自述不得自动升级为行业已实现事实；
- 正式运行只使用冻结内容，不在评测过程中临时联网补证。

旧证据快照中仅有结构记录、且标记 `raw_content_included: false` 的 `source_captures` 不能代替本证据包。

## 4. 系统产物与推理材料

`system_artifact` 指向待评的最终允许产物。`stage` 可以是完整报告，也可以是正确停止的判断简报。

`reasoning_materials` 只供推理审阅器使用，可以包含研究逻辑、判断简报和推理审计。运行时会：

- 删除文件名和内部来源路径；
- 删除质量状态、置信标签、发布状态和阶段自评；
- 将结构化审计材料中的内部流程字段递归移除；
- 保留实际推理内容、判断路径和改判条件。

系统产物在打开密封裁决契约前必须已经冻结并计算哈希。

## 5. 密封裁决契约

`sealed/adjudication.yaml` 只在产物冻结后开放。它不是标准答案报告，而是裁决边界，必须声明 `not_a_reference_report: true`。

### 5.1 核心判断单元

每个案例准备 3—7 条 `core_claims`：

| 字段 | 含义 |
|---|---|
| `claim_id` | 密封判断标识 |
| `statement` | 需要被覆盖或正确限制的研究判断 |
| `criticality` | `primary`、`supporting` 或 `boundary` |
| `strength_ceiling` | 当前证据允许的最高强度 |
| `minimum_evidence_basket` | 该判断最低需要的冻结证据组合 |

`primary` 判断用于案例级 `R` 的最低等级聚合；`boundary` 用于检查窗口、预测和弃答边界。

### 5.2 其他密封字段

- `allowed_disagreements`：允许研究者合理分歧的空间；
- `strongest_counterevidence`：必须实际处理的最强反证；
- `prohibited_expressions`：会构成越级或误导的表达；
- `update_scenarios`：新增信息、预期动作和受影响判断；
- `downstream_required_units`：复述、跟踪和调研任务必须覆盖的关键单元。

## 6. 隔离规则

| 角色 | 可以读取 | 不得读取 |
|---|---|---|
| 系统生产者 | `task_input`、规定证据材料 | 系统产物答案、推理材料、密封裁决、缺陷目录 |
| 基线生产者 | 对应 A/B 条件 | 系统流程、密封裁决、质量标签 |
| 核心判断提取器 | 盲化系统产物 | 冻结证据、密封裁决、报告来源 |
| 归并协调器 | 两份提取结果、盲化产物、密封判断单元 | 评分权和新增论证权 |
| 证据审阅器 | 判断、冻结证据、最低证据组合 | 生产者自评和包外事实 |
| 推理审阅器 | 判断、盲化推理材料、强度上限 | 质量标签和包外论证 |
| 对抗审阅器 | 判断与冻结证据 | 总体评分权 |
| 裁决器 | 三份审阅记录 | 原始报告、原始证据、重新论证 |
| 下游执行模型 | A—E 对应上下文 | 密封评分单元 |
| 下游评分模型 | 任务输出、冻结证据、密封单元 | 执行模型自评分 |

校验器要求生产者可见字段恰好为 `task_input` 与 `evidence.yaml`，并显式禁止系统产物、推理材料、密封裁决和缺陷目录。

## 7. 扰动契约

每个案例至少准备四类扰动：

1. 删除关键证据；
2. 替换公司、产品、指标或时间口径；
3. 注入最强反证或竞争解释；
4. 调整判断时点并过滤截止日后的证据。

每项扰动必须预先保存 `expected_action`，例如维持、降级、加强、转为争议或弃答。运行后直接比较评测器动作与预期方向，不接受评测器事后自行解释标准答案。

## 9. 新增案例准入条件

新增案例必须同时满足：

- 公开任务输入不泄漏预期结论；
- 至少三条可离线复核的冻结证据；
- 全部证据通过截止日和哈希校验；
- 3—7 条密封核心判断及最低证据组合；
- 至少一个最强反证和两个更新场景；
- 四类扰动齐全；
- 系统产物已经冻结；
- 明确属于 `report_value`、`restraint` 或未来新增的独立分层；
- 先通过缺陷校准，再进入正式结果统计。

仅有任务标题、静态答案轮廓或旧评分，不构成可运行案例。
