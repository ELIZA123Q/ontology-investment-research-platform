# 研究质量评测集

本目录是**研究质量评测集**，不是软件测试平台。

它判断：

> 一次输出是否达到可信、克制、研究员可使用的最低质量要求；不同版本之间可通过多次评分表结果进行比较。

规则校验（`validate_*`）仍是输出结构检查；本评测集评价问题是否保持、证据是否支撑、推理是否成立、反证是否处理、强度是否克制、交付是否可用。

**终点命中 ≠ 研究质量通过。** 命中预期终点只说明方向没有明显走错。

## 3. 任务卡用法

| 区块 | 给谁 | 何时用 |
|---|---|---|
| `任务输入` | 执行方 | **只**在运行前提供 |
| `evaluation_scope` | 执行方与评测方 | 预先固定评到哪一阶段、缺什么产物可扣分 |
| `评审参考` | 评测人 | 跑完后再打开 |

`任务输入` 只保留：用户问题、对象/时间/范围、信息截止日、可用信息边界、通用研究约束。  
**不得**写入预期终点、本体缺口预判、“应争议/应阻断/应暂不可判断”等答案提示。

`评审参考` 至少含：

1. 预期判断状态与核心判断轮廓  
2. **最低证据锚点**（必须确认 / 可接受代理 / 必须声明缺口）  
3. **关键反证**（未处理则不得直接通过）  
4. **结论边界**（可接受终点 + 禁止表达）

任务状态：

- `active`：信息截止日已到，可正式评测（`evaluation_status=scored`）
- `planned`：截止日未到；记 `evaluation_status=not_yet_eligible`，`overall=null`，指标「不适用」

## 4. 正确终点

评测看是否走到与证据和本体条件匹配的正确终点，而不是统一要求生成 05 或 `PUBLISHABLE`。

争议、阻断、暂不可判断、削弱、01 退回都可以是**正确终点**；是否“通过”仍取决于证据、反证、强度与 `evaluation_scope` 内交付。

---

## 5. 六项核心评价 + 运行记录

核心：问题保持、证据支撑、推理成立、反证处理、判断强度、交付可用性。  

等级：`通过` / `轻微问题` / `明显问题` / `失败`（未启用任务用 `不适用`）。

总体结果：`通过` / `修改后通过` / `不通过`（未启用为 `null`）。

简要规则：

- **通过**：核心结论、证据链、反证、强度均无实质缺口；仅有文字或排版问题。  
- **修改后通过**：终点基本正确，但缺关键引用、scope 内必需产物、样本边界或一类重要反证。  
- **不通过**：终点错误、证据不支撑、强度越权、忽略决定性反证、截止日穿越、应停止却继续。

评分说明须任务特定；正式评测至少点明一项关键反证及其裁决。详见 `02_指标定义.yaml`。

独立审阅：`independence_status=independent` 才可作为正式评测结论；`self_check` 仅作内部基线。

## 6. 评测建议

回归优先：

1. `EVAL-T01` / `EVAL-T02`（锚定，单独统计）  
2. `EVAL-T08`、`EVAL-T11`、`EVAL-T16`（停止类）  
3. `EVAL-T07` / `EVAL-T14`（冲突）  
4. 其余常规能力题  

`EVAL-T05`、`EVAL-T12` 到达 `available_after` 后再启用。

评分写入 `04_评测结果/`。报告通过率时须区分：锚定基线 / 高区分度 / 常规能力；并标明是否独立审阅。
