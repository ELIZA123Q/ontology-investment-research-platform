# 研究价值评测报告：示例1 两版对比

**评测对象：** 存储芯片分产品周期判断（RV-T01）  
**产物 A：** `示例1-基线-20260713-1/05-存储芯片周期行业周期判断-20260713-1.md`（2026-07-13）  
**产物 B：** `示例1-重跑-20260715-1/05-存储芯片周期行业周期判断-20260715-1.md`（2026-07-15）  
**评测方式：** 按评测集密封裁决契约做双评测员独立审阅后归并（pilot_manual）；非正式「双模型 × 三种子」全量跑分。  
**冻结证据边界：** RV-T01 证据包 T01-E01—E06，信息截止日 2026-07-13。

## 一句话结论

| 版本 | 能不能当研究输入用 | 可靠性 | 有用性 |
|---|---|---|---|
| **7/13** | **可以，带着边界用** | **R2** | **U2** |

---

## 研究问题（评测在评什么）

截至给定时点，全球存储芯片中 **HBM、非 HBM DRAM、NAND** 分别处于什么供需与价格周期阶段？未来 6—24 个月哪些信号支持延续或转向？  
不做个股评级或交易建议。

评测只问三件事：

1. **判断站不站得住（R）**：核心判断有没有被冻结证据撑住，有没有越级或硬错误。  
2. **下游能不能接着用（U）**：别人能不能据此复述、跟踪、更新、设计调研问题。  
3. **相对「同证据直接写一篇」有没有增益（delta）**：本次为试点人工裁决，未跑完整盲评基线；文末只给方向性比较。

---

## 两版各自在说什么

**7/13：** 行业仍处「稀缺定价强化期」。价格仍在大幅上涨，三类产品不能合并，但共同处于供给约束；2027H2—2028 是供给验证窗口，不是结束日；最早风险来自消费端需求破坏。

**7/15：** 改成「供给短缺下的高位消化期」。价格仍涨，但服务器 DRAM 3Q26 涨幅预计显著放缓；部分美国 CSP 库存累积是早期削弱信号，成因含 CPU 短缺与预防性备货，尚不足以确认见顶。分产品与验证窗口表述大体沿用 7/13。

---

## 1. 判断站不站得住（可靠性 R）

### 7/13：R2 — 方向成立，证据仍有缺口

| 密封核心判断 | 是否覆盖 | 强度 | 评测意见 |
|---|---|---|---|
| 价格仍强化，但 DRAM/NAND 口径必须分开 | 是 | 可达 R3 | Micron 实现价与 TrendForce 2Q26 合约价均在冻结包内，且明确不混口径 |
| HBM / 通用 DRAM / NAND 不能并成同一周期位置 | 是 | R2 | 分产品阶段清楚 |
| HBM/服务器资源对通用品是方向性供给约束 | 是 | R2 | 未假装已精确量化挤出 |
| 企业级 NAND 强 ≠ 全 NAND 繁荣 | 是 | R2 | 方向对；消费端反证未直接钉死包内笔记本下修证据（T01-E05），略弱 |
| 2027H2 是验证窗口，不是统一结束日 | 是 | R2 | 合规，未写成确定见顶日 |

- **硬错误：** 无  
- **禁止表达：** 未触碰（未写统一结束月、未把 Micron 价当成全行业价、未确认无条件超周期）  
- **最弱环节：** 消费端反证与「HBM 挤出」仍偏方向性  
- **必须盯住的反证：** 消费端需求破坏可能早于供给释放；客户预防性备货可能放大价格/订单信号  

**对研究员意味着什么：** 可以把 7/13 当作「分产品、高位稀缺、结束日不可确认」的工作底稿；不要把它升级成「已确认超周期」或精确挤出比例。

### 7/15：正式 R0 — 主结论改写在冻结包内站不住

正式评测只认冻结证据包。7/15 标题与投资要点第一条（「高位消化 / 不再支持继续强化」）主要靠 **TrendForce 2026-07-09**（3Q26 服务器 DRAM +13—18%、CSP 库存）。该文**不在** RV-T01 冻结包内。

| 密封核心判断 | 冻结包内 | 说明 |
|---|---|---|
| 价格强化且口径分开（C1） | **失败** | 包内最新价格证据仍是强涨；无法支撑「高位消化」这一主标签 |
| 分产品 / 挤出 / NAND 分化 / 验证窗口（C2—C5） | 仍成立 | 与 7/13 基本同构，约 R2 |

- **硬错误（正式轨道）：** 主结论依赖冻结包外证据 → 按契约视为「无来源核心判断」  
- **不是时间穿越：** 该源发布于 7/9，早于截止日 7/13；问题是**包未更新**，不是用了截止日后材料  
- **两评测员分歧：** 一人判 R1（证据不足），一人判 R0（硬错误）；按保守规则取 **R0**

### 7/15 补证后的诊断分：R2（仅供理解，非正式）

若把 TrendForce 2026-07-09 补进冻结包，两评测员一致认为可回到约 **R2**：

- 价格未转负 + 斜率放缓 + 局部库存，写成「高位消化」是合理改挡；  
- 文中区分了 CPU 错配 / 预防性备货 vs 真实需求见顶，没有写成已确认见顶；  
- 仍难到 R3：关键更新偏单一行业预测源，缺跨厂交叉验证。

**对研究员意味着什么：** 7/15 的研究直觉可能更贴边际，但**在现有评测契约下不能直接过关**。要用 7/15，先冻证据、再评一次。

## 2. 下游能不能接着用（有用性 U）

两版正式归并为 **U2**（一评测员给到 U3，取保守侧）。

| 下游任务 | 7/13 | 7/15 | 说明 |
|---|---|---|---|
| 核心判断复述 | 强 | 强 | 分产品、依据、结束日不可确认都写得清楚 |
| 跟踪计划 | 强 | **更强** | 7/15 把库存基线写成「部分 CSP 已累积」，触发条件更可执行 |
| 新信息更新 | 够用 | **更强** | 对「库存上升但成因复杂」已有改判钩子，贴近密封场景 T01-U1 |
| 调研问题线索 | 偏弱 | 略好 | 有观察表，但面向公司/客户/专家的可追问清单仍不够显式 |

**对研究员意味着什么：** 两版都能当跟踪底稿；若你更关心「下一季怎么改判」，7/15 的钩子更好——但前提是证据包先对齐。

## 3. 相对谁更好（delta，方向性）

本次未跑「同证据直接生成报告」的完整盲评，不能报正式胜率。方向性结论：

- **在旧冻结包内：** 7/13 胜（主结论与证据对齐）。  
- **若证据更新到含 7/9 TrendForce：** 7/15 在「阶段命名是否跟上斜率与库存」上更有增量；分产品与边界纪律与 7/13 相当。  
- **不要**用「7/15 更新了所以一定更好」替代证据对齐检查。

## 4. 研究员接下来建议做什么

1. **若继续用 7/13：** 可作为当前工作底稿；季度跟踪优先看价格转弱、三层库存、长约执行、HBM 认证、新增合格供给。

3. **两版都要补的短板：** 消费端反证尽量回指包内 T01-E05（或等价独立源），减少「只用包外移动 DRAM 文章」的依赖。  
4. **正式发布级数字：** 需配置真实生产/双评测/双下游模型，跑 `prepare → run → aggregate → report`；本次报告是试点人工裁决，不能当系统研究可靠率。

## 使用限制

- R、U 分项给出，不合成单一总分。  
- 「裁决支持频率 / 通过比例」不是该结论在现实中正确的概率。  
- 评测只判断冻结证据边界内是否站得住，不替代研究员对市场真实性的独立复核。  
- 当前密封契约为 `pilot_manual`，测的是「产物相对既定裁决边界是否一致」，不是外部真值标签。
