# 03-证据域规范

## 研究员先看什么

证据域回答：**依据是什么、本次能否用**——来源、主张、归一事实与使用评价；保留冲突、替代、失效。

研究时用它：区分「来源说了什么」与「可当作事实的什么」；评价单项证据能不能用；评价某个核心判断整体够不够进入推理。

本域**不生成方向性判断**。单项能否用 → 证据评价；核心判断整体能否进推理 → 「证据是否够用」评价。

> 机器权威：[`evidence.yaml`](evidence.yaml)。下文是概念速查；完整字段与端点以 YAML 为准。正文禁用「证据篮子」「取证配方」等词替代研究语言；系统名仅在下表与 YAML。

## 1. 概念速查

| 中文 | 系统名 | 作用 |
|---|---|---|
| 证据要求 | `EvidenceRequirement` | 本次必须取得什么证据 |
| 来源文档 | `SourceDocument` | 实际取得的原始材料载体 |
| 来源说法 | `EvidenceClaim` | 从来源提取的最小可定位说法 |
| 归一事实 | `EvidenceFact` | 由主张归一得到的结构化事实候选 |
| 来源画像 / 取数通道 | `SourceProfile` / `AcquisitionChannel` | 来源类型与获取方式 |
| 代理指标 | `ProxyIndicator` | 直接证据不可得时的代理及折扣 |
| 单项可用性评价 | `EvidenceAssessment` | 某条材料在本次判断中能否用 |
| 证据是否够用 | `EvidenceReadinessAssessment` | 核心判断整体能否进入推理 |
| 可复用证据类别 | `EvidenceProfile` | 证据类别、来源优先级与缺失降级策略 |
| 必要证据组合（计划/满足） | `EvidenceBasketRequirement` / `EvidenceBasket` | 计划门槛与本次满足状态（系统名；正文称「必要证据组合」） |
| 取证方法引用 | `EvidenceRecipe` | 可复用取证策略在本体中的稳定引用（系统名；正文称「取证方法」） |

常见关系：主张引用来源、事实由主张支撑、证据支撑推理输入。完整端点见 YAML。

## 2. 与语义域、推理域的交界

| 内容 | 放哪 |
|---|---|
| 稳定对象身份 | 语义域 |
| 来源、主张、事实、够不够用 | 证据域 |
| 判断、路径结果、结论强度 | 推理域 |
