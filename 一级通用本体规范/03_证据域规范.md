# 03-证据域规范

## 1. 域定位与边界

证据域把材料中的内容转化为可定位、可复核、可比较的依据。它区分“材料声称什么”和“当前证据可以归并出什么事实候选”。

证据域不保存材料全文，不直接生成 Judgment 或 AssetImpact，不修改语义对象，也不在冲突未解决时静默选择一方。

本域新增一层“判断单元到证据准入”的规划结构，用于承接 02 到 03 的证据准备接口：

```text
关键判断 → 证据需求 → 最低证据组合 → 必要证据完成情况 → 来源类型 / 获取方式
→ 具体来源 → 证据主张 → 证据事实 → 准入评估 → 04 最多能形成的结论
```

其中，指向 02 判断单元、路径节点和状态变量的内容以稳定 ID 字段保存，不在证据域中反向依赖推理域对象。

## 2. 字段设置原则

证据字段必须回答四个问题：

- 来源在哪里。
- 材料具体说了什么。
- 说法属于事实、数据、估算、预测、指引、判断还是假设。
- 该内容在当前业务时间是否仍可使用。

证据字段天然需要更多追溯信息，但仍只保留来源定位、主张分类、业务时间、可信度和生命周期所需内容。解析器版本、任务状态等纯运行信息不进入证据核心对象。单次运行中的具体查询日志、失败重试和文件索引继续保存在 03 快照；正式本体保存稳定的证据结构、规则、关系和词表。

## 3. 对象（Object）

### 3.1 来源文档（`SourceDocument`）

来源文档表示本次实际取得的原始材料、数据文件、接口响应、网页、人工记录、文件检索结果或上传文件。它回答“这次拿到的材料是什么、从哪里来、怎么取得、能否使用、如何复核”。

SourceDocument 的核心字段包括：

| 字段 | 说明 |
|---|---|
| `sourceDocumentId` / `id` | 本次来源文档唯一 ID |
| `title` | 来源标题或稳定名称 |
| `sourceProfileId` | 匹配的稳定 SourceProfile ID |
| `sourceName` | 来源生产者、发布者或数据提供方 |
| `sourceTier` | 来源层级 |
| `contentDomain` | 本材料实际覆盖的内容领域 |
| `acquisitionChannel` | 本次获取方式，例如 web、api、mcp、file、manual、internal_system |
| `accessScope` | 访问和使用边界 |
| `artifactType` | 材料形态，例如 PDF、HTML、CSV、API response、数据库字段、访谈纪要 |
| `publisher` / `publishedAt` | 发布者和发布时间 |
| `capturedAt` | 本次捕获、下载、调用、上传或登记时间 |
| `businessTime` | 材料描述事项的业务时间或统计期锚点 |
| `location` / `locator` | 稳定位置和页码、段落、字段、行列或接口参数 |
| `methodologyNote` | 方法论、样本、字段口径或统计规则说明 |
| `usageLimit` | 本次证据包中的使用限制 |
| `sourceReliability` | 来源本身可靠性，不得直接复制为主张可信度 |

发布者文本（`publisher`）和发布时间（`publishedAt`）是推荐字段；发布者能够归一到稳定组织时，再通过 `sourcePublishedBy` 连接 Organization。`RegisterSource` 创建来源，`claimCitesSource` 将主张定位到来源。

来源文档不能替代其中的具体主张；来源可靠也不表示每条主张都可靠。

### 3.2 证据主张（`EvidenceClaim`）

证据主张表示从来源中提取的一条最小、可定位的说法。陈述（`statement`）、主张类型（`claimType`）、原文位置（`locator`）和主张可信度（`claimConfidence`）是核心字段；动态内容还应有业务时间（`businessTime`）。

主张通过 `claimCitesSource` 回到来源，通过 `claimAbout` 指向稳定语义对象，并可成为 EvidenceFact 的支撑。涉及关键变量的内容由推理域先形成 Observation 或 Event，再通过推理关系绑定 StateVariable。`ExtractClaim` 创建主张，`NormalizeClaim` 对齐口径。

主张不能因为来自高可靠来源就自动成为事实，也不能把多个对象、时间或核心断言塞进一条记录。

### 3.3 证据事实（`EvidenceFact`）

证据事实表示由一条或多条主张归一得到的结构化事实候选。陈述、事实类别（`factType`）、业务时间和事实可信度（`factConfidence`）是核心字段；数值和单位只在内容可结构化时填写。

事实通过 `factSupportedByClaim` 回到主张，通过 `factAbout` 指向稳定语义对象。推理域可以消费事实候选并通过 `evidenceGroundsReasoning` 支撑允许的推理输入，但该跨域关系不在证据域声明。`SynthesizeFact` 创建事实候选。

EvidenceFact 不是不可推翻的最终真相。新证据可以与其冲突、替代它或使其失效。

### 3.4 证据需求（`EvidenceRequirement`）

证据需求表示“本次必须取得什么证据”。它绑定 `targetJudgmentUnitId`、可选路径节点和状态变量，并说明需求目的、证据角色、证据类别、内容域、对象/时间/粒度、最低质量、来源层级、独立来源数、代理许可、停止条件、缺失策略和 04 降级方式。

EvidenceRequirement 不保存完整取证策略，也不保存实际证据结果；策略由 EvidenceRecipe 表达，实际满足情况由 EvidenceBasket 和 EvidenceReadinessAssessment 表达。

### 3.5 最低证据组合（`EvidenceRecipe`）

最低证据组合表示可复用的取证策略引用，保存判断类型、策略库文件、策略版本、必要证据类型、反证类型、最低通过规则、代理规则和降级规则。

通用方法留在 `知识库_03取证`，本体中的 EvidenceRecipe 只保存稳定引用和机器可校验的规则边界。

### 3.5.1 证据篮子需求（`EvidenceBasketRequirement`）

计划阶段冻结的证据组合门槛。它保存篮子类型、目标判断单元、篮子角色、最低来源层级、独立来源数与代理许可；**不**保存本次运行的满足状态。

判断单元通过 `judgmentUnitRequiresEvidence` 引用本对象；02 任务图中的必要证据组合以本类型为权威，不再嵌在 `JudgmentUnit` 属性里。

### 3.6 必要证据组合运行评估（`EvidenceBasket`）

`EvidenceBasket` 只表示本次运行对某项 `EvidenceBasketRequirement` 的满足状态评估。它必须引用 `basketRequirementRef`，并记录篮子状态、反证检查、冲突状态、质量等级、使用限制和缺口动作。篮子类型、角色与计划门槛字段若出现在 CSV 投影中，只能作为需求对象的只读投影，不得另行维护第二套权威。

必需篮子未满足时，不得将判断单元交给 04 做强方向判断；反证篮子未检查时，不得方向性输出。

### 3.7 来源画像（`SourceProfile`）与取数通道（`AcquisitionChannel`）

SourceProfile 是稳定来源生产者或来源类型的画像，说明默认权威性、常见内容领域、允许主张类型、禁用用途、默认可靠性、独立来源组和常见限制。例如监管原文、公司披露、金融数据库、行业数据库、一手调研、卖方研报、新闻或搜索入口。

SourceProfile 不是具体材料；具体材料必须登记为 SourceDocument。SourceProfile 也不是获取方式；MCP、API、网页、人工上传、文件检索、数据库终端和内部系统都属于 AcquisitionChannel。来源可靠不等于主张可靠，低层级或线索型来源原则上只能作为线索、预期、竞争解释或背景，不能冒充硬事实。

AcquisitionChannel 说明通过什么方式取数，记录通道类型、可复现性、留痕等级、权限要求、典型失败模式、允许用途和禁用用途。取数通道不是证据来源本身。

### 3.8 代理指标（`ProxyIndicator`）

代理指标表示在直接证据不可得时，哪些指标可以有条件代理目标变量或证据需求。它必须保存代理逻辑、有效条件、失效条件、置信折扣、不能替代的直接证据和披露要求。

代理指标必须被标记和披露，不得被写成直接事实，也不得替代直接成交价、实际出货、正式财务数据等直接证据。

### 3.9 单项证据可用性评估（`EvidenceAssessment`）

EvidenceAssessment 记录一项来源、主张或事实在本次任务、研究范围和核心结论下能否使用。它保存证据质量、使用限制、理由和缺口，但不改写 SourceDocument、EvidenceClaim 或 EvidenceFact 的原始状态。

### 3.10 核心结论证据准入评估（`EvidenceReadinessAssessment`）

证据准入评估结构化保存 03 对判断单元证据是否足够的结论。它综合支持证据、交叉验证、反证、冲突、来源质量、代理依赖、时效、追溯和口径，输出 `allowed04Output`、`confidenceCeiling`、禁止表达、缺口动作和准入理由。

04 的每条观点必须回到 readiness assessment，且不得超过其可支持结论上限。

## 4. 关系（Relation）

证据关系负责保留来源链、对象指向和冲突历史。关系不能直接修改语义对象，也不能把证据提升为判断。

### 4.1 主张引用来源（`claimCitesSource`）

连接 EvidenceClaim 与 SourceDocument，并用原文位置定位主张。由 `ExtractClaim` 创建，受 `source_traceability` 检查。

### 4.2 主张涉及对象（`claimAbout`）

连接 EvidenceClaim 与稳定语义对象，包括 Organization、PolicyInstrument、PolicyRequirement、TechnicalConstraint、Region、Application、FinancialInstrument、Identifier、TradingVenue、Listing 和 RoleAssignment。由 `NormalizeClaim` 创建，只说明主张讨论谁，不表示主张已经被证实。

### 4.3 事实由主张支撑（`factSupportedByClaim`）

连接 EvidenceFact 与一条或多条 EvidenceClaim。支撑角色可区分主要、交叉或背景依据；由 `SynthesizeFact` 创建。

### 4.4 事实涉及对象（`factAbout`）

连接 EvidenceFact 与稳定语义对象，包括 Organization、PolicyInstrument、PolicyRequirement、TechnicalConstraint、Region、Application、FinancialInstrument、Identifier、TradingVenue、Listing 和 RoleAssignment。它只提供事实候选的主题锚点，不直接修改对象属性。

### 4.5 来源由组织发布（`sourcePublishedBy`）

连接 SourceDocument 与稳定 Organization。它用于归一官方机构、监管机构、标准组织和公司的多种名称；原始 `publisher` 文本仍保留，不能被归一结果覆盖。

### 4.6 证据冲突（`conflictsWith`）

连接两项同类型证据，记录冲突类别和范围。由 `RecordEvidenceConflict` 创建；冲突存在时双方都保留。

### 4.7 证据替代（`supersedes`）

表示新证据在相同口径下替代旧证据。由 `SupersedeEvidence` 创建，必须说明替代原因，不能把普通冲突误写成替代。

### 4.8 证据失效（`invalidates`）

表示新证据或适用条件变化使旧证据不再有效。由 `InvalidateEvidence` 创建，并保留旧证据历史。

### 4.9 取证规划与准入关系

证据域新增以下内部关系：

- `requirementUsesRecipe`：证据需求采用最低证据组合。
- `recipeRequiresBasket`：配方要求必要证据组合。
- `requirementRequiresBasket`：需求要求必要证据组合。
- `requirementRequiresSourceProfile`：需求要求来源画像。
- `requirementAllowsAcquisitionChannel`：需求允许取数通道。
- `sourceDocumentUsesProfile`：具体来源文档使用稳定来源画像。
- `sourceAcquiredThrough`：具体来源通过通道取得。
- `claimSatisfiesRequirement` / `factSatisfiesRequirement`：主张或事实满足证据需求。
- `claimFillsEvidenceBasket` / `factFillsEvidenceBasket`：主张或事实填充必要证据组合。
- `claimActsAsCounterEvidenceFor` / `factActsAsCounterEvidenceFor`：主张或事实作为反证。
- `proxySupportsRequirement`：代理指标受限支持证据需求。
- `readinessAssessesRequirement` / `readinessEvaluatesBasket`：准入评估覆盖需求和篮子。

## 5. 动作（Action）

### 5.1 登记来源（`RegisterSource`）

接收来源标题、类型、原始发布者文本、可选 Organization 引用、定位和权限，应用 `source_traceability`，调用 `AssessSourceReliability`，写入 SourceDocument；发布者已归一时同时创建 `sourcePublishedBy`。

### 5.2 抽取主张（`ExtractClaim`）

接收来源和内容范围，进入 `SourceToClaimLogic`，调用 `ExtractClaims`，应用 `source_traceability` 和 `claim_atomicity`，写入 EvidenceClaim 与 `claimCitesSource`。

### 5.3 归一主张（`NormalizeClaim`）

接收主张、对象口径、单位和业务时间，调用 `NormalizeClaimValue` 与 `business_time_required`，更新主张归一信息并创建 `claimAbout`。

### 5.4 归并事实候选（`SynthesizeFact`）

接收主张集合和归一口径，进入 `ClaimToFactLogic`，调用 `AssessClaimConfidence`，应用来源独立性、来源与主张可靠性分离、冲突保留和事实支撑规则，写入 EvidenceFact 与 `factSupportedByClaim`。

### 5.5 记录证据冲突（`RecordEvidenceConflict`）

接收两项同类型证据，进入 `ConflictHandlingLogic`，调用 `DetectEvidenceConflict` 和 `conflict_preservation`，写入 `conflictsWith` 并标记双方冲突状态。

### 5.6 替代证据（`SupersedeEvidence`）

在新旧证据口径一致且替代依据明确时，经 `ConflictHandlingLogic` 创建 `supersedes`，并把旧证据标记为被替代。

### 5.7 使证据失效（`InvalidateEvidence`）

在存在明确反面证据或适用条件终止时，经 `ConflictHandlingLogic` 创建 `invalidates`，并把旧证据标记为失效。

### 5.8 评价证据是否可用于本次判断（`AssessEvidenceForUse`）

按正式 evidence profile、任务范围、判断单元、支持与反面证据及缺口，生成 EvidenceAssessment 和 `assessmentEvaluatesEvidence`。证据不足时应记录 `insufficient` 或 `blocked`，不得为了通过门槛改变原证据状态。

### 5.9 证据规划与准入动作

新增动作包括：

- `CreateEvidenceRequirement`：根据判断单元交接字段创建证据需求。
- `MatchEvidenceRecipe`：根据 judgment_type 和配方标签匹配 03 取证策略库。
- `CreateEvidenceBasket`：创建必需、反证、代理或背景必要证据组合。
- `RegisterSourceProfile`：登记稳定 SourceProfile。
- `RegisterAcquisitionChannel`：登记取数通道、权限和留痕要求。
- `RegisterProxyIndicator`：登记代理指标、有效/失效条件和披露要求。
- `AssessBasketReadiness`：评价必要证据组合满足状态。
- `AssessEvidenceReadiness`：形成判断单元证据准入评估和 04 最多能形成的结论。

## 6. 函数（Function）

### 6.1 主张抽取（`ExtractClaims`）

由 `ExtractClaim` 经 `SourceToClaimLogic` 调用，读取 SourceDocument 的指定范围，返回主张候选，不直接写入证据对象。

### 6.2 主张口径归一（`NormalizeClaimValue`）

由 `NormalizeClaim` 和 `ClaimToFactLogic` 调用，读取主张与语义对象，返回对象、时间、数值和单位的归一结果。

### 6.3 来源可靠性评价（`AssessSourceReliability`）

由 `RegisterSource` 调用，根据来源类型、发布者和可追溯信息返回来源可靠性。

### 6.4 主张可信度评价（`AssessClaimConfidence`）

由 `SynthesizeFact` 调用，读取来源、主张类型、冲突和独立来源，返回主张可信度及依据。

### 6.5 证据冲突检测（`DetectEvidenceConflict`）

由冲突动作、`ClaimToFactLogic` 和 `ConflictHandlingLogic` 调用，识别口径、数值、时间或方向冲突。

### 6.6 证据新鲜度计算（`CalculateEvidenceFreshness`）

由 `LinkEvidenceToReasoning` 经 `FreshnessEvaluationLogic` 调用，根据业务时间、有效期和评估时点返回可用、过期或不确定。

### 6.7 证据规划与准入函数

新增函数包括：

- `DeriveEvidenceRequirements`：从判断类型和证据角色生成需求候选。
- `MatchEvidenceRecipeFunction`：匹配最低证据组合。
- `EvaluateEvidenceBasketFunction`：评价必要证据组合。
- `MatchSourceProfileFunction`：匹配来源画像和取数通道。
- `ValidateProxyIndicatorFunction`：校验代理指标。
- `AssessEvidenceReadinessFunction`：生成准入结论和 04 最多能形成的结论。

## 7. 逻辑（Logic）

### 7.1 来源到主张逻辑（`SourceToClaimLogic`）

入口是 `ExtractClaim`。它先检查来源，再抽取和拆分主张，输出 EvidenceClaim；无法定位原文时不生成正式主张。

### 7.2 主张到事实逻辑（`ClaimToFactLogic`）

入口是 `SynthesizeFact`。它依次完成口径归一、独立来源去重、来源与主张可靠性分离、冲突检测和支撑检查，输出 EvidenceFact 或冲突状态。

### 7.3 证据冲突处理逻辑（`ConflictHandlingLogic`）

入口是冲突、替代和失效动作。它调用冲突检测和保留规则，区分 conflictsWith、supersedes 与 invalidates。

### 7.4 证据新鲜度逻辑（`FreshnessEvaluationLogic`）

它提供只读的新鲜度评价能力，检查业务时间并调用 `CalculateEvidenceFreshness`；时间缺失时降低可信度。推理域的 `LinkEvidenceToReasoning` 可以调用该能力，但证据域不反向引用推理动作或对象。

### 7.5 证据需求与准入逻辑

新增逻辑包括：

- `JudgmentToEvidenceRequirementLogic`：把判断类型和证据角色拆成可执行证据需求。
- `EvidenceRecipeMatchingLogic`：为证据需求匹配可复用的最低证据组合。
- `EvidenceBasketEvaluationLogic`：检查必需篮子、反证篮子和实际证据填充状态。
- `SourceProfileMatchingLogic`：检查来源画像、来源层级和取数通道是否满足需求。
- `ProxyIndicatorValidationLogic`：校验代理指标、披露和不能替代的直接证据。
- `EvidenceAssessmentLogic`：评估单项证据在本次范围内的可用性，不改写原始证据。
- `EvidenceReadinessAssessmentLogic`：综合需求、配方、篮子、来源、代理、反证和冲突生成 04 最多能形成的结论。

## 8. 规则（Rule）

### 8.1 来源可追溯（`source_traceability`）

由来源登记、主张抽取和 `SourceToClaimLogic` 调用。来源或原文位置不可复核时保持候选或拒绝。

### 8.2 主张最小化（`claim_atomicity`）

由主张抽取动作和 Logic 调用。一条主张混合多个对象、时间或核心断言时必须拆分。

### 8.3 来源与主张可靠性分离（`source_claim_reliability_separation`）

由 `SynthesizeFact` 和 `ClaimToFactLogic` 调用。来源可靠性不能直接复制为主张可信度。

### 8.4 事实必须有主张支撑（`fact_requires_claim`）

由事实归并动作和 Logic 调用。没有 `factSupportedByClaim` 时阻止创建 EvidenceFact。

### 8.5 独立来源追溯（`original_source_independence`）

由事实归并动作和 Logic 调用。同一原始来源的多次转述只计算一次。

### 8.6 冲突保留（`conflict_preservation`）

由事实归并、冲突、替代和失效动作及相关 Logic 调用。未判断冲突不得删除任一方。

### 8.7 业务时间完整（`business_time_required`）

由主张归一和新鲜度 Logic 调用。动态内容没有业务时间时降低可信度。

### 8.8 证据规划和准入规则

新增规则包括：

- `judgment_type_required`：判断单元必须声明判断类型。
- `evidence_requirement_required`：没有 EvidenceRequirement，不准正式取证。
- `recipe_before_acquisition`：没有 EvidenceRecipe，不得标记 high_quality_pass。
- `mandatory_basket_required`：必需篮子不满足，不得 04 强方向判断。
- `counter_basket_required`：反证篮子未检查，不得方向性输出。
- `source_profile_required`：正式证据必须匹配来源画像。
- `acquisition_channel_not_source_profile`：MCP、API、网页、人工上传、文件检索等获取方式不得写成 SourceProfile。
- `access_scope_required_for_formal_evidence`：AccessScope 不清时不得进入正式证据包。
- `artifact_type_drives_traceability`：ArtifactType 决定原文定位、字段血缘、快照和复核要求。
- `content_domain_must_match_basket`：ContentDomain 必须适合当前必要证据组合。
- `proxy_must_be_disclosed`：代理指标必须披露代理性质和限制。
- `proxy_cannot_replace_direct_evidence`：代理不能替代直接证据。
- `source_tier_must_match_requirement`：来源层级必须匹配证据需求。
- `acquisition_channel_must_be_allowed`：取数通道必须被允许并留痕。
- `stop_condition_must_be_recorded`：停止条件必须记录。
- `readiness_limits_04_output`：准入评估限制 04 输出上限。
