# 00-投研本体框架概述

## 研究员先看什么

本体解决的是：**大家用同一套说法谈对象、关系、证据和判断**，避免「同一公司多种叫法」「材料说法当事实」「结论回不到依据」。

研究时你通常不需要读完整对象目录。记住三层即可：

| 层 | 回答 | 研究时用来干什么 |
|---|---|---|
| 语义 | 研究什么 | 锚定稳定对象与关系（公司、产品、环节、政策……） |
| 证据 | 依据是什么、本次能否用 | 来源、主张、事实、冲突与「够不够用」 |
| 推理 | 如何形成与复盘判断 | 变量、信号、判断、预期差、影响、留痕 |

职责互斥：稳定身份不进证据域；材料说法不进语义域；动态判断不进前两域。

**本体不是什么：** 不是库表设计、材料仓库、调度系统、报告模板库或投资建议系统；不保存行业具体实例，也不把单次运行临时信息写成通用定义。

正式字段与机器校验以各域 YAML 为准；本文与各域 MD 是可读说明。

---

## 1. 概念速查（完整目录见各域 MD / YAML）

- **语义**：概念、组织/公司、产业/环节、产品/材料/工序、地区、应用、政策与要求、资产与金融工具、识别码与上市等
- **证据**：来源文档、来源说法、归一事实、单项评价、「证据是否够用」评价（及规划类对象）
- **推理**：状态变量、观测、事件、假设、信号、判断、市场预期、预期差、资产影响、情景、规则评价、推理留痕、验证记录（及任务结构设计对象）

单项证据能否用 → 证据评价；核心判断整体能否进入推理 → 「证据是否够用」评价。正式判断链在推理层完成；报告格式不属于本体定义。

---

## 2. 六类资源（原则）

| 资源 | 原则 |
|---|---|
| 对象 | 需独立身份、连接或生命周期才建；类型≠实例；一级只定义跨行业类型 |
| 关系 | 可查询的语义连接；条件结果属规则/流程；时点变化属推理对象 |
| 动作 | 完整业务行为；正式写入须经授权范围 |
| 函数 | 可调用计算/归一；默认只读 |
| 流程 | 可声明、可复现的步骤流 |
| 规则 | 校验 / 推理 / 评分 / 阻断；简单条件用规则，复杂计算用函数 |

同一效果只保留一处权威实现。

---

## 3. 一级对象准入与粒度

进入一级须：跨行业反复使用、边界可区分、无法仅靠属性或行业扩展表达。人物/技术/设施/项目先入行业扩展。

粒度要点：类型与实例分离；核心与行业扩展分离；主张/事实/判断分离；稳定结构与动态变化分离；避免重复权威；保持可追溯。

---

## 4. 判断结果与展示边界

正式结果用判断、推理留痕、预期差、资产影响、验证记录表达。展示层引用这些对象，不在本体 YAML 中另建报告模板，不得抬升已有结论等级。
