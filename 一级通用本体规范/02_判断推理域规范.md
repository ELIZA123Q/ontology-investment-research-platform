# 02-判断推理域规范

## 1. 域定位与边界

判断推理域消费语义对象和证据，把它们转化为可解释、可反证、可分级、可复盘的研究判断，并用后续结果完成事后验证。

本域不保存原始材料，不重新定义产业、公司、产品等稳定对象，也不输出买卖建议。它只表达状态如何变化、假设如何验证、结论如何降级，以及资产影响相对什么预期成立。

最小主线为：

```text
语义锚点 + 证据
→ 事件或观测
→ 状态变量变化
→ 假设
→ 支持、削弱或阻断信号
→ 判断
→ 市场预期
→ 预期差
→ 资产影响或降级
→ 推理留痕
→ 后续结果与事后验证
```

推理域内部按职责分为四组，而不是把所有对象视为同一类并列实体：

- 状态与事实：`StateVariable`、`Observation`、`Event`。
- 假设与判断：`Hypothesis`、`Signal`、`Judgment`。
- 定价比较：`MarketExpectation`、`ExpectationGap`、`AssetImpact`。
- 情景与记录：`Scenario`、`ReasoningTrace`、`ValidationRecord`。

## 2. 字段设置原则

推理字段不是为了保存完整分析文章，而是保证判断能够被拆解、验证、反证、分级和复盘。

- 状态和事件必须说明观察对象、业务时间和证据。
- 假设必须说明方向、时间尺度和证伪条件。
- 信号必须说明作用角色，不能只说“有利”或“不利”。
- 判断必须把结论等级与置信度分开。
- 资产影响必须引用明确预期差。
- 正式输出必须引用公开可复核的推理留痕。
- 事后验证必须保留原始留痕，不得用后见信息覆盖当时的输入和判断。

完整数据类型、枚举和扩展字段由 `reasoning.yaml` 定义。

## 3. 对象（Object）

### 3.1 状态变量（`StateVariable`）

状态变量说明“持续观察什么”。名称（`name`）用于识别，观测口径（`measurementDefinition`）说明如何读取或计算，变量类别（`variableKind`）区分直接观测、派生和定性变量。

变量通过 `variableAnchoredOn` 挂到语义对象，包括 Organization 和 PolicyInstrument，通过 `observationOf` 接收观测，并通过 `variableInfluencesVariable` 参与传导。`DefineStateVariable` 创建变量。

状态变量不能保存某一时点的具体值，也不能直接保存方向判断。

### 3.2 观测（`Observation`）

观测表示某个状态变量在特定业务时间的读数或明确来源估算。观测值（`value`）、业务时间（`observedAt`）、数值状态（`valueStatus`）和证据引用（`evidenceRefs`）共同防止无时间、无来源的数值进入推理。

观测由 `RecordObservation` 直接记录，或由 `ComputeDerivedObservation` 调用 `ComputeDerivedVariable` 计算，并通过 `observationOf` 绑定变量。

观测不能包含未来判断、因果解释或资产结论。

### 3.3 研究事件（`Event`）

研究事件表示已发生或正在发生、可能影响研究对象或状态变量的外部事实。事件名称、事件类别（`eventType`）、发生时间（`occurredAt`）和证据引用是最小信息。

事件通过 `eventAnchoredOn` 连接语义对象，通过 `eventAffectsVariable` 进入状态推理。政策发布、修订、执行、延期和失效作为 Event 锚定 PolicyInstrument；`RegisterEvent` 只接收证据支撑的事实。

材料中的预测、作者观点和未证实消息不能直接建成 Event。

### 3.4 假设（`Hypothesis`）

假设表示对状态变量未来方向的可证伪判断。陈述（`statement`）、方向（`direction`）、时间尺度（`timeHorizon`）和证伪条件（`falsificationConditions`）缺一不可。

假设通过 `hypothesisAbout` 绑定变量，通过 `hypothesisBasedOn` 回到事件、观测或证据主张，并由 `signalEvaluates` 接收信号。`hypothesisCompetesWith` 表达替代解释，`hypothesisContradicts` 表达互不相容的反向假设。

假设不强制在创建时已有验证证据，但必须绑定具有语义锚点的状态变量，并具有方向、时间尺度和证伪条件。研究员前提或情景假设写入 `premiseStatements`；它们是待验证前提，不得当作事实。`FormHypothesis` 创建候选假设，`EvaluateHypothesis` 再根据后续信号更新评价。

假设不能伪装成已发生事实，也不能省略证伪条件。

### 3.5 信号（`Signal`）

信号表示证据、事件或观测对假设和判断所起的作用。陈述、角色（`role`）、业务时间和证据引用是核心字段；强度（`strength`）用于必要的分级。

信号通过 `signalEvaluates` 支持、催化、跟踪、削弱或阻断 Hypothesis 与 Judgment。`RecordSignal` 创建信号，`EvaluateHypothesis` 汇总信号。

信号不能只写“利好”“利空”，也不能在没有目标对象和证据时独立存在。

### 3.6 判断（`Judgment`）

判断表示基于假设和信号形成的研究结论。陈述、结论等级（`conclusionLevel`）、时间尺度、置信度（`confidence`）和不确定性（`uncertainty`）用于防止简单二元结论。

判断通过 `judgmentBasedOn` 回到假设，通过 `gapComparesJudgment` 进入预期比较，通过 `impactDerivedFrom` 产生资产影响，并由 `traceForJudgment` 连接推理留痕。

判断不能直接等同于事实、预期或买卖建议。

### 3.7 市场预期（`MarketExpectation`）

市场预期表示特定截面下市场、管理层、卖方、买方内部、研究者、用户输入或价格隐含的预期。陈述、预期类别（`expectationType`）、预期持有者（`expectationOwner`）、形成依据（`expectationBasis`）、截面时间（`asOf`）、时间尺度和证据引用共同保证预期可比较。

预期通过 `expectationAbout` 指向语义对象或变量，通过 `gapComparesExpectation` 成为预期差的比较基准。`RegisterExpectation` 创建预期。

市场预期不能当作已经发生的事实，也不能缺少截面时间。

### 3.8 预期差（`ExpectationGap`）

预期差是判断与某条可比预期之间的独立比较结果。它需要自己的陈述、方向（`direction`）、比较依据（`comparisonBasis`）、截面时间和时间尺度；可量化时再记录幅度（`magnitude`）。

预期差通过 `gapComparesJudgment` 和 `gapComparesExpectation` 同时引用判断与预期，再由 `impactReferencesGap` 被资产影响引用。`CompareWithExpectation` 创建该对象。

预期差不能只作为 AssetImpact 中的一段字符串，也不能在判断和预期口径不可比时强行形成。

### 3.9 资产影响（`AssetImpact`）

资产影响表示判断相对预期可能对资产产生的方向性影响。除影响陈述、方向、时间尺度和定价反映状态（`pricedInAssessment`）外，还必须说明影响机制（`impactMechanism`）和影响置信度（`impactConfidence`）；敏感变量与风险信号分别通过 `sensitivityVariableRefs`、`riskSignalRefs` 引用。

资产影响通过 `impactDerivedFrom` 回到判断，通过 `impactOnAsset` 指向资产，通过 `impactReferencesGap` 引用预期差；情景化影响还通过 `impactUnderScenario` 限定成立条件。`AssessAssetImpact` 创建或降级该对象。

资产影响不能脱离判断和预期差，也不能转换为买卖建议、目标价或收益率预测。

### 3.10 情景（`Scenario`）

情景表示一组假设、触发条件、规则和失效条件构成的未来状态组合。名称、情景类别、关键假设、规则引用（`ruleRefs`）、触发条件和失效条件是核心信息。

情景通过 `scenarioIncludesHypothesis` 组织假设，Rule 通过 `ruleRefs` 引用。判断和资产影响分别通过 `judgmentUnderScenario`、`impactUnderScenario` 指向情景，使 base、upside、downside 和 stress 路径自然落到结论。`ConstructScenario` 创建情景。

情景不是事实预测，也不能把互相冲突的路径混成一个结果。

### 3.11 推理留痕（`ReasoningTrace`）

推理留痕保存一次判断从输入到输出的公开可复核路径。评估时间、输入引用、处理步骤、Rule、Function、Logic、输出引用和完成状态共同说明结论如何形成。

它通过 `traceForJudgment` 指向判断，由 `RecordReasoningTrace` 调用 `ReasoningTraceLogic` 创建。

推理留痕不能保存模型内部思维过程，也不能用无法解析的自由文本代替资源引用。

### 3.12 事后验证记录（`ValidationRecord`）

事后验证记录说明某条 Hypothesis、Judgment 或 AssetImpact 后来是已验证、部分验证、被证伪还是仍不确定。它记录验证时间、后续结果摘要、偏差原因、是否建议修订本体以及下一验证点。

`validationOf` 指向验证目标，`validationUsesOutcome` 引用后续 Observation、Event 或 EvidenceFact，`validationReferencesTrace` 回到当时的 ReasoningTrace。验证记录只能追加，不得修改原始留痕；`revisionRequired=true` 也只产生修订建议，不自动修改 Rule、StateVariable 或 Scenario。

## 4. 关系（Relation）

推理关系负责把动态对象连成可回放链路。重要关系必须保留时间、证据或适用条件。创建这些关系的动作和 Logic 在后续章节说明。

### 4.1 变量挂载对象（`variableAnchoredOn`）

连接 StateVariable 与稳定语义对象，说明变量观察谁；Organization 和 PolicyInstrument 可分别承载机构行为、政策执行强度等变量。由 `DefineStateVariable` 创建；没有具体对象的宏观变量必须说明适用范围。

### 4.2 观测绑定变量（`observationOf`）

连接 Observation 与 StateVariable。由记录或计算观测动作创建；它只表示观测归属，不解释观测原因。

### 4.3 事件挂载对象（`eventAnchoredOn`）

连接 Event 与语义对象。政策变化事件应锚定 PolicyInstrument，执行主体变化可同时锚定 Organization；由 `RegisterEvent` 创建，并受 `semantic_anchor_required` 检查。

### 4.4 事件影响变量（`eventAffectsVariable`）

连接 Event 与 StateVariable，记录方向、机制和可能的滞后。由 `EventToStateLogic` 使用，并受 `event_to_state_inference` 约束；它不能直接替代 Hypothesis。

### 4.5 变量传导（`variableInfluencesVariable`）

连接两个 StateVariable，说明传导方向、机制、成立条件和滞后。由 `StatePropagationLogic`、`PropagateVariableImpact` 和 `variable_propagation_inference` 使用。

### 4.6 假设绑定变量（`hypothesisAbout`）

连接 Hypothesis 与它讨论的 StateVariable。由 `FormHypothesis` 创建，保证假设不是无对象的泛泛判断。

### 4.7 假设依据（`hypothesisBasedOn`）

连接 Hypothesis 与 Event、Observation 或 EvidenceClaim。由 `FormHypothesis` 在存在依据时创建，用于回溯假设的触发、前提或上下文；它不表示假设已经得到验证。

### 4.8 信号评价（`signalEvaluates`）

连接 Signal 与 Hypothesis 或 Judgment。角色必须与 Signal.role 一致，并由 `signal_role_compatibility` 校验。

### 4.9 判断依据（`judgmentBasedOn`）

连接 Judgment 与一个或多个 Hypothesis。由 `FormJudgment` 创建，不能直接跳过假设连接到证据。

### 4.10 预期指向（`expectationAbout`）

连接 MarketExpectation 与语义对象或 StateVariable，包括市场对组织行为或政策工具的预期。由 `RegisterExpectation` 创建，用于确保判断和预期比较同一对象。

### 4.11 预期差比较判断（`gapComparesJudgment`）

连接 ExpectationGap 与 Judgment。由 `CompareWithExpectation` 创建，是预期差的判断端。

### 4.12 预期差比较预期（`gapComparesExpectation`）

连接 ExpectationGap 与 MarketExpectation。与上一关系成对创建，缺少任一端都不能形成有效预期差。

### 4.13 资产影响来源（`impactDerivedFrom`）

连接 AssetImpact 与 Judgment。由 `AssessAssetImpact` 创建，保证资产结论不能脱离研究判断。

### 4.14 影响作用资产（`impactOnAsset`）

连接 AssetImpact 与语义域的 Asset。它只说明影响对象，不表达交易动作。

### 4.15 资产影响引用预期差（`impactReferencesGap`）

连接 AssetImpact 与 ExpectationGap。由 `AssessAssetImpact` 创建，并受 `expectation_required_for_asset_impact` 阻断规则约束。

### 4.16 情景包含假设（`scenarioIncludesHypothesis`）

连接 Scenario 与 Hypothesis，并用顺序说明路径位置。Rule 不作为对象连接，而由 Scenario.ruleRefs 引用。

### 4.17 推理留痕对应判断（`traceForJudgment`）

连接 ReasoningTrace 与 Judgment。由 `RecordReasoningTrace` 创建，是正式输出追溯判断形成过程的入口。

### 4.18 证据支撑推理（`evidenceGroundsReasoning`）

连接 EvidenceClaim 或 EvidenceFact 与 Observation、Event、MarketExpectation 或 Signal。该关系由推理域拥有，因为推理对象是证据的消费者；它不能直接指向 Judgment 或 AssetImpact。

### 4.19 假设竞争解释（`hypothesisCompetesWith`）

连接两个对同一现象提供替代解释的 Hypothesis。竞争假设可能部分并存，但判断升级前必须比较解释力和未解决差异。

### 4.20 假设相互矛盾（`hypothesisContradicts`）

连接方向、前提或可观察结果互不相容的 Hypothesis。矛盾依据必须明确，不能只用它代替削弱或阻断信号。

### 4.21 情景下判断（`judgmentUnderScenario`）

连接 Judgment 与 Scenario，说明判断只在该情景条件下成立。没有场景差异的判断可以不创建该关系。

### 4.22 情景下资产影响（`impactUnderScenario`）

连接 AssetImpact 与 Scenario。资产影响的情景必须与来源 Judgment 一致，避免把 base 路径判断和 downside 路径影响混接。

### 4.23 验证目标（`validationOf`）

连接 ValidationRecord 与 Hypothesis、Judgment 或 AssetImpact，说明事后复盘验证什么。

### 4.24 验证使用后续结果（`validationUsesOutcome`）

连接 ValidationRecord 与后续 Observation、Event 或 EvidenceFact。已验证、部分验证和证伪必须至少引用一项结果依据。

### 4.25 验证引用原始留痕（`validationReferencesTrace`）

连接 ValidationRecord 与 ReasoningTrace。验证只能引用原始留痕，不得用事后结果改写原有步骤。

## 5. 动作（Action）

### 5.1 定义状态变量（`DefineStateVariable`）

接收变量名称、口径、类别和语义锚点，检查 `semantic_anchor_required`，写入 StateVariable 和 `variableAnchoredOn`。

### 5.2 计算派生观测（`ComputeDerivedObservation`）

接收派生变量、输入观测和明确计算式，检查 `evidence_grounding_required` 与 `time_alignment`，调用 `ComputeDerivedVariable`，写入 Observation 和 `observationOf`。

### 5.3 记录观测（`RecordObservation`）

接收变量、数值、业务时间和证据，检查证据与时间，写入 Observation 和 `observationOf`。

### 5.4 登记研究事件（`RegisterEvent`）

接收有证据支撑的已发生事实，检查 `evidence_grounding_required` 和 `semantic_anchor_required`，写入 Event 与 `eventAnchoredOn`。

### 5.5 形成假设（`FormHypothesis`）

接收陈述、变量、方向、时间尺度、证伪条件以及可选依据或研究员前提，调用 `HypothesisAdmissionLogic` 检查语义锚点与可证伪性，写入 Hypothesis 和 `hypothesisAbout`；只有提供依据时才创建 `hypothesisBasedOn`。已有证据不是候选假设的前置条件。

### 5.6 记录信号（`RecordSignal`）

接收信号内容、角色、目标和证据，检查 `signal_role_compatibility` 与证据要求，写入 Signal 和 `signalEvaluates`。

### 5.7 评价假设（`EvaluateHypothesis`）

调用 `HypothesisEvaluationLogic` 和 `AggregateSignals`，应用 `blocking_signal_precedence` 与 `time_alignment`，更新 Hypothesis 的评价状态。

### 5.8 应用推理规则（`ApplyInferenceRule`）

接收 Rule 标识和输入对象，调用 `EvaluateRuleCondition` 与 `StatePropagationLogic`，应用 `variable_propagation_inference`，只返回临时 `ruleEvaluation`，不创建一级对象。需要复核或复用的评价结果写入 `ReasoningTrace.steps`。

### 5.9 形成判断（`FormJudgment`）

调用 `JudgmentFormationLogic` 和 `CalculateConfidence`，检查竞争假设、反向假设及证据门槛，写入 Judgment 和 `judgmentBasedOn`；提供 `scenarioRef` 时同时创建 `judgmentUnderScenario`。判断形成后，再由独立动作记录推理留痕。

### 5.10 登记市场预期（`RegisterExpectation`）

接收预期内容、类型、持有者、形成依据、截面、时间尺度和证据，检查证据与时间，写入 MarketExpectation 和 `expectationAbout`。

### 5.11 比较市场预期（`CompareWithExpectation`）

接收 Judgment 与 MarketExpectation，调用 `ExpectationGapLogic` 和 `CompareExpectation`，检查 `time_alignment`，写入 ExpectationGap、`gapComparesJudgment` 和 `gapComparesExpectation`。

### 5.12 评估资产影响（`AssessAssetImpact`）

接收判断、资产、预期差、定价状态、影响机制、影响置信度、敏感变量、风险信号和可选情景，调用 `AssetImpactLogic` 检查阻断信号、预期差及情景一致性，写入 AssetImpact 及来源关系；条件不足时只返回降级原因。

### 5.13 构建情景（`ConstructScenario`）

接收假设、Rule、触发和失效条件，调用 `ScenarioReasoningLogic`，写入 Scenario 和 `scenarioIncludesHypothesis`。

### 5.14 记录推理留痕（`RecordReasoningTrace`）

接收判断及本次推理使用的输入、步骤和资源引用，调用 `ReasoningTraceLogic` 与 `reasoning_trace_required`，写入 ReasoningTrace 和 `traceForJudgment`。

### 5.15 连接证据与推理（`LinkEvidenceToReasoning`）

接收证据、推理输入对象、支撑角色和评估时间，先调用证据域的 `FreshnessEvaluationLogic`，再由本域 `EvidenceGroundingLogic` 检查目标类型并创建 `evidenceGroundsReasoning`。

### 5.16 记录事后验证（`RecordValidation`）

接收验证目标、后续结果、原始留痕、结果分类和修订建议，调用 `ExPostValidationLogic`、`validation_outcome_required` 与 `validation_time_order`，追加 ValidationRecord 及三类验证关系。该动作无权修改原始 ReasoningTrace 或直接修订本体资源。

## 6. 函数（Function）

### 6.1 派生变量计算（`ComputeDerivedVariable`）

由 `ComputeDerivedObservation` 调用，读取 StateVariable 与 Observation，按明确口径返回派生值，不直接写入观测。

### 6.2 变量影响传播（`PropagateVariableImpact`）

由 `StatePropagationLogic` 调用，读取 `variableInfluencesVariable` 及条件，返回目标变量影响候选。

### 6.3 规则条件计算（`EvaluateRuleCondition`）

由 `ApplyInferenceRule` 和 `StatePropagationLogic` 调用，读取 Rule 与输入对象，返回命中结果和缺口。

### 6.4 信号聚合（`AggregateSignals`）

由 `EvaluateHypothesis` 和 `HypothesisEvaluationLogic` 调用，读取 Signal 与 `signalEvaluates`，返回综合支持、削弱和阻断结果。

### 6.5 置信度计算（`CalculateConfidence`）

由 `FormJudgment` 和 `JudgmentFormationLogic` 调用，读取证据、信号和规则结果，返回置信度及其依据。

### 6.6 预期比较（`CompareExpectation`）

由 `CompareWithExpectation` 和 `ExpectationGapLogic` 调用，读取 Judgment 与 MarketExpectation，返回预期差候选。

## 7. 逻辑（Logic）

### 7.1 事件到状态逻辑（`EventToStateLogic`）

当 `FormHypothesis` 提供 Event 依据时，由 `HypothesisAdmissionLogic` 条件调用。它检查事件证据和语义锚点，读取 `eventAffectsVariable`，输出状态变化与 Hypothesis 候选；无 Event 依据时不执行该分支。

### 7.2 状态传导逻辑（`StatePropagationLogic`）

入口是 `ApplyInferenceRule`。它调用 `EvaluateRuleCondition`、`variable_propagation_inference` 和 `PropagateVariableImpact`，输出目标变量影响候选。

### 7.3 假设评价逻辑（`HypothesisEvaluationLogic`）

入口是 `EvaluateHypothesis`。它聚合信号、优先处理阻断条件并检查时间尺度，输出假设评价。

### 7.4 判断形成逻辑（`JudgmentFormationLogic`）

入口是 `FormJudgment`。它检查判断门槛并调用置信度计算，输出分级 Judgment。

### 7.5 预期差逻辑（`ExpectationGapLogic`）

入口是 `CompareWithExpectation`。它先对齐对象和时间，再调用 `CompareExpectation`，输出 ExpectationGap。

### 7.6 资产影响逻辑（`AssetImpactLogic`）

入口是 `AssessAssetImpact`。它依次检查阻断信号、有效预期差和定价状态，输出 AssetImpact 或降级原因。

### 7.7 情景推演逻辑（`ScenarioReasoningLogic`）

入口是 `ConstructScenario`。它组织 `scenarioIncludesHypothesis` 和 Rule 引用，检查路径与失效条件，输出 Scenario。

### 7.8 推理留痕逻辑（`ReasoningTraceLogic`）

入口是 `RecordReasoningTrace`。它校验所有引用并按顺序整理公开步骤，输出 complete、partial 或 failed 的 ReasoningTrace。

### 7.9 证据映射推理逻辑（`EvidenceGroundingLogic`）

入口是 `LinkEvidenceToReasoning`。它消费证据域的新鲜度评价，检查目标只能是 Observation、Event、MarketExpectation 或 Signal，再创建 `evidenceGroundsReasoning`。

### 7.10 假设准入逻辑（`HypothesisAdmissionLogic`）

入口是 `FormHypothesis`。它检查变量及语义锚点、方向、时间尺度和证伪条件，区分事件、观测、证据主张与研究员前提；有事件依据时才调用 `EventToStateLogic`。

### 7.11 事后验证逻辑（`ExPostValidationLogic`）

入口是 `RecordValidation`。它对齐原始判断时点和后续结果，检查结果依据，引用但不修改原始 ReasoningTrace，并输出 ValidationRecord 或降级为 still_uncertain。

## 8. 规则（Rule）

### 8.1 事件到状态推理（`event_to_state_inference`）

由 `FormHypothesis` 和 `EventToStateLogic` 调用。事件有有效证据、语义锚点和完整影响机制时，产生状态变化和假设候选。

### 8.2 变量传导推理（`variable_propagation_inference`）

由 `ApplyInferenceRule` 和 `StatePropagationLogic` 调用。源变量已有观测、传导条件成立且无阻断时，产生目标变量影响候选。

### 8.3 语义锚点要求（`semantic_anchor_required`）

由变量、事件、假设和判断相关动作调用。Hypothesis 可通过 `hypothesisAbout → StateVariable → variableAnchoredOn` 间接取得语义锚点；没有锚点或明确适用范围时保持候选。

### 8.4 证据支撑要求（`evidence_grounding_required`）

由观测、事件、信号、预期及派生观测动作调用。动态事实或信号没有有效证据时拒绝或降级。

### 8.5 时间尺度对齐（`time_alignment`）

由观测、假设、预期比较和多个 Logic 调用。业务时间和时间尺度不可比时停止聚合或比较。

### 8.6 信号角色兼容（`signal_role_compatibility`）

由 `RecordSignal` 调用。Signal.role 与 `signalEvaluates` 的作用不一致时阻止创建关系。

### 8.7 阻断信号优先（`blocking_signal_precedence`）

由假设评价和资产影响动作及 Logic 调用。有效 block 信号存在时，结论优先置为 blocked。

### 8.8 判断证据门槛（`judgment_evidence_threshold`）

由 `FormJudgment` 和 `JudgmentFormationLogic` 调用，根据证据、信号、`hypothesisCompetesWith`、`hypothesisContradicts` 和反证产生结论等级与置信度。

### 8.9 资产影响必须比较预期（`expectation_required_for_asset_impact`）

由 `AssessAssetImpact` 和 `AssetImpactLogic` 调用。没有通过 `impactReferencesGap` 引用有效预期差时，只能输出基本面观察；PolicyInstrument 或政策 Event 不能直接连接 AssetImpact。

### 8.10 推理链可追溯（`reasoning_trace_required`）

由 `RecordReasoningTrace` 和 `ReasoningTraceLogic` 调用。输入、公开步骤和资源引用不完整时，留痕只能标记为 partial 或 failed，相关判断不得进入正式输出。

### 8.11 证据不得直达判断（`no_direct_evidence_to_judgment`）

由 `LinkEvidenceToReasoning` 和 `EvidenceGroundingLogic` 调用。证据只能直接支撑 Observation、Event、MarketExpectation 或 Signal，不能直接支撑 Judgment 或 AssetImpact。

### 8.12 假设可证伪要求（`hypothesis_falsifiability_required`）

由 `FormHypothesis` 和 `HypothesisAdmissionLogic` 调用。候选假设可以尚无验证证据，但必须绑定状态变量，并具有方向、时间尺度和至少一项可观察的证伪条件。

### 8.13 事后验证结果依据（`validation_outcome_required`）

已验证、部分验证或证伪必须引用后续结果；still_uncertain 必须说明当前缺口或下一验证点。

### 8.14 事后验证时间顺序（`validation_time_order`）

后续结果不得早于原始判断或推理评估时点，事后信息只能追加 ValidationRecord，不能回写覆盖 ReasoningTrace。

## 9. 资源协作链路

```text
FormHypothesis
→ HypothesisAdmissionLogic
→ semantic_anchor_required / hypothesis_falsifiability_required
→ 可选 EventToStateLogic
→ Hypothesis

LinkEvidenceToReasoning
→ FreshnessEvaluationLogic（证据域）
→ EvidenceGroundingLogic
→ no_direct_evidence_to_judgment
→ evidenceGroundsReasoning

EvaluateHypothesis
→ HypothesisEvaluationLogic
→ AggregateSignals
→ blocking_signal_precedence
→ Hypothesis 评价

FormJudgment
→ JudgmentFormationLogic
→ judgment_evidence_threshold
→ CalculateConfidence
→ Judgment

CompareWithExpectation
→ ExpectationGapLogic
→ CompareExpectation
→ ExpectationGap

AssessAssetImpact
→ expectation_required_for_asset_impact
→ AssetImpactLogic
→ AssetImpact

RecordReasoningTrace
→ reasoning_trace_required
→ ReasoningTraceLogic
→ ReasoningTrace

RecordValidation
→ validation_time_order / validation_outcome_required
→ ExPostValidationLogic
→ ValidationRecord
```

推理域的每一条正式判断都应能沿对象、关系、Action、Logic、Function 和 Rule 回到语义锚点与证据。
