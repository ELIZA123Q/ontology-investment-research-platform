# 02-判断推理域规范

## 研究员先看什么

推理域回答：**如何形成与复盘判断**——把语义锚点与证据转为可验证、可推翻、可分级的结论。

研究时用它：状态变量与观测、主路径与竞争解释、信号与规则评价、判断强度、预期差与影响、改判与复盘留痕。

不重定义稳定语义对象，不输出买卖建议。

主线（研究语言）：

```text
证据 → 事件/观测 → 状态变量 → 假设 → 信号 → 规则评价 → 判断
→ 预期/预期差/资产影响 → 留痕 → 验证
```

> 机器权威：[`reasoning.yaml`](reasoning.yaml)。下文是概念速查；完整字段与端点以 YAML 为准。

## 1. 概念速查

### 任务结构设计（02 常用）

| 中文 | 系统名 | 作用 |
|---|---|---|
| 研究计划 | `ResearchPlan` | 一次任务冻结的研究设计根对象 |
| 研究范围 | `ResearchScope` | 对象、地域、指标与时间等可引用范围 |
| 研究子问题 | `ResearchQuestion` | 可排序、可失败路由的子问题 |
| 核心判断 | `JudgmentUnit` | 可被独立证据支持/削弱/保留未知的判断单元 |
| 待验证观点 | `CandidateClaim` | 02 冻结、等待验证的可证伪命题（不是来源主张） |
| 研究路径 / 路径节点 | `ResearchPath` / `PathNode` | 可检查的传导与验证节点 |
| 竞争解释 / 路径条件 | `CompetingExplanation` / `PathCondition` | 替代解释与削弱/阻断条件 |
| 框架/语义/证据选用 | `ResearchFrameworkSelection` 等 | 本次调用哪些框架、语义范围与证据边界 |

### 判断与复盘（04 常用）

| 中文 | 系统名 | 作用 |
|---|---|---|
| 状态变量 / 观测 / 事件 | `StateVariable` / `Observation` / `Event` | 持续观察什么、某时点读到什么、发生了什么 |
| 假设 / 信号 | `Hypothesis` / `Signal` | 待检验命题与触发信息 |
| 规则评价 / 判断 | `RuleEvaluation` / `Judgment` | 规则命中与正式判断 |
| 市场预期 / 预期差 / 资产影响 | `MarketExpectation` / `ExpectationGap` / `AssetImpact` | 定价比较与影响落点 |
| 情景 / 推理留痕 / 验证记录 | `Scenario` / `ReasoningTrace` / `ValidationRecord` | 情景、过程留痕与事后验证 |

关系与动作的完整端点名见 YAML。修订用 `reasoningSupersedes`；情景下影响见 `impactUnderScenario`。

## 2. 与语义域、证据域的交界

| 内容 | 放哪 |
|---|---|
| 稳定身份与结构 | 语义域 |
| 来源、主张、事实、够不够用 | 证据域 |
| 时点变化、判断、影响、复盘 | 推理域 |
