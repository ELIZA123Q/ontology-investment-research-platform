# 03-证据域规范

本文解释证据域如何把原始材料转成来源文档、摄入记录、最小主张和事实候选。证据域只提供可追溯依据，不直接生成投资判断、不直接修改正式对象，也不直接裁决所有冲突。

证据域负责把原始材料(研报、公告、财报、新闻、纪要、数据)变成可追溯、可复核、可供推理使用的证据。它回答四个问题:**依据是什么、来源在哪、可不可靠、有没有冲突。**

正文用通俗语言叙述,英文名是系统内部对象/关系/动作的代号,集中在对照表里,平时阅读可以跳过。

本文主体参考 `schemas/证据域/` 的文件结构组织:先看 `objects_evidence.yaml` 对应的对象,再看 `relations_evidence.yaml`、`actions_evidence.yaml`、`rules.yaml` 和 `policies_evidence.yaml`,最后看输入输出、上下游和边界。ActionFollowup 契约见 `actions_evidence.yaml#side_effects`。

---

## 1. 它产出什么

| 产出 | 说明 |
|---|---|
| 来源资产 | 记录材料来自哪里、什么时候发布、什么时候采集、权限标记和定位位置。 |
| 摄入记录 | 记录某份材料一次进系统的过程(解析、抽取、反馈)。 |
| 最小主张 | 材料里可追溯的最小一条事实/估算/预测/判断线索。 |
| 事实候选 | 把若干条主张归并成一条结构化事实,供推理或优化使用。 |
| 冲突与替代 | 主张/事实之间的冲突、失效、替代,进入治理流程。 |
| 补丁依据 | 证据缺口或新增事实可以触发补丁。 |

这六类产出分别回应开篇四个问题:来源资产和摄入记录回答"来源在哪";最小主张和事实候选回答"依据是什么";可靠性、权限和状态回答"可不可靠";冲突与替代回答"有没有冲突"。

---

## 2. 基本原则

- 来源可定位:证据保留来源、引用位置、发布时间和采集时间。
- 主张拆到最小:一条主张只说一件事,方便复核和判断冲突。
- 事实可归并:一条事实由一条或多条主张支撑,并记录归并口径。
- 冲突要保留:有冲突时双方证据都留着,交给治理裁决。
- 证据支撑变更:证据作为推理或补丁的依据,正式对象或关系变更通过动作和治理流程完成。
- 权限可控:用保密级别、来源归属、可靠性约束证据的可见性和使用等级。
- 不替代判断:证据域不直接生成投资判断,不直接形成资产影响,不直接修改正式对象和正式关系,也不直接裁决所有冲突。
- 可靠性分层:来源可靠性只评价材料来源本身;主张可信度还要结合主张类型、原文位置、是否为一手来源、是否可交叉验证、是否存在利益相关和是否有冲突来确定。

## 3. Objects：对象一览

完整字段以 `schemas/证据域/objects_evidence.yaml` 为准;所有对象都继承公共字段(id、治理层级、记录状态、有效期、观测时间等)。

| 对象代号 | 中文名 | 用途 |
|---|---|---|
| SourceDocument | 来源文档 | 记录材料来源、可靠性、时间、定位和权限。 |
| EvidenceEpisode | 证据摄入事件 | 记录材料进入系统的批次、路径和解析版本。 |
| EvidenceClaim | 证据主张 | 表达材料中的最小可追溯主张。 |
| EvidenceFact | 证据事实 | 归并多条主张为当前证据下的事实候选。 |

四个概念的分工:来源文档说"材料从哪来",摄入事件说"这次怎么进来的",主张说"材料里说了什么",事实说"多条主张归并后在当前证据下可以怎样表达"。

四个层次的处理流程见第 4 节;本节只说明对象分工。

`EvidenceFact` 不是最终事实裁决，而是当前证据下可被引用的事实候选。是否可用于推理升级，取决于来源可靠性、独立来源数量、冲突状态、新鲜度和治理状态。

来源可靠不代表其中每条主张都可靠;来源一般也可能包含可验证数据点。例如公司公告里的财务数据可靠性高,但未来展望仍是管理层口径;新闻转载本身可靠性较低,但如果引用交易所公告,应追溯原始来源;研报里的事实、估算、预测和判断要拆开处理。

### 3.1 常用主张类型

| 主张类型 | 含义 | 后续去向 |
|---|---|---|
| `reported_fact` | 材料声称已经发生的事实 | 事件、事实候选 |
| `data_point` | 表格、财报、数据库中的数值点 | 状态观测 |
| `estimate` | 估算值 | 观测或预期,低一档置信度 |
| `forecast` | 对未来的预测 | 市场预期或作者判断 |
| `guidance` | 管理层指引 | 市场预期/预期基准 |
| `author_judgment` | 作者判断 | 判断线索,不当事实 |
| `assumption` | 假设前提 | 状态假设或情景输入 |
| `rumor_or_unverified` | 未证实信息 | 隔离或低可信候选 |
| `correction` | 更正或修订 | 替代/失效旧主张 |

历史枚举如 `fact_observation`、`validation_evidence`、`falsification_evidence` 仍可兼容使用,但新抽取应优先按上表拆分事实、数据、估算、预测、判断和假设。

## 4. 证据是怎么一层层做出来的

| 层级 | 输入 | 产出 | 要求 |
|---|---|---|---|
| 来源文档 | 链接、文件、数据流、人工记录 | 来源 | 类型、可靠性、时间、定位齐全。 |
| 摄入事件 | 来源文档、摄入路径、解析配置 | 摄入记录 | 记录业务时间、系统时间、解析版本、操作者。 |
| 主张 | 摄入事件、原文片段、表格、数据点 | 最小主张 | 留原文位置、类型、状态、可信度、归一键。 |
| 事实 | 一条或多条主张 | 事实候选 | 记录支撑主张、置信度、冲突、有效期、归并口径。 |

这里的主张/事实和判断推理域的"信号""观测"分工不同:主张/事实是证据侧素材,信号表达它在推理链中的作用,观测表达变量在某时点的读数。

### 4.1 主张拆分规则

一条 `EvidenceClaim` 只表达一个最小可复核主张。凡是同时包含多个对象、多个时间、多个指标、多个方向或多个因果关系的句子,都应拆分为多条主张。

例如,"公司预计 2026 年 AI 服务器收入增长 30%,主要受北美云厂商需求拉动,同时毛利率可能改善"应拆成至少三条主张:

1. 公司预计 2026 年 AI 服务器收入增长 30%。
2. 北美云厂商需求是收入增长的主要驱动。
3. 毛利率可能改善。

其中,第 1 条是预测/指引类主张,第 2 条是原因解释类主张,第 3 条是预测类主张。它们不能被合并成一条事实。

### 4.2 证据状态分层

| 状态 | 含义 | 允许用途 |
|---|---|---|
| `candidate` | 自动抽取或人工录入的候选证据,尚未完成定位、归一、冲突和来源检查 | 可用于提示线索,不用于判断升级 |
| `normalized` | 已完成对象映射、口径归一和原文定位,但尚未通过可信度检查 | 可进入补证、冲突检测和人工审核 |
| `active` | 来源可追溯、原文可定位、类型清楚、冲突可控,允许被推理引用 | 可用于观测、信号、预期、判断的依据 |
| `quarantined` | 来源、权限、冲突或可信度存在问题,暂时隔离 | 不得用于正式推理,只能作为待核查线索 |
| `rejected` | 被明确拒绝的主张或事实候选 | 保留审计,不参与推理 |
| `invalidated` | 曾经有效,但被新证据证明失效 | 保留历史,可用于复盘 |
| `superseded` | 被更新版本替代 | 保留版本链,不再作为当前证据使用 |
| `conflicted` | 与其他证据存在未裁决冲突 | 降低置信度或阻断判断升级 |

新鲜度判断不得只看来源发布时间,还要看主张对应的业务时间和事实有效期。推理使用证据时,应优先按业务时间、`validFrom / validTo` 和状态过滤。

## 5. Relations：关系一览

完整定义以 `schemas/证据域/relations_evidence.yaml` 为准,关系都有方向。

| 关系代号 | 起点 → 终点 | 含义 |
|---|---|---|
| claimFromEpisode | 主张 → 摄入事件 | 主张来自某次摄入。 |
| episodeFromSource | 摄入事件 → 来源文档 | 摄入来自某来源。 |
| claimCitesSource | 主张 → 来源文档 | 主张引用来源里的具体位置。 |
| factSupportedByClaim | 事实 → 主张 | 事实由主张支撑。 |
| episodeMentionsObject | 摄入事件 → 任意对象 | 摄入提及某个对象。 |
| claimSupportsObject | 主张 → 对象候选/属性/边界/事实/补丁 | 主张支持对象候选、对象属性、边界裁定、事实候选或治理补丁,不直接证明正式对象变更。 |
| claimSupportsRelation | 主张 → 补丁 | 主张支持候选关系、关系修订或关系补丁,不直接改正式关系。 |
| claimInvalidatesClaim | 主张 → 主张 | 新主张使旧主张失效。 |
| claimSupersedesClaim | 主张 → 主张 | 新主张替代旧主张。 |
| claimConflictsWithClaim | 主张 → 主张 | 两条主张存在待裁决冲突。 |
| factConflictsWithFact | 事实 → 事实 | 两条事实存在待裁决冲突。 |
| factInvalidatesFact | 事实 → 事实 | 新事实使旧事实失效。 |
| factSupersedesFact | 事实 → 事实 | 新事实替代旧事实。 |
| factSupportsObject | 事实 → 对象属性/状态/补丁 | 事实支持对象属性、对象状态、候选观测或治理补丁,不直接改正式对象。 |
| factSupportsRelation | 事实 → 补丁 | 事实支持候选关系或关系补丁,不直接改正式关系。 |

证据不直接修改正式对象和正式关系,只能支持对象候选、属性修订、关系候选、边界裁定或治理补丁。正式变更必须通过语义结构域或治理域动作完成。

## 6. Actions：可以做哪些动作

完整定义以 `schemas/证据域/actions_evidence.yaml` 为准;每个动作都生成动作记录。

证据的状态走"候选 → 激活 / 拒绝 / 隔离 / 失效 / 替代"这条线:主张默认是候选,来源可追溯、原文可定位、冲突和归一化检查都通过后激活;事实根据交叉验证、时效、冲突和新鲜度决定状态。冲突保留双方证据,送冲突裁决。证据输出给推理或优化时作为依据,正式变更由治理域的补丁承接。第 7 节说明各动作的门禁规则与 ActionFollowup 侧 effect。

| 动作代号 | 作用 |
|---|---|
| RegisterSourceDocument | 登记来源文档。 |
| CreateEvidenceEpisode | 新建摄入事件。 |
| CreateEvidenceClaim | 新建主张。 |
| CreateEvidenceFact | 新建事实。 |
| ExtractEvidenceClaim | 从材料抽取候选主张。 |
| NormalizeEvidenceClaim | 归一化主张(对齐口径、映射对象)。 |
| ActivateEvidenceClaim | 主张通过检查后激活。 |
| RejectEvidenceClaim | 拒绝主张。 |
| QuarantineEvidenceClaim | 隔离主张。 |
| MarkEvidenceClaimConflicted | 将存在未裁决冲突的主张标记为冲突状态。 |
| InvalidateEvidenceClaim | 使主张失效。 |
| SupersedeEvidenceClaim | 用新主张替代旧主张。 |
| ValidateEvidenceFact | 校验事实并确定状态。 |
| MarkEvidenceFactConflicted | 将存在未裁决冲突的事实候选标记为冲突状态。 |
| RecordEvidenceConflict | 记录一次证据冲突。 |
| ExportEvidenceForReasoning | 把证据导出给判断推理使用。 |
| ExportEvidenceForOptimization | 把证据导出给本体优化使用。 |

## 7. Action 执行契约（Rules + Events）

证据域是全域推理的**输入阀门**：规则决定主张/事实能否激活或导出；事件驱动归一、冲突裁决和跨域推理入口。公共约定见 `00_框架概述` §8.2–8.3。

### 7.1 跨域出口链

```text
ActivateEvidenceClaim → EvidenceClaimValidated → ExportEvidenceForReasoning
  → EvidenceExportedForReasoning → CreateInferenceRun（判断推理域）
RecordEvidenceConflict → EvidenceConflictRecorded → HumanReviewRequested（治理域，同名不同域）
```

材料里声称发生的外部事实应进入 `EvidenceClaim`/`EvidenceFact`，再由判断推理域按需创建研究 `Event`；不得把材料原文塞进 ActionFollowup 载荷。

### 7.2 按动作族看门禁与事件

| 动作族 | 代表动作 | 必经规则 | 通过后 | 发出事件 | 典型下游 |
|---|---|---|---|---|---|
| 主张摄入 | `CreateEvidenceClaim`、`ExtractEvidenceClaim` | `claim_source_traceability` | 候选或隔离 | `EvidenceClaimCreated` | `NormalizeEvidenceClaim` |
| 主张激活 | `ActivateEvidenceClaim` | `claim_type_location_compatibility` | active | `EvidenceClaimValidated` | 导出推理/优化 |
| 受限导出 | `ExportEvidenceForReasoning` | `restricted_source_usage_gate` | 允许或进权限审核 | — | 治理审核 |
| 事实校验 | `CreateEvidenceFact`、`ValidateEvidenceFact` | `fact_claim_support_required`（`rule_refs`） | 事实候选可校验 | `EvidenceClaimValidated` | 导出 |
| 冲突登记 | `RecordEvidenceConflict` 等 | — | 冲突可见 | `EvidenceConflictRecorded` | `CreateActionProposal` |

### 7.3 规则卡片

#### `evidence.quality.claim_source_traceability`
- **回答问题**：主张能不能追溯到材料？
- **检查时机**：Create / Extract / Normalize 之前
- **执行者**：`schema_enforced` + `skill_must_check`
- **通过**：保留 candidate → **失败**：`quarantined`
- **正/反例**：有 `sourceEpisodeId` 或原文定位 ✓；只有二手摘要 ✗

#### `evidence.validation.claim_type_location_compatibility`
- **回答问题**：主张类型和原文位置是否相容？
- **检查时机**：Extract / Normalize / Activate
- **执行者**：`policy_gate`
- **通过**：`claim_type_allowed` → **失败**：`normalization_required` 或进审核
- **正/反例**：`data_point` 带表格坐标 ✓；`forecast` 无业务时间 ✗

#### `evidence.blocking.restricted_source_usage_gate`
- **回答问题**：受限来源能否导出给推理？
- **检查时机**：Export / Quarantine
- **执行者**：`schema_enforced` + `human_review_required`
- **通过**：`export_allowed` → **失败**：`permission_review_required`
- **正/反例**：继承最严格 `classification_marking` 且任务有权限 ✓；内幕材料无标记导出 ✗

#### `evidence.action_precondition.fact_claim_support_required`
- **回答问题**：事实候选有没有主张支撑？
- **检查时机**：Create / Validate / MarkConflicted
- **执行者**：`schema_enforced`
- **通过**：`fact_validation_allowed` → **失败**：`evidence_gap`
- **正/反例**：≥1 条 `factSupportedByClaim` ✓；空单方断言 ✗

### 7.4 ActionFollowup 差异字段

| 事件 | 触发源 | 额外说明 |
|---|---|---|
| `SourceDocumentRegistered` | Action | 终端事件，无后续 |
| `EvidenceClaimCreated` | Action | 同步触发归一 |
| `EvidenceClaimValidated` | Action | 可跨域触发导出 |
| `EvidenceConflictRecorded` | Action | `followup_kind: human_review_requested` |
| `EvidenceExportedForReasoning` | Action | 跨域触发 `CreateInferenceRun` |

## 9. Policies：合规标记与信息墙

这部分对需要处理内幕信息、受限材料、供应商数据或跨信息墙材料的研究员特别重要。

来源文档是整条证据链保密标记的起点。由受限证据派生出的主张、事实、观测、信号、判断、资产影响,都继承最严格的标记:

| 标记维度 | 规则 |
|---|---|
| 保密级别 | 公开 < 内部 < 受限 < 内幕,派生对象继承最严格输入标记。 |
| 信息墙 | 跨互斥隔离域时标记为冲突,进入信息墙审核。 |
| 许可范围 | 不可再分发、受供应商限制的内容保留使用限制。 |

一旦受限材料参与生成主张、事实、观测、信号、判断或资产影响,派生对象必须记录受限来源链路;即使后续内容被摘要、改写或归并,也不得丢失原始权限标记。

## 10. 输入与输出

| 输入 | 处理成 | 给谁用 |
|---|---|---|
| 文件、链接、数据库记录 | 来源文档 | 证据摄入、来源审计 |
| 材料解析批次 | 摄入事件 | 主张抽取、解析质量追踪 |
| 原文片段、表格、数据点 | 主张 | 对象支持、关系支持、冲突检测 |
| 多条主张 | 事实候选 | 判断推理域、优化、治理 |
| 证据冲突或缺口 | 触发补丁的依据 | 补丁、复盘 |

### 10.1 导出给判断推理域的出口

| 证据域输出 | 判断推理域承接对象 |
|---|---|
| 已发生事实 | 判断推理域 `Event`,表示外部研究事件,不等于 ActionFollowup |
| 数值数据点 | `StateVariableObservation` |
| 多条主张归并结果 | `EvidenceFact` 被引用为依据 |
| 管理层指引/卖方预测/价格隐含口径 | `MarketExpectation` |
| 作者判断/假设/预测 | `StateHypothesis` 或 `JudgmentOutput(candidate)` 的线索 |
| 支持/削弱/阻断某假设的证据 | `Signal` |
| 不确定、冲突或低可信内容 | 补证队列、冲突裁决或低置信信号 |

证据导出不是判断生成。运行端 / 消费型任务能力必须根据证据类型、状态、时间、权限和冲突情况,决定它应进入事件、观测、预期、信号、判断线索还是补证队列。

## RuntimeEvidenceSnapshot 的边界

`RuntimeEvidenceSnapshot` 是一次运行使用的证据截面，可以作为当次推理输入，但不是正式证据资产。若某条运行时证据需要沉淀为长期资产，必须回到 workbench 完成来源登记、主张拆分、冲突检查、归一和治理审核。

## 11. Policies：质量底线

机器策略见 `schemas/证据域/policies_evidence.yaml`。

| 检查 | 通过条件 | 处理方式 |
|---|---|---|
| 来源完整 | 来源文档有类型、可靠性、时间、定位。 | 标记低可信或进补证队列。 |
| 摄入可追溯 | 摄入事件关联来源,记录路径、解析版本、系统时间。 | 标记解析部分/失败/隔离。 |
| 主张可定位 | 主张有原文位置、类型、状态、归一键。 | 保持候选或隔离。 |
| 事实有支撑 | 事实由一条或多条主张支撑。 | 保持候选,进缺证据队列。 |
| 冲突可见 | 冲突用冲突关系记录。 | 进冲突裁决。 |
| 新鲜度可查 | 推理用证据时执行新鲜度过滤。 | 降置信度或阻断推理升级。 |

## 12. 上游与下游关系

| 方向 | 本域提供 | 下游怎么用 |
|---|---|---|
| 语义结构域 | 摄入、主张、事实 | 用提及/支持关系支撑各类研究对象。 |
| 判断推理域 | 主张、事实、来源 | 支撑事件、变量、假设、信号、判断,可兜底追溯来源。 |
| 治理域 | 证据冲突、缺口、候选关系 | 触发补丁,冲突进审核队列。 |
| 本体包 | 来源索引、证据矩阵、事实候选 | 作为复盘、规则评测、历史回放的证据资产。 |

## 13. 边界与交接

| 边界项 | 本域做的 | 交给谁 |
|---|---|---|
| 正式对象创建 | 提供对象候选和证据依据 | 语义结构域或生产型任务能力承接正式写入 |
| 判断生成 | 提供主张/事实和来源 | 信号、假设、判断由判断推理域承接 |
| 补丁处理 | 提供触发依据和材料 | 补丁由治理域承接 |
| 冲突裁决 | 记录冲突双方和类型 | 审核队列和复盘承接裁决 |
| 受限材料 | 记录权限和来源 | 可见性控制由权限系统和治理承接 |

证据域的边界可以按下面理解:

- 不直接生成投资判断或资产影响,只提供可追溯依据。
- 不直接修改正式对象和正式关系,只支持候选、属性修订、边界裁定或补丁。
- 不直接裁决所有冲突,只记录冲突双方和冲突类型。

当证据需要影响其他资产时,按方向交接:

| 证据影响的对象 | 承接位置 |
|---|---|
| 对象和关系变更 | 语义结构域动作或治理补丁 |
| 状态读数 | 判断推理域的状态变量观测 |
| 假设、信号、判断和资产影响 | 判断推理域 |
| 冲突裁决和权限审核 | 治理域 |
| 补丁发布 | 工程交付与Bundle契约 |
