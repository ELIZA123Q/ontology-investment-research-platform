# 基于本体的投研推理平台

把投研判断问题收敛成可验证任务：同一套概念、同一套证据要求、同一套推理规则，形成可复盘的判断，而不是临时拼材料、临时改口径。

## 目录怎么读

仓库分四层。编号相同不一定同类——例如 `02_判断结构` 是一次任务里「怎么拆问题」的阶段规范，`知识库_02框架` 是跨任务可复用的分析框架。

| 层 | 目录 | 回答什么 |
|---|---|---|
| 全局 | [`00_全局/`](00_全局/)、根目录 `validate_project.py` | 项目定位、最小跨阶段引用约定、全局质量标准（00A）、全库自检 |
| 研究阶段 | [`01_任务受理/`](01_任务受理/) … [`05_表达交付/`](05_表达交付/) | 单次任务本阶段怎么做、交什么、如何检查 |
| 知识库 / 本体 | [`知识库_02框架/`](知识库_02框架/)、[`知识库_03取证/`](知识库_03取证/)、[`知识库_04推理/`](知识库_04推理/)、[`一级通用本体规范/`](一级通用本体规范/)、[`二级半导体领域本体规范/`](二级半导体领域本体规范/) | 跨任务可复用的框架、取证、推理方法与正式定义 |
| 运行与评测 | [`运行校验/`](运行校验/)、[`示例1/`](示例1/)、[`示例2/`](示例2/)、[`评测集/`](评测集/) | 跨阶段检查工具、完整案例、评测任务 |

每个研究阶段目录通常包含：规范、（可选）附录、模板，以及本阶段检查脚本。

```text
00_全局/                 定位、质量标准
01_任务受理/ … 05_表达交付/   阶段规范 · 附录 · 模板 · 检查脚本
知识库_02框架/           分析框架（对应 02 选用）
知识库_03取证/           取证策略（对应 03 取证）
知识库_04推理/           推理方法（对应 04 定稿）
一级/二级…本体规范/      正式对象、关系、规则
运行校验/                全链发布前检查、结论强度对照规则、公共工具
示例1/ 示例2/            01—05 完整案例
评测集/                  研究价值评测（规范 docs/ + 运行时 runtime/）
validate_project.py      全库正式自检入口
```

职责边界见 [`00_全局/00_项目定位与边界.md`](00_全局/00_项目定位与边界.md) 第 9 节。

## 从哪开始跑

全库正式自检（本体、三知识库、评测集、双示例全链）：

```bash
python3 validate_project.py
```

单次运行的发布前检查：

```bash
python3 运行校验/validate_run.py 示例1
python3 运行校验/validate_run.py 示例2
```

分阶段检查命令见 [`运行校验/README.md`](运行校验/README.md)。各知识库目录内也有各自的检查脚本。

## 阶段与知识库的对应

- **02 阶段**决定本次判断什么；**知识库_02框架**提供一类问题通常怎样拆解。
- **03 阶段**决定本次证据是否够用；**知识库_03取证**提供证据组合、来源与停止规则。
- **04 阶段**形成本次判断；**知识库_04推理**提供合格证据怎样支持、削弱或改判。
