# 基于本体的投研推理平台

把投研问题收成可验证、可反证、可复盘的判断：依据是什么、能说到多强、什么情况下要改。

**v0.1**：目前完整样例主要在**半导体**（存储周期、管制与国产设备替代）。不是全行业自动投研产品。

## 你怎么用

1. **提出问题**（对象、时间、你要回答什么，尽量说清）。
2. **按本项目方法做一次研究**（人或助手让AI按照01-95规范执行，每个阶段都会输出结果，可分步骤输出，也可一次性输出所有结果）。
3. **读结果**：先看研报正文（05输出），再看判断简报（04输出）。

| 适合问 | 不适合问 |
|--------|----------|
| 供需/趋势会不会变、事件有没有影响、冲击怎么传导、某个假设还成不成立 | 查数、买卖建议、必须给出确定价格或涨跌 |

对照样例：[`示例1` 存储周期](示例1/) · [`示例2` 管制与国产替代](示例2/)。

## 你拿到的最终结果长什么样

一次完整研究，对外主要看两份：

| 文件 | 里面有什么 |
|------|------------|
| **研报（05）** | 当前判断、主要依据、适用范围、还要跟踪什么 |
| **判断简报（04）** | 每条结论能说到多强、最大限制、出现什么信号需要改判 |

前面的需求说明、研究逻辑、证据材料是过程底稿；只有要核对「问题有没有被偷换、证据够不够」时再翻。

读结果时看四件事即可：

- 现在的判断是什么；
- 凭什么（关键依据，而不是材料堆砌）；
- 边界在哪（不能外推到哪里）；
- 证据不够时有没有硬撑——**说不清就应写「暂不可判断」并标明缺什么**，这仍然可以是合格交付。

## 结论会受数据与来源限制

本项目**不自带数据库，也不保证能拿到所有行业数据**。能用的只有当时有权限、可核对原文的材料。常见情况：

| 实际情况 | 结果上你会看到 |
|----------|----------------|
| 关键数据要订阅库 / 没权限 / 公司未披露 | 对应结论变弱，或写成暂不可判断 |
| 只有新闻、转述、搜索或 AI 摘要 | 不能当硬证据；最多作线索 |
| 两套说法冲突又消不掉 | 两边都保留，把握下调，不选边抹平 |
| 只能用间接、代理指标 | 结论通常只能说到「有条件 / 观察」，不能写成确认 |

因此：**流程走完不等于一定有强观点。** 缺数据时，合格结果往往是「边界清楚的弱判断或缺口说明」，而不是编一个方向。

当前样例也主要证明半导体这类问题怎么写清楚；换行业时，方法和数据两边都可能更紧。

## 和日常工作的关系

- **第一次**：把问题问清楚 → 收集证据 → 下判断 → 写成研报。
- **有新材料**：在原判断上更新，并写明改了什么；不悄悄覆盖旧结论。
- **问题变了**：当作新问题重做。
