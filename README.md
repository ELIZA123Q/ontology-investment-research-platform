# 基于本体的投研推理平台

把投研判断问题收敛成可验证任务：同一套概念、同一套证据要求、同一套推理规则，形成可复盘的判断。

## 当前版本

**v0.1（方法试点）**。一级通用流程与校验已可跑通，但领域资产与完整样例仍主要聚焦**半导体产业**（周期判断、出口管制与国产设备替代等）；其他行业与更多应用场景尚未铺开，不视为通用投研产品。

定位与文档职责见 [`00_全局/00_项目定位与边界.md`](00_全局/00_项目定位与边界.md)。表达原则：正文用研究语言；系统 ID 与状态码进 YAML/CSV（§9.3）。

## 研究员从哪读起

1. [`00_全局/00_项目定位与边界.md`](00_全局/00_项目定位与边界.md) — 项目做什么、不做什么  
2. [`00_全局/00A_高质量产出判别标准.md`](00_全局/00A_高质量产出判别标准.md) — 文首「研究员读法」  
3. 按阶段读规范：[`01`](01_任务受理/) → [`02`](02_判断结构/) → [`03`](03_数据与证据/) → [`04`](04_推理/) → [`05`](05_表达交付/)（每份开篇有「研究员先看什么」）  
4. 方法库：[`知识库_02框架`](知识库_02框架/README.md)、[`知识库_03取证`](知识库_03取证/README.md)、[`知识库_04推理`](知识库_04推理/README.md)  
5. 完整案例：[`示例1`](示例1/)、[`示例2`](示例2/)（尤其看 `05` 研报与 `04` 判断简报）

以 **`知识库_*`** 为跨任务方法权威入口；根下若仍有旧版 `02框架库` / `03取证策略库` / `04推理方法库` 等目录，请以知识库为准。

## 目录怎么读

| 层 | 目录 | 回答什么 |
|---|---|---|
| 全局 | [`00_全局/`](00_全局/) | 项目定位、全局质量（00A）、跨阶段约定 |
| 研究阶段 | [`01_任务受理/`](01_任务受理/) … [`05_表达交付/`](05_表达交付/) | 单次任务本阶段怎么做、交什么、如何检查 |
| 知识库 / 本体 | [`知识库_02/03/04`](知识库_02框架/)、[`一级/二级本体规范`](一级通用本体规范/) | 跨任务可复用的框架、取证、推理方法与正式定义 |
| 运行与评测 | [`运行校验/`](运行校验/)、[`示例1/`](示例1/)、[`示例2/`](示例2/)、[`评测集/`](评测集/) | 检查工具、完整案例、评测任务 |

阶段与知识库分工：

- **02 阶段**决定本次判断什么；**知识库_02框架**提供一类问题通常怎样拆解。
- **03 阶段**决定本次证据是否够用；**知识库_03取证**提供证据组合、来源与停止规则。
- **04 阶段**形成本次判断；**知识库_04推理**提供合格证据怎样支持、削弱或改判。

## 执行与校验（可跳过）

```bash
python3 validate_project.py
python3 运行校验/validate_run.py 示例1
python3 运行校验/validate_run.py 示例2
```

分阶段检查见 [`运行校验/README.md`](运行校验/README.md)。业务权威分层：一级本体定义类型与规则；二级 `business_instances.yaml` 管理可复用变量与模板；单次任务范围与判断结构由 02 的任务本体视图承载；CSV、审计 YAML 与报告字段是投影，不是第二套事实来源。
