# 分析师视角使用协议

## 研究设计

视角库位于 `研究方法/分析师视角/analyst-lenses.yaml`，记录有日期的原始研报或本人著作、讲话所支持的候选假设。先确定任务问题、市场、研究期限及已选框架，再按适用边界选择零至少数视角。不得根据任务文字中的人名或关键词自动选人，也不要求四人同时出现。未能核对原文时，不得归因给分析师；可另以研究者自己的假说提出，但不要冒用视角卡。

新增或修订卡片时，先核对 `研究方法/分析师视角/README.md` 的原文审计原则。尤其区分卡片的 `proposition`/`theoretical_structure` 与本项目的 `research_operationalization`；同一作者的第二篇材料只是上下文核验，不自动证明第一篇命题普遍成立。

请求仅在选用视角时声明：

```yaml
methodology:
  analyst_lens_refs: [AL-GL-01]
  analyst_lens_horizon: medium # short | medium | long；由研究设计显式确定
  analyst_lens_selection_reasons:
    AL-GL-01: 经济与融资条件可能背离，影响本题的行业风格解释
```

`market_scope` 也须显式声明。选择理由必须说明对问题的增量解释，不得写“该分析师著名”等权威诉求。原文发布日期晚于研究信息截面的卡不能使用。时点性观点不得改写为当下建议。

## 使用与报告

每张卡只提出可证伪预测、竞争解释和待观察信号。先查原始出处、发表日期和适用期限，再用当前独立证据检验；原文自身不是当前市场事实。证据相同的多个视角只算一份证据，观点冲突时保留冲突和区分它们的未来信号，不做投票或平均分。

只有视角实质改变主解释、增加重要竞争解释或改变监测信号时，报告才展示：视角及实际使用的 `source_refs` 所指原文链接/日期、当前支持证据、反证或未获反证的限制、对结论的具体影响。无实质影响的已选视角只留在计划审计记录，不在正文机械罗列。正式判断和人工发布门槛维持不变。

将方法提升为通用宏观、产业或市场定价框架前，须另行完成跨来源、跨任务的独立验证，并确认概念区分、机制和停止条件稳定成立。视角卡不会自动晋升为框架；未完成验证的时点性观点仍只保留在有日期的卡中。
