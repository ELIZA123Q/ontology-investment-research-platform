# 投研因果识别

## 职责

把显式因果问题转成可检验的 `CausalDesign`，并在公开证据完成后形成有表达边界的 `CausalAssessment`。开始前读取[因果识别合同](references/causal-contract.md)和[R00-CAUSAL 通用协议](../../../研究方法/推理/A00-附录5_因果识别协议.md)。证据查询交给 `$touyan-gongkai-zhengju-diaoyan`；本 Skill 不自行增加来源角色、行业规则、投资判断或目标价。

仅当 `judgment_types` 包含 `mechanism_validation`、`causal_attribution`、`transmission_path` 或 `impact_realization` 时启用。纯事实、状态、趋势和阶段任务继续走原流程。自然语言出现因果词不能代替显式任务声明。

## 设计阶段

在取证前冻结 A、B、分析单位、适用范围、业务时间、作用时滞、估计对象和反事实。至少登记并区分：

- 正向结构 `A → B`；
- 反向结构 `B → A`；
- 共同原因结构 `C → A` 且 `C → B`；
- 有理论依据时登记反馈结构 `A ↔ B`。

记录已知混杂变量、中介、碰撞变量和识别假设。每个结构必须给出与其他结构不同的可观察预测和证伪条件。证据任务至少覆盖时序、机制中介、暴露差异、反向因果和共同原因；随机或准实验设计再按策略加入负向对照、安慰剂、事前趋势与稳健性检查。

缺少反向结构、共同原因结构、反事实或五类必要任务时停止取证并返回设计错误，不用事后解释补齐设计。

## 评估阶段

逐项引用 `evidence_handoff` 中的证据，评价时序、中介、暴露梯度、反向方向、共同原因及已启用的识别检查。来源数量按独立生产者和数据生成链计算。

输出必须选择一个 `relationship_conclusion` 和一个 `causal_status`。关系可为正向、反向、共同原因、双向、多重原因、仅相关或未决；状态可为已识别、较强支持、部分支持、仅一致、未识别或被反驳。不要用解释完整性替代方向识别，也不要把代表公司共变外推为行业因果。

表达严格跟随状态：

- `identified`：可写“A导致B”；
- `strongly_supported`：写“证据较强支持A对B存在因果作用”；
- `partially_supported`：只写“可能促成”；
- `consistent_only`：只写“相关”或“变化一致”；
- `not_identified`：明确无法区分 A→B、B→A 和共同原因；
- `contradicted`：明确目标方向被时序、必要中介或更强竞争结构反驳。

共同原因结论必须明确写出“A与B存在相关，但当前不支持A直接导致B”。只有两个方向分别具备合理时滞和中介证据，且设计阶段已登记反馈结构，才能输出双向关系。

## 交接

使用 `scripts/validate_causal.py` 校验设计与评估。校验通过后，把 `CausalAssessment` 交给研究总控形成 `form_causal_judgment`；正式判断必须回指该评估。第一阶段由 Agent 提供合同内容，不自动估计效应或发现因果结构。
