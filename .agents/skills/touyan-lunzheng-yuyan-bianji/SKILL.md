# 论证与语言编辑

## 职责

在最终报告或摘要发布前，提升论证清晰度和语言边界。不得新增事实、补写来源、改变判断等级、提高置信度或替代独立成品验证。

需要交付机器可检查的结果时，先阅读 [references/argument-language-edit-contract.md](references/argument-language-edit-contract.md)，并用 `scripts/validate_argument_language_edit.py` 校验输出。

## 检查顺序

1. 把用户问题拆成子问题，确认正文逐项回答。
2. 标出事实、计算、解释、假设、判断、建议和监测信号，避免混写。
3. 检查每个核心结论是否有最短证据链、竞争解释、决定性反证和改判条件。
4. 检查因果、超预期、低估、高估、确定性概率等强表达是否有相应流程和基线。
5. 删除或降级交易、仓位、目标价、收益承诺、下单执行和未授权择时表达。
6. 把长句、含混代词和口径跳跃改成清楚、克制、可审计的表达。

## 输出

交付顶层对象 `argument_language_edit`，包含：

- 可直接替换的修订文本或段落级修改建议；
- 被降级或删除的越界表达；
- 仍需生产者补证或改判的问题；
- 不应由编辑者修改的判断门槛。

语言编辑不得把 `needs_revision` 或 `block` 的研究包装成可交付版本。
