# 论证与语言编辑

<<<<<<< Updated upstream
## 职责

在最终报告或摘要发布前，提升论证清晰度和语言边界。不得新增事实、补写来源、改变判断等级、提高置信度或替代独立成品验证。

需要交付机器可检查的结果时，先阅读 [references/argument-language-edit-contract.md](references/argument-language-edit-contract.md)，并用 `scripts/validate_argument_language_edit.py` 校验输出。

## 检查顺序

1. 把用户问题拆成子问题，确认正文逐项回答。
2. 标出事实、计算、解释、假设、判断、建议和监测信号，避免混写。
3. 检查每个核心结论是否有最短证据链、竞争解释、决定性反证和改判条件。
4. 检查因果、超预期、低估、高估、确定性概率等强表达是否有相应流程和基线。
5. 删除或降级交易、仓位、目标价、收益承诺、下单执行和未授权择时表达。
6. 把长句、含混代词和口径跳跃改成清楚、克制、可审计的表达。

## 输出

交付顶层对象 `argument_language_edit`，包含：

- 可直接替换的修订文本或段落级修改建议；
- 被降级或删除的越界表达；
- 仍需生产者补证或改判的问题；
- 不应由编辑者修改的判断门槛。

语言编辑不得把 `needs_revision` 或 `block` 的研究包装成可交付版本。

## 强制规则

凡是战略研究、竞争分析、业务战略、增长路径、组织取舍、进入/退出或给 CEO/业务负责人/战略委员会阅读的报告，不得直接凭公开资料写正文，必须按项目 01—05 链路使用已批准判断与证据。

研究范围、读者和深度可以在对话或 01 中确认；但语言编辑不得把“范围较小”或“需要快一点”理解为可以降低成品质量。正式报告仍必须形成观点清楚、证据支撑、反证处理、行动可执行的战略研究表达。

CEO 战略报告必须读取并遵守：

- `delivery/01_标准/05_投研表达标准.md` 中的 CEO 战略报告要求；
- `delivery/02_模板/05F_CEO战略报告模板.md`；
- `workflow/stages/05_表达/05_投研表达与交付规范.md`；
- `references/ceo-strategy-report-quality-rubric.md`。

成稿后运行：

```bash
python3 governance/03_校验/validate_ceo_strategy_report.py <report.md>
```

## 输出原则

- 正文先给 CEO 可用的结论，不把研究过程、口径说明或免责写成主章节。
- 每个正文章节标题必须是实质判断，而不是“研究问题”“结论边界”“背景介绍”。
- 每段首句原则上是观点句，后续句子解释机制、证据、影响、反证或行动。
- 优势要拆到来源、机制、可持续性和失效条件。
- 劣势要拆到成因、后果、改善路径和观察指标。
- 战略举措要写清做什么、为什么现在做、依赖能力、落地动作、衡量指标和失败信号。
- 所有强因果表达都必须能回指到上游批准的事实、机制和反证；没有因果识别时，只能写相关、伴随、可能传导或假设性机制。

语言编辑不得补造上游没有批准的事实、因果、判断或建议；发现上游缺口时返回 02、03 或 04，而不是在 05 用写作补齐。
