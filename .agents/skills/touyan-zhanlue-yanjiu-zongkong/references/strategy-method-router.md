# 战略方法路由

本文件用于在 02 拆解前选择战略分析骨架。方法路由的目的不是把经典框架写成正文目录，而是把问题转化为可证伪、可取证、可行动的战略判断。

## 先判定问题类型

每个战略任务至少选择一个主方法，必要时选择一个辅助方法。不要同时堆叠多个框架，除非它们分别回答不同层级的问题。

| 问题类型 | 主方法 | 适用原因 | 必须产出的判断 |
|---|---|---|---|
| 企业或业务陷入增长、利润、竞争地位不清晰 | Rumelt Kernel | 先压缩关键挑战，避免把目标当战略 | 关键诊断、指导方针、协调行动 |
| 业务优先级、进入/退出、增长路径、资源配置 | Strategy Choice Cascade | 战略必须说明选择什么、放弃什么、靠什么赢 | 胜利目标、在哪里竞争、如何取胜、所需能力、管理系统 |
| 行业利润池、竞争压力、定位变化 | Porter Five Forces / Value Chain | 解释利润如何被供应商、客户、替代品、新进入者和同业竞争分配 | 行业吸引力、利润池迁移、位置选择 |
| 竞争优势、护城河、能力建设 | Capability / Activity System | 优势来自互相强化的活动系统，而不是单点资源 | 核心能力、活动组合、可持续性、失效条件 |
| 高不确定政策、技术、周期或监管变化 | Scenario / What-must-be-true | 用情景和必要条件替代单一路径预测 | 基准情景、上行情景、下行情景、触发条件 |
| 资本市场或资产管理战略 | Expectation / Pricing / Client Allocation Logic | 需要区分事实改善、预期差和客户配置行为 | 预期基线、超预期来源、配置转化路径 |

## 强制因果链

每个关键战略判断必须写成以下链条：

```text
事实或约束 -> 机制 -> 业务结果 -> 战略含义 -> 失效或改判条件
```

示例：

```text
若客户从单品购买转向组合配置，且公司拥有投顾、产品和账户入口，
则客户关系会从交易关系转为配置关系；
这会提升留存和交叉销售，但前提是产品线能覆盖核心风险收益需求；
若产品能力仍集中在单一赛道，则入口优势只能带来流量，不能形成资管壁垒。
```

禁止把相关性写成因果。以下写法必须退回 03 或 04：

- 只有同向变化，却写成“导致”“驱动”“证明”；
- 只有公司宣传或行业共识，却写成“优势来自”；
- 只有短期表现，却写成“长期可持续”；
- 只有愿景或规划，却写成“将形成壁垒”；
- 只有单一来源证据，却排除竞争解释。

## 方法到项目阶段的映射

- 01 受理：明确读者、决策用途、时间窗口和可接受交付深度。
- 02 结构：选择主方法，形成主问题、竞争解释、关键变量和候选因果链。
- 03 取证：为因果链中的每个环节分别找证据，尤其要找反证和替代解释。
- 04 裁决：确认哪些因果表达可以写成判断，哪些只能写成假设或观察项。
- 05 表达：不展示方法名称堆叠，只展示 CEO 可用的结论、取舍、动作和指标。

## 输出检查

进入 05 前，至少回答：

- 关键挑战是否被压缩成 1—2 个真正矛盾，而不是背景罗列；
- “在哪里竞争”和“如何取胜”是否同时成立，是否明确放弃项；
- 所需能力是否具体到活动系统，而不是“品牌、人才、科技”等泛词；
- 行动之间是否互相强化，还是只是并列项目清单；
- 每个强因果判断是否有事实、机制、反证和失效条件支撑。
