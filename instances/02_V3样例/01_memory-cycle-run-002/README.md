# 存储芯片周期研究样例

这是一个完整的存储器行业周期判断案例。可以跟着文件顺序走一遍，看研究逻辑是怎么从提问一步步串到报告和改判条件的。

## 研究问题

> 存储芯片库存是否在持续去化？是否已进入全面上行��期？需求修复的贡献能不能确认？

## 核心判断

- **库存**：多个独立口径指向持续去化，方向在改善（但不定量）
- **周期**：已进入去库后段。但合约价跌幅虽收窄却未转正，现货价仍在跌——**不够确认全面上行**
- **需求归因**：缺 OEM 出货/补库的终端数据，**不能确认需求修复贡献，也不应强行归因**

三条判断都有明确的边界和改判条件。证据不够的地方没有硬撑，直接写了「不可判断」。

## 为什么值得看这个案例

1. **示范了「说不清就写说不清」**——需求归因缺数据，判断简报明确写了 indeterminate
2. **区分了库存状态和周期阶段**——两个层面的判断各有独立依据和等级
3. **披露了证据冲突**——合约价在涨、现货价在跌，这个冲突没被回避
4. **给出了改判条件**——什么信号出现后需要重算结论

## 文件阅读顺序

```
01_task.yaml        → 研究问题和交付要求
02_structure.yaml   → 选了哪些分析框架、拆成几个判断单元
03_evidence.yaml    → 找到了什么证据、哪里缺数据
04_judgment.yaml    → 每条结论的等级和边界（最核心）
05_report.md        → 最终研报
05_expression.yaml  → 表达审计（报告有没有越权）
```

建议先读 `05_report.md` 看结论，再回看 `04_judgment.yaml` 理解「结论—依据—边界—改判条件」怎么落盘。

## 系统示范要点（维护者用）

三个判断单元（库存状态 J3 / 周期阶段 J2 / 需求归因 indeterminate），方法全链含 A09 拒绝和 A04 阻断，四类证据（支持/反证/冲突/缺口），竞争解释与信号链可追溯。增量更新仅使 JU-02 链 stale，JU-01 和 JU-03 保持 current。
