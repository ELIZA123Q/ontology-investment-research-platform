# 04_推理输出规范

## 研究员先看什么

04 回答：**在现有证据边界内，判断定到什么强度；05 可以写什么、不能写什么。**

**阶段定位：** 04 是运行时规则应用与判断生成，不是预先写好的推理库自动运行。真正推理发生在本次任务面对具体证据时：检查方法适用性、比较竞争解释、识别反证与阻断，并在 `method_application_register` 与 `RuleEvaluation` 中留痕。

| 你要交什么 | 业务说法 |
|---|---|
| 判断简报（2—4 页） | 一句话结论、各核心判断结果、已确认状态变化、主路径与最强竞争解释、对象分化、投资命题是否成立、改判信号、05 表达许可 |
| 推理审计 | 可复核的完整推理记录（机器侧；简报不堆状态码）。**完整推理域实例**只保存在本文件的 `business_instance_graph`；不另交 `04-*推理域实例清单*.yaml`（与 03 的跨域实例清单不对称，属 schema 4.0.0 设计） |

**怎样算完成：** 首句直接回答 01 的核心问题；每条方向性观点单独核对证据；不超过 03 给出的结论强度上限；事实 / 推论 / 未决分开；清楚限定 05。

**常见失败：** 用整包证据状态支持所有观点；叙事抬高结论强度；把「没找到」写成「不存在」；预写 05 标题、章节或图表方案；输出买卖建议或目标价。

风格锚点：[`instances/01_正式样例/01_存储周期`](../../../instances/01_正式样例/01_存储周期) / [`instances/01_正式样例/02_管制与国产替代`](../../../instances/01_正式样例/02_管制与国产替代) 的判断简报。方法见 [`methods/04_裁决`](../../../methods/04_裁决/README.md)。正文语言继承 [`00` §9.3](../../../governance/01_架构/00_项目定位与边界.md)。

工作链（研究语言）：

```text
冻结证据与推理输入 → 信号 → 规则评价 → 判断 → 边界与改判信号 → 05 表达许可
```

## 1. 本阶段负责什么、不负责什么

### 1.1 负责

1. 继承 01—03 的任务、对象、范围、判断时点和版本；
2. 检查输入配套一致，且未发生未说明的范围漂移；
3. 审阅 03 的可用范围、反证、冲突和缺口；
4. 使用 02 已选定的路径，按 `methods/04_裁决` 中的裁决原则对本次证据逐段应用；由运行时确认哪些方法 `executed`、哪些 `rejected/blocked/degraded`；
5. 对每条方向性观点单独核对证据；
6. 形成观点级判断、整体把握、关键不确定性和验证信号；
7. 输出判断简报与可复核推理审计；
8. 向 05 只交接：允许、限制、禁止表达哪些已审计判断，以及必须保留的条件、范围和改判信号；
9. 将边界、结构或证据问题反馈给 01、02 或 03；
10. 判定草稿、最低通过或高质量交付。

当 01 要求投资观点，或 05 拟将某条判断作为投资主线时，还必须调用 A10，分别判断「研究判断是否成立」和「是否足以形成投资命题」。

### 1.2 不负责

1. 不重新定义研究问题、对象范围或时间边界；
2. 不新增判断路径、关键变量或正式推理规则；发现结构变化须退回完整 02，不能借“方法”之名静默改结构；
3. 不搜索新材料、替换来源或改变 03 取数口径；
4. 不用 03 整体证据评估替代单条观点核对；
5. 不把未找到材料写成事实不存在，也不把证据不足写成反向结论；
6. 不把局部事实外推为整体方向；
7. 不输出个股评级、买卖建议、目标价、收益率预测或仓位建议；
8. 不承担完整论证、章节设计、标题摘要、图表组织或研报正文写作；
9. 不向 05 预写标题、摘要、章节计划、叙事主线或图表方案；
10. 不将单次结果直接写回正式本体。

上游不足时按返工去向退回，不自行补造证据或结构。

## 2. 正式输入与配套检查

04 必须同时读取同一任务链的：01 需求说明、02 研究逻辑与本体视图、03 准备说明与证据归档、已引用的正式本体版本、00A 质量标准。

开始前确认：任务与运行标识、判断时点与对象范围一致；01 核心问题未被偷换；02 每个关键路径与变量在 03 有对应准备结果；03 已完成且每个核心判断的最终把握、反证依据和关联路径可解析。身份冲突、关键引用断裂或范围不一致时，相关路径不得进入正式推理。

每次运行生成一对同主题、同日期、同序号的文件（判断简报 + 推理审计）。简报面向研究员，使用业务语言，不放质量自检表，不复制完整证据表。质量检查与完整证据链只进入审计。

## 3. 证据是否够用与推理边界

只有 03 标记为已完成的归档可进入正式 04。阶段完成只表示取证工作结束，不能自动允许任何观点进入正文。

04 必须读取 03 对每个核心判断给出的证据把握、反证记录和关联路径，并精确继承 02 的判断类型与内容指纹。主方法使用知识库 A01—A10；偏离默认须说明理由。结论强度等级的研究含义见 [`A00`](../../../methods/04_裁决/A00_裁决总则.md#统一等级规则)。

每条正式观点必须引用对应的「证据是否够用」评价；实际结论强度不得高于校验器给出的上限。若正文需要更强观点，须退回 03 补证据或解除路径限制，不能靠更完整的叙事提高等级。

**覆盖率 ≠ 充分性：** 覆盖率回答变量—锚点完成多少；充分性回答某个具体观点所需的关键前提、口径、时间序列、反证和传导条件是否已满足。

| 缺口类型 | 处理 |
|---|---|
| 逻辑失效性 | 关键前提或必要反证缺失；相关路径停止 |
| 限制性 | 主方向可判断，但强度、持续或范围不清；缩小观点或降低强度 |
| 补充性 | 不改变当前方向；放入审计或后续跟踪 |

须说明缺口影响哪个观点或路径，不能把所有缺口放进泛泛风险提示。

## 4. 推理执行与观点形成

先按 [`methods/04_裁决`](../../../methods/04_裁决/README.md#4-怎么用) 检查输入边界，再按 [`A00`](../../../methods/04_裁决/A00_裁决总则.md) 选择主方法；共用规则见 A00 及四份附录：附录1 路径与阻断、附录2 反证与竞争解释、附录3 改判与版本、附录4 通用认知错误。传导见 A06。规则库说明「怎样判断」，02 决定「判断什么」，03 决定「哪些证据可用」。

### 4.1 路径推理

每个关键传导环节须记录：待验证问题；对象与关键变量；支持/反证/冲突/缺口；适用、削弱与失效条件；路径走到哪一步及对后续影响。正文写成「成立、部分成立、受到削弱、证据不足、存在争议或不能继续向下推」，不直接堆英文状态码。

03 的「路径能否推理」与 04 的「推出来是什么」必须分开填写。

### 4.2 观点级标签与不确定性

读者用语见 [`00A`](../../../governance/03_校验/00A_高质量产出判别标准.md#33-结论强度)。每条重要观点单独标明当前能说到什么程度，不能用一个整体等级代替所有子结论。正文优先写成完整句子。

不确定性应区分：事实缺口、口径不一致、机制不确定、时点不确定、外推不确定、本体不确定——并影响观点强度，而不是只出现在简报末尾。

### 4.3 事实、推论和未决分开

必须区分：已发生事实；来源观点或预测；系统推论；条件假设；未决问题；后续跟踪信号。不得把来源预测写成事实，也不得把系统推论写成来源结论。

### 4.4 投资含义与投资命题

投资含义回答「这项判断对基本面、预期或风险意味着什么」，不回答买卖。常见落点：基本面趋势改善、边际改善、高位分化、原逻辑弱化、观察阶段。证据不足或冲突未解时原则上落在观察阶段。

需要投资观点时，按 [`A10`](../../../methods/04_裁决/A10_投资命题裁决.md) 另行检查：研究判断是否成立 → 相对事前预期有何差异 → 是否已反映在盈利修订/价格/估值 → 上行与下行是否不对称 → 是否有可验证收敛信号。结果：形成 / 条件性形成 / 观察 / 不形成 / 不能继续成立。无论等级如何，均不得输出评级、目标价或仓位建议。

## 5. 判断简报结构

04 的研究员文件是 2—4 页判断简报，不是缩短版研报。只承担：把判断定死、把边界说清、把表达许可交给 05。不得出现一页摘要、完整研报目录、长篇背景、图表设计或章节级论证。

1. **一句话结论** — 直接回答 01 核心问题，固定对象、时间与结论强度；
2. **核心判断结果表** — 对象、结论、强度、成立条件、限制、对总判断的作用（ID 只在审计）；
3. **已确认状态变化** — 对象自身发生了什么；起点未确认不得外推终点；
4. **主路径与最强竞争解释** — 一条主路径 + 裁决到哪一环 + 最强竞争解释如何改写主判断；
5. **对象分化** — 仅在机制或结论确有不同时保留；
6. **投资命题是否成立** — A10 裁决，不写交易建议；
7. **改判信号** — 2—5 个真正会增强/削弱/阻断/改判的信号；
8. **允许 05 表达什么** — 可作为核心论点 / 只能附条件或作观察 / 禁止表达；不得替 05 预写标题与章节。

## 6. 质量门槛与返工

本节是 04 质量要求与返工条件的唯一权威。全局见 [`00A`](../../../governance/03_校验/00A_高质量产出判别标准.md)。

### 6.1 阶段质量状态

| 状态 | 含义 | 处理 |
|---|---|---|
| 草稿 | 尚未完成校验 | 不得正式交付 |
| 最低通过 | 可内部试做 | 不得作为高质量交付 |
| 高质量通过 | 规则校验通过并达本节门槛 | 可正式交接 05 |
| 需返工 | 存在关键缺陷 | 返工 |
| 缺口停止 | 当前无法形成方向性判断 | 输出缺口说明 |

### 6.2 高质量要点

首句直接回答核心问题；简报只保留规定功能且状态变化与主路径分开；每条方向性观点单独核对证据；不超过 03 结论强度上限；事实/推论/未决分开；对象分化清楚；改判信号可观察；05 表达许可与审计一致；简报适合研究员快速审阅且控制在 2—4 页；审计能复核简报观点。

### 6.3 不得发布

开头未答核心问题；观点超过证据上限；用整体证据评估支持所有观点；细分被整体掩盖；验证信号不可观察；暂不可判断被包装成方向判断；只写风险不写验证信号；预写 05 标题/章节/图表组织；审计无法复核简报；简报膨胀为研报。

### 6.4 返工去向

| 问题 | 处理 |
|---|---|
| 观点过弱 / 过强 | 重写结论或降级 / 退回 03 |
| 对象分化不清 | 重写分化表 |
| 主导机制不清 | 回看 02 核心待验证命题，必要时退回 02 |
| 改判条件不可执行 | 重写改判信号 |
| 04 承担了完整论证 | 删除表达职责，交 05 |
| 审计与简报不一致 | 同步修正 |
| 上游证据无法支撑方向性判断 | 缺口报告或退回 03 |

## 7. 流程关系与原则

```text
01 明确要判断什么
→ 02 明确怎么判断
→ 03 明确证据支持到哪里
→ 04 在证据边界内定稿判断，并限定 05 表达许可
```

> 用最短篇幅把判断、边界、竞争解释、对象分化、投资命题和改判信号定稿，并清楚限定 05 可以表达什么。

## 8. MethodApplication 与显式规则评估

04 使用 `method_application_register` 取代仅列方法名称的 `method_library_usage`。每个关键 Claim/Judgment 必须引用至少一个 `executed` 的 `MA-nn`；被拒绝、阻断或降级的方法必须保留原因和替代方法，禁止删除不利记录。

`RuleEvaluation` 只执行 [`rule_authority_registry.yaml`](../../../governance/02_合同/rule_authority_registry.yaml) 登记的正式语义约束、证据约束或状态一致性约束。每个 `condition_result` 必须包含条件 ID、表达式、输入引用、结果和理由；仅写 `matched` 不合格。`reasoning_trace_required` 等旧治理检查只能映射到治理检查记录，不得作为商业结论支撑；A01—A10 只能通过 `MethodApplication` 使用，不得登记为本体规则。

完整追溯链为：`EvidenceClaim → EvidenceFact → Observation/Event/Signal → Hypothesis → RuleEvaluation + MethodApplication → Judgment → ReasoningTrace`。任何跳过信号/假设直接从证据事实生成最终 Judgment 的链路必须退回 03 或 04 重做。
