# 个人研究原则与案例复盘

`principles.yaml` 是候选和已确认原则的版本化档案。首批条目由用户在本任务明确提出的方向及两个历史研究设计提炼，**全部仍为候选**：案例反映系统的研究做法，不等于用户亲自认可。只有用户逐条明确确认后，才能将条目改为 `confirmed`，记录确认日期、确认依据及版本；被撤销的原则改为 `retired`。修改原则内容时新增同一 `lineage_id` 的条目，用 `supersedes` 指向旧版并递增版本，保留旧条目；同一谱系不得同时有两个已确认版本。确认前，规划器选择到的个人原则集合为空。

`case-ledger.yaml` 只登记已完成且可追溯的复盘，不复制研报正文。每条案例需有研究请求与原始设计路径、当时信息截面、验证窗口、原先命题、事后可观察结果、结果命中与否、当时推理质量、误差类型、原始证据引用和方法修订建议。结果命中不等于方法正确，结果落空也不自动说明方法错误。当前两个历史研究只用于回放测试，不补造复盘结果。

方法修订沿用[改判与版本协议](../推理/A00-附录3_改判与版本协议.md)：同类裁决错误在至少两个独立任务中重复并经复核，才可提出稳定方法变更；任何原则确认或晋升仍由用户决定。分析师视角库只给候选解释，不作为个人原则的自动来源或验证票数。

复盘条目最小字段：`request_ref`、`design_ref`、`information_cutoff`、`verification_window`、`original_thesis`、`observed_outcome`、`outcome_hit`、`ex_ante_reasoning_quality`、`error_type`、`evidence_refs`、`method_change_proposal`、`reviewed_on`。尚未到验证窗口或证据不足时，保留空台账，不伪造结案。
