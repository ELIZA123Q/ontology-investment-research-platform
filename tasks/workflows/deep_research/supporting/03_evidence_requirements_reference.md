本附录是**易错点与最常填项速查**，不平行维护机器合同。准入与返工以 [`runtime/workflow/stage_specs/03_证据/03_数据与证据准备规范.md`](03_数据与证据准备规范.md) 为准；枚举与 ID 以 [`public_contract.yaml`](../../../governance/02_合同/public_contract.yaml) 为准；完整列定义以 [`模板/03_数据与证据快照模板/字段清单.csv`](模板/03_数据与证据快照模板/字段清单.csv)、快照模板与 `snapshot_layout_03.py` 为准。

## 1. 最常填的 10 项（业务含义）

写证据要求或评价时，优先想清这十项；机器列名见字段清单 CSV。

| # | 要想清的问题 | 常见机器落点 |
|---|---|---|
| 1 | 服务哪个核心判断？ | `target_judgment_unit_id` |
| 2 | 这条证据起什么作用（主证据 / 交叉 / 反证…）？ | `evidence_role` / 角色列 |
| 3 | 对象、时间、产品规格等口径是否与 02 一致？ | `required_object_scope`、`required_time_scope`、可比口径字段 |
| 4 | 最低要什么质量、几个独立来源？ | `minimum_quality_level`、`minimum_independent_source_count` |
| 5 | 缺了怎么办（降级 / 补证 / 停止）？ | `missing_policy`、`stop_condition` |
| 6 | 是否允许代理、代理失效条件？ | `allowed_proxy`、代理相关表 |
| 7 | 实际取到了什么、缺口是什么，具体对应哪条 ER？ | 证据记录 / `GAP-*` / `evidence_requirement_ids` |
| 8 | 本核心判断最终把握（充分/受限/观察/不可用）？ | `evidence_grade`（Q0—Q4，界面用人话） |
| 9 | 反证查过没有、冲突消解了没有？ | 反证与冲突状态列 |
| 10 | 展示素材有没有、限制是什么（不写章节）？ | `delivery_readiness`、展示候选表 |

## 2. 易错点

1. **先搜后定要求** — 未预设证据要求就开始正式取数。
2. **用覆盖率当充分** — 变量填得多不等于核心观点门槛已满足。
3. **角色填满强迫症** — 不为凑齐五类角色而补无关材料。
4. **把搜索页 / AI 回答当证据** — 只能作线索，不可计入关键证据。
5. **同源当交叉验证** — 同一转述链不算独立来源。
6. **静默换口径** — 主源不可用时应明示替代口径及对强度的影响，或降级。
7. **预测当事实** — 指引、一致预期、卖方观点不得归一为已发生事实。
8. **在 03 写观点或 05 目录** — 03 只交代证据与素材边界。
9. **手工填写结论强度上限** — J 上限由校验器从把握、反证与路径派生。
10. **`ER-JU-nn` 替代 `ER-nn`** — 汇总行不能顶替 02 继承的规范主键。
11. **只绑 JU、不绑 ER** — 同一 JU 常有多个主证、反证或边界要求；事实和 gap 必须指向具体 `ER-nn`。
12. **证据门通过就把素材记 ready** — `evidence_readiness` 与 `delivery_readiness` 各自独立派生。

## 3. 需求拆解时至少想清的维度

需求目的、证据角色、对应对象/变量、最低字段、时间与口径、覆盖范围、质量门槛、来源结构、获取方式、路径与反证绑定、是否可能作展示素材、优先级。细则列名见字段清单，不必在 Markdown 平行维护长表。

---

## 4. 单项需求状态（人话）

| 状态 | 含义 |
|---|---|
| 已满足 | 达到最低证据要求 |
| 部分满足 | 有有效输入，但不足以完整支持 |
| 缺失 | 未取得有效材料 |
| 冲突 | 存在无法消解的证据冲突 |
| 阻断 | 关键来源、权限、口径或实例缺失，无法继续 |
| 不适用 | 经确认不适用于本次范围 |

机器枚举：`met` / `partial` / `missing` / `conflicted` / `blocked` / `not_applicable`。

单项状态的主键是 `ER-nn`，不是整个 JU。JU 把握由其必需 ER 的最薄弱项汇总；根问题能否完整回答再由 02 的 `task_answer_contract` 汇总必需 JU。

---

## 5. 覆盖率怎么算才不算作弊

须说明分母、计入规则、`partial` 是否计入及理由、未计入单元的影响。不得靠删锚点、缩小范围或复用宽泛主张抬高覆盖率。覆盖率高 ≠ 核心结论门槛已满足。

---

## 6. 展示素材就绪（只答素材，不答写法）

目标报告类型继承 01。总体状态：`ready` / `partially_ready` / `not_ready`。分维度看图表、表格、来源注释是否齐备；不适用可标 `not_applicable`。

`delivery_limit` 只写素材形态上限与必须保留的限制，不得写成章节、故事线、标题或投资要点。可展示数据候选必须来自本次归档，不得为图表补造数值。

## 7. 快照目录职责（一句话）

| 层 | 做什么 |
|---|---|
| `01_plan` | 本次证据要求与取证计划 |
| `02_assets` | 实际取得的来源、主张、事实、语义实例、推理输入 |
| `03_gate` | 证据是否够用、变量覆盖、路径就绪、缺口 |
| `04_05_materials` | 图表/表格/来源注释素材与交付准备度 |
| `manifest.csv` | 总索引与阶段/质量状态 |

完整目录树以governance/03_校验 README 与 `snapshot_layout_03.py` 为准。摘要给人读，CSV 给机器校验；两处出现时口径必须一致。
