# 01_附录1_任务受理字段与场景参考

本附录解释**场景、改写示例与易错点**，不平行维护机器合同。准入与返工以 [`01_投研判断任务受理与整理规范.md`](01_投研判断任务受理与整理规范.md) 为准；正式输出结构以 [`模板/01_投研需求说明模板.md`](模板/01_投研需求说明模板.md) 为准。

---

## 1. 运行场景（先看这里）

| 场景 | 怎么处理 | 必须检查 | 不应做 |
|---|---|---|---|
| 一次性完整输入 | 直接提取 | 核心内容是否完整、是否互相冲突 | 重复询问用户已经说清的事项 |
| 批量任务 | 继承或逐条直接提取 | 每条是否有独立边界 | 用统一批处理话术冒充每条用户回答 |
| 历史回放 | 继承 | 当时信息截止边界、原对象与原版本 | 把后见事实混入当时输入 |
| 定期更新 | 继承 | 既有需求是否仍有效；滚动时间是否需刷新 | 每次机械重复三问 |
| 增量运行 | 继承 | 本轮变更是否触及主对象、主通道、关键范围或交付 | 静默覆盖既有需求或把增量扩成全量重做 |
| 新问题且有歧义 | 用户澄清 | 哪一个问题最能消除结构性歧义 | 一次抛出固定问题清单 |

**批量：** 可共享批次级范围，但每个子任务仍需独立对象和规范化问题。  
**回放：** 事后事实只能进复盘，不能反向改写原始 01。  
**增量：** 只有结构性变更才触发追问或新版本；新增材料通常由 03 处理。

## 2. 改写与收敛示例

### 2.1 状态与趋势

原始：`存储芯片目前处于什么周期，本轮周期什么时候结束？`  
不合格：`研究存储芯片行业周期变化。`  
可用：`截至每次运行的数据截止时点，全球存储芯片中 HBM、非 HBM DRAM 与 NAND 分别处于什么供需与价格周期阶段；未来 6—24 个月内，哪些需求、库存、有效供给、价格和产能信号将支持周期延续，或表明周期转入见顶、正常化或下行？`

### 2.2 未经验证的事实前提

原始：`近半年 HBM 已经上涨，原因是什么？`  
可用：`近半年是否存在具有代表性的 HBM 价格上涨；若存在，其主要驱动来自 AI 需求、供给约束、客户提前采购、产品结构变化，还是其他因素？`

### 2.3 过宽事件问题

原始：`某地缘谈判对半导体产业有什么影响？`  
不能直接整理成「全球半导体全链综合影响」。应先判断能否提取唯一主线；不能时只问主线选择。收敛后可形成：`谈判缓和是否已经构成半导体材料与制造实物流压力缓解的信号，还是影响主要停留在市场情绪定价层面？`

## 3. 动态范围与交付原型

| 原始表达 | 01 的处理 | 不应处理 |
|---|---|---|
| 当前 / 近半年 | 按运行数据截止时点滚动解析 | 固化为文档生成日或某次绝对区间 |
| 代表性公司 / 最新公告 | 写明选择口径和刷新规则 | 写死一次性名单或不说明口径 |
| 历史时点 | 写明当时信息截止边界 | 使用回放时才知道的后见事实 |

| 交付原型（业务） | 适用问题 |
|---|---|
| 事件点评 | 事件、政策、公告或产业消息的影响 |
| 行业动态点评 | 行业数据、业绩会或多家公司信息反映的变化 |
| 行业周期判断 | 周期状态、拐点和切换条件 |
| 公司业绩点评 | 财报、指引、订单或经营更新 |
| 主题深度研究 | 技术、赛道、制度或产业趋势的深度研究 |

用户未指定报告类型时，可按核心问题推荐一个并标为可回滚假设；只有当选择会改变范围或拆分时才追问。

## 4. 常见输入怎么处理

| 输入 | 处理方式 |
|---|---|
| 明确判断问题 | 直接提取并检查质量门槛 |
| 行业状态 / 事件或政策线索 | 收敛为状态趋势或影响判断；多段机制时考虑路径判断 |
| 新公告、新数据 | 边界不变时继承原任务作增量更新 |
| 「这个逻辑还成立吗」 | 收敛为假设验证与更新判断 |
| 「当时判断对不对」 | 明确历史信息边界和原主任务类型 |
| 纯资料总结 / 行情查询 / 文本润色 | 通常不进本流程；用于更新判断时才进入 |
| 直接买卖建议 | 尝试改写为具体投资假设；仍不具体则澄清或不予受理 |
| 问题过大 | 收窄、拆题或追问核心主线；无法收敛则不予受理 |

## 5. 需求说明要写清的业务块

| 内容 | 要点 |
|---|---|
| 核心研究主线 | 主对象、比较范围（或「无比较」）、判断动作、唯一主通道、核心待验证问题、05 落点 |
| 时间口径 | 回看期 / 当前时点 / 前瞻期；不适用须标明原因 |
| 交付深度 | 结论说到什么粒度即可停；最低交付要求；不写成 02 路径或 04 结论 |
| 范围过宽 | 已收敛 / 需澄清 / 须拆题 / 不予受理 |
| 研究价值 | 分歧或未知、变化变量、影响路径、决策用途、为什么是现在 |
| 前提三分 | 已知事实 / 用户假设 / 待验证假设；系统默认可回滚，不混入用户假设 |
| 观察与线索 | 只保留能区分不同解释的维度；含支持、削弱、反证与竞争解释方向 |

观察维度用业务语言（需求、订单、库存、产能、价格等），不做指标堆砌。

## 机器结构（可跳过）

完整 YAML 以模板为准。输入解析 `input_resolution` 须标明：模式（`direct_extract` / `inherited_context` / `user_clarified`）、来源引用、系统理解五项、可回滚假设、真实澄清记录、未决结构性歧义（正式通过版须为空）。

正式通过版：`stage_status=complete`，`task_disposition=accepted`，范围过宽检查为 `pass`，研究价值通过且等级非 `low`。当前 schema `1.5.0`（含 `task_scope_contract`）；历史版本兼容规则见模板注释。不予受理说明 schema `1.1.0`，处置为 `out_of_scope` 或 `split_required`。
