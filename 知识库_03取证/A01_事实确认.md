# A01 事实状态取证

事实状态取证：先确认「有没有发生、走到哪一步」，再谈影响。

## 1. 什么时候使用

用于取得政策、公告、项目、交易、认证、客户关系或事件的**状态材料**：是否发生，以及处于计划、发布、生效、执行、完成、修订还是终止。

本方法只准备状态材料，不裁决影响多大。政策怎样传导转 A04；公司暴露转 A05／A06；市场反应转 A07。若起点事实未定，后续路径或预期问题通常先补本方法。

## 2. 取证逻辑

先固定目标事实的最小状态节点，再取材料。不要用模糊的「已经发生」跨越中间节点：

| 事实类型 | 状态序列 | 最常见错取 |
|---|---|---|
| 政策／规则 | 征求意见 → 发布 → 生效 → 执行 → 修订／失效 | 只拿到「发布」却缺生效／执行材料 |
| 项目／产能 | 规划 → 批准 → 开工 → 试产 → 量产 → 达产 | 只有开工材料却缺量产／达产材料 |
| 认证／导入 | 送样 → 测试 → 认证 → 小批 → 量产 → 复购 | 只有认证材料却缺复购／量产材料 |
| 交易 | 意向 → 签约 → 条件满足 → 交割 → 整合／终止 | 只有签约材料却缺交割材料 |

把复合陈述拆成主体、动作、对象、状态、业务时间和适用范围。发布时间、生效时间、业务发生时间和系统获取时间分别留痕。最新有效版本优先，但历史版本、修订和撤回不得删除。

做轻量反向检查即可：修订、撤回、失效、豁免、延期、否认、范围排除。不必单独做完整反向检索。

## 3. 最少必须取得什么

| 这份材料起什么作用 | 最低要求 |
|---|---|
| 主证据 | 承担法律、披露或统计责任的原文、原始字段或授权记录；能定位页码、段落或字段 |
| 反证与限制 | 修订、撤回、失效、豁免、延期、否认或适用范围排除材料 |

取数前先核对：对象、业务时间、定义、版本可追溯且匹配。

每项材料写一句：「覆盖了哪个状态节点；尚未覆盖什么。」只有标题、搜索摘要或二手转述时，材料只能作线索。

## 4. 优先来源

| 事实 | 首选 | 交叉来源 |
|---|---|---|
| 政策／监管 | 法规、监管机构、政府部门、法院、交易所原文 | 官方问答、执行细则、公司公告 |
| 公司事实 | 法定公告、年报、季报、招股书、问询回复 | 公司 IR、业绩会、可回源数据库字段 |
| 项目／交易 | 合同、批准、交割、备案、环评或招标文件 | 双方公告、地方正式文件 |
| 关系／认证 | 双方披露、客户名单、认证清单、合同披露 | 公司案例、产业数据库、一手调研 |

## 5. 完备度怎样受限

- 找不到原文或无法定位：观察或不可用。
- 状态动词材料不清：不得把材料写成「已执行／已交付／已量产」。
- 主体、时间或范围不清：完备度只能覆盖已确认范围。
- 后续修订／撤回材料改变原文：必须一并归档。
- 不同责任主体材料冲突且不能由口径解释：保留双方，完备度通常受限或不可用。

## 6. 交给 04 什么

```text
已覆盖的状态节点与确认范围（主体 + 对象 + 业务时间 + 产品／地区）
主证据定位：原文／字段／页码／版本
尚未覆盖的节点或范围
已检索的修订／撤回／否认材料
证据完备度：充分／受限／观察／不可用
待裁决问题：该事实在目标范围内处于哪一状态（由 04 裁决；本方法不写「已确认／已否定」类裁决语）
```
