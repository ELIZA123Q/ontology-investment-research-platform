# 03 取证策略知识库

本库保存可复用的取证知识，回答“某类判断需要什么证据、优先去哪里找、怎样评价证据能否使用、何时停止或降低结论强度”。单次任务的证据归档结构和交付要求由 [`03_数据与证据准备规范.md`](../03_数据与证据/03_数据与证据准备规范.md) 规定。

## 1. 库里有什么

| 目录或文件 | 内容 | 用途 |
|---|---|---|
| [`A_取证规则`](A_取证规则/A00_取证规则总览.md) | 事实、状态、趋势、传导、比较、财务、预期、反证和代理指标的取证方法 | 说明某类证据怎样取得和验收 |
| [`B_取证来源`](B_取证来源/README.md) | 来源分层、通用来源、半导体来源、专题来源和 OPS 查询手册 | 说明优先去哪里找、怎样查、数据是什么口径以及失败后怎样回退 |
| [`C_最低证据组合`](C_最低证据组合/00_最低证据组合使用说明.md) | 八类核心最低证据组合 | 防止用单一材料替代完整验证 |
| [`D_研究工作单`](D_研究工作单/01_取证任务单.md) | 任务单、来源经验、冲突处理、更新监测和复盘 | 执行单次取证并沉淀经验 |
| `00_strategy_registry.yaml` | 判断类型、规则和最低证据组合映射 | 系统对照用的权威索引 |
| `00_basket_registry.yaml` | 全库唯一的证据类别稳定 ID 与中文名称 | 防止 A、C、工作单和校验器使用同义异名 |
| `00_source_registry.yaml` | 来源画像、获取渠道和使用边界 | 系统对照用的来源索引 |
| `00_quality_gates.yaml` | 证据评价、冲突和缺失数据处理规则 | 校验用的质量标准 |

## 2. 本库与其他资产的边界

- [`知识库_02框架`](../知识库_02框架/README.md)负责确定判断结构和待验证观点。
- 03 取证策略库负责证据组合、来源选择、取得方法和质量评价。
- [`知识库_04推理`](../知识库_04推理/README.md)负责把已经确认可用的证据转化为判断。
- 单次证据、来源状态和「证据是否够用」的结论只保存在本次 03 证据归档中，不写回知识库。

搜索、数据库、MCP 和 AI 是获取或处理方式，不是事实来源。03 可以说明证据最多支持到什么程度，但不执行推理规则，也不形成最终研究结论。

## 3. 如何使用

每个关键判断按以下顺序处理：

1. 从 02 读取待验证观点、判断类型、竞争解释和改判信号。
2. 找出最可能改变方向、强度或排序的关键证据。
3. 由 03 按 `judgment_type_registry` 自动得到 `matched_recipe`，展开必要证据、强验证证据和反证；02 不提供 `default_recipe`。
4. 按来源指引安排主源、独立交叉源、反证源和失败后的替代来源。
5. 固定对象、业务时间、范围、单位、分母和修订状态后再取数。
6. 每取得一项材料，都说明它证明了什么、没有证明什么以及是否改变当前证据状态。
7. 处理冲突和代理指标，形成证据准入结论、缺口和下一验证点。

单次任务可直接使用 [`D_研究工作单/01_取证任务单.md`](D_研究工作单/01_取证任务单.md)。

## 4. 判断类型与主要规则

| 判断类型 | 主要规则 | 默认最低证据组合 |
|---|---|---|
| 事实确认 | A01 | 作为其他组合的事实部分 |
| 状态测量 | A02 | `ER-STATE-01` |
| 趋势或阶段 | A03 | `ER-TREND-01` |
| 周期阶段 | A03 | `ER-CYCLE-01` |
| 归因判断 | A04 | `ER-ATTR-01` |
| 机制传导 | A04 | `ER-TRANS-01` |
| 对象比较 | A05 | `ER-DIFF-01` |
| 业绩影响 | A06 | `ER-EARN-01` |
| 市场预期 | A07 | `ER-EXPECT-01` |
| 反证与竞争解释 | A08 | 使用主组合中的反证部分 |
| 代理指标 | A09 | 作为主组合的受限补充 |

完整映射以 `00_strategy_registry.yaml` 为准；所有证据类别 ID 以 `00_basket_registry.yaml` 为准；Q0—Q4 只在 `00_quality_gates.yaml` 定义。

## 5. 质量与准入标准

一项取证策略只有同时满足以下条件，才可作为正式知识资产：

1. 输入对象、时间、范围和口径明确；
2. 说明为什么需要这组互补证据，哪些材料不能互相替代；
3. 说明来源角色、独立性、获取方式和失败后的替代方案；
4. 主动检查反证、竞争解释、口径冲突和代理指标失效条件；
5. 给出停止条件、证据缺失时的处理方式和允许的结论强度；
6. 结果能够写入现有 03 快照和证据评价结构；
7. 单次案例不得直接升级为稳定规则，至少需要两个独立任务复现。

证据质量不能只用来源等级或材料数量表示。来源身份、主张性质、任务适配和证据组合位置必须分别评价。

## 6. 自动校验

```bash
python3 知识库_03取证/validate_strategies.py --strict-links
```

校验器检查四个注册表、判断类型选用、证据类别语义一致性、最低证据组合文档同步、质量与 04 枚举、来源指引、内部链接和三个最小端到端案例，不生成研究结论。复制本库到其他目录校验时可使用 `--root <目录>`。
