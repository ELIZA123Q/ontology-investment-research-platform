# B00_取证来源扩展治理规则

本文件不再重复目录导航、来源分层和具体来源清单。导航见 [README](README.md)，正式来源分层见 [B01](B01_来源分层与使用边界.md)，通用/行业/专题来源分别见 B02、B03、B04。本文件只保留跨文件的扩展治理和失败回退规则。

## 1. 来源选择顺序

```text
02 JudgmentUnit
→ 03 自动匹配 Recipe
→ 按 00_basket_registry.yaml 实例化 Basket
→ A 类规则确定取得、留痕与验收方法
→ B02/B03/B04 选择主源、独立交叉源和反证源
→ 对应 OPS 手册固定真实入口、查询参数、数据口径和回退路线
→ B01 检查来源角色和使用边界
→ 00_quality_gates.yaml 决定证据质量与 04 使用边界
```

不得先按手头资料拼观点，再倒推 Basket 是否满足。

## 2. 来源、内容与通道分离

| 概念 | 回答的问题 | 示例 |
|---|---|---|
| `SourceProfile` | 谁生产或发布信息 | 公司、监管机构、交易所、统计机构、行业数据库 |
| `ContentDomain` | 信息描述什么 | 政策、财务、供需、价格、贸易、航运、市场预期 |
| `AcquisitionChannel` | 怎样取得 | 官网、数据库终端、API、MCP、文件、内部系统 |
| `ArtifactType` | 实际取得什么 | PDF、HTML、CSV、API response、字段导出、纪要 |
| `AccessScope` | 能否使用和表达 | public、licensed、internal、confidential、restricted |

MCP、API、网页、搜索结果和文件检索都是通道或发现方式，不是事实来源。AI 摘要只能帮助定位原始材料。

## 3. 来源计划最小合同

每个 mandatory/counter Basket 在检索前至少记录：

| 字段 | 要求 |
|---|---|
| `basket_id` | 必须来自 `00_basket_registry.yaml` |
| `claim_or_measurement_type` | 事实、测量、关系、预测、观点或假设 |
| `primary_source_profile` | 最直接且最匹配的主源 |
| `cross_source_profile` | 生产链不同的交叉源 |
| `counter_source_profile` | 最可能发现反证或阻断的来源 |
| `independence_group` | 原始数据和转述链去重组 |
| `methodology_requirements` | 样本、定义、字段、修订和覆盖要求 |
| `acquisition_channel` | 通道、参数和留痕 |
| `fallback_sequence` | 主源不可得时的回退顺序 |
| `failure_effect` | 换源对质量、直接性和 04 上限的影响 |

## 4. 来源适配原则

S1—S8 描述默认来源角色，不是跨任务通用分数。按以下顺序选择：

1. 是否直接生产当前事实或测量；
2. 对象、业务时间、范围和口径是否匹配；
3. 方法、样本和修订是否透明；
4. 能否定位原文或原始字段；
5. 是否与其他证据真正独立；
6. 权限是否允许当前用途和表达；
7. 更新频率是否满足判断窗口。

公司法定披露适合确认公司财务，行业专业数据库更适合测量行业价格。不能因前者“层级更高”就让公司观点覆盖行业测量。

## 5. 非白名单原则

B02/B03/B04 是推荐优先来源，不是封闭白名单。新来源进入关键判断前必须补齐生产者、内容域、发布时间、业务时间、口径、方法、权限、定位和使用限制；未补齐时只作线索。

同一公司披露的新闻转述、同一数据库字段的多家转售、同一通讯社稿件的多次转载只计一个 `independence_group`。

## 6. 中国侧与全球侧检查

涉及中国政策、公司、贸易、物流或 A/H 股时，必须检查相应中国主源；涉及海外政策或海外公司对中国资产的影响时，同时检查海外原文与中国主管部门、公司或交易所披露。双侧材料口径不可比时保留各自“来源主张”身份，不强行合并为共同事实。

## 7. 来源失败与回退

主源失败先分类：

| 失败类型 | 处理 |
|---|---|
| 无结果 | 扩大预设检索范围或执行 fallback |
| 权限受限 | 记录 AccessScope，不绕过授权 |
| 字段停更/页面变化 | 查修订、替代字段或历史快照 |
| 口径或时间不符 | 不把“可取得”误当“可使用” |
| 方法不透明 | 降为受限来源或线索 |
| 获取故障 | 可在同一 SourceProfile 下换通道 |

只有获取故障可以在不改变来源身份的情况下换通道。换成另一来源时，必须重新评价直接性、独立性、业务时间、样本、口径、权限和 Recipe 最低门槛。

## 8. 扩展准入

新增行业或专题来源文件时，不得同时复制判断结构、传导规则或质量等级：

- B 文件只维护来源、适合证明什么、不适合证明什么、定位要求和回退方式；
- 场景路径和研究问题归 02 框架/场景卡；
- 取证方法归 A 类规则；
- 最低证据组合、反证与停止条件归 C 类 Recipe；
- Q0—Q4 只由 `00_quality_gates.yaml` 定义。

当来源接入达到高频、自动选择、接口版本、字段血缘和权限治理需求时，再升级独立数据源治理系统；当前 B 类不承担该职责。
