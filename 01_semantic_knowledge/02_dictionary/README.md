# 语义词典 — 术语统一表

> 上级目录：[`01_semantic_knowledge/`](../README.md) | 根目录：[`README.md`](../../README.md)

研究员说的话先在这里弄清楚「到底是什么意思」，再交给本体去认「系统正式认为什么对象」。好比行研报告里的术语规范——同一个概念可能有好几种叫法，这里负责统一。

## 里面有什么

| 文件 | 一句话说明 | 你需要管吗 |
|------|-----------|-----------|
| `01_core_terms.yaml` | **标准术语表**：系统正式使用的术语清单 | 加新术语时改 |
| `02_aliases.yaml` | **同义词**：不同叫法指向同一个标准术语 | 加新同义词时改 |
| `03_research_terms.yaml` | **投研概念**：投研里的模糊概念映射到可验证语义 | 加新投研概念时改 |
| `04_ambiguity_rules.yaml` | **歧义规则**：一词多义时怎么澄清 | 发现歧义时改 |
| `05_deprecated_terms.yaml` | **旧词兼容**：过时术语怎么处理 | 淘汰旧术语时改 |
| `domains/` | **领域补充**：行业专属术语 | 加行业术语时改 |

## 日常怎么用

1. 研究员说了一个词 → 系统先查词典，找到对应的标准术语
2. 标准术语再去本体（`01_ontology/`）找正式定义
3. 如果有歧义，按歧义规则先澄清口径

## 怎么维护

- 加新术语或同义词：写在对应 YAML 文件里
- **词典不是语义权威**——只管「叫什么」，不管「是什么」
- 语义定义在 [`01_ontology/`](../01_ontology/README.md)，不要在词典里另写一套定义
- 改完跑：
  ```bash
  cd 06_runtime && npm run domain:sync
  ```

## 常见问题

**Q：词典和本体什么关系？**
A：词典是「翻译层」——把人的自然语言翻译成系统认识的标准术语。本体是「定义层」——定义这些标准术语到底是什么。信息流：研究员说的话 → 词典归一 → 本体定义 → 知识图组织。

**Q：旧术语怎么处理？**
A：写在 `05_deprecated_terms.yaml` 里做兼容映射，不要直接删除——旧报告可能还在用。

## 技术附录（给开发维护者）

### 语义域四层分工

```
01_semantic_knowledge/
├── 01_ontology/         系统正式认什么（Object/State/Evidence/Judgment/Relation）
├── 02_dictionary/       人的话是什么意思（Term/Alias/Ambiguity/Research Concept）
├── 03_knowledge_graph/  对象与关系如何组织成图视图
```

### 信息流

```
研究员说的话
    ↓ 02_dictionary（他说的到底是什么意思？）
    ↓ 01_ontology（系统正式认为什么对象/状态/关系/证据？）
    ↓ 03_knowledge_graph（实例怎么连、provenance 图怎么投影）
```
