# 返工与重规划技能集

## 触发条件

- 下游阶段发现上游产物需要修改
- 高质量门禁失败需要返工
- 研究过程中需要调整判断结构或范围
- 关键词：返工、修改、补丁、重规划、变更集

## 核心原则

**返工是有成本的，必须受控、留痕、可追溯。** 每次返工记录返工原因、返工前快照、修改内容与影响范围。

## 组成文件

| 文件 | 职责 |
|------|------|
| `workflow_revise.ts` | 工作流返工主逻辑：支持 Stage01（范围）、Stage02（结构）、Stage04（判断）的受控返工，含补丁校验与下游影响分析 |
| `change_set.ts` | 变更集管理：变更的 diff 表示、合并、冲突检测 |
| `change_set_apply.ts` | 变更集应用：将变更集应用到当前产物，保留返工前快照 |

## 支持返工的阶段

| 阶段 | 返工触发 | 影响下游 |
|------|---------|---------|
| Stage01 | 范围变更、澄清补充 | 02→03→04→05 全链返工 |
| Stage02 | 结构调整、判断单元拆分/合并 | 03→04→05 返工 |
| Stage04 | 判断修正 | 05 返工 |

Stage03 和 Stage05 不支持独立返工入口——03 的修改通常由 02 返工触发，05 的修改由 04 返工触发。

## 使用流程

1. 确定返工目标阶段（target_stage: 1-4）
2. 加载当前产物与上游依赖
3. 生成受控补丁（controlled patch）
4. 校验补丁合规性（schema + 本体约束）
5. 计算下游影响范围
6. 应用补丁 → 保留返工前快照
7. 标记受影响的下游阶段为待重生成

## 输出规范

- 每次返工记录：target_stage、返工原因、返工前 attempt 编号、补丁内容、影响范围
- 返工后 attempt 编号递增
- supersedes_attempt 指向前一版本
