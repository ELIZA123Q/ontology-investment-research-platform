## 1. 单项证据可靠度评价细则

EvidenceAssessment 必须解释一项证据为什么能用于当前判断，而不能只继承来源层级或写一个 high / medium / low。评估采用五个可解释维度，每项 1—5 分：

| 维度 | 1 分 | 5 分 |
|---|---|---|
| 来源可靠性 | 来源身份、方法或责任边界不清 | 原始责任主体或权威数据生产者，方法与权限清楚 |
| 数据直接性 | 仅为主题相关背景或多手转述 | 直接测量、原文披露或直接对应判断对象 |
| 时间新鲜度 | 超出本次有效窗口 | 覆盖本次判断时点和业务窗口 |
| 口径匹配度 | 对象、单位、范围或定义不可比 | 与核心判断的对象、时间、地域和统计口径一致 |
| 独立验证程度 | 无独立来源，或所谓验证来自同源转述 | 至少一组真正独立且口径可比的验证 |

诊断总分为五项之和，范围 5—25：

| 总分 | 建议可靠度 | 使用含义 |
|---|---|---|
| 22—25 | high | 仍需服从证据角色、反证与判断类型门槛 |
| 17—21 | medium | 可使用，但必须披露最弱维度与范围限制 |
| 5—16 | low | 原则上只作背景、线索或受限输入 |

分数用于解释和排序，不是事实为真的概率，也不得与判断置信度相乘。以下硬限制优先于总分：

1. 无法追溯原始来源、权限不清或来源身份不明，直接 blocked；
2. 动态变量缺业务时间，时间维度最高 2 分，且不得支撑趋势判断；
3. 同源转述不得提高独立验证分；
4. 对象或口径错配时，即使来源权威，口径匹配度也不得高于 2 分；
5. 代理指标必须记录置信折扣，不能因其他维度较高而替代必需直接证据；
6. 单项 EvidenceAssessment 的 reliability_band 不得直接复制为 EvidenceReadinessAssessment 或 Judgment 的 confidence。

每项评估必须保存五维分数、总分、可靠度、最弱维度、评分理由和硬限制。EvidenceReadinessAssessment 再基于多项证据、必要证据组合、反证、冲突和代理依赖评价整个核心判断。

机器侧方法、证据角色与研究语言映射见 [`../03_agent_capability/02_skills/evidence_research/registry.yaml`](../../../03_agent_capability/02_skills/evidence_research/registry.yaml)；本附录与主规范冲突时，以主规范硬限制与校验器为准。

## 2. 基础质量底线检查维度

所有进入有效证据计数的材料，至少检查以下维度：

| 维度 | 要求 |
|---|---|
| 可追溯性 | 能回到原始来源、字段、页码、段落、查询参数、文件版本或内容指纹 |
| 来源清晰 | 来源生产者、发布者、获取位置和访问权限明确 |
| 主张类型清晰 | 区分事实、数据、估算、预测、指引、观点、假设 |
| 业务时间明确 | 动态内容必须说明业务发生时间、统计期或观测窗口 |
| 口径清晰 | 指标定义、单位、统计范围、产品规格、地域和币种明确 |
| 权限合规 | 获取和使用符合公开、授权、内部或保密边界 |
| 独立性 | 交叉验证来源不能来自同一原始来源或转述链 |
| 一致性 | 与本次固定口径、历史口径和其他来源不发生未解释冲突 |
| 完整性 | 核心字段不缺失，缺失字段已说明影响 |
| 适用性 | 与当前核心判断直接相关，不只是主题相关 |

以下材料不得进入有效证据计数：

1. 无法定位原始来源的网页摘要；
2. 搜索结果页或 AI 回答；
3. 来源权限不清的内部材料；
4. 无业务时间的动态变量材料；
5. 未区分事实和观点的二手转述；
6. 与当前核心判断无直接绑定的宽泛背景材料。

## 3. 判断类型加严

不同证据角色有不同专项质量门槛：

| 证据角色 | 专项质量要求 |
|---|---|
| 事实确认 | 必须有原文、主体、时间、适用范围；新闻转述不能替代官方或公司原文 |
| 状态测量 | 必须有业务时间、口径、单位、统计周期；动态变量不得只用发布时间替代业务时间 |
| 趋势与阶段 | 不得用单点数据判断趋势；至少说明方向、持续性、时间窗口和反向信号 |
| 机制验证 | 不得跳过中间节点；每个关键传导节点必须有证据或明确降级 |
| 对象比较 | 强弱排序必须绑定暴露度、弹性、约束或财务承接变量 |
| 财务影响 | 缺收入拆分、量价拆分、成本或毛利率口径时，不得做精细利润测算 |
| 市场预期 | 基本面改善不等于预期差；必须同时看盈利预期、价格反应或市场叙事 |
| 反证解释 | 无反证检查不得高质量通过；竞争解释未排除时只能条件判断 |
| 代理指标 | 必须说明代理对象、代理逻辑、适用条件、失效条件和置信度折扣 |

## 4. 质量问题与 04 结论上限映射

| 质量问题 | 04 最多能形成的结论 |
|---|---|
| 无法追溯原始来源 | `blocked`，不得进入方向性推理 |
| 权限或合规边界不清 | `blocked`，不得进入正式证据包 |
| 动态变量缺业务时间 | `conditional_only` 或以下 |
| 来源不独立却被当作交叉验证 | 不得作为交叉验证计入 |
| 核心证据完全依赖代理指标 | 原则上不高于 `conditional_only` |
| 单点数据用于趋势判断 | 不得形成趋势或阶段判断 |
| 财务测算缺关键拆分 | 只能方向性说明，不得精细测算 |
| 反证检查缺失 | 不得 `high_quality_pass`，不得强方向性输出 |
| 证据冲突未处理 | `contested`，必须表达争议或待验证 |
| 图表数据口径不稳定 | 不得标记为 `report_grade_ready` |

## 5. 取数方式修正与留痕

不同获取方式需要不同留痕要求：

| 获取方式 | 质量重点 |
|---|---|
| 网页 / 搜索 | 必须回到原始来源，记录 URL、发布时间、获取时间、段落或页码，搜索结果不得作为证据 |
| 数据库终端 | 必须记录库名、字段、查询条件、口径、导出时间和权限范围 |
| API | 必须记录接口版本、请求参数、响应时间、原始响应、字段血缘和错误状态 |
| MCP | 必须记录 Connector 名称、上游来源、查询参数、原始响应、字段血缘、权限范围和回放能力 |
| 文件上传 | 必须记录文件名、来源、版本、页码、表格、内容指纹和上传时间 |
| 人工调研 | 必须记录样本来源、访谈时间、样本偏差、是否一手、是否可交叉验证 |
| 内部系统 | 必须记录系统名称、字段定义、权限、脱敏状态、更新时间和可表达边界 |
| AI 抽取 | 必须回溯原文，标注模型抽取过程，关键字段需人工或规则校验，不得把 AI 生成内容作为来源 |

MCP、API、数据库终端和 AI 工具是获取通道，不是来源生产者。它们影响可审计性，不自动提高来源权威性。

## 6. 获取过程与工具留痕

每次获取至少保留查询或检索条件、对象和时间范围、获取时间、原始响应或材料快照、关键字段口径、异常与失败记录。数据库、API、MCP 和内部系统还应保留库或接口名称、版本、字段血缘和权限范围，使后续能够重新读取或复算。

原始文件可保存时，`raw_artifact_ref` 必须直接指向快照目录内的原始 PDF、网页响应、表格、接口返回或数据库导出。确因许可、权限、技术或存储限制无法保存原文时，可保存结构化取证记录包，但必须明示 `capture_kind=structured_evidence_packet` 和 `raw_content_included=false`，并保留原始定位、访问限制和每条主张的可复核位置。这种结构化包不等同于原始材料，审阅时必须按未保存原文的限制处理。

AI 可以辅助发现、抽取和归一材料，但关键数值、时间、单位和原文位置必须回到原始材料核验；模型生成内容不能作为正式证据来源。只能获得摘要而无法回到原始材料时，该内容只作为背景线索。

## 7. 正式材料的最低记录

进入正式证据包的材料必须保留来源身份、材料标题、业务时间、发布时间或统计期、获取方式、权限边界、原文或字段定位、口径说明、版本或内容指纹，以及本次允许和禁止的用途。结构化数据另记字段、单位、频率、币种、调整方式和查询条件；文本材料另记页码、段落或表格位置；人工材料另记样本、时间、偏差和权限。

缺少来源身份、业务时间、权限或复核位置的材料，可以保留为线索，但不得计入关键证据已经满足。

## 8. 材料处理留痕链路

每条进入快照的记录，至少应能回溯以下链路：

```text
证据要求预设
→ 取证规则
→ SourceProfile / 推荐取证来源
→ 获取方式
→ 原始材料或原始字段
→ 原子主张或原始数值
→ 清洗与归一处理
→ 对象/关系/事件/观测/证据记录
→ 绑定的状态变量、路径节点或核心判断
→ 质量等级
→ 04 可使用范围
```

不能回溯的材料不得进入有效证据计数。

## 9. 身份、数值、证据与定位归一

### 9.1 身份和关系归一

公司、产品、材料、设施、客户、供应关系、地区和资产必须进行身份归一。至少记录：原始名称、标准名称、别名、来源、归一规则、不确定性、是否为正式本体实例或本次任务记录。

关系实例必须说明关系类型、方向、时间、来源和证据状态。不得把推测关系写成已确认关系。

### 9.2 数值和时间归一

数值类材料必须保留：原始值、原始单位、转换后值、转换规则、业务时间、发布时间、获取时间、统计周期、口径说明、字段来源和查询参数。

时间必须区分业务发生时间、材料发布时间、系统获取时间和本次数据截止时点。

### 9.3 证据归一

证据记录应拆成最小可复核主张。每条证据至少说明：

| 字段 | 说明 |
|---|---|
| `source_document` | 来源文档 |
| `claim_text` | 来源中的最小主张 |
| `fact_candidate` | 归一后的事实候选 |
| `statement_type` | 事实、数据、预测、观点、指引、假设或估计 |
| `effect_on_judgment` | 支持、削弱、阻断、冲突或补充 |
| `target_node` | 绑定的路径节点或核心判断 |
| `evidence_basket` | 所属必要证据组合 |
| `quality_level` | 证据质量等级 |
| `confidence_limit` | 可支持的最高判断强度 |
| `counter_check` | 是否完成反证检查 |
| `usage_limit` | 可用边界和不可外推范围 |

来源观点不得被归一为已发生事实。预测和指引可以作为预期或情景输入，但不得替代实际观测。

### 9.4 原始材料定位与内容指纹

每个来源文档应保留：来源名称、标题、发布时间、获取时间、URL/文件名/数据库查询/API 请求/MCP 调用或内部文档 ID、页码/表格/段落/字段位置或响应字段路径、内容指纹或版本标识、访问权限和使用限制。

## 10. 执行流程

03 按以下顺序执行：

1. 读取并校验 02 产物；
2. 固定运行标识、时间范围、对象范围、数据截止时点、来源范围、取数方式范围和口径范围；
3. 识别核心判断的证据角色；
4. 为核心判断预设证据要求；
5. 调用取证策略库，匹配主取证规则、辅助取证规则、反证规则和必要的代理指标规则；
6. 展开必需证据组合和可选证据组合；
7. 查询 B00—B02 来源速查，匹配推荐来源和 SourceProfile，并明确 ContentDomain、AccessScope 和 ArtifactType；
8. 选择 AcquisitionChannel，并确定取数留痕要求；
9. 将判断路径拆解为数据、实例、证据和反证需求；
10. 为核心判断建立证据门槛表；
11. 按关键、必要、补充的优先级排序；
12. 按约定口径获取材料；
13. 记录每次获取尝试、参数、结果、失败原因和停止原因；
14. 对材料进行清洗、去重、身份归一、口径转换和时间对齐；
15. 将材料映射为对象实例、关系实例、推理输入和证据记录；
16. 对单条材料、证据记录、必要证据组合和判断单元进行质量评价；
17. 按“状态变量 × 锚点实例”形成覆盖矩阵；
18. 按核心判断检查最低证据门槛；
19. 检查支持证据、反证、竞争解释和来源冲突；
20. 判断每项需求、每个状态变量锚点、每条路径和每个核心判断的就绪状态；
21. 判断 05 可展示数据和成稿素材成熟度；
22. 形成准备 Markdown 和数据证据快照；
23. 输出 `stage_status`、各核心判断最终 `evidence_grade`、反证与路径依据以及 `quality_status`。

同一来源在同一参数和同一口径下，应产生可解释的一致结果。来源发生修订时，应保留获取时间、业务时间、版本说明和内容指纹，不得覆盖历史记录。

## 11. 补充、停止与反馈细则

### 11.1 补充规则

以下情况应继续补充材料：

1. 关键判断单元尚未满足最低证据门槛；
2. 证据要求预设中的必需证据组合缺失；
3. 反证或竞争解释尚未检查；
4. 来源不独立；
5. 口径冲突尚未解释；
6. 时间窗口不匹配；
7. 代理指标使用边界不清；
8. 证据冲突会改变 04 观点等级；
9. 03 无法说明 04 最多能形成的结论；
10. 目标 05 所需成稿素材缺口会导致交付形态降级。

### 11.2 单项停止规则

单项需求可以停止补充的条件是：

1. 已满足证据要求预设中的最低要求；
2. 支持证据和反证检查达到最低要求；
3. 口径和时间范围匹配；
4. 来源质量和取数方式可解释；
5. 继续补充不会改变该单元可推理状态；
6. 停止原因已记录。

### 11.3 整体停止规则

整体停止只区分阶段是否完成；证据是否够用、结论能说到多强，按每个核心判断分别记录：

1. 取证、评级、反证与路径记录已完成 → `stage_status=complete`；各核心判断按实际证据等级、反证结果与路径是否可推分别处理；
2. 部分路径因候选结构、口径或范围受限 → 对应核心判断/路径记为受限可推，不对整份材料包另写统一标签；
3. 证据不足但缺口清楚、取证过程已完成 → 仍可 `stage_status=complete`，相关核心判断最多只能到观察/线索级；
4. 引用链、来源、权限或关键前提断裂，无法完成取证 → `stage_status=blocked` 或 `returned`。

不得因为时间耗尽、材料数量较多或覆盖率表面达标而将 `stage_status` 标为 `complete`。

### 11.4 反馈规则

| 问题类型 | 反馈对象 |
|---|---|
| 研究问题、范围或用途不清 | 01 |
| 核心问题、路径、最低验证条件不清 | 02 |
| 本体无法承接关键机制 | 02 或本体优化 |
| 证据要求无法设定 | 02 |
| 来源、口径、权限或材料缺失 | 03 自身补充 |
| 数据质量不足以支撑方向性观点 | 03 降级或返工 |
| 证据不足以支撑方向性观点 | 04 降级或 03 返工 |
| 05 素材不足 | 05 降级或 03 补齐素材 |

## 12. 运行检查清单

每次 03 完成前，至少检查：

1. 是否继承 02 的核心问题和路径；
2. 是否固定运行范围；
3. 是否完成证据要求预设；
