# 方法库

研究员做分析时最常来的地方：可复用的研究框架、取证方法、裁决方法与表达模板。Runtime / Agent 选方法、组知识包时也默认读这里。

## 给谁看

- **研究员：** 日常主入口
- **维护者：** 方法登记、校验与和 Runtime 的边界

## 材料从哪来

| 库 | 回答什么 | 入口 |
|---|---|---|
| 研究框架 | 判断什么、怎么拆 | [`02_研究框架/`](02_研究框架/README.md) |
| 取证 | 证据够不够、去哪找 | [`03_取证/`](03_取证/README.md) |
| 裁决 | 证据能支持多强结论 | [`04_裁决/`](04_裁决/README.md) |
| 表达 | 怎么写成合格交付 | [`05_表达/`](05_表达/README.md) |

**不放在这里的：**

- 本体模型 YAML（含证据对象） → `01_semantic_knowledge/01_ontology`
- MCP 通道注册与 OPS → `03_agent_capability/04_protocols/mcp`
- 旧阶段产出模板 → `02_scenario_task/04_workflows/deep_research/templates`

## 怎么用（最短路径）

1. 先定要验证的命题与判断单元 → **02 研究框架**。
2. 为每个证据需求取数并评估完备度 → **03 取证**（通道见 MCP）。
3. 在合格证据上形成/削弱判断 → **04 裁决**。
4. 写成报告 → **05 表达**（不得新增未经 03/04 确认的事实）。

## 怎么维护

- 各库改正文后跑各自 `validate_*.py`（见子目录维护附录）。
- 路径稳定后可将本库 status 升为 authoritative；当前多为 migrating。
- 不在方法库复制本体枚举或 MCP 通道表。
