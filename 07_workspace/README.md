# 用户可见产品面

> 还不了解本项目？先读仓库根目录 [新手导读.md](../新手导读.md)。

说明「研究员打开工作台后看到什么」。真正的页面与接口实现不在本目录，而在 [`06_runtime/app/`](../06_runtime/app/)。

## 给谁看

- **研究员**：了解界面三块区域各自干什么
- **产品/维护者**：确认可信组件边界；改 UI 去 Runtime

## 材料从哪来

- **唯一实现**：[`06_runtime/app/`](../06_runtime/app/)
- **访问地址**：`http://127.0.0.1:3000`
- 本目录只作产品面登记与说明，不保存第二套前端代码

## 怎么用

1. 按根目录 [`README.md`](../README.md) 或 [`06_runtime/README.md`](../06_runtime/README.md) 启动服务。
2. 打开 `http://127.0.0.1:3000`。
3. 主界面三块：
   - **左侧**：研究主题与长期会话
   - **中间**：与 Research Lead 的连续对话、计划与执行状态
   - **右侧**：证据矩阵、假设、判断卡、报告与审计时间线等可信制品

关键证据与判断生成后，Runtime 会暂停并把确认集中放在中间区域。判断卡和报告支持直接编辑：每次保存生成新版本，判断修改后重新确认，报告修改后重新审计；证据事实不能在界面中随意改写。Agent 生成的初始判断只是提案，占位版本不能直接批准；研究员必须在判断卡中完成一次结构化复核并保存。

发起研究时可以展开“交付设置”，选择公司/行业/专题/更新报告、主要读者、深度与希望固定查看的章节。系统始终保留核心摘要、范围、判断、证据、风险与改判条件、来源附录；某一专业章节缺少输入时会显示“证据受限”，不会自动填入无依据内容。

确认研究计划时，右侧会同时显示“专业方法蓝图”，列出每个核心章节选用的研究框架、取证方法、裁决方法和退出条件。报告章节保留 MethodApplication、方法输入事实和缺口追溯；即使来源数量达标，核心方法所需的需求、供给、价格、机制或财务输入不完整，也不会弹出正式判断确认。

你不需要理解五域、阶段编号、Agent、Skill 或内部 ID。工程管理能力只出现在开发者设置，不进主导航。

## 怎么维护

- 改界面、路由、可信组件：只改 `06_runtime/app/` 与相关 Runtime 代码。
- 可信组件白名单在 `06_runtime/src/capabilities/registry.ts` 的 `TRUSTED_COMPONENTS`；Agent 只能组合预批准组件，不能生成任意 HTML/JavaScript。
- 改完在 `06_runtime/` 跑 `npm test`、`npm run typecheck`、`npm run build`。
