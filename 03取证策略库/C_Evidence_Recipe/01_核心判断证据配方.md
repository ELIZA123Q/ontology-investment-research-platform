# 核心判断证据组合（Evidence Recipe）

## 研究员快速选择

| 你正在回答的问题 | 先拿什么 | 再用什么确认 | 必须主动找什么反证 |
|---|---|---|---|
| 现在处于什么状态 | 直接指标、时间和口径 | 独立来源、历史位置 | 反向指标和口径冲突 |
| 是否形成趋势或拐点 | 同口径序列 | 相邻变量、扩散度 | 季节性、基数、修订和断点 |
| 周期在哪一阶段 | 需求、供给、库存/订单、价格 | 利润率、稼动、交期、资本开支 | 需求下修、库存回升、供给释放、分项背离 |
| 为什么发生变化 | 结果、候选原因、时间先后 | 不同暴露对象或历史相似期 | 共同驱动和替代解释 |
| 事件怎样传导 | 起点事实、中间节点、暴露和结果 | 路径两端独立来源、时滞 | 缓冲、替代、弱执行和结果未出现 |
| 谁更受益/受损 | 可比口径、暴露、弹性、承接 | 实际结果、权重敏感性 | 换口径后排序是否反转 |
| 对财务影响多大 | 暴露、量价、成本、确认与现金 | 历史校准和情景敏感性 | 成本抵消、交付、确认和回款风险 |
| 是否有预期差 | 事前共识、新信息、修订和价格反应 | 同业、历史、催化兑现 | 已计价、样本变化、市场共振 |

## 1. 配方总表

| Recipe ID | 主判断 | 主规则 | 必需篮子 | 强验证 | 必查反证 | 关键缺失时上限 |
|---|---|---|---|---|---|---|
| ER-STATE-01 | 当前状态 | A02 | 直接指标、业务时间与口径、范围基准 | 独立交叉验证、历史位置 | 反向指标、口径冲突 | 无直接指标且仅代理：`conditional_only` |
| ER-TREND-01 | 趋势/阶段 | A03 | 同口径序列、持续性/斜率、比较基准 | 相邻变量、扩散度 | 季节性、基数、序列断点、反向变量 | 无序列：只允许状态描述 |
| ER-CYCLE-01 | 周期位置 | A03 | 需求、供给、库存/订单、价格 | 企业毛利率/指引、资本开支、交期/稼动 | 需求下修、库存回升、供给释放、分项背离 | 四类核心篮子任一缺失：`conditional_only` |
| ER-ATTR-01 | 变化归因 | A04 | 被解释变化、候选原因、时间先后、暴露/反事实 | 多对象差异、历史相似期 | 替代解释、反向样本、共同驱动 | 无反事实或区分信号：`contested` |
| ER-TRANS-01 | 机制/事件传导 | A04 | 起点事实、中间节点、暴露对象、结果变量 | 路径两端独立来源、时滞验证 | 库存/合同缓冲、替代、执行弱化、无实际结果 | 中间节点缺失：`conditional_only`；起点不成立：停止 |
| ER-DIFF-01 | 对象分化 | A05 | 可比口径、暴露度、弹性、承接能力/约束 | 同窗口结果、敏感性 | 指标不可比、排序反转、兑现约束 | 无可比口径：不得排序 |
| ER-EARN-01 | 财务影响 | A06 | 收入暴露、量价、成本、利润率/现金 | 产能利用、订单/交付、情景敏感性 | 成本抵消、销量不足、确认时点、回款风险 | 缺量价成本桥：只能描述收入方向或更低 |
| ER-EXPECT-01 | 预期差/估值影响 | A07 | 事前一致预期、预测修订、价格反应、估值输入 | 同业与历史区间、催化兑现 | 已计价、样本变化、风险溢价或市场共振 | 无事前基线：禁止“预期差”判断 |

所有配方共同要求：证据可追溯、业务时间和范围匹配、主张类型清晰，并完成 A08 反证检查。配方只规定组合，不改变 `00_quality_gates.yaml` 的硬门槛。

## 2. 周期判断配方 ER-CYCLE-01

```text
Mandatory:
  demand + supply + inventory_or_order + price
Strong validation:
  company_margin_or_guidance + capex + lead_time_or_utilization
Counter:
  demand_revision_down + inventory_rebuild + capacity_release + segment_divergence
Minimum pass:
  四类必需篮子同一对象/分项/窗口，且至少两类变量方向一致、反证已检查
```

不能把全行业总量掩盖分项差异。若 HBM、通用 DRAM、NAND 的机制和价格方向不同，应分别建篮子和 JudgmentUnit。

## 3. 变化归因配方 ER-ATTR-01

```text
Mandatory:
  observed_change
  candidate_causes
  time_order
  exposure_or_counterfactual
Counter:
  alternative_explanation
  low_exposure_same_result
  common_driver
Minimum pass:
  主因发生在结果之前，并比至少一个主要竞争解释具有更强区分力
```

同期出现不等于因果。缺少反事实时，只能表述“与……一致”或“可能由……解释”，不得写“主要由……导致”。

## 4. 事件传导配方 ER-TRANS-01

适用于政策、地缘、供给中断、技术突破等事件：

```text
Layer 1 — Fact:
  official_text_or_event_fact + scope + effective_time
Layer 2 — Exposure:
  affected_link + dependency + inventory_or_contract_buffer + substitution
Layer 3 — Outcome:
  price_or_lead_time + order_or_delivery + company_financial_bridge
Counter:
  no_actual_supply_change + rapid_substitution + weak_execution + no_result_variable_change
```

必须逐层准入。只有事件事实而无暴露证据，只能确认事件；有暴露而无结果证据，只能形成条件性影响判断；起点事实不成立或关键中介被阻断时，停止向公司和资产层外推。

## 5. 三个组合预设

组合预设只负责选择主配方，不新增证据篮子。

| Preset ID | 适用问题 | 配方组合 | 最小逻辑 |
|---|---|---|---|
| RP-POLICY-IMPACT-01 | 政策是否产生实际影响 | ER-TRANS-01 + ER-DIFF-01；涉及财务再接 ER-EARN-01 | 正式文本 → 执行 → 行为 → 产业结果 → 对象分化 |
| RP-SUPPLY-SHOCK-01 | 地缘或供给中断是否冲击产业链 | ER-TRANS-01 + ER-STATE-01；涉及价格周期再接 ER-CYCLE-01 | 事件 → 暴露 → 缓冲/替代 → 价格/交期/订单 |
| RP-TECH-SUB-01 | 技术替代是否进入商业兑现 | ER-TRANS-01 + ER-DIFF-01 + ER-EARN-01 | 技术可行 → 认证/导入 → 量产/复购 → 财务兑现 |

## 6. 配方选择与停止

- 先按 02 的 `judgment_type` 选主配方，不按手头已有数据选配方。
- 一个 JudgmentUnit 原则上只有一个主配方；组合预设中的后续配方对应后续 JudgmentUnit。
- 背景材料、观点数量或来源数量不能替代必需篮子。
- 当继续取证不会改变当前准入等级，或关键材料在权限/时间边界内不可得，应记录缺口并停止；不得无限扩展来源清单。

## 7. 状态判断配方 ER-STATE-01

```text
Applicable:
  判断一个明确对象在冻结时点/窗口的状态，不判断持续趋势
Mandatory:
  direct_indicator
  business_time_and_scope
  definition_and_unit
  comparison_baseline
  counter_check
Strong validation:
  independent_cross_check
  historical_position
  revision_or_vintage_check
Proxy:
  允许代理补充；代理不能填满 direct_indicator 以获得 full_reasoning_ready
Minimum pass:
  直接观测可追溯，口径、对象、时间和单位匹配，反向指标未形成未解释冲突
Stop:
  状态、范围、反证和使用上限已确定
```

失败例：只有“渠道反馈偏紧”且无样本、规格、业务时间，用它确认全行业库存低位。处理：最多 `background_only`。

## 8. 趋势判断配方 ER-TREND-01

```text
Applicable:
  判断方向、持续性、斜率、扩散或阶段变化
Mandatory:
  comparable_time_series
  frozen_window_and_baseline
  persistence_or_slope
  seasonality_base_and_break_check
  counter_check
Strong validation:
  adjacent_variable
  breadth_or_diffusion
  first_release_vs_revised_vintage
Proxy:
  代理序列需验证方向与领先滞后稳定性；代理主导时最高 conditional_only
Minimum pass:
  同口径多点序列在预设窗口内持续，变化不是基数、季节性或口径断点主导
Stop:
  趋势标签、持续性、切换条件及竞争解释均可判定
```

失败例：单月同比转正便称需求拐点。处理：退回状态观察，等待持续性或互补变量。

## 9. 周期判断配方 ER-CYCLE-01 完整门槛

除第 2 节外，必须增加：

| 层 | 最低要求 |
|---|---|
| 分项 | 产品、地区或客户机制不同则分篮子，不先求行业平均 |
| 时序 | 说明需求/订单、库存、价格、供给的预期先后 |
| 阶段规则 | 在取数前定义阶段标签和切换条件 |
| 企业验证 | 至少检查毛利率/指引、稼动/交期、资本开支中的两类互补信号 |
| 反证 | 需求下修、库存回升、供给释放和分项背离必须检查 |

`Q3_directional_ready` 要求四类核心篮子对象和窗口一致，并符合预设阶段逻辑；仅“至少两个指标同向”只能达到受限方向判断。

## 10. 归因判断配方 ER-ATTR-01 完整门槛

除第 3 节外，每个候选原因必须形成相同结构：

```text
cause → expected_timing → expected_exposed_objects
      → expected_intermediate_signal → expected_counterfactual
```

主因至少比一个最强竞争解释多解释一项区分信号。只有同期发生和相关性时，表达上限为“与……一致/可能由……解释”。主因发生在结果之后、低暴露对象同样变化或共同驱动更强时，状态为 `contested` 或 `insufficient`。

## 11. 传导判断配方 ER-TRANS-01 完整门槛

除第 4 节外，实例化时必须将路径拆成 edge-level basket：

```text
start_fact
edge_01_mechanism_and_lag
intermediate_state
edge_12_exposure_and_behavior
outcome_variable
blocking_conditions
alternative_path
```

起点不成立直接 `blocked`；关键边只有概念逻辑时为 `hypothesis_only`；有中介和暴露但结果尚未出现时可形成带窗口的 `conditional_only`，不能写成已实现影响。

## 12. 对象分化配方 ER-DIFF-01

```text
Applicable:
  同一驱动下比较对象暴露、弹性、承接和兑现差异
Mandatory:
  comparison_universe_and_exclusion
  comparable_basis
  exposure
  sensitivity
  capture_constraint
  counter_ranking_check
Strong validation:
  realized_outcome
  weight_metric_window_sensitivity
Proxy:
  代理暴露只能支持分组，不能单独支持精确排序
Minimum pass:
  统一口径下至少覆盖 exposure + sensitivity + capture，unknown 与 zero 分开
Stop:
  排序/分层对合理口径变化稳定，或已确认只能描述暴露差异
```

失败例：按产业链位置和概念关联度给公司排序。处理：不得排序，最多背景名单。

## 13. 财务影响配方 ER-EARN-01

```text
Applicable:
  已验证的业务驱动向收入、利润、现金或资产负债表传导
Mandatory:
  company_or_segment_exposure
  volume_price_bridge
  cost_and_margin_baseline
  capacity_delivery_and_recognition
  parameter_provenance
  counter_financial_check
Strong validation:
  model_reconciliation
  historical_calibration
  scenario_sensitivity
  cash_and_working_capital
Proxy:
  行业均值和卖方参数只作受限情景，不替代公司实际输入
Minimum pass:
  目标科目到业务驱动的桥可复算，期间匹配，假设和事实分离
Stop:
  方向、范围、关键假设、最敏感参数和抵消项均明确
```

失败例：行业价格上涨 10%，直接推公司利润上涨 10%。处理：缺暴露、销量、成本和经营杠杆，不得利润测算。

## 14. 预期差与估值配方 ER-EXPECT-01

```text
Applicable:
  已准入基本面新信息与事前市场预期、价格和估值输入比较
Mandatory:
  admitted_fundamental_input
  prior_consensus_vintage
  estimate_revision
  relative_price_reaction
  valuation_input_change
  counter_pricing_check
Strong validation:
  consensus_distribution_and_sample
  event_timing_and_benchmark_control
  peer_and_history
  catalyst_realization
Proxy:
  单篇研报、目标价、新闻热度或股价不能代理完整共识
Minimum pass:
  事前基线可追溯，新信息和反应窗口匹配，市场/行业共振已处理
Stop:
  能区分基本面、共识修订、价格反应和风险溢价，或确认无法判断预期差
```

失败例：股价上涨后称市场已充分计价。处理：缺事前预期和基准控制，只能描述价格表现。

## 15. Recipe 准入矩阵

| 状态 | 条件 | 04 上限 |
|---|---|---|
| `full_reasoning_ready` | mandatory 全满足，强验证达到配方要求，反证与重大冲突处理完成 | 完整路径内推理 |
| `directional_only` | 主方向满足，但独立性、范围或强验证受限 | 弱方向判断 |
| `conditional_only` | 关键节点依赖代理、假设或尚未发生的结果 | 条件判断 |
| `insufficient` | 核心篮子缺失或方法不可复核 | 暂不可判断 |
| `blocked` | 起点、权限、核心对象或引用链断裂 | 路径停止 |
| `contested` | 支持和反证在同口径下重大冲突 | 并列争议与下一验证点 |

配方实例的状态不能高于最薄弱 mandatory basket，也不能高于关键前置 JudgmentUnit。
