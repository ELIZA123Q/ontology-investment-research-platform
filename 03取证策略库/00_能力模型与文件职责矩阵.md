# 03 能力模型与文件职责矩阵

> 本文是库管理员的完整性检查，不是研究员的日常操作手册。研究员使用 [00_研究员取证工作台](00_研究员取证工作台.md) 和 `D_研究工作单` 即可；管理员再把有效方法同步到注册表和校验规则。

## 1. 03 应该具备的九项能力（管理员视角）

03 的最大效用不是“找到更多材料”，而是把 02 的可证伪判断转换为 04 可以安全消费的、带边界的推理输入。完整能力闭环包括：

| 能力 | 必须回答的问题 | 主要资产 | 失败时结果 |
|---|---|---|---|
| C1 入口与冻结 | 上游结构是否可执行，本次对象、时间、口径和来源边界是什么 | 总览、03 规范 | 退回 01/02 或新建运行版本 |
| C2 证据需求设计 | 每个 JudgmentUnit 为何取证、最低需要什么、缺失如何降级 | EvidenceRequirement、A00 | 禁止无需求取数 |
| C3 配方匹配 | 这类判断需要哪些支持、强验证、反证和阻断篮子 | C_Evidence_Recipe、strategy registry | 不得 high_quality_pass |
| C4 来源与通道规划 | 每个篮子由哪类来源证明，如何取得、失败如何切换 | B 类、source registry | 降级、换源或停止 |
| C5 获取执行 | 查询参数、版本、权限、失败、重试和停止是否可复现 | A01—A09、acquisition_log | 材料不进入正式计数 |
| C6 抽取与归一 | 原始材料如何变成原子主张、事实候选、观测和关系 | A01/A02、证据本体 | 不得绑定推理节点 |
| C7 证据评价 | 来源可靠不等于主张可靠；证据对本次判断是否适用 | quality gates、EvidenceAssessment | 降低质量和使用上限 |
| C8 冲突与反证 | 支持与反证如何并存、竞争解释如何比较、何时阻断 | A08、counter basket | contested / blocked |
| C9 准入与反馈 | 判断单元能支持什么强度、获得何种推理权限，完整案例如何反馈 Recipe | EvidenceReadinessAssessment、Evidence Permission Matrix、D05 Evidence Pattern Case | 限制 04/05、返工或形成候选经验 |

任何文件若只罗列“关注哪些指标或网站”，但没有改变上述任一能力的执行结果，就不是核心策略资产。

## 2. 最小运行闭环

```text
冻结运行范围
→ 为 JudgmentUnit 建 EvidenceRequirement
→ 匹配 1 个主 Recipe 并展开篮子
→ 为每个篮子制定来源/通道/失败回退计划
→ 获取并保留原始材料、参数、版本与权限
→ 抽取 EvidenceClaim，归一 EvidenceFact / Observation
→ 评估单项证据的适用性、独立性、时间与口径
→ 主动检索反证并保留冲突
→ 评估篮子、路径与 JudgmentUnit readiness
→ 输出 04 最多能形成的结论、05 素材状态和返工路由
```

## 3. 文件职责与禁止重复

| 文件层 | 应保存 | 不应保存 |
|---|---|---|
| `00_*` | 总体流程、注册表、全局门槛、跨文件合同 | 行业事实、单次任务结论 |
| `A_取证规则` | 可重复执行的方法、输入合同、专项门槛、失败与停止 | 大量具体网站名单 |
| `B_取证来源` | 来源角色、适用主张、方法透明度、独立组、回退顺序 | 判断结构和结论方向 |
| `C_Evidence_Recipe` | 判断所需的篮子组合、最低通过、反证和降级 | 实际证据、当期数据、公司预测 |
| 单次 03 快照 | 本次 requirement、recipe 实例、篮子、来源、证据和准入状态 | 稳定方法论定义 |

## 4. 证据设计的四个正交维度

03 不得用一个“来源等级”代替所有判断。每项证据必须分别评价：

1. **来源身份**：谁生产或发布，责任边界与方法是否清楚；
2. **主张性质**：事实、数据、估计、预测、指引、观点还是代理；
3. **任务适配**：对象、时间、口径和证据角色是否匹配；
4. **组合位置**：它是主证据、交叉验证、反证、阻断还是背景。

S1 来源可以准确证明政策文本，但不能单独证明产业影响；S6 观点不能确认硬事实，却可能是预期差和竞争解释的必要证据。来源层级不是通用真值分数。

## 5. 最小充分与取证预算

取证优先级由“决策价值”决定，而不是材料易得性：

```text
优先分 = JudgmentUnit 决策权重
       × 该证据改变准入状态的可能性
       × 当前缺口严重度
       ÷ 获取成本与时效风险
```

不要求机械计算数值，但必须按此顺序组织工作：

1. 先取会阻断路径的起点事实和 critical 必需篮子；
2. 再取能够区分竞争解释的证据；
3. 再取真正独立的交叉验证；
4. 再取 05 必需展示材料；
5. 不会改变准入、范围或表达质量的材料停止补充。

## 6. 深度判别标准

一条 03 策略只有同时回答以下问题，才算达到可执行深度：

- 输入字段和冻结口径是什么；
- 证据篮子为何必要；
- 如何测量、归一、比较或验证；
- 什么来源能够证明何种主张；
- 哪些混杂因素、口径陷阱和失败模式必须检查；
- 冲突如何保留和裁决；
- 达到什么条件可以停止；
- 缺失或失败后 04/05 如何降级；
- 结果写入哪个快照文件和字段。

本矩阵是 03 策略库后续增补、评审和自动校验的总判据。
