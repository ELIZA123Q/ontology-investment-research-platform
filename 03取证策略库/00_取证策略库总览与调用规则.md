# 00_取证策略库总览与调用规则

## 1. 定位

03 取证策略库是 03 阶段的取证方法库。它位于 02 判断结构与 03 证据执行之间，负责把“这个问题该怎么分析”转化为“这个判断该如何取证”。

它不替代 02 框架库。02 框架库回答分析框架、判断单元、路径节点和最低验证条件；03 取证策略库回答证据篮子、推荐取证来源、取数通道留痕、质量门槛和降级规则。

```text
01 明确问题、范围、交付形态
→ 02 形成判断单元、路径节点、状态变量和最低验证条件
→ 03 调用取证策略库，预设证据要求并执行取证
→ 04 只消费 03 已准入的推理输入包
→ 05 在 03/04 限制内形成可读报告
```

## 2. 核心设计原则

### 2.1 先定证据要求，再取数

03 不得在未预设证据要求的情况下开始取数。每个核心判断单元都必须先声明：

1. 证据角色；
2. 最低证据等级；
3. 必需证据篮子；
4. 是否允许代理指标；
5. 首选 SourceProfile 和推荐取证来源；
6. 可接受取数通道；
7. 取数留痕要求；
8. 缺失时的 04 降级方式；
9. 停止条件。

### 2.2 取证规则保持有限 MECE

取证规则不按行业、公司或报告类型拆分，而按金融判断中稳定复用的取证问题拆分。

正式规则只保留九类：

| 规则 | 名称 | 解决的问题 |
|---|---|---|
| A01 | 事实确认取证规则 | 事情是否真实发生、是否正式生效、事实边界是什么 |
| A02 | 状态变量测量取证规则 | 某个状态变量当前是什么、如何测量 |
| A03 | 趋势与阶段判断取证规则 | 变量是否形成趋势、是否进入阶段或周期位置 |
| A04 | 机制传导验证取证规则 | A 如何影响 B，传导链是否成立 |
| A05 | 对象分化比较取证规则 | 谁更受益、谁更受损、谁更强或更弱 |
| A06 | 财务影响测算取证规则 | 变量变化如何传导到收入、利润、现金流或资产负债表 |
| A07 | 市场预期与定价取证规则 | 市场是否已反映、是否存在预期差和估值重估 |
| A08 | 反证与竞争解释取证规则 | 主判断可能错在哪里，是否有其他解释 |
| A09 | 代理指标使用规则 | 主数据不可得时，能否使用代理指标以及如何降级 |

不因单个行业、单个事件、单个数据源或单次任务失败而新增主规则。此类差异应进入 B_取证来源、代理指标目录、案例示例或 03 单次运行说明。

### 2.3 来源结构由证据域承接，B 类只给推荐来源

不得把来源生产者、内容领域、获取方式、权限边界和材料形态混在一个层级。

以下概念由一级通用本体证据域承接，03 取证策略库只消费这些对象和字段：

| 维度 | 回答的问题 | 示例 |
|---|---|---|
| SourceProfile | 谁生产或发布该材料，权威性如何 | 交易所、上市公司、Wind、TrendForce、内部数仓 |
| ContentDomain | 内容属于什么数据领域 | 金融市场、公司财务、行业供需、政策监管、经营链路 |
| AcquisitionChannel | 通过什么方式取得 | 官网、数据库终端、API、MCP、人工上传、内部系统 |
| AccessScope | 能否使用、如何使用 | public、licensed、internal、confidential、restricted |
| ArtifactType | 实际拿到的材料形态 | PDF、HTML、CSV、API response、数据库字段、访谈纪要 |

B_取证来源只回答“优先去哪取、哪些来源适合哪个证据篮子、主源缺失时如何降级”。它不是 SourceProfile 本体目录，也不是封闭白名单。

MCP、API、网页、人工上传、文件检索、数据库终端和内部系统都是 AcquisitionChannel，不是 SourceProfile。金融市场是 ContentDomain，不是 SourceProfile。内部数据需要拆成内部来源生产者、内部权限边界和内部取数通道。

### 2.4 质量规则三层叠加

数据质量不是只写在某个取证规则里，而是三层叠加：

```text
全局质量底线
+ 判断类型专项质量要求
+ 取数方式留痕修正
```

全局质量底线由 `00_quality_gates.yaml` 统一管理。A 类取证规则只补充专项要求，例如趋势判断不能用单点数据、财务测算不能缺量价成本拆分、政策事实必须回到官方原文。

### 2.5 04 使用上限必须由证据质量决定

03 的结果不是“材料包”，而是“带使用边界的推理输入包”。每条证据、每个证据篮子、每个判断单元都必须明确 04 使用上限。

可用等级建议如下：

| 证据等级 | 含义 | 04 使用上限 |
|---|---|---|
| Q0_unusable | 不可追溯、权限不清、口径不明或来源不合格 | 不得使用 |
| Q1_background | 可作为背景、线索或市场叙事 | 不得支撑方向判断 |
| Q2_reasoning_usable | 可作为受限推理输入 | 条件判断或倾向判断 |
| Q3_directional_ready | 可支撑方向性判断 | 可形成方向性观点 |
| Q4_report_grade | 可支撑高质量 05 图表、排序或核心论证 | 可进入研报级表达 |

## 3. 调用流程

03 调用策略库时，按以下顺序执行：

```text
读取 02 判断单元
→ 识别 judgment_type / required_evidence_roles
→ 生成 evidence_requirements
→ 查询 00_strategy_registry.yaml
→ 调用 A_取证规则
→ 匹配 evidence_recipes 并展开 evidence_baskets
→ 查询 B_取证来源与 00_source_registry.yaml
→ 选择推荐来源、SourceProfile 和 AcquisitionChannel
→ 执行取数并留痕
→ 应用 00_quality_gates.yaml
→ 形成 EvidenceReadinessAssessment 与 04 使用上限
→ 形成快照与准入结论
```

## 4. 证据要求预设

每个核心判断单元必须生成 `evidence_requirements.csv`。本文件只说明通用方法；单次运行必须把判断需求、配方、篮子、来源、证据和准入拆开记录。

| 字段 | 说明 |
|---|---|
| evidence_requirement_id | 本次证据要求 ID |
| target_judgment_unit_id | 02 核心判断单元 |
| target_path_node_id / target_state_variable_id | 对应路径节点和状态变量 |
| requirement_purpose | support / cross_validate / counter / block / background |
| evidence_role | primary_support / cross_validation / counter_evidence / blocking_condition / proxy_indicator / background_evidence |
| required_evidence_category | 价格、需求、供给、库存、订单、政策、估值等证据类别 |
| required_content_domains | 内容领域 |
| minimum_quality_level | 最低证据等级 |
| minimum_source_tier | 最低来源层级 |
| minimum_independent_source_count | 最少独立来源数 |
| mandatory_baskets | 必需证据篮子 ID |
| counter_baskets | 必须检查的反证篮子 ID |
| allowed_proxy | 是否允许代理指标 |
| preferred_source_profiles | 首选 SourceProfile ID |
| allowed_acquisition_channels | 允许取数通道 ID |
| stop_condition | 停止方向性推理的条件 |
| missing_policy / allowed_04_output_if_missing | 缺失时的处理和 04 降级 |

## 5. judgment_type 与取证规则映射

| judgment_type | 主规则 | 辅助规则 | 必需证据篮子 | 缺失时上限 |
|---|---|---|---|---|
| fact_confirmation | A01 | A08 | 原文、主体、时间、范围、修订/失效、反证 | insufficient |
| state_measurement | A02 | A09、A08 | 直接指标、业务时间、口径、交叉验证、反证 | conditional_only |
| trend_or_phase | A03 | A02、A08、A09 | 当前值、历史序列、持续性、对照变量、反证 | directional_only 或更低 |
| cycle_phase | A03 | A02、A08、A09 | 价格、需求、供给、库存/订单、反证 | conditional_only |
| mechanism_transmission | A04 | A01、A08 | 起点、中间节点、承接主体、阻断条件、反证 | conditional_only |
| object_comparison | A05 | A06、A08 | 暴露度、弹性、约束、可比口径、反证 | directional_only |
| earnings_impact | A06 | A02、A08 | 收入拆分、量价、成本、毛利率、敏感性、反证 | conditional_only |
| valuation_expectation | A07 | A06、A08 | 一致预期、股价反应、估值区间、同业比较、反证 | directional_only |
| counter_explanation | A08 | 视主判断而定 | 方向相反证据、竞争解释、阻断条件、冲突证据 | 不适用 |
| proxy_indicator | A09 | 视主判断而定 | 代理逻辑、适用条件、失效条件、交叉验证 | conditional_only |

## 6. 常见调用预设

调用预设不是独立策略文件，只是为了减少 03 执行时的选择成本。

| 任务类型 | 默认调用 |
|---|---|
| 行业周期报告 | A02 + A03 + A08 + A09 |
| 政策事件影响分析 | A01 + A04 + A05 + A08 |
| 供应链瓶颈分析 | A02 + A04 + A05 + A08 + A09 |
| 公司业绩弹性分析 | A02 + A05 + A06 + A08 |
| 估值重估与预期差分析 | A06 + A07 + A08 |
| 快速事件点评 | A01 + A04 + A08 |

预设只用于初始化，不能替代 judgment_unit 级别的证据要求预设。

## 7. 推荐取证来源调用规则

每个证据需求至少应明确：

```text
SourceProfile + ContentDomain + AcquisitionChannel + AccessScope + ArtifactType
```

03 运行时按以下顺序使用 B_取证来源：

```text
先用 A 类规则确定证据篮子
→ 用 B02 匹配跨行业通用来源
→ 如涉及行业专业变量，进入 B03_行业专用来源
→ 如涉及跨行业专题冲击，进入 B04_专题来源
→ 用 B01 校验 S1-S8 来源分层和使用上限
→ 将实际取得材料登记为 SourceDocument
```

B02/B03/B04 中的来源清单是推荐优先来源，不是封闭白名单。新来源可以使用，但进入关键判断前必须补充来源生产者、内容领域、发布时间、业务时间、口径、权限、可复核路径和使用限制。

示例：

```text
需求：获取公司近三年收入和毛利率
SourceProfile：公司年报 / 交易所文件 / Wind 财务数据库
ContentDomain：公司财务
AcquisitionChannel：交易所官网、Wind API、MCP Connector
AccessScope：public 或 licensed
ArtifactType：PDF、数据库字段、CSV export、API response
```

## 8. MCP 与 AI 工具规则

MCP、API、搜索、文件检索和模型摘要都是获取方式或处理方式，不是证据来源。

正确记录方式：

```text
来源：Wind 一致预期数据库
获取方式：MCP Connector
材料形态：API response / CSV export
留痕：查询参数、字段名、接口版本、获取时间、原始响应或内容指纹
```

错误记录方式：

```text
来源：MCP
来源：搜索结果
来源：AI 总结
```

AI 可以辅助发现、抽取、归一和生成摘要，但关键事实、数值和主张必须回到 SourceDocument 和 EvidenceClaim。

## 10. 扩展规则

新增 A 类取证规则必须同时满足：

1. 现有九类规则无法覆盖；
2. 它不是行业案例、来源类型或报告类型；
3. 它有独立证据篮子和降级规则；
4. 至少可在两个以上行业或任务中复用；
5. 会改变 04 使用上限。

新增 B 类取证来源时，应放入 B02/B03/B04 中最合适的位置，并说明它适合的证据篮子、来源层级、使用边界、常见口径陷阱和降级规则。若需要新增或修改 SourceProfile、SourceDocument、AcquisitionChannel、AccessScope、ArtifactType 或 ContentDomain 的对象定义，应修改一级通用本体证据域，而不是在 03 取证策略库中新建平行来源画像文件。

## 11. 一句话原则

> 03 取证策略库的价值，不在于列出更多来源，而在于让每个判断单元在取数前就知道：需要什么证据、用什么来源、如何留痕、何时降级、何时停止。
