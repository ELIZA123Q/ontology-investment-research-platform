# 00_取证策略库总览与调用规则

> 本文保留完整制度与系统接口。若是研究员第一次使用，请先看 [00_研究员取证工作台](00_研究员取证工作台.md)。日常工作按“判断分歧 → 最小证据组合 → 来源顺序 → 边取边判 → 冲突/反证 → 更新点”推进，不需要先读字段合同。

## 1. 定位

03 取证策略库是 03 阶段的取证方法库。它位于 02 判断结构与 03 证据执行之间，负责把“这个问题该怎么分析”转化为“这个判断该如何取证”。

本文件是方法库总览，不是 03 阶段规范。单次任务的入口检查、研究口径和截止时间、快照文件、阶段准入及 03→04 交接，以 [`03_数据与证据准备规范.md`](../03_数据与证据准备规范.md) 为准。本库只维护可复用的取证方法、最低证据组合、来源经验和专项降级规则。

它不替代 02 框架库。02 框架库回答分析框架、判断单元、路径节点和最低验证条件；03 先用 Evidence Recipe 把判断转为证据组合，再回答取证规则、来源映射、取数通道留痕、质量门槛和降级规则。

03 必须覆盖入口固定、证据需求、配方、来源规划、获取执行、抽取归一、单项评价、反证冲突、判断准入和返工反馈。完整能力定义见[能力模型与文件职责矩阵](00_能力模型与文件职责矩阵.md)。

用研究语言概括，03 最终交付五件事：

- **结论能说到哪里**：已确认、较支持、条件成立还是仅线索；
- **依据为什么够**：直接证据、互补验证和反证分别承担什么作用；
- **哪些问题仍未解决**：冲突、缺口、代理和时滞；
- **下一次何时更新**：日历节点、触发信号和改判规则；
- **本次经验如何复用**：来源经验、指标经验和对 02 的框架反馈。

```text
01 明确问题、范围、交付形态
→ 02 形成判断单元、路径节点、状态变量和最低验证条件
→ 03 调用取证策略库，预设证据要求并执行取证
→ 04 只使用 03 已准入的推理输入包
→ 05 在 03/04 限制内形成可读报告
```

## 2. 核心设计原则

### 2.1 先定证据要求，再取数

03 不得在未预设证据要求的情况下开始取数。每个核心判断单元都必须先声明：

1. 证据角色；
2. 最低证据等级；
3. 必需证据组合；
4. 是否允许代理指标；
5. 首选 SourceProfile 和推荐取证来源；
6. 可接受取数通道；
7. 取数留痕要求；
8. 缺失时的 04 降级方式；
9. 停止条件。

### 2.2 取证规则保持有限 MECE

取证规则不按行业、公司或报告类型拆分，而按金融判断中稳定复用的取证问题拆分。

正式规则只保留九类：

| 规则 | 名称 | 解决的问题 |
|---|---|---|
| A01 | 事实确认取证规则 | 事情是否真实发生、是否正式生效、事实边界是什么 |
| A02 | 状态变量测量取证规则 | 某个状态变量当前是什么、如何测量 |
| A03 | 趋势与阶段判断取证规则 | 变量是否形成趋势、是否进入阶段或周期位置 |
| A04 | 机制传导验证取证规则 | A 如何影响 B，传导链是否成立 |
| A05 | 对象分化比较取证规则 | 谁更受益、谁更受损、谁更强或更弱 |
| A06 | 财务影响测算取证规则 | 变量变化如何传导到收入、利润、现金流或资产负债表 |
| A07 | 市场预期与定价取证规则 | 市场是否已反映、是否存在预期差和估值重估 |
| A08 | 反证与竞争解释取证规则 | 主判断可能错在哪里，是否有其他解释 |
| A09 | 代理指标使用规则 | 主数据不可得时，能否使用代理指标以及如何降级 |

不因单个行业、单个事件、单个数据源或单次任务失败而新增主规则。此类差异应进入 B_取证来源、代理指标目录、案例示例或 03 单次运行说明。

### 2.2A 最低证据组合（系统名 Evidence Recipe）

Evidence Recipe 不等于 A 类取证规则。规则说明“某类证据怎样取得和验收”，Recipe 说明“某类判断必须由哪些必要证据组合共同支撑”。核心配方与组合预设见 [C_Evidence_Recipe](C_Evidence_Recipe/00_证据配方使用说明.md) 和 [核心判断最低证据组合](C_Evidence_Recipe/01_核心判断证据配方.md)。

```text
JudgmentUnit
→ 1 个主 Evidence Recipe
→ mandatory / strong_validation / counter 篮子
→ A 类取证规则
→ B 类来源映射
```

配方按判断类型稳定复用，不按网站、行业或报告章节扩张。行业和事件差异优先用组合预设和篮子参数表达。

### 2.2B 02→03 的固定交接要求

03 接收的每个关键判断（系统对象 `JudgmentUnit`）必须带三个系统交接字段：

```yaml
judgment_type: <稳定判断类型>
required_evidence_role: <首要证据角色>
default_recipe: <与 judgment_type 绑定的默认 Recipe ID>
```

03 的顺序固定为“读取 `judgment_type` → 取得 `default_recipe` → 检查是否适用于本次任务 → 按本次对象和范围展开最低证据组合”。缺任一字段，03 应退回 02，不得自行猜测。只有默认组合的前置条件明确不成立时，才允许记录 `parent_recipe_id / override_recipe_id / override_reason` 后更换；“某来源难取”或“手头恰好有另一类材料”不是更换理由。

稳定映射以 `00_strategy_registry.yaml#judgment_unit_default_recipe` 为唯一机器合同。`candidate_evidence_recipe_tags` 只能推荐辅助配方，不能覆盖默认主配方。

### 2.3 来源结构由证据域承接，B 类只给推荐来源

来源生产者、内容领域、获取方式、权限边界和材料形态的定义，只在[一级通用本体证据域](../一级通用本体规范/03_证据域规范.md)维护。本库不复制对象定义。

`B_取证来源` 只回答三个方法问题：某类证据优先去哪里找、哪些来源适合证明什么、主源不可得时怎样替代或降低结论强度。它不是来源本体目录，也不是封闭白名单。

### 2.4 质量规则三层叠加

全项目通用的质量底线、Q0—Q4 证据等级和取数留痕要求，只在 [03 阶段规范](../03_数据与证据准备规范.md#5-数据质量控制) 与 `00_quality_gates.yaml` 定义。本库不复制这些规则。A 类取证规则只补充某类判断特有的要求，例如趋势判断需要可比序列，财务测算需要量价成本拆分。

### 2.5 证据质量决定可以形成多强的结论

每套最低证据组合和专项取证规则都必须说明：关键证据缺失、相反证据命中或代理依赖过高时，应降低到哪种结论。具体等级和值域不在本库重复解释，统一引用 03 阶段规范和 `00_quality_gates.yaml`。

### 2.6 证据优先级按决策价值排序

critical JudgmentUnit 的阻断项、必需篮子和竞争解释区分证据优先于易得背景材料。每次取证计划至少区分：

| 优先级 | 内容 | 停止条件 |
|---|---|---|
| P0 阻断 | 起点事实、权限、核心对象、关键口径 | 不满足则路径停止 |
| P1 决策 | 会改变方向、强度或分化的必需篮子 | 达到最低准入或确认不可得 |
| P2 消歧 | 竞争解释、独立交叉验证、重大冲突 | 冲突已解释或状态确定为 contested |
| P3 表达 | 05 图表、排序、来源注释 | 达到目标交付素材门槛 |
| P4 背景 | 不改变准入的补充材料 | 默认不继续扩展 |

材料易得、来源知名或篇幅较长，不构成更高优先级。

## 3. 调用流程

03 调用策略库时，按以下顺序执行：

```text
读取 02 判断单元
→ 校验 judgment_type / required_evidence_role / default_recipe
→ 生成 evidence_requirements
→ 查询 00_strategy_registry.yaml
→ 继承 default_recipe；仅在记录 override_reason 后允许偏离
→ 展开 mandatory / strong_validation / counter evidence_baskets
→ 调用 A_取证规则
→ 按篮子查询 B_取证来源与 00_source_registry.yaml
→ 选择推荐来源、SourceProfile 和 AcquisitionChannel
→ 执行取数并留痕
→ 应用 00_quality_gates.yaml
→ 形成 EvidenceReadinessAssessment 与 04 最多能形成的结论
→ 形成快照与准入结论
```

## 4. 证据要求预设

单次任务怎样生成和保存 `evidence_requirements.csv`，只由 [03 阶段规范](../03_数据与证据准备规范.md#33-证据要求预设) 规定。本库负责为这些要求提供可复用内容：默认最低证据组合、必须检查的相反证据、可接受的代理指标、推荐来源以及证据缺失时的处理方法。

库文件不得自行增加一套单次任务字段；需要新增稳定机器字段时，应先修改正式本体、registry 或阶段输出 schema。

## 5. 判断类型、最低证据组合与取证规则映射

| judgment_type | 主配方 | 主规则 | 必需证据组合 | 缺失时上限 |
|---|---|---|---|---|
| fact_confirmation | 不单设配方，作为其他配方的事实篮子 | A01 | 原文、主体、时间、范围、修订/失效、反证 | insufficient |
| state_measurement | ER-STATE-01 | A02 | 直接指标、业务时间、口径、范围基准、反证 | conditional_only |
| trend_or_phase | ER-TREND-01 | A03 | 同口径序列、持续性/斜率、比较基准、反证 | 状态描述或更低 |
| cycle_phase | ER-CYCLE-01 | A03 | 需求、供给、库存/订单、价格、反证 | conditional_only |
| causal_attribution | ER-ATTR-01 | A04 | 被解释变化、候选原因、时间先后、反事实、反证 | contested |
| mechanism_transmission | ER-TRANS-01 | A04 | 起点、中间节点、暴露对象、结果、阻断/反证 | conditional_only |
| object_comparison | ER-DIFF-01 | A05 | 可比口径、暴露、弹性、承接能力/约束、反证 | 不得排序 |
| earnings_impact | ER-EARN-01 | A06 | 收入暴露、量价、成本、利润率/现金、反证 | 收入方向或更低 |
| valuation_expectation | ER-EXPECT-01 | A07 | 事前预期、修订、价格反应、估值输入、反证 | 禁止预期差判断 |
| risk_reassessment | ER-TRANS-01 + ER-DIFF-01 | A04/A05 | 触发、暴露、缓冲、结果、恢复条件、反证 | conditional_only |
| counter_explanation | 主配方的 counter 篮子 | A08 | 方向相反证据、竞争解释、阻断条件、冲突证据 | 不适用 |
| proxy_indicator | 主配方的代理补充 | A09 | 代理逻辑、适用条件、失效条件、交叉验证 | conditional_only |

## 6. 常见调用预设

调用预设用于减少 03 执行时的选择成本。通用 A 类规则预设保留如下；涉及政策影响、供给冲击和技术替代时，优先使用 C 类组合预设。

| 任务类型 | 默认调用 |
|---|---|
| 行业周期报告 | A02 + A03 + A08 + A09 |
| 政策事件影响分析 | A01 + A04 + A05 + A08 |
| 供应链瓶颈分析 | A02 + A04 + A05 + A08 + A09 |
| 公司业绩弹性分析 | A02 + A05 + A06 + A08 |
| 估值重估与预期差分析 | A06 + A07 + A08 |
| 快速事件点评 | A01 + A04 + A08 |

预设只用于初始化，不能替代 judgment_unit 级别的证据要求预设。

## 7. 推荐取证来源调用规则

每个证据需求至少应明确：

```text
SourceProfile + ContentDomain + AcquisitionChannel + AccessScope + ArtifactType
```

03 运行时按以下顺序使用 B_取证来源：

```text
先用最低证据组合确定必须取得的证据
→ 用 A 类规则明确取证和留痕要求
→ 用 B02 匹配跨行业通用来源
→ 如涉及行业专业变量，进入 B03_行业专用来源
→ 如涉及跨行业专题冲击，进入 B04_专题来源
→ 用 B01 校验 S1-S8 来源分层和使用上限
→ 将实际取得材料登记为 SourceDocument
```

B02/B03/B04 中的来源清单是推荐优先来源，不是封闭白名单。新来源可以使用，但进入关键判断前必须补充来源生产者、内容领域、发布时间、业务时间、口径、权限、可复核路径和使用限制。

示例：

```text
需求：获取公司近三年收入和毛利率
SourceProfile：公司年报 / 交易所文件 / Wind 财务数据库
ContentDomain：公司财务
AcquisitionChannel：交易所官网、Wind API、MCP Connector
AccessScope：public 或 licensed
ArtifactType：PDF、数据库字段、CSV export、API response
```

## 8. MCP 与 AI 工具规则

工具留痕和 AI 使用边界只在 [03 阶段规范](../03_数据与证据准备规范.md#63-获取过程与工具留痕) 维护。本库只保留一条选源原则：MCP、API、搜索、文件检索和模型摘要是获取或处理方式，不是来源；B 类来源文件必须指向实际的数据生产者或发布者。

## 9. 产物接口

单次快照的目录、文件、对账关系和 03→04 交接，只在 [03 阶段规范](../03_数据与证据准备规范.md#10-单次运行产物) 与输出模板中定义。本库不维护另一份文件清单。

本库只要求单次任务记录采用了哪个稳定规则、最低证据组合和来源指引，为什么适用，是否发生替换，以及本次结果应反馈到哪项方法资产。

### 9.1 完整案例如何反馈方法库

来源经验、指标经验、冲突处理和复盘反馈解决的是单项经验；Evidence Pattern Case 负责保存“一类判断在一次完整任务中，哪套 Recipe 为什么有效或失效”。它不新增 E 类目录，直接嵌入 `D_研究工作单/05_研究复盘与框架反馈.md`。

每个案例至少记录：判断类型、实际有效 Recipe、最有效证据组合、误判来源、新增反证、结构性不可得证据、04 无法消费之处和建议反馈对象。单个案例只能标记为 `candidate`；至少两个独立任务重复出现，并包含一个成功例和一个失败/降级例，才可提议修改稳定 Recipe 或规则。

案例必须保留“当时可得证据”和后验结果的时间边界，禁止事后把新增事实回填进原证据包。案例的价值是发现最低证据组合缺项、来源不可得和下游无法使用，不是证明原判断永远正确。

## 10. 扩展规则

新增 A 类取证规则必须同时满足：

1. 现有九类规则无法覆盖；
2. 它不是行业案例、来源类型或报告类型；
3. 它有独立必要证据组合和降级规则；
4. 至少可在两个以上行业或任务中复用；
5. 会改变 04 最多能形成的结论。

新增 B 类取证来源时，应放入 B02/B03/B04 中最合适的位置，并说明它适合的必要证据组合、来源层级、使用边界、常见口径陷阱和降级规则。若需要新增或修改 SourceProfile、SourceDocument、AcquisitionChannel、AccessScope、ArtifactType 或 ContentDomain 的对象定义，应修改一级通用本体证据域，而不是在 03 取证策略库中新建平行来源画像文件。

下一阶段不再新增 A/B/C/D 文件，先运行三类案例：存储芯片周期、地缘冲击半导体、公司业绩弹性。每次只观察五个问题：Recipe 是否漏项、A 规则是否缺步骤、B 来源是否真能取得、哪些证据结构性不可得、哪些输出 04 无法消费。只有案例重复暴露稳定缺口，才进入扩展评审。

## 11. 一句话原则

> 03 取证策略库的核心资产是“判断 → 最低证据组合 → 必要证据组合 → 来源映射”，不是来源清单；每个判断单元在取数前必须知道需要什么证据、何时降级、何时停止。
