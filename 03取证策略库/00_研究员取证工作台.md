# 03 研究员取证工作台

## 一句话定位

03 的价值不是“把资料找全”，而是用最少但足够的证据，判断 02 的核心命题目前能成立到什么程度。研究员应先处理最可能改变结论的证据，再处理背景和表达素材。

## 一张取证任务单

每个核心判断先填写一张任务单，不要求先理解 registry、字段表或脚本。

| 项目 | 需要写清楚的内容 |
|---|---|
| 待验证判断 | 02 的可证伪命题，不是宽泛主题 |
| 当前分歧 | 主解释与最强竞争解释差在哪里 |
| 决胜证据 | 哪项证据最可能改变方向、强度或排名 |
| 最低组合 | 至少需要哪几类互补证据，哪些不能互相替代 |
| 首选来源 | 谁最接近事实、谁能独立验证、谁代表市场预期 |
| 时间与口径 | 业务时间、发布日期、范围、单位、分母、是否修订 |
| 反证 | 主动去哪里找与主判断相反的材料 |
| 停止条件 | 何时证据已够；何时确认不可得并降级 |
| 更新安排 | 下一个验证节点、预计日期、触发式更新信号 |

## 研究员实际使用的六步法

1. **定胜负点**：从 02 找出最可能导致改判的节点，不先搜容易找到的材料。
2. **配最小组合**：直接事实、机制/状态、结果验证、反证通常承担不同角色，不能用同类材料堆数量。
3. **排来源顺序**：先原始责任方和直接数据，再独立验证，再解释性研究；搜索摘要只作线索。
4. **边取边判**：每拿到一项材料，就判断它证明了什么、没证明什么、是否改变当前判断。
5. **处理冲突**：先查口径、时间和样本，再比较方法和独立性；无法解释就保留争议，不强行平均。
6. **形成更新点**：输出的不只是本次证据结论，还要留下下一次更新看什么和何时改判。

## 证据够不够：四档研究语言

| 档位 | 证据状态 | 允许的表达 |
|---|---|---|
| A 已确认 | 关键直接证据、独立验证和反证检查均通过 | “已发生”“方向明确”，同时写边界 |
| B 较支持 | 主组合基本齐，仍有一项时滞或样本限制 | “证据较支持”“大概率”，写待验证点 |
| C 条件成立 | 机制合理但关键中介或结果尚未出现 | “若……则……”“目前与……一致” |
| D 仅线索 | 只有转述、观点、代理或单点数据 | “市场线索显示”，不得支撑方向结论 |

系统记录中的 Q0—Q4 必须对应到 04 可以使用的结论强度：Q4 核心判断、Q3 方向判断、Q2 条件判断、Q1 仅作背景、Q0 禁止使用。研究员日常讨论优先使用上述中文档位，交付时再由库管理员同步到系统字段。

## 03 为项目效用最大化应沉淀什么

03 不应只沉淀某次任务的材料链接，还应持续积累五类研究资产：

1. **来源经验**：哪个来源证明什么最强，更新频率、修订习惯、样本偏差和访问限制是什么；
2. **指标经验**：直接指标与代理指标的关系、领先滞后、失效场景和历史误判；
3. **冲突案例**：哪些来源曾经冲突，最后由什么口径或后续事实解释；
4. **判断校准**：当时允许的判断强度与后来结果是否匹配；
5. **框架反馈**：哪些关键变量或阻断节点在 02 中缺失，哪些变量长期没有辨识价值；
6. **完整取证案例**：一套最低证据组合在完整任务中为何有效或失效，最关键证据、误判来源和新增反证是什么。

这样 03 才会让下一次研究更快、更准，而不只是增加一次性文件数量。

## 两层目录怎么读

研究员日常只需阅读：

- `A_取证规则`：这类问题怎样证明；
- `B_取证来源`：优先去哪里找、各来源能证明什么；
- `C_Evidence_Recipe`：改称“证据组合”，告诉你最低需要哪几类互补材料；
- `D_研究工作单`：直接复制使用的任务单、更新表和冲突处理表。

`00_*yaml`、manifest 和校验脚本属于系统接口。第一版不要求研究员维护其技术细节，只需在方法变化后由库管理员同步。
