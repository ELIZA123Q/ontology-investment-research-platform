# A01_事实确认取证规则

## 研究员先做这五步

1. 找到承担法律、披露或统计责任的原始发布者；
2. 截取能完整表达主张的原文和上下文，不只保存搜索摘要；
3. 核对主体、对象、适用范围、生效/业务时间；
4. 继续查附件、修订、撤回、豁免和后续执行文件；
5. 写一句“该材料确认了什么、尚未确认什么”。

最常见误判是把“宣布/计划/签约/送样”写成“已执行/已交付/已量产”。遇到阶段性事实，必须用动词精确区分。

## 1. 定位

事实确认取证规则用于确认某件事是否真实发生、是否正式发布、是否已经生效、适用范围是什么、是否存在修订、失效、豁免或反向证据。

它解决的是“事实是否成立”，不是“事实意味着什么”。事实影响、传导路径、受益排序和投资判断属于 A04、A05、A06、A07 或 04 阶段。

## 2. 适用场景

适用于以下 judgment_type：

| judgment_type | 示例 |
|---|---|
| `policy_fact` | 某项政策、监管措施、出口管制是否发布或生效 |
| `official_disclosure_fact` | 公司是否公告扩产、业绩、订单、交易、回购或重大事项 |
| `event_fact` | 某个事件是否发生，例如停产、事故、制裁、并购完成 |
| `transaction_fact` | 某项交易是否签署、交割、终止或变更 |
| `project_fact` | 某个项目是否开工、投产、认证、延期或取消 |
| `relationship_fact` | 某公司是否与客户、供应商、合作方存在正式关系 |

## 3. 不适用场景

以下问题不应只用 A01：

| 问题 | 应转向 |
|---|---|
| 政策会如何影响产业链 | A04 机制传导验证 |
| 公司是否真正受益 | A05 对象分化比较 / A06 财务影响测算 |
| 价格是否进入上行趋势 | A02 状态变量测量 / A03 趋势与阶段判断 |
| 市场是否已经反映 | A07 市场预期与定价 |
| 某事实是否存在争议或其他解释 | A08 反证与竞争解释 |

## 4. 入口输入

A01 调用前，03 应从 02 或本次运行中获得：

| 字段 | 说明 |
|---|---|
| `judgment_unit_id` | 绑定的判断单元 |
| `fact_question` | 要确认的事实问题 |
| `target_object` | 政策、公司、产品、项目、事件、交易、关系等目标对象 |
| `required_scope` | 地区、时间、产品、主体、业务范围 |
| `required_time_type` | 发布时间、生效时间、业务发生时间、交割时间、截止时间 |
| `expected_source_profile` | 预期来源类型，例如官方监管、交易所、公司公告 |
| `allowed_04_view` | 若事实成立，04 可能使用的最高方式 |
| `counter_requirement` | 需要检查的反证或失效条件 |

## 5. 必需证据组合

A01 的最低必要证据组合如下。

| 必要证据组合 | 目的 | 最低要求 |
|---|---|---|
| `original_text` 原文证据 | 确认事实来源 | 必须可回到官方原文、公司公告、交易所文件、合同摘录、数据库原字段或授权材料 |
| `actor_subject` 主体证据 | 确认谁发布、谁执行、谁受影响 | 发布主体、执行主体、披露主体、被影响主体必须可区分 |
| `business_time` 时间证据 | 确认何时发生或生效 | 必须区分发布时间、业务发生时间、生效时间、统计期和系统获取时间 |
| `scope_boundary` 范围证据 | 确认适用于谁、哪里、什么产品 | 地区、产品、对象、业务环节、金额或数量范围必须明确 |
| `status_evidence` 状态证据 | 确认计划、已发布、已生效、已完成或已终止 | 不得把计划、传闻、考虑中、预计、指引写成已发生事实 |
| `revision_or_invalidity_check` 修订/失效检查 | 确认是否被更新、撤回、替代、豁免 | 必须检查后续修订、补充说明、豁免条款、终止公告或过渡期 |
| `counter_check` 反证检查 | 避免单边确认 | 至少检查是否存在否认公告、延期、撤回、适用范围排除或冲突来源 |

最低进入 04 的条件：

```text
original_text + actor_subject + business_time + scope_boundary + revision_or_invalidity_check
```

若缺少 `counter_check`，不得标记为高质量通过。

## 6. 来源优先级

### 6.1 政策事实

| 优先级 | 来源 |
|---|---|
| 第一优先 | 监管机构、政府部门、立法机构、海关、财政、商务、央行、交易所等官方原文 |
| 第二优先 | 官方问答、执行细则、补充通知、制裁清单、监管数据库 |
| 第三优先 | 公司公告中对政策适用范围的披露 |
| 辅助来源 | 新闻、研报、专家解读，只能用于发现线索或影响分析 |

不可省略的规则：没有官方原文或可复核官方数据库，不得确认政策事实。

### 6.2 公司披露事实

| 优先级 | 来源 |
|---|---|
| 第一优先 | 交易所公告、年报、季报、招股书、临时公告、监管问询回复 |
| 第二优先 | 公司 IR 材料、业绩会纪要、投资者日材料、官网新闻稿 |
| 第三优先 | 授权金融数据库中可追溯至公告的字段 |
| 辅助来源 | 新闻、卖方研报、第三方转述 |

不可省略的规则：公司自身事实优先公司正式披露；卖方研报不得作为公司未披露事实的唯一证据。

### 6.3 交易或项目事实

| 优先级 | 来源 |
|---|---|
| 第一优先 | 合同公告、交割公告、监管批准文件、交易所文件 |
| 第二优先 | 公司公告、项目备案、地方政府项目公开信息、环评或招标文件 |
| 第三优先 | 公司官网、客户公告、供应商公告 |
| 辅助来源 | 新闻、行业媒体、调研纪要 |

不可省略的规则：项目“规划”“拟建设”“预计投产”不得直接写为“已投产”。

### 6.4 关系事实

| 优先级 | 来源 |
|---|---|
| 第一优先 | 双方公告、合同披露、监管文件、招股书客户/供应商披露 |
| 第二优先 | 公司年报、官网案例、认证名单、客户公开供应商名单 |
| 第三优先 | 行业数据库、产业链图谱、访谈材料 |
| 辅助来源 | 新闻、卖方研报、传闻 |

不可省略的规则：供应关系、客户关系、认证关系必须说明是正式披露、推断、调研线索还是市场传闻。

## 7. 取数方式与留痕要求

A01 支持以下取数通道，但通道不改变来源权威性。

| 通道 | 必须留痕 |
|---|---|
| Web / 官网 | URL、标题、发布者、发布时间、获取时间、页码/段落/截图或快照 |
| 数据库终端 | 数据库名称、字段名称、查询条件、导出时间、原始来源字段、权限范围 |
| API | endpoint、参数、接口版本、响应时间、原始响应或 hash、字段血缘 |
| MCP | connector 名称、底层 SourceProfile、参数、响应时间、原始材料或 hash、字段血缘 |
| 文件上传 | 文件名、版本、上传时间、原始发布者、页码/表格/段落定位 |
| 人工记录 | 记录人、样本说明、记录时间、业务时间、权限边界、可否复核 |

禁止把取数通道写成来源。例如：

```text
错误：来源 = MCP
正确：来源 = 公司 2025 年年报；获取通道 = MCP 文件读取
```

## 8. 专项质量门槛

A01 在全局质量门槛基础上，增加以下专项门槛。

| 质量项 | 要求 | 不满足时处理 |
|---|---|---|
| 原文定位 | 必须能定位到原文、字段、页码、表格或段落 | 不得进入正式证据 |
| 主体明确 | 发布主体、披露主体、执行主体或受影响主体不能混淆 | 降级或退回拆分 |
| 时间明确 | 必须区分发布时间、生效时间、业务发生时间 | 动态事实降为背景或条件 |
| 状态明确 | 计划、预计、指引、已发生、已完成必须区分 | 不得确认已发生事实 |
| 范围明确 | 地区、对象、产品、业务环节必须匹配 02 范围 | 不得外推 |
| 修订检查 | 检查是否存在更新、撤回、失效、豁免 | 未检查不得 high_quality_pass |
| 主张类型 | 事实、估算、预测、观点、指引必须分开 | 混淆时退回抽取 |

## 9. 反证要求

A01 的反证不是分析附录，而是事实确认的一部分。

必须检查：

1. 是否存在撤回、终止、延期或修订；
2. 是否存在官方否认、公司澄清或监管更正；
3. 是否存在适用范围排除；
4. 是否存在生效时间尚未到达；
5. 是否存在“报道发生”但“官方未确认”；
6. 是否存在不同来源对同一事实的主体、时间、范围或状态冲突。

反证检查结果应写入 `evidence_baskets.csv`、`evidence_readiness_assessments.csv` 和 `gaps_and_risks.csv`。

## 10. 降级规则

| 问题 | 03 处理 | 04 最多能形成的结论 |
|---|---|---|
| 找不到原文，只找到新闻转述 | 保留为线索 | background_only |
| 有原文但无生效时间 | 降级为待确认事实 | conditional_only |
| 主体不清 | 拆分或退回补证据 | insufficient |
| 范围不匹配 02 | 限定范围使用 | conditional_only |
| 仅有公司指引，未发生 | 记录为指引或预期 | background_or_scenario_input |
| 有冲突且未消解 | 标记 contested | contested |
| 未检查修订或失效 | 不得 high_quality_pass | directional_only_or_lower |
| 来源权限不清 | 阻断 | none |

## 11. 停止规则

单项事实确认可以停止补充的条件：

1. 原文证据可定位；
2. 主体、时间、范围、状态已明确；
3. 已检查修订、失效和主要反证；
4. 证据主张已拆成最小主张；
5. 事实候选已说明可支持的最高使用方式；
6. 继续补充不会改变事实状态或 04 最多能形成的结论。

如果事实确认缺失会导致整个路径起点不成立，应停止对应路径，不得用下游推测补足上游事实。

## 13. 示例

### 示例 1：政策是否生效

问题：某出口管制是否已经生效。

最低证据：

```text
官方原文
+ 生效时间
+ 适用产品和地区
+ 执行主体
+ 修订/豁免检查
+ 反证检查
```

新闻报道只能用于发现线索，不能直接确认政策事实。

### 示例 2：公司是否扩产

问题：某公司是否扩建产能。

需要区分：

```text
拟建设
已公告
已开工
设备进场
试生产
正式投产
满产
```

不同状态对应不同事实等级，不得用“规划产能”替代“有效产能”。

## 14. 一句话原则

> A01 的目标不是证明观点正确，而是把事实是否成立、何时成立、在哪个范围内成立、是否仍然有效说清楚。

## 15. 专项执行协议：事实状态机

事实确认必须先定义目标事实的状态机，再检索材料。不同类型不能共用一个模糊的“已发生”：

| 事实类型 | 推荐状态序列 | 不能跨越的节点 |
|---|---|---|
| 政策/规则 | 征求意见 → 正式发布 → 生效 → 执行 → 修订/失效 | 发布不等于生效，生效不等于实际执行 |
| 项目/产能 | 规划 → 备案/批准 → 开工 → 设备进场 → 试产 → 量产 → 达产 | 开工不等于投产，名义产能不等于有效供给 |
| 认证/导入 | 送样 → 测试 → 认证 → 小批 → 量产 → 复购/跨线复制 | 认证不等于收入，首单不等于规模采用 |
| 交易 | 意向 → 签约 → 条件满足 → 交割 → 整合/终止 | 签约不等于交割 |
| 冲突/中断 | 报告 → 官方确认 → 发生 → 持续/扩大 → 缓和/结束 | 媒体报道不等于可确认事实 |

执行步骤：

1. 固定要确认的最小状态和截止时点；
2. 获取当前状态的原始材料；
3. 向前检查前置状态，防止孤立公告；
4. 向后检查修订、撤回、延期、豁免和完成状态；
5. 将一句复合陈述拆成主体、动作、对象、状态、时间和范围；
6. 每个原子主张单独绑定 locator，不得用一段材料支撑未明确写出的多个事实；
7. 形成 `confirmed / partial / contested / invalidated / not_confirmed` 状态，而不是简单 true/false。

## 16. 版本与冲突判断

同一事实存在多个版本时，按“同一发布主体的有效最新版本优先，但保留历史版本”处理：

- 修订文件通过 `supersedes` 连接旧文件，不删除旧主张；
- 更正公告只覆盖明确更正的字段，不自动否定整份材料；
- 公司披露与监管文件冲突时，先检查披露时点、定义和法定责任边界，不机械按 S1 覆盖 S2；
- 双方公告冲突时分别保留，并以合同、监管批准或后续完成公告消解；
- 无法消解时事实状态为 `contested`，不得挑选更符合主观点的一方。

## 17. 典型失败模式

| 失败模式 | 识别信号 | 处理 |
|---|---|---|
| 标题事实化 | 标题比正文范围更强 | 以正文原子主张为准 |
| 未来时态误读 | 计划、预计、目标、力争 | claimType=guidance/forecast，不生成已发生事实 |
| 状态跳跃 | “建设项目”被写成“新增供给” | 回到状态机，补中间状态 |
| 时间偷换 | 发布日被当成生效日或业务发生日 | 分开记录三类时间 |
| 范围扩大 | 个别产品/地区外推全部业务 | 限定 scope，必要时拆 JudgmentUnit |
| 多媒体转述投票 | 多篇新闻来自同一原始消息 | 归为同一 independence_group |
| 否认即反证 | 主体否认被自动视为事实不存在 | 将否认作为冲突主张，继续查可验证记录 |
