# A04_机制传导验证取证规则

## 研究员按边取证，不按故事取证

把“A 导致 B”拆成 `起点事实 → 行为变化 → 中间状态 → 结果变量`，每一条边分别写：谁改变了什么行为、预计多久发生、用什么观察、什么会阻断。若中间节点只有逻辑推演而无现实观测，只能写成条件路径。

优先验证最脆弱的边，而不是最容易找到材料的边。起点事实不成立则停止；缓冲、替代或弱执行足以吸收冲击时，不再外推公司和资产结果。

## 1. 定位

机制传导验证取证规则用于验证一个事实、变量或事件如何通过中间环节影响另一个对象、变量或结果。

它回答：

```text
起点是否成立；
中间节点是否有证据；
承接主体是否真实暴露；
传导是否可能被阻断；
是否存在更好的替代解释。
```

A04 不直接测算财务影响；财务测算应调用 A06。A04 也不负责市场是否已反映；预期和定价应调用 A07。

## 2. 适用场景

| judgment_type | 示例 |
|---|---|
| `mechanism_transmission` | AI 需求如何传导到 HBM 和 DDR5 供给紧张 |
| `policy_impact_path` | 出口管制如何影响公司供应和收入 |
| `supply_chain_path` | 上游材料瓶颈如何传导到交付和价格 |
| `demand_to_price_path` | 需求改善如何传导到订单、库存、价格 |
| `cost_pass_through` | 成本上涨是否能传导到产品价格 |
| `constraint_migration` | 瓶颈是否从外部环节迁移到内部工序 |

## 3. 不适用场景

| 问题 | 应转向 |
|---|---|
| 起点事实是否发生 | A01 |
| 中间变量当前状态 | A02 |
| 传导是否已进入趋势阶段 | A03 |
| 谁更受益 | A05 |
| 财务影响多大 | A06 |
| 市场是否定价 | A07 |
| 竞争解释与反证 | A08，但 A04 必须调用其最低检查 |

## 4. 入口输入

| 字段 | 说明 |
|---|---|
| `judgment_unit_id` | 绑定判断单元 |
| `path_id` | 02 中的路径或传导模板 |
| `start_node` | 传导起点 |
| `intermediate_nodes` | 中间节点 |
| `end_node` | 结果节点 |
| `anchor_objects` | 参与传导的对象、产品、环节、公司 |
| `blocking_conditions` | 可能阻断传导的条件 |
| `alternative_explanations` | 竞争解释 |

## 5. 必需证据组合

| 必要证据组合 | 目的 | 最低要求 |
|---|---|---|
| `TRANS_START_FACT` 起点证据 | 证明起点成立 | 起点事实调用 A01，起点变量调用 A02 |
| `TRANS_INTERMEDIATE_NODE` 中间节点与关键边 | 防止跳节点 | 核心中间节点至少有事实、变量或受限代理，边需记录方向和时滞 |
| `TRANS_EXPOSED_SUBJECT` 暴露证据 | 证明对象承接传导 | 公司、产品、客户、供应商、地区或产能暴露必须可追溯 |
| `TRANS_OUTCOME_VARIABLE` 结果变量 | 确认传导是否实际发生 | 使用价格、交期、订单、交付、经营或财务结果，并匹配合理窗口 |
| `TRANS_BLOCKER_COUNTER` 阻断与反证 | 检查传导是否中断 | 替代供应、库存缓冲、合同锁价、政策豁免和竞争路径必须检查 |

当问题是“已观察变化主要由什么造成”时，A04 使用同一逐边方法，但将最低组合实例化为：`ATTR_OBSERVED_CHANGE`、`ATTR_CANDIDATE_CAUSES`、`ATTR_TIME_ORDER`、`ATTR_EXPOSURE_COUNTERFACTUAL` 和 `COUNTER_GENERAL`。这些 ID 与 `ER-ATTR-01` 完全一致，不另建 `start_node` 等近义篮子。

## 6. 来源优先级

| 节点类型 | 首选来源 | 辅助来源 |
|---|---|---|
| 起点事实 | A01 认可的原文、公告、政策、项目文件 | 新闻线索 |
| 状态变量 | A02 认可的数据库、披露、行业统计 | 研报解释 |
| 暴露关系 | 公司披露、招股书、客户/供应商披露、认证名单、内部数据 | 产业链图谱、调研 |
| 传导逻辑 | 历史数据、合同机制、业务流程、公司解释、行业方法论 | 卖方研报、专家观点 |
| 阻断条件 | 公司披露、一手调研、替代供应证据、库存证据 | 新闻和观点材料 |

## 7. 专项质量门槛

| 质量项 | 要求 | 不满足时处理 |
|---|---|---|
| 起点成立 | 起点必须经过 A01 或 A02 准入 | 路径停止 |
| 节点完整 | 不得跳过关键中间节点 | 降为假设路径 |
| 暴露真实 | 承接对象必须有可追溯暴露证据 | 不得推到公司/资产 |
| 方向明确 | 不能只因相关性就写传导 | 降为相关观察 |
| 时间窗口 | 传导窗口必须匹配研究问题 | 不得外推 |
| 阻断检查 | 必须主动查阻断条件 | 不得 high_quality_pass |
| 替代解释 | 必须记录至少一个竞争解释或说明不适用 | 降级 |

## 8. 降级规则

| 问题 | 03 处理 | 04 最多能形成的结论 |
|---|---|---|
| 起点事实未确认 | 路径 blocked | none |
| 中间节点缺失 | 标记 path_gap | conditional_only |
| 暴露关系只来自推测图谱 | 不得对象化推理 | background_only |
| 只证明相关性 | 记录为相关观察 | conditional_only |
| 阻断条件未查 | 降级 | directional_only_or_lower |
| 替代解释更强 | 标记 contested | contested |

## 9. 停止规则

传导验证可以停止的条件：

1. 起点已经通过 A01/A02；
2. 核心中间节点有证据或明确缺口；
3. 承接对象暴露证据可追溯；
4. 阻断条件和替代解释已检查；
5. 路径状态、使用范围和 04 上限已明确。

## 11. 示例

问题：HBM 需求是否挤占传统 DRAM 有效供给。

最低证据：

```text
HBM 需求或订单证据
+ 先进 DRAM wafer / 封装资源分配证据
+ 传统 DRAM 供给或交期变化
+ 原厂产能/资本开支披露
+ 客户锁单或供应协议线索
+ 替代解释：传统需求恢复、库存低位、供给纪律
```

## 12. 专项执行协议：逐边验证

机制路径必须拆为节点和边，不能只验证路径两端：

```text
N0 起点事实/状态
→ E01 传导边（机制、方向、时滞、必要条件）
→ N1 中介状态
→ E12
→ N2 暴露对象行为
→ E23
→ N3 经营/财务/市场结果
```

每条关键边至少记录：

| 字段 | 含义 |
|---|---|
| `from_node / to_node` | 边连接的节点 |
| `mechanism` | 通过价格、数量、准入、合同、技术、行为或融资传导 |
| `expected_direction` | 正、负、非线性或条件性 |
| `lag_window` | 合理领先/滞后范围 |
| `necessary_conditions` | 边成立所需条件 |
| `blocking_conditions` | 会中断或吸收冲击的条件 |
| `observed_signal` | 本次实际观察到的边证据 |
| `edge_status` | supported / partial / hypothesis_only / blocked / contested |

路径状态由最关键的未满足边决定，不得因起点和终点同时变化就越过中介。

## 13. 机制证据强度阶梯

从弱到强区分：

1. **概念可行**：业务上可能发生，只能形成 hypothesis；
2. **时间一致**：起点在先、结果在后，但仍可能有共同原因；
3. **机制观测**：中介变量或主体行为实际变化；
4. **暴露差异**：高暴露对象变化更明显，低暴露对象较弱；
5. **反事实/自然对照**：在相似条件下，无该冲击的对象或时期未出现结果；
6. **重复验证**：不同时间、对象或独立来源重复出现符合机制的模式。

03 应记录当前达到哪一级，不把“相关性 + 业务故事”写成因果确认。

## 14. 竞争路径比较

对每个主机制至少选择一个最强竞争解释，建立区分表：

| 区分问题 | 主路径预测 | 竞争路径预测 | 实际观测 |
|---|---|---|---|
| 时间先后 | 哪个变量先变 | 哪个变量先变 | 业务时间证据 |
| 对象差异 | 哪类对象更敏感 | 哪类对象更敏感 | 暴露比较 |
| 中介变量 | 哪个中介必须变化 | 是否无需该中介 | 中介证据 |
| 阻断测试 | 哪种缓冲会削弱结果 | 是否不受影响 | 阻断样本 |
| 分项表现 | 哪些产品/地区应变化 | 竞争解释预测何种分项 | 分项数据 |

若两条路径对所有可观察信号预测相同，02 的竞争解释尚不可区分，应返回 02 改写或将结论保持为多解释并存。

## 15. 典型失败模式

| 失败模式 | 处理 |
|---|---|
| 两端相关、无中介 | 路径最高 hypothesis_only / conditional_only |
| 把主体表述当机制结果 | 将表述记为观点，再查行为和结果 |
| 暴露用产业链标签代替 | 补收入、产能、客户、采购或地域暴露 |
| 忽略合同和库存缓冲 | 将缓冲设为必查阻断篮子 |
| 时间窗口过短 | 延长到业务传导窗口，避免“暂未发生”误判无影响 |
| 时间窗口过长 | 防止其他事件进入，拆分路径或控制共同冲击 |
| 结果变量先于起点变化 | 主因归因失败，转 A08 竞争解释 |
