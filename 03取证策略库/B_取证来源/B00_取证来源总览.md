# B00_取证来源总览

## 研究员的来源选择原则

- **事实责任**：谁对这项事实承担发布、法律或经营责任；
- **观察距离**：谁离真实行为、交易或实物流最近；
- **方法透明**：样本、定义、计算和修订是否可解释；
- **独立性**：不同来源是否共享同一上游数据或叙事；
- **时间适配**：发布日、业务时间和判断窗口是否一致；
- **反证价值**：该来源是否有能力暴露主判断的盲点。

先选择“来源角色”，再选择具体机构和获取通道。数据库方便，不代表它是原始来源；官方权威，也不代表它能证明产业传导或公司结果。

## 1. 定位

本目录是 03 取证策略库中的“取证来源”部分，负责为 03 阶段提供轻量、可复用、可审计的来源选择规则。

它不追求建设完整数据源治理平台，也不替代正式的数据权限、采购、合规和接口管理体系。现阶段目标是：

1. 避免 03 每次临时搜索来源；
2. 避免把新闻、研报、AI 摘要、MCP 工具和正式数据源混为一类；
3. 让不同必要证据组合优先匹配更合适的来源；
4. 让行业专用来源和专题冲击来源可以逐步扩展，而不污染通用来源清单；
5. 让 03 能说明来源为什么可用、为什么受限、缺失时如何降级；
6. 为后续接入 MCP、API、数据库和内部系统预留最小留痕口径。

本文管理的是“去哪取证”和“取到后能不能用”，不是“取数程序怎么写”。

SourceProfile、SourceDocument、AcquisitionChannel、AccessScope、ArtifactType 和 ContentDomain 的对象定义由 `一级通用本体规范/evidence.yaml` 承接。本目录只提供推荐优先来源、来源分层、必要证据组合映射和降级规则；不得把本目录当作 SourceProfile 本体目录。

## 2. 本目录包含什么

当前版本采用“通用来源 + 行业专用来源 + 专题来源”的三层结构：

```text

├── manifest.md
├── B00_取证来源总览.md
├── B01_来源分层与使用边界.md

├── B03_行业专用来源/
│   └── B03-IND-SEMI_半导体取证来源清单.md
└── B04_专题来源/
    └── B04-TOPIC-GEOPOLITICAL_地缘冲击取证来源清单.md
```

文件分工如下：

| 文件/目录 | 作用 |
|---|---|
| README.md | 说明本包内容、适用范围和快速使用方式 |
| manifest.md | 记录文件清单、版本和设计原则 |
| B00_取证来源总览.md | 说明来源库定位、边界、目录结构和使用流程 |

| B02_通用来源清单与必要证据组合映射.md | 维护跨行业通用来源，如政策、公司披露、金融市场、宏观、贸易、商品、新闻、研报 |
| B03_行业专用来源/ | 存通过验证业专用来源文件，如半导体、汽车、医药、能源、消费等行业来源 |
| B04_专题来源/ | 存放跨行业专题来源文件，如地缘冲击、制裁管制、供应链扰动、能源冲击等专题来源 |

## 3. 三类来源文件的边界

### 3.1 B02：通用来源

B02 只维护跨行业通用来源，解决以下问题：

1. 政策、监管、法律、制裁、出口管制去哪查；
2. 公司公告、财报、招股书、IR 材料去哪查；
3. 金融市场、股价、估值、一致预期去哪查；
4. 宏观、利率、汇率、通胀、就业、财政和货币数据去哪查；
5. 贸易、海关、进出口、关税、商品、能源、运价和物流数据去哪查；
6. 新闻、研报、专家、智库材料如何作为线索或预期来源使用。

B02 不维护完整行业数据源清单。某个来源如果主要服务于特定行业的供需、价格、库存、产能、份额、下游需求等专业变量，应进入 B03。

### 3.2 B03：行业专用来源

B03 维护行业专用来源，解决以下问题：

1. 某个行业的核心变量有哪些；
2. 行业供需、价格、库存、产能、份额、下游需求应该去哪取；
3. 行业数据和公司披露如何交叉验证；
4. 行业来源有哪些常见口径陷阱；
5. 行业判断中反证应去哪找。

当前已包含：

```text
B03_行业专用来源/
└── B03-IND-SEMI_半导体取证来源清单.md
```

后续可扩展：

```text
B03-IND-AUTO_汽车取证来源清单.md
B03-IND-PHARMA_医药取证来源清单.md
B03-IND-ENERGY_能源取证来源清单.md
B03-IND-CONSUMER_消费取证来源清单.md
B03-IND-CLOUD_云计算与AI算力取证来源清单.md
```

### 3.3 B04：专题来源

B04 维护跨行业专题来源，解决以下问题：

1. 地缘冲击、制裁管制、战争冲突、航道扰动、能源冲击等专题事实去哪确认；
2. 专题冲击通过哪些机制影响行业、公司和资产；
3. 冲击事实、政策动作、贸易暴露、商品价格、物流扰动、金融市场反应应分别去哪取；
4. 如何找到反证和缓释证据。

当前已包含：

```text
B04_专题来源/
└── B04-TOPIC-GEOPOLITICAL_地缘冲击取证来源清单.md
```

后续可扩展：

```text
B04-TOPIC-SANCTION_制裁与出口管制取证来源清单.md
B04-TOPIC-SUPPLYCHAIN_供应链扰动取证来源清单.md
B04-TOPIC-ENERGY-SHOCK_能源冲击取证来源清单.md
B04-TOPIC-TRADE_贸易摩擦取证来源清单.md
B04-TOPIC-RATE-FX_利率汇率冲击取证来源清单.md
```

## 4. 不做什么

现阶段不单独建设以下内容：

```text
source_catalog/
source_onboarding/
source_selection_matrix/
MCP Connector 全套接口注册表
```

原因是：当前目标是提升 03 取证质量，不是建设数据源治理平台。

权限边界、材料形态、内容领域、SourceDocument 和 SourceProfile 的最小字段已经由通用证据域承接；03 单次运行只需要在快照中落实这些字段，不需要在 B 目录中再建一套平行模型。

当后续出现以下情况时，再升级为完整来源治理库：

1. 接入 Wind、Bloomberg、iFinD、FactSet、OpenBB、内部数仓或其他固定接口；
2. 同一类取数任务高频重复；
3. 需要机器自动选择来源；
4. 需要记录字段血缘、接口版本、原始响应和权限范围；
5. 需要前端化、产品化或自动化运行。

## 5. 使用原则

03 使用取证来源库时，应遵循以下顺序：

```text
02 判断单元
→ C 类 Evidence Recipe
→ 必要证据组合
→ A 类取证执行协议
→ B02 通用来源匹配
→ 如涉及行业专业变量，进入 B03_行业专用来源/
→ 如涉及跨行业专题冲击，进入 B04_专题来源/
→ B01 来源分层和使用边界校验
→ 选择具体来源和取数方式
→ 执行取证
→ 记录来源、口径、时间、权限、留痕和 04 最多能形成的结论
```

不要先搜索资料，再倒推证据是否充分。

## 6. 来源、内容领域、获取方式必须分开

03 不得把以下概念混在一起：

| 概念 | 回答的问题 | 示例 |
|---|---|---|
| SourceProfile / 来源生产者 | 谁生产、发布或维护数据 | 公司、交易所、监管机构、Wind、Bloomberg、国家统计局、海关总署、TrendForce、SEMI、内部数仓 |
| ContentDomain / 内容领域 | 数据描述什么 | 政策、公司财务、金融市场、行业供需、产业链经营、宏观、贸易、航运、商品 |
| AcquisitionChannel / 获取方式 | 怎么拿到 | 官网、数据库终端、API、MCP、文件上传、人工调研、内部系统、文件检索 |
| ArtifactType / 材料形态 | 实际拿到什么 | PDF、HTML、CSV、API response、数据库字段、访谈纪要 |
| AccessScope / 权限边界 | 能不能用、怎么用 | public、licensed、internal、confidential、restricted |

正确示例：

```text
来源生产者：Wind
内容领域：金融市场 / 一致预期
获取方式：Wind 终端 / API / MCP Connector
材料形态：导出表格 / API response
权限边界：licensed
```

错误示例：

```text
来源：MCP
来源：金融市场
来源：搜索结果
来源：网页
```

MCP、API、网页搜索、文件上传、文件检索都是获取方式，不是来源本身。

## 7. 常用来源清单的性质

B02、B03、B04 中的来源清单都是“优先来源清单”，不是封闭白名单。

使用规则：

1. 优先使用本库中已有来源；
2. 本库没有覆盖的新来源，可以作为候选来源；
3. 新来源用于关键判断前，必须说明来源生产者、内容领域、发布时间、业务时间、口径、权限、可复核路径和使用限制；
4. 未完成来源说明的新来源，只能作为线索，不得单独支撑关键判断；
5. 搜索引擎、AI 摘要和二手转载不得作为正式证据来源，只能帮助发现原始来源；
6. 行业来源和专题来源不能绕过 B01 的来源分层、降级规则和 04 最多能形成的结论。

## 8. 全球来源与中国来源的使用要求

本库同时覆盖全球来源和中国来源。03 不得只依赖海外数据库解释中国资产、中国政策、中国贸易和 A/H 股公司，也不得只用中文新闻或二手整理替代中国官方、监管、交易所、海关、统计和公司披露原文。

基本要求：

1. 涉及中国政策时，优先检查中国政府网、国务院政策文件库、主管部委、监管机构和政策原文；
2. 涉及 A 股和中国公司时，优先检查巨潮资讯、上交所、深交所、北交所、港交所、公司 IR 和定期报告；
3. 涉及中国宏观和行业运行时，优先检查国家统计局、央行、外汇局、财政部、工信部、商务部、海关总署等主源；
4. 涉及中国贸易和产业链暴露时，优先检查海关总署、商务部、UN Comtrade、USITC、Eurostat 等可对照来源；
5. 涉及中国商品、运价和物流时，优先检查国内交易所、上海航运交易所、海关、行业协会和权威商品数据源；
6. 涉及海外政策或海外公司对中国公司的影响时，应同时检查海外原文和中国主管部门、公司公告或交易所披露。

## 9. 与 A 类取证规则的关系

C 类 Recipe 回答“一个判断需要哪些证据组合”。

A 类规则回答“这些证据如何取得、归一、验收和降级”。

B 类来源回答“优先去哪取、怎么取、能不能用”。

例如：

```text
A03 趋势与阶段判断
→ 需要价格、需求、供给、库存、订单、反证等必要证据

B02 通用来源
→ 价格证据优先使用交易所/授权行情/商品数据/宏观数据

B03 行业来源
→ 行业价格、行业库存、行业产能、行业下游需求优先使用对应行业专业来源

B04 专题来源
→ 若趋势变化由地缘冲击、制裁、航运、能源或贸易冲击触发，需补充专题来源确认冲击事实和传导通道

B01 来源分层
→ 判断上述来源是否足以进入 04 推理和 05 表达
```

## 10. 质量控制位置

来源质量控制不只在 B 类文件中完成，而是由三层共同完成：

| 层级 | 质量控制内容 |
|---|---|
| 00_quality_gates | 全局数据质量底线，包括可追溯、时间、口径、权限、主张类型、适用判断 |
| B01 来源分层 | 判断某类来源默认能支撑什么、不能支撑什么、何时降级 |
| A 类取证规则 | 判断某类问题下的专项质量要求，例如周期判断不能只用单点价格，财务测算不能缺量价和成本拆分 |
| B02/B03/B04 来源清单 | 判断当前必要证据组合优先去哪取、主源缺失时如何降级、是否需要全球和中国侧交叉验证 |

## 11. 现阶段一句话原则

取证来源库现阶段只做一件事：

> 让 03 在开始取数前，就知道每类证据优先去哪取、哪些来源只能作线索、哪些来源不够支撑方向性判断，并能在通用、行业、专题三类来源之间正确切换。

## 12. 来源选择执行协议

为每个 mandatory/counter basket 建立 source plan，而不是从清单中随意挑网站：

| 字段 | 要求 |
|---|---|
| `basket_id` | 来源服务于哪个必要证据组合 |
| `claim_or_measurement_type` | 要证明事实、测量、预测、观点还是关系 |
| `primary_source_profile` | 最直接、最匹配的主源 |
| `cross_source_profile` | 生成机制不同的交叉源 |
| `counter_source_profile` | 最可能发现反证的来源 |
| `independence_group` | 原始数据和转述链去重组 |
| `methodology_requirements` | 样本、字段、口径、修订和覆盖要求 |
| `acquisition_channel` | 获取通道、参数和留痕 |
| `fallback_sequence` | 主源不可得时的回退顺序 |
| `failure_effect` | 换源后对直接性、质量和 04 上限的影响 |

来源计划先于检索执行。临时发现的新来源可以加入，但必须补齐上述字段。

## 13. 来源适配而非机械排序

S1—S8 描述默认来源角色，不是一个可跨证据类型通用相加的权威分。选择来源时按以下顺序：

1. 是否直接生产当前事实或测量；
2. 对象、时间、口径和内容域是否匹配；
3. 方法、样本和修订是否透明；
4. 是否能定位原文或原始字段；
5. 是否与其他证据真正独立；
6. 权限是否允许当前用途和 05 表达；
7. 更新频率是否满足判断窗口。

例如，公司法定披露适合确认公司财务，行业专业数据库更适合测行业价格；不能因为前者层级数字更小，就用公司观点覆盖行业测量。

## 14. 来源失败与替换

主源失败必须区分：无结果、权限受限、字段停更、页面变化、口径不符、时间不符、方法不透明或获取故障。只有获取故障可以在保持同一 SourceProfile 的情况下换通道；换成另一来源时必须重新评估：

- 主张是否仍可直接支持；
- 独立来源数是否改变；
- 业务时间、样本和口径是否改变；
- 使用权限和可引用范围是否改变；
- Recipe 的最低质量是否仍满足。
