# B02_通用来源清单与证据篮子映射

## 研究员使用提示

本清单用于确定“去哪一类地方找”，不是要求穷举。每个关键篮子优先安排：一个最接近事实的主源、一个方法或样本真正独立的交叉源，以及一个可能提供反向信息的来源。三篇引用同一数据或同一访谈的报告只算一个独立信息组。

当主源不可得时，记录降级路径：直接数据 → 受控估算 → 经校准代理 → 市场线索。来源数量增加不能抵消证据角色缺失。

## 1. 定位

本文是 03 取证策略库中的**通用来源清单**，用于回答：

1. 某类通用证据优先去哪取；
2. 哪些来源可以作为主源，哪些只能作为交叉验证、替代来源或线索；
3. 主源不可得时如何降级；
4. 行业专用变量应何时进入 B03 行业来源文件。

本文不维护完整行业数据源清单，不把半导体、汽车、医药、能源等行业专用来源混入通用清单。行业供需、行业价格、行业库存、行业产能、行业份额、下游需求等专业来源，应进入对应的 `B03_行业专用来源` 文件。

本次修订特别补强中国数据来源。使用时应避免两种偏差：

1. 只用海外数据库解释中国资产、A/H 股公司、中国贸易和国内政策；
2. 只用中文新闻或二手整理替代中国官方、监管、交易所、海关、统计和公司披露原文。

对涉及中国资产、中国供应链、中国政策、中国需求或中国进出口的问题，应同时检查全球来源与中国侧来源；两者冲突时，应优先回到原始发布机构、法定披露文件和口径说明，而不是直接取一个“看起来更完整”的二手表格。


## 2. 使用规则

03 使用来源时应按以下顺序执行：

```text
02 判断单元
→ C 类 Evidence Recipe
→ 证据篮子
→ A 类取证规则
→ B02 通用来源匹配
→ 如涉及行业专业变量，进入对应 B03 行业专用来源文件
→ B01 来源分层和使用边界校验
→ 执行取证
→ 记录来源、口径、时间、权限、留痕和 04 最多能形成的结论
```

基本规则：

1. 对关键判断，优先使用 S1-S5 来源。
2. S6-S8 只能用于线索、观点、市场预期、竞争解释或来源发现。
3. 数据库、API、MCP、网页、文件上传都是获取方式，不改变来源本身层级。
4. 新闻、研报、AI 摘要、搜索结果不得替代政策原文、公司披露、交易所文件、监管清单或专业数据源。
5. 如果本文未列来源被用于关键判断，必须补充说明来源生产者、发布时间、业务时间、口径、权限、可复核路径和使用限制。
6. 通用来源只能解决跨行业证据问题；行业专业变量必须查 B03。
7. 涉及中国资产、中国公司、中国政策、中国贸易、中国宏观或中国商品物流时，必须优先检查中国侧主源，不得只用海外二手转述。
8. 涉及海外政策或海外公司对中国公司的影响时，应同时检查海外原文与中国主管部门、公司公告或交易所披露。

公司披露使用规则：

1. 历史财务和已披露经营事实优先使用交易所、监管披露系统或公司正式报告。
2. IR presentation、earnings call、investor day 可用于管理层口径和边际变化，但其中的目标、指引、展望不得写成已发生事实。
3. 同一家公司不同材料之间不构成独立交叉验证；行业判断需要同业、行业数据或下游证据补充。
4. 重大风险暴露、客户集中度、产能、资本开支、库存、价格压力等信息，优先查年报、10-K/20-F、招股书和 MD&A。

### 4.7 S4 行业专业数据源的通用入口规则

B02 不维护具体行业专业来源清单。凡涉及以下证据，应进入对应 B03 行业来源文件：

1. 行业供需；
2. 行业价格；
3. 行业库存；
4. 行业产能和利用率；
5. 行业出货量；
6. 行业份额；
7. 下游需求；
8. 产业链瓶颈；
9. 专业材料、设备、工艺、渠道变量。

通用规则：

| 来源类型 | 用法 | 使用限制 |
|---|---|---|
| 行业协会 | 适合行业规模、出货、产销、会员统计、长期趋势 | 需核对统计范围、样本和更新频率 |
| 专业研究机构 | 适合价格、份额、出货、库存、产能、需求 | 多数为商业数据，需记录授权和方法论 |
| 公司披露 | 适合公司自身经营、订单、库存、价格、产能、资本开支 | 单家公司不能直接代表行业 |
| 下游统计 | 适合需求侧交叉验证 | 需要通过库存和 BOM/单耗映射到上游 |
| 一手调研 | 适合边际变化和滞后数据补充 | 必须说明样本、时间、权限和偏差 |

### 4.11 S8 搜索结果、AI 摘要和模型回答

S8 只能用于：

1. 发现关键词；
2. 发现候选来源；
3. 生成检索路径；
4. 辅助整理已验证来源。

S8 不得用于：

1. 任何正式事实；
2. 任何关键数据；
3. 任何方向性结论；
4. 任何需要可追溯引用的证据。

只要证据来源停留在搜索结果、AI 摘要或模型回答层面，不得进入有效证据计数。

## 5. 典型取证路径

### 5.1 政策或监管事件

```text
政策/监管问题
→ 查政策原文或监管公告
→ 查适用范围、生效时间、过渡期、豁免和修订
→ 查公司公告或交易所问询确认对象暴露
→ 查行业/贸易/市场数据确认影响是否发生
→ 查反证：未受影响对象、替代路径、政策豁免、执行延迟
```

### 5.2 公司业绩变化

```text
公司业绩问题
→ 查公司定期报告和公告
→ 查业绩会和 IR 材料理解管理层口径
→ 查数据库财务字段复核历史数据和估值
→ 查同业披露确认是否为行业共性
→ 查行业或下游数据验证需求/价格/成本变化
→ 查反证：一次性因素、会计口径、库存周期、费用确认
```

### 5.3 周期或趋势判断

```text
周期/趋势问题
→ 查行业专业来源或 B03 行业文件
→ 查价格、出货、库存、产能、订单、下游需求
→ 查公司披露确认边际变化是否传导到收入/利润
→ 查市场预期确认是否已经被定价
→ 查反证：价格单点波动、库存错位、需求透支、供给恢复
```

### 5.4 地缘、贸易或供应链冲击

```text
地缘/贸易/供应链问题
→ 查官方政策、制裁、管制、关税、海关规则
→ 查贸易流和关键商品/材料价格
→ 查物流、运价、港口或供应链扰动数据
→ 查公司风险因素、供应商/客户暴露和替代方案
→ 查行业专业来源确认瓶颈是否真实影响供需
→ 查反证：库存缓冲、替代路线、豁免、长协、未受影响区域
```

## 6. 使用检查清单

每次 03 使用来源前，至少检查：

1. 这个证据篮子需要什么来源层级；
2. 是否已有首选来源；
3. 是否涉及行业专业变量，是否需要进入 B03；
4. 是否需要交叉验证；
5. 替代来源是否会降低 04 最多能形成的结论；
6. 来源是否可复核；
7. 是否记录发布时间、业务时间、获取时间和数据截止点；
8. 是否记录字段、口径、单位、查询条件和版本；
9. 是否存在权限或引用限制；
10. 是否区分事实、预测、观点、假设和估算；
11. 是否主动查找反证来源；
12. 是否避免把新闻、研报、AI 摘要、搜索结果当作正式证据。

## 7. 一句话原则

> B02 只维护跨行业通用来源；凡是行业价格、供需、库存、产能、份额、下游需求等专业变量，一律进入对应 B03 行业来源文件。


## 8. 中国来源使用上限与常见误区

| 情况 | 04 最多能形成的结论 |
|---|---|
| 中国官方原文、交易所公告、法定披露、海关/统计原始数据齐备，且口径匹配 | 可进入事实确认或方向性判断 |
| 只有中文新闻、公众号、行业媒体转述，没有原始公告或数据 | 只能作为线索 |
| 只有海外数据库或海外媒体解释中国政策，但未查中国主管部门原文 | 不能作为中国政策事实主源 |
| 只有国内商业数据报价，但未记录规格、地区、含税、频率、权限 | 只能作为弱信号或背景 |
| A/H/美/台多地上市公司披露口径不一致，但未分别核对 | 不得形成强结论 |
| 中国宏观或贸易数据使用累计同比、当月同比、季调环比混用 | 只能作条件判断，必须返工口径 |

一句话原则：涉及中国的问题，先回到中国侧原始主源；涉及全球比较的问题，再用全球数据库和海外主源做交叉验证。

## 9. 通用来源计划模板

来源清单只有转成篮子级计划才可执行：

| 证据任务 | 主源角色 | 交叉源角色 | 反证源角色 | 常见回退 | 回退后的限制 |
|---|---|---|---|---|---|
| 政策事实 | 法规/主管机关原文 | 官方问答、执行名单 | 修订、豁免、法院/监管更正 | 权威媒体定位原文 | 找不到原文只能作线索 |
| 公司财务 | 法定报告/交易所 | 授权数据库复算 | 审计意见、问询、重述 | 公司 IR | IR 不替代法定口径 |
| 公司经营 | 公司披露/内部实际值 | 客户、供应商、同业 | 延期、取消、库存和回款 | 一手调研 | 限定样本和权限 |
| 市场价格 | 交易所/授权行情 | 独立行情或复算 | 流动性、复权、停牌检查 | 公开行情 API | 限制精度和稳定引用 |
| 一致预期 | 有 vintage 的授权数据库 | 卖方预测分布 | 样本变化、已修订、分歧 | 手工研报样本 | 不得称完整一致预期 |
| 宏观/贸易 | 统计/海关原始数据 | 国际组织或对方口径 | 修订、季调、分类变化 | 商业数据库 | 必须追溯原始字段 |
| 商品/运价 | 交易所/专业价格源 | 库存、现货、公司披露 | 规格、地区、成交量、风险溢价 | 新闻报价 | 只能背景或弱信号 |

## 11. 获取失败代码与回退

| failure_code | 含义 | 默认动作 |
|---|---|---|
| `not_found` | 当前查询未发现 | 扩展关键词/时间/对象后按停止规则判断 |
| `access_denied` | 无权限或授权过期 | 切换合规公开源并降低上限 |
| `field_unavailable` | 目标字段不存在或停更 | 查方法说明、替代字段或代理规则 |
| `scope_mismatch` | 对象/地区/产品不匹配 | 不计入，寻找匹配来源 |
| `time_mismatch` | 业务时间不覆盖窗口 | 更换频率或等待更新 |
| `method_opaque` | 样本/方法不透明 | 只作受限输入或交叉线索 |
| `trace_missing` | 无原始定位/字段血缘 | 回源；失败则不得正式使用 |
| `channel_error` | API/MCP/网页获取故障 | 可换通道但保持同一来源身份 |

每次回退必须记录替代来源是否改变独立性、方法、权限和 Recipe 门槛。

## 12. 来源发现与正式取证分离

搜索引擎、新闻、研报和 AI 可生成候选来源队列；只有回到原始材料并完成 SourceDocument 登记后，候选材料才能转为正式证据。来源发现阶段的摘要不得复制为 `normalized_fact`。
