# B01_来源分层与使用边界

## 分层不是简单打分

同一来源在不同主张上的价值不同：监管原文适合确认规则，不适合单独证明商业影响；公司披露适合确认自身经营口径，但对行业总量和竞争对手可能存在选择性；专业调研适合观察细分趋势，却必须核对样本。研究员应同时写“最适合证明什么”和“绝不能据此推出什么”。

遇到冲突时，先比对象、业务时间、定义、样本和方法，再比来源层级；不要机械地让“更高层级”覆盖更贴近业务的观测。

## 1. 定位

本文定义 03 取证时的来源分层和使用边界。它解决的问题不是“来源数量够不够”，而是：

1. 这个来源能不能支撑当前证据角色；
2. 这个来源最多能支持什么判断强度；
3. 这个来源是否需要交叉验证；
4. 这个来源在哪些情况下必须降级；
5. 这个来源能否用于 04 推理和 05 表达。

## 2. 来源分层总览

| 层级 | 来源类型 | 典型来源 | 主要用途 | 默认使用边界 |
|---|---|---|---|---|
| S1 | 官方、监管、交易所、政策原文 | 政府部门、监管机构、交易所、法院、海关、统计局 | 政策事实、监管要求、公告事实、官方统计 | 可作为事实确认主源，但不能自动推出实际影响 |
| S2 | 公司正式披露 | 年报、季报、公告、招股书、IR 材料、业绩会纪要 | 公司财务、经营披露、管理层指引 | 可作为公司事实主源；指引和观点必须与已发生事实区分 |
| S3 | 授权金融市场数据库 | Wind、Bloomberg、FactSet、Refinitiv、iFinD、Capital IQ、交易所行情库 | 行情、估值、财务、预测一致预期、可比公司数据 | 适合结构化数据，但必须记录字段口径和授权边界 |
| S4 | 行业专业数据源 | 行业协会、专业研究机构、细分行业数据库、行业交易平台、行业统计口径；具体见 B03 行业来源文件 | 行业规模、价格、出货、库存、产能、份额 | 适合行业证据，但要说明方法论、覆盖范围和更新频率 |
| S5 | 一手经营、调研和内部材料 | 内部数仓、业务系统、渠道调研、专家访谈、客户反馈、供应链反馈 | 订单、库存、交期、客户需求、经营边际变化 | 对边际变化很有价值，但要处理样本偏差、权限和可表达边界 |
| S6 | 卖方研报、专家观点、第三方研究 | 券商报告、专家会议纪要、产业研究报告、咨询报告 | 逻辑线索、市场预期、竞争解释、来源发现 | 不能单独作为硬事实证据；引用其中数据时需追溯原始来源 |
| S7 | 新闻媒体、公开网页和转载 | 财经媒体、行业媒体、公司新闻稿、博客、论坛 | 事件线索、公开叙事、市场情绪、来源发现 | 一般不能作为关键事实唯一证据 |
| S8 | 搜索结果、AI 摘要、模型回答 | 搜索引擎摘要、AI 回答、网页聚合摘要 | 帮助发现来源、整理线索 | 不得作为正式证据来源 |

### 2.1 B02/B03/B04 与来源层级的关系

B02、B03、B04 是来源组织方式，不是新的来源等级。

| 文件/目录 | 组织逻辑 | 与 S1-S8 的关系 |
|---|---|---|
| B02 通用来源 | 按通用证据篮子组织来源 | 可包含 S1-S8 各层来源 |
| B03 行业专用来源 | 按行业变量组织来源 | 通常以 S2/S4/S5 为主，也会引用 S1/S3/S6/S7 |
| B04 专题来源 | 按跨行业冲击机制组织来源 | 通常以 S1/S2/S3/S4/S7 为主，视专题而定 |

因此，不能说“B03 来源天然更权威”或“B04 来源天然可以支撑结论”。任何具体来源仍必须回到 S1-S8 分层中判断：它能证明什么、不能证明什么、是否需要交叉验证、是否会降低 04 最多能形成的结论。

S1-S8 是 03 取证来源选择时的分层规则，可映射到 SourceProfile.sourceTier，但不等同于 SourceProfile 对象本身。实际取得材料仍必须登记为 SourceDocument，并单独记录 acquisitionChannel、accessScope、artifactType、contentDomain 和 locator。

### 2.2 全球来源与中国来源的分层规则

全球来源和中国来源按同一套 S1-S8 规则处理。来源是否可用，不取决于来源所在国家或语言，而取决于：

1. 是否为原始生产者或法定披露渠道；
2. 是否有明确发布时间、业务时间和适用范围；
3. 是否有可复核路径；
4. 是否说明口径、单位、样本、频率和修订情况；
5. 是否能支撑当前证据角色。

涉及中国资产、中国政策、中国贸易、中国公司、中国行业运行时，中国官方、监管、交易所、海关、统计、公司披露等主源应优先检查；涉及海外政策、海外市场或海外公司时，应同时检查海外原文和中国侧响应、公告或披露。

## 3. S1 官方、监管、交易所、政策原文

### 3.1 适合支持

1. 政策是否发布；
2. 监管要求是否存在；
3. 交易所公告是否披露；
4. 统计口径明确的官方数据；
5. 法律、规则、制裁、关税、出口管制等正式文本。

### 3.2 不足以支持

1. 政策对产业链的实际影响；
2. 公司经营结果；
3. 市场预期；
4. 投资结论；
5. 执行效果是否已经发生。

### 3.3 降级规则

出现以下情况应降级：

1. 只找到新闻转述，未找到原文；
2. 原文发布时间、生效时间、适用范围不清；
3. 文件有修订、豁免、过渡期但未检查；
4. 用政策名称推断影响对象，未核对正文适用范围。

## 4. S2 公司正式披露

### 4.1 适合支持

1. 公司历史财务数据；
2. 公司已披露经营事实；
3. 公司产品、客户、产能、资本开支、业务线结构；
4. 管理层指引和经营计划；
5. 公司对政策、需求、价格、成本变化的正式表述。

### 4.2 不足以支持

1. 行业整体状态；
2. 未披露订单和客户真实需求；
3. 同业比较结论；
4. 管理层观点本身不能替代已发生事实；
5. 单家公司披露不能直接代表全行业。

### 4.3 降级规则

出现以下情况应降级：

1. 把“预计”“计划”“指引”写成已发生事实；
2. 只引用公司新闻稿，不核对公告或财报；
3. 使用非同口径历史数据做趋势判断；
4. 用单家公司信息外推全行业，且无交叉验证。

## 5. S3 授权金融市场数据库

### 5.1 适合支持

1. 股价、成交量、估值倍数；
2. 财务数据和财务预测；
3. 一致预期；
4. 可比公司数据；
5. 利率、汇率、商品、债券、指数等市场数据。

### 5.2 不足以支持

1. 未披露订单；
2. 产业链真实交期；
3. 专业行业价格口径；
4. 公司未公开经营变化；
5. 政策原文事实。

### 5.3 降级规则

出现以下情况应降级：

1. 没有记录字段名、查询条件和数据截止时间；
2. 一致预期未说明样本变化和更新时间；
3. 不同数据库字段混用但未说明口径差异；
4. 授权边界不清；
5. 通过截图或二次整理表格取数，无法复核原字段。

## 6. S4 行业专业数据源

S4 行业专业数据源应优先在 B03_行业专用来源目录中维护。B01 只定义其通用使用边界，不维护完整行业名单。

### 6.1 适合支持

1. 行业价格；
2. 行业规模；
3. 出货量；
4. 库存；
5. 产能和利用率；
6. 市占率；
7. 细分产品供需。

### 6.2 不足以支持

1. 单家公司未披露经营事实；
2. 投资评级；
3. 估值结论；
4. 具体客户订单；
5. 公司财务结果。

### 6.3 降级规则

出现以下情况应降级：

1. 数据供应商方法论不清；
2. 产品口径、地区口径、统计周期不清；
3. 用行业数据直接推公司弹性；
4. 把预测数据当作已发生事实；
5. 只使用单点数据判断趋势。

## 7. S5 一手经营、调研和内部材料

### 7.1 适合支持

1. 订单边际变化；
2. 交期变化；
3. 渠道库存；
4. 客户需求反馈；
5. 供应链瓶颈；
6. 内部业务事实；
7. 公开数据无法覆盖的高频或边际变化。

### 7.2 不足以支持

1. 全市场统计结论；
2. 可外发的正式事实；
3. 无样本说明的行业判断；
4. 无权限说明的正式证据；
5. 不经处理的投资结论。

### 7.3 降级规则

出现以下情况应降级：

1. 样本来源不清；
2. 样本数量和代表性不清；
3. 无业务时间；
4. 无权限边界；
5. 无交叉验证；
6. 调研对象存在明显立场偏差但未说明。

## 8. S6 卖方研报、专家观点、第三方研究

### 8.1 适合支持

1. 市场主流叙事；
2. 竞争解释；
3. 预期差线索；
4. 行业逻辑线索；
5. 原始来源发现；
6. 观点分歧和情景假设。

### 8.2 不足以支持

1. 已发生事实的唯一证据；
2. 官方政策事实；
3. 公司财务披露事实；
4. 未披露订单和真实库存；
5. 未追溯来源的关键数值。

### 8.3 降级规则

出现以下情况应降级：

1. 不追溯研报引用的数据原始来源；
2. 把分析师预测当作事实；
3. 用多篇研报观点数量替代独立交叉验证；
4. 用单一卖方观点代表市场预期；
5. 没有区分事实、估算、预测、观点和假设。

## 9. S7 新闻媒体、公开网页和转载

### 9.1 适合支持

1. 事件线索；
2. 公开叙事；
3. 市场关注点；
4. 来源发现；
5. 时间线辅助整理。

### 9.2 不足以支持

1. 政策事实唯一证据；
2. 公司财务唯一证据；
3. 行业趋势唯一证据；
4. 订单、库存、交期等关键经营事实；
5. 方向性投资判断。

### 9.3 降级规则

出现以下情况应降级：

1. 只有标题，没有原文；
2. 没有发布时间；
3. 转述链不清；
4. 引用匿名消息源；
5. 多家媒体转述同一原始消息，却当作独立验证。

## 10. S8 搜索结果、AI 摘要、模型回答

### 10.1 适合支持

1. 快速发现可能来源；
2. 提取候选关键词；
3. 生成初步检索路径；
4. 辅助整理已验证来源。

### 10.2 不足以支持

1. 任何正式事实；
2. 任何关键数据；
3. 任何方向性结论；
4. 任何需要可追溯引用的证据。

### 10.3 降级规则

只要证据来源停留在搜索结果、AI 摘要或模型回答层面，不得进入有效证据计数。

## 11. 来源层级与 04 最多能形成的结论

B02/B03/B04 只帮助选择来源，不自动提高判断强度。04 最多能形成的结论仍以具体证据的来源层级、可复核性、口径匹配度和反证完成度为准。

| 证据情况 | 04 最多能形成的结论 |
|---|---|
| S1/S2/S3/S4 主源可复核，口径匹配，反证检查完成 | 可进入方向性判断 |
| S3/S4 数据可复核但口径有限 | 只能方向性或条件判断 |
| S5 一手材料有样本说明并交叉验证 | 可作为边际变化证据 |
| S5 无样本说明或权限不清 | 只能作为背景或线索 |
| S6 只有观点，无原始来源追溯 | 只能作为市场预期或竞争解释 |
| S7 只有新闻线索，无原始来源 | 只能作为线索 |
| S8 搜索或 AI 摘要 | 不得作为正式证据 |

## 12. 一句话原则

> 来源分层不是按“看起来权威”排序，而是按它能否以可复核方式支撑当前判断单元排序。

## 13. 证据角色适配矩阵

同一来源在不同证据角色中的适用性不同：

| 来源层 | 事实确认 | 状态测量 | 机制/暴露 | 市场预期 | 反证 | 默认不能替代 |
|---|---|---|---|---|---|---|
| S1 | 强 | 官方统计可强 | 执行事实中等，实际影响弱 | 弱 | 修订/否认强 | 公司经营结果 |
| S2 | 公司事实强 | 公司变量强 | 公司暴露/行为强 | 管理层预期，不是市场共识 | 公司约束中强 | 全行业状态 |
| S3 | 结构化市场事实强 | 市场/财务强 | 机制通常弱 | 一致预期和定价强 | 价格/共识反证强 | 政策原文、未披露经营事实 |
| S4 | 行业数据事实中强 | 行业状态强 | 行业机制中强 | 行业预测不等于市场共识 | 分项与方法反证强 | 公司未披露事实 |
| S5 | 样本内事实中强 | 高频边际强 | 行为/瓶颈强 | 投资者反馈有限 | 阻断与反向样本强 | 无样本说明的总体结论 |
| S6 | 需回源 | 估计/预测有限 | 逻辑和竞争解释强 | 观点分布中强 | 竞争解释强 | 硬事实唯一证据 |
| S7 | 线索 | 弱 | 事件线索中等 | 叙事热度中等 | 线索 | 方向性判断主证据 |
| S8 | 不可 | 不可 | 不可 | 仅发现线索 | 仅发现线索 | 任何正式证据 |

“强/中/弱”仍需服从具体 SourceProfile、SourceDocument 和任务适配评价。

## 14. 独立来源组判定

以下通常属于同一 independence_group：

- 多家媒体转述同一官方文件或匿名消息；
- 多篇研报引用同一行业数据库字段；
- 同一公司年报、IR 演示和业绩会对同一数字的重复披露；
- 不同数据库转售同一交易所或统计机构原始数据；
- 同一专家访谈被多个纪要或摘要重复整理。

互补来源不一定完全独立，但可以承担不同角色。例如公司披露证明自身出货，行业数据库证明行业价格，客户披露验证需求。03 应记录 `independence_group_id` 和“独立/互补/同源”的性质，不把材料数量当独立性。

## 15. 方法透明度与修订风险

S3/S4/S5 来源用于动态测量时，至少检查：

1. 样本总体、覆盖率和样本变化；
2. 指标定义、单位、加权和异常处理；
3. 发布时间、业务时间、更新频率和历史修订；
4. 预测、估计与实际值的标识；
5. 历史序列是否回填或重述；
6. 是否允许导出、引用和对外展示。

方法不透明不必一律弃用，但不得达到依赖方法透明度的 Q4 图表或精确排序用途。

## 16. 来源组合最低原则

- 事实问题优先“责任主体原文 + 修订/反证检查”；不机械要求两个来源；
- 状态和趋势优先“直接测量 + 独立或机制互补验证”；
- 机制问题优先“起点主源 + 中介行为/状态 + 结果来源”；
- 对象排序优先“同口径数据 + 公司承接约束 + 排序反证”；
- 预期差优先“事前一致预期 vintage + 相对价格 + 估值输入”；
- 反证来源应尽量独立于支持链，但必须保持对象、时间和口径对称。

## 17. `minimumSourceTier` 的解释

现有 EvidenceRequirement/EvidenceBasket 使用单值 `minimumSourceTier` 作为快速门槛，但 S1—S8 本质是来源角色分类，不是严格连续分数。运行时必须同时检查 `requiredContentDomains`、`allowedClaimTypes`、`forbiddenUse` 和 SourceProfile 方法透明度。

因此：

- `minimumSourceTier=S4` 不表示 S1/S2 在所有场景都自动优于 S4；
- 行业价格需求若要求 S4，S1 政策文件不能替代行业专业测量；
- 市场一致预期若要求 S3，公司指引 S2 不能自动替代市场共识；
- 如实际来源类型不同但更直接适配，应记录例外理由，而不是只改层级数字；
- 后续自动化匹配应优先使用“允许 SourceProfile 集合 + 内容域 + 主张类型”，单值 tier 只作粗筛。
