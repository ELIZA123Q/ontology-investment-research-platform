# 00A_高质量产出判别标准

## 研究员读法

不读 YAML，也能用这五条自检「能不能用」：

1. **问题有没有被偷换** — 对象、时间、范围、用途是否仍是 01 要答的那个问题；
2. **有没有判断价值** — 是否说清分歧、主导机制、竞争解释，而不是材料堆砌；
3. **证据有没有越权** — 每条重要观点是否超过证据最多能支持的强度；
4. **读者能不能直接用** — 当前判断、依据、边界、下一步跟踪是否一目了然；
5. **证据不足时有没有硬撑** — 「暂不可判断」但边界清楚，可以是高质量；硬编方向反而不合格。

正式发布还须通过全链校验（见第 5 节）。下面「权威状态字段」与组合矩阵供执行/校验；研究员日常用上表即可。

人话对照（结论能说到哪一层）：

| 强度 | 研究员读作 |
|---|---|
| J0 | 只能说明缺口，不形成方向 |
| J1 | 事实观察或线索 |
| J2 | 有条件的方向判断 |
| J3 | 方向判断或高概率判断 |
| J4 | 在明确对象、时间、范围内可确认 |

证据把握人话：充分 / 受限 / 观察 / 不可用（机器字段 Q3–Q4 / Q2 / Q1 / Q0）。

## 2. 高质量的总体定义

高质量产出必须同时满足以下原则：

1. **不偷换问题**：对象、比较范围、时间口径、范围、用途、前提约束、结论粒度和最终要回答的问题与 01《投研需求说明》一致。
2. **有判断价值**：产出能够识别关键分歧、主导机制、竞争解释和影响判断的信号，不是材料堆砌或模板拼贴。
3. **证据不越权**：每条重要观点不超过对应证据最多能支持的强度，反面证据、冲突和限制得到处理。
4. **读者可使用**：研究员不阅读 YAML 或审计字段，也能理解当前判断、依据、边界和下一步跟踪。05 正式稿必须使用研究语言表达边界；不得把 04 的权限否定句、禁止项原文抬成标题或投资要点。
5. **可复核、可返工**：上游输入、证据、路径、观点和表达能够对应，失败时可以定位到具体阶段。

高质量不等于必须形成方向性结论。证据不足时，边界清楚、缺口明确、没有强行下结论的“暂不可判断”可以是高质量结果。

## 3. 权威状态字段（校验用）

执行端只允许人工维护下列权威字段。同一对象、同一运行、同一层级只能有一个权威值；其他带 `status`、`level` 或 `permission` 的字段只能是过程观测或规则结果，不能反向覆盖这些字段。

| 维度 | 唯一权威字段 | 研究员读作 |
|---|---|---|
| 阶段是否完成 | `stage_status` | 本阶段还在做、做完了、卡住了还是退回了 |
| 本阶段输出质量 | `quality_status` | 草稿 / 最低通过 / 高质量 / 需返工 / 缺口停止 |
| 证据质量 | `evidence_grade`（Q0—Q4） | 不可用 / 观察 / 受限 / 充分 |
| 判断强度 | `judgment_level`（J0—J4） | 见文首人话对照 |
| 路径是否够用（03） | `path_readiness_status` | 能不能推：够用 / 受限 / 阻断 / 不适用 |
| 路径推理结果（04） | `path_result_status` | 推出来是什么：成立 / 部分成立 / 削弱 / … |

`path_readiness_status` 与 `path_result_status` 必须分开填写：前者「能不能推」，后者「推出来是什么」。

`stage_status` 统一使用 `not_started`、`in_progress`、`complete`、`blocked`、`returned`。不得混入业务处置结果。01 另用 `task_disposition` 记录受理处置（`accepted` / `needs_clarification` / `out_of_scope` / `split_required`）。

以下字段只能由规则计算，不得人工填写：`evidence_permission`、`allowed_04_output`、`maximum_judgment_level`、`publishable`。

### 3.1 本阶段输出质量

| 状态 | 含义 | 正式发布 |
|---|---|---|
| `draft` | 尚未完成检查 | 不允许 |
| `minimum_pass` | 达到最低内部流转条件 | 不允许 |
| `high_quality_pass` | 本阶段规则校验通过 | 允许进入全链发布检查 |
| `return_required` | 存在必须修正的问题 | 不允许 |
| `stop_with_gap_report` | 当前条件不足，只能形成缺口说明 | 仅可发布高质量缺口结果，不得包装成方向性判断 |

### 3.2 证据质量

`evidence_grade` 是对一个核心判断的最终证据把握，不能用来源层级、单项可靠度或材料数量替代。

### 3.3 结论强度

结论强度回答具体观点能够说到什么程度，与阶段状态和本阶段输出质量无关。04 必须为每条重要观点单独确定强度。

### 3.4 结论强度上限怎么确定（校验用）

项目只在 [`../governance/03_校验/status_derivation.py`](status_derivation.py) 维护一套规则：根据证据等级、反证检查结果、路径是否够用，按规则给出该核心判断的结论强度上限（最大 J）以及允许的表达方式。规范、策略库、模板和示例不得另建第二套可编辑对照表。

规则按三个输入分别给出上限，再取其中最低值：

| 输入（业务含义） | 取值 | 对最大 J 的上限 |
|---|---|---|
| 证据等级 `evidence_grade` | `Q0 / Q1 / Q2 / Q3 / Q4` | `J0 / J1 / J2 / J3 / J4` |
| 反证检查结果（机器归一化） | `cleared / weakened / contested / decisive / not_checked / not_applicable` | `J4 / J2 / J1 / J0 / J1 / J4` |
| 路径是否够用 `path_readiness_status` | `ready / restricted / blocked / not_applicable` | `J4 / J2 / J0 / J4` |

展开后共有 120 种组合。系统对三个上限取最低值一次，得到唯一的最大 J。路径推理结果不得拿来反推最大 J。04 只填写实际 `judgment_level` 与 `path_result_status`，校验器确认未超上限。

## 4. 规则校验

规则校验处理能够无歧义执行的要求，包括：文件/版本/字段是否合法；任务与范围是否一致；上下游引用与证据哈希是否可解析；跨阶段主链是否可对账；是否超过上游允许范围；应返回哪个阶段。

规则校验由各阶段 `validate_*_outputs.py` 与 `validate_publish.py` 执行。规则未通过时不得发布。

03 必须维护两个正交结果：证据是否够用、展示素材是否就绪。`high_quality_pass` 只评价证据准备，不得因缺少图表而失败；相关缺口只影响展示就绪度。

## 5. 正式发布条件

正式发布必须同时满足：

1. 01—05 所需本阶段输出完整，且属于同一次任务和运行；
2. 每阶段规则校验通过；
3. 每阶段达到 `high_quality_pass`，或形成符合阶段规范的高质量缺口结果；
4. 03 明确证据能够支持到什么程度；
5. 04 每条观点未超过 03 的证据上限；
6. 05 未新增未经 03/04 支撑的事实、判断或更强表达；
7. 全链不存在未说明的范围漂移、引用断裂或越权结论。

`validate_run.py` 是新 run 的正式发布入口。本阶段输出中填写的 `quality_status` 不能单独证明可以发布；任何交付物不得人工填写 `publishable`。高质量的 J0/J1 缺口或观察结果可以发布，不能把“没有方向性结论”误判为研究失败。

## 6. 返工原则

质量问题必须回到最早产生问题的阶段，不得只在下游改写措辞掩盖上游缺陷。

| 问题来源 | 返回阶段 |
|---|---|
| 问题、用途、对象、时间或范围不清 | 01 |
| 核心待验证命题、问题拆解、变量、路径或竞争解释有误 | 02 |
| 数据、来源、口径、证据质量、反证或展示素材不足 | 03 |
| 证据已经具备，但推理、观点强度、分化判断或审计有误 | 04 |
| 上游判断正确，但报告结构、表达、图表组织、审计腔未改写或追溯关系不合格 | 05 |

返工记录必须说明具体问题、影响对象、返回阶段、需要修改的内容和重新检查方式。返回上游后，下游依赖本阶段输出必须重新校验。

## 7. 唯一发布原则

项目可以保存草稿、内部流转件和历史版本，但不能把它们作为正式结果交付。正式目录中一次运行只能有一份正式 05 交付物；任何未达到高质量要求的环节都必须继续修正、返回上游或形成高质量缺口说明，不能通过降低发布标准结束流程。
