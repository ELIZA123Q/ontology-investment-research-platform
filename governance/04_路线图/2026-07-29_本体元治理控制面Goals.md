# 2026-07-29 本体演进治理本体 Goals

状态：completed

版本：2.0.0

当前权威：`governance/05_元治理本体/model_registry.yaml`

## 一、目标决策

在 `governance/` 内建立独立的本体演进治理本体，借鉴 Palantir Ontology 的 Object Type、
Link Type、Action Type、Interface、Branch、Proposal、Check、Approval、Action Log 和 Release 思路，
完整管理正式投研本体的演进。

它不是与语义结构域、判断推理域、证据域并列的第四个投研业务域。治理模型只管理资产与变更，
不得进入正式本体注册表、投研业务实例图或商业规则求值。

## 二、成功标准

1. `governance/05_元治理本体/` 具有独立元模式、模型注册表、模型文件和实例图。
2. YAML 明确定义共享属性、接口、治理对象、治理关系、Action、规则、角色和批准策略。
3. 变更闭环覆盖 Branch—Proposal—Impact—Rebase—Approval—Implementation—Validation—Migration—Release。
4. Runtime 的 ChangeProposal 状态与迁移直接读取治理本体 YAML，不维护平行状态机。
5. 变更写入使用类型化 Action API；旧 `next_status` API 仅作为标记过时的兼容投影。
6. 每次 Action Log 保存 Action 类型、版本、角色、输入、结果、编辑对象和前后指纹。
7. 机器校验覆盖模型注册闭包、接口实现、关系逆向、Action 引用、状态图、实例类型和正式本体隔离。
8. 旧控制合同与资产目录降级为只读兼容指针，不再作为事实源。

## 四、不可违反的边界

1. 不在 `ontology/01_通用/model_registry.yaml` 注册任何 `gov.*` 模型。
2. 不把审批、权限、分支、发布状态编码成投研业务对象。
3. 不允许治理检查、批准结果或 ActionLog 支撑投资判断。
4. 不由候选队列直接修改正式本体 YAML；候选只负责创建 ChangeProposal。
5. 不因本体升级覆盖历史研究产物；只记录影响、迁移、重算或历史只读状态。
6. 治理例外不得覆盖正式本体语义正确性。

## 五、发布条件

```text
ProposeOntologyChange
  → FreezeImpactAssessment
  → 必要时 RebaseOntologyProposal
  → ApproveOntologyChange
  → RecordOntologyImplementation
  → AttestValidationResults
  → 破坏性变更完成 MigrationTask
  → ReleaseOntologyBaseline
```

每个箭头都由 Action Type 定义；状态是执行结果，不是调用方可任意指定的命令。
