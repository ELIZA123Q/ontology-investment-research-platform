# 仓库地图与文件治理

本文回答两个问题：

1. 一个不熟悉项目的研究员应从哪里读、哪些目录可以先跳过；
2. 一个文件为什么存在，什么时候应合并、归档或删除。

项目入口仍是根目录 [`README.md`](../../README.md)。本文是目录职责与保留规则的权威说明，不重复各阶段的业务规范。

## 1. 先按读者选择入口

| 你现在要做什么 | 第一入口 | 后续按需打开 | 先不要读 |
|---|---|---|---|
| 快速理解项目 | [`README.md`](../../README.md) | 两个 [`V3 样例`](../../instances/02_V3样例) 的 `05_report.md` | 合同、校验脚本、Runtime 源码 |
| 做一次研究 | [`workflow/`](../../workflow) | 对应阶段的 [`methods/`](../../methods) 与 [`delivery/`](../../delivery) | 迁移账本、路线图 |
| 核对概念或关系 | [`ontology/README.md`](../../ontology/README.md) | 通用或半导体说明；最后才看 YAML | 评测运行产物 |
| 使用本机工作台 | [`runtime/README.md`](../../runtime/README.md) | 页面；发生错误时再看开发说明 | `runtime/engine/` |
| 维护合同或代码 | [`CONTRIBUTING.md`](../../CONTRIBUTING.md) | `governance/`、`runtime/`、测试 | 本机导出 |
| 判断项目是否真有增益 | [`evaluation/README.md`](../../evaluation/README.md) | 决策日志、协议、冻结运行 | 只看工程测试数 |

研究员理解主线只有一条：

```text
问题 → 01 受理 → 02 结构 → 03 证据 → 04 判断 → 05 表达
```

`workflow` 规定每一步交什么，`methods` 提供可复用做法，`ontology` 提供统一语义和约束，`runtime` 执行流程，`instances` 保存冻结结果，`delivery` 负责表达，`evaluation` 判断结果是否真有研究价值。

## 2. 顶层目录审计结论

| 目录 | 角色与权威边界 | 是否过程稿 | 当前处置 |
|---|---|---|---|
| [`workflow/`](../../workflow) | 01—05 阶段合同；规定每阶段输入、动作、产出和门槛 | 否 | 保留独立，不与方法或模板合并 |
| [`methods/`](../../methods) | 判断结构、取证、裁决的可复用方法正文 | 否 | 保留独立；单次结论不得写回 |
| [`ontology/`](../../ontology) | 稳定对象、关系、枚举与正式约束 | 否；`03_迁移` 是历史账本 | 保留；迁移文件不作为当前入口 |
| [`instances/`](../../instances) | 黄金样例、正式包回归、本机运行 | 部分是生成结果 | Git 只保留冻结夹具；本机运行不入库 |
| [`delivery/`](../../delivery) | 05 表达标准与报告模板 | 否 | 保留；与 `workflow/stages/05` 分工不同 |
| [`evaluation/`](../../evaluation) | 研究价值评测协议、案例、运行、报告和决策 | 运行目录是冻结过程证据 | 协议/案例/决策入库；报告按规则筛选 |
| [`runtime/`](../../runtime) | 本机工作台、编排引擎、适配器与测试 | 构建缓存是生成物 | 源码保留；`.next`、`node_modules` 不入库 |
| [`governance/`](../../governance) | 项目定位、机器合同、校验、路线图 | `04_路线图` 有时效但不是草稿堆 | 当前契约保留；路线图用索引区分状态 |

## 3. 相似文件为什么暂不合并

### 3.1 `workflow/05` 与 `delivery/`

- `workflow/stages/05_表达` 是阶段合同：什么时候可以进入 05、必须消费哪些上游判断、交什么。
- `delivery/` 是表达资产：不同报告类型怎样组织、怎样避免抬高结论强度。

二者看起来都谈“表达”，但权威问题不同，合并后会把阶段门与写作资产混成一套。

### 3.2 Ontology 的 Markdown 与 YAML

- Markdown 是给人看的解释和边界。
- YAML 是 Runtime 与校验器读取的机器权威。

它们是同一语义的两种投影，不是两个平行定义。冲突时以 `model_registry.yaml` 纳入的正式 YAML 和治理合同为准，Markdown 必须随之更新。

### 3.3 三种研究包

| 包类型 | 位置 | 保留原因 |
|---|---|---|
| `semantic_fixture` | `instances/02_V3样例` | 验证本体与公共合同语义 |
| `formal_pack` | `instances/03_回归/02_memory-cycle-formal-pack` | 验证正式中文发布包与发布门 |
| `workbench_export` | `instances/03_回归/01_tsmc-revenue-workbench` | 验证工作台紧凑导出、回放和 A/B 绑定 |

相同课题出现在不同包中不等于冗余。包的入口、字段和校验目标不同，不应互相冒充。

### 3.4 评测案例中的冻结副本

`evaluation/02_案例/RV-T01` 的 `reasoning_logic.md`、`judgment_brief.md`、`system_artifact.md` 与
`instances/03_回归/02_memory-cycle-formal-pack` 中三份文件内容相同。这里有意保留副本：

- 评测案例需要冻结输入，避免正式包日后更新导致历史评测不可复现；
- 正式回归包需要完整、自包含地通过自己的包校验。

这类副本必须注明来源并以哈希冻结，不应人工分别修改。若内容升级，应通过案例准备流程同时刷新，而不是只改一边。

### 3.5 AI 工具上下文

`CLAUDE.md`、`.cursor/rules/03-evidence-sources.mdc` 与 `.workbuddy/project.md` 为不同工具的自动加载入口。它们不是研究文档，不合并成单文件是工具约束；核心事实应保持一致。`CLAUDE.md` 是人工维护主文件，通道变化时按 [`CONTRIBUTING.md`](../../CONTRIBUTING.md) 同步。

### 3.6 评测报告与决策日志

- `evaluation/04_报告` 保存带运行细节的完整报告或历史审计；
- `evaluation/05_决策日志` 保存可公开复述、需要长期记住的结论和硬门。

完整报告可能过时，但仍解释“当时为何作出决定”；决策日志才是后续工作的短入口。两者不应逐字复制，历史报告必须在文首标明状态。

## 4. 什么应删除、什么应保留

### 直接删除

- `.DS_Store`、`__pycache__`、`*.pyc`；
- `.next/`、`node_modules/`、`.vite/`；
- 测试产生的临时 SQLite；
- 已经回写到正式文档的按日 AI 工作日志；
- 没有引用、没有冻结用途、可以由脚本无损重建的中间产物。

### 本地保留但不进 Git

- `instances/00_本机运行/workbench.sqlite`；
- `instances/00_本机运行/exports/<run-id>`；
- `instances/00_本机运行/formal/<主题>-<日期>-<序号>`；
- `.env.local`、API Key、临时评测目录。

这些文件可能对当前研究有用，不能因为“未入库”就自动删除。正式交付或回归需要的内容应经过校验后复制为冻结包。

### 入库保留

- 当前权威规范、合同、本体、方法、模板；
- 能被校验器或测试引用的冻结夹具；
- 支撑决策边界的评测协议与里程碑决策；
- 仍需追溯兼容性的迁移账本；
- 有明确状态、负责人或验收条件的路线图账本。

## 5. 文件新增与收口规则

新增文件前先给它选择一种角色：

| 角色 | 应放哪里 | 必须说明 |
|---|---|---|
| 权威规范 / 合同 | `workflow`、`methods`、`ontology`、`governance/02_合同` | 管什么、不管什么、机器权威在哪里 |
| 人类导览 | 就近 `README.md` 或本文件 | 读者、推荐顺序、跳转入口 |
| 模板 | 对应阶段的 `模板/` 或 `delivery/02_模板` | 产物类型与校验入口 |
| 冻结样例 / 回归 | `instances/02_V3样例` 或 `instances/03_回归` | 包类型、来源、冻结日期、校验命令 |
| 评测证据 / 决策 | `evaluation/04_报告` 或 `evaluation/05_决策日志` | 日期、范围、已证明、未证明 |
| 路线图 / 迁移账本 | `governance/04_路线图` 或 `ontology/03_迁移` | 状态、替代入口、剩余事项 |
| 本地生成物 | 已忽略目录 | 生成方式与是否可删 |

禁止用 `最终版`、`最新版`、`v2-final`、`copy` 继续堆副本。版本应写入合同字段、文件内版本号或 Git 历史；同一角色只能有一个当前入口。
